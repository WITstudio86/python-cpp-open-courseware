第21课：Kruskal 算法
最小生成树 · 并查集 · 贪心策略 · 割性质证明

🎯 本课核心

  • Kruskal 算法：基于边排序的贪心 MST 算法，复杂度 O(E log E)
  • 并查集 (DSU)：路径压缩 + 按秩/大小合并，操作近乎 O(1)
  • 正确性证明：利用割性质 (Cut Property) 的反证法
  • MST 唯一性：同权边组判定法
  • 最小瓶颈生成树 (MBST)：最大边权最小化
⚡ Kruskal 核心思想：将所有边排序，从小到大依次尝试加入，若不会形成环（并查集判定）则入选，直到选满 n-1 条边。
并查集 (DSU)
Kruskal 算法的核心数据结构

📌 两个核心操作

  • Find(x)：查找 x 所在集合的代表元（根节点）
  • Union(x, y)：合并 x 和 y 所在的两个集合

⚡ 两大优化

  • 路径压缩 (Path Compression)：查找时把沿途节点直接挂到根上
  • 按大小合并 (Union by Size)：始终把小树合并到大树上
同时使用两种优化后，m 次操作均摊复杂度 O(m · α(n))，其中 α(n) 是反阿克曼函数，在实际中 ≤ 4，可视为常数。

💻 实现代码

struct DSU { vector<int> fa, sz; DSU(int n) { fa.resize(n + 1); sz.resize(n + 1, 1); for (int i = 1; i <= n; i++) fa[i] = i; } int find(int x) { return fa[x] == x ? x : fa[x] = find(fa[x]); } bool merge(int x, int y) { x = find(x); y = find(y); if (x == y) return false; if (sz[x] < sz[y]) swap(x, y); fa[y] = x; sz[x] += sz[y]; return true; } };
Kruskal 算法流程
贪心选边 + 并查集判环

📋 算法步骤

  1. 将所有 m 条边按权值从小到大排序
  2. 初始化并查集，每个顶点自成一个集合
  3. 遍历排序后的边列表：若 u, v 不在同一集合（不形成环），则选中此边，合并 u, v
  4. 已选边数达到 n-1 时提前退出
  5. 若最终选中边数 < n-1，说明图不连通

💻 核心代码

long long kruskal(int n, vector<Edge>& edges) { sort(edges.begin(), edges.end()); // O(E log E) DSU dsu(n); long long mst = 0; int cnt = 0; for (auto& e : edges) { if (dsu.merge(e.u, e.v)) { mst += e.w; cnt++; if (cnt == n - 1) break; // 提前退出 } } return (cnt == n - 1) ? mst : -1; }
步骤复杂度
边排序O(E log E)
并查集初始化O(V)
遍历边 + 合并O(E · α(V))
总计O(E log E)
📌 适用场景：稀疏图 (E ≈ V) 表现优异。稠密图考虑 Prim。
贪心正确性证明
割性质 + 反证法

📐 割性质 (Cut Property)

设 S 是顶点集 V 的任意非空真子集，e = (u, v) 是跨越割 (S, V\S) 的最小权边，则 e 一定属于某棵 MST。

🧾 Kruskal 正确性证明（反证法）

  1. 设 Kruskal 选择的边集为 T = {e₁, ..., eₙ₋₁}
  2. 假设 T 不是最小生成树
  3. 令 T* 是与 T 前 k 条边一致的最优 MST（k 尽可能大，k < n-1）
  4. 将 eₖ₊₁ 加入 T* 会形成一个环 C
  5. 环 C 上必然存在边 f 跨越 eₖ₊₁ 选择时 u,v 所在的两个不同集合
  6. 由贪心排序知 w(eₖ₊₁) ≤ w(f)
  7. 若严格小于 → 替换后得到更优 MST，矛盾
  8. 若相等 → 替换后 MST 与 T 前 k+1 条边一致，与 k 最大性矛盾
  9. 因此 T 是最小生成树 ✅
结论：Kruskal 算法的贪心策略在数学上保证能得到最优解。关键在于边排序的全局贪心不会损害未来的选择。
完整代码模板
并查集 + Kruskal + MST 唯一性判定

🗂️ Edge 结构体

struct Edge { int u, v, w; bool operator<(const Edge& rhs) const { return w < rhs.w; // 按边权升序 } };

🔍 MST 唯一性判定

bool is_mst_unique(int n, vector<Edge> edges) { sort(edges.begin(), edges.end()); DSU dsu(n); int m = edges.size(); for (int i = 0; i < m; ) { int j = i; while (j < m && edges[j].w == edges[i].w) j++; int avail = 0, merged = 0; for (int k = i; k < j; k++) if (dsu.find(edges[k].u) != dsu.find(edges[k].v)) avail++; for (int k = i; k < j; k++) if (dsu.merge(edges[k].u, edges[k].v)) merged++; if (avail > merged) return false; // 存在替代方案 i = j; } return true; }
判定原理：对每组同权边，若可选边数大于实际合并数，说明存在可替换的等价边，MST 不唯一。
真题精练
经典 MST 及变种题型

📝 例题 1：洛谷 P3366【模板】最小生成树

  • n ≤ 5000，m ≤ 2×10⁵，求 MST 总权值
  • 解法：直接 Kruskal，排序 O(m log m)，并查集 O(m α(n))
  • 注意：使用 long long 存储总权值防止溢出；不连通输出 "orz"

📝 例题 2：最小瓶颈路（货车运输 / 繁忙的都市）

  • 求任意两点间路径上最大边权的最小值
  • 解法：
    1. Kruskal 构建 MST（任意 MST 都是最小瓶颈生成树）
    2. 在 MST 上做树上倍增，预处理 up[u][k] 和 maxw[u][k]
    3. 每次查询在 LCA 处合并路径最大值，复杂度 O(log n)
关键技巧：MST 有一个优良性质——任意两点在 MST 上的路径最大边权 = 原图中所有路径的最大边权的最小值。这就是最小瓶颈生成树定理。
易错点与优化技巧
竞赛中的常见坑与应对

⚠️ 常见错误

  • ❌ 并查集未初始化：fa[i] = i 必须覆盖 1..n，忘写或范围错误
  • ❌ 忘记排序：不对边按权值排序，贪心无效
  • ❌ 未判连通性：最终选中边数少于 n-1 说明图不连通，需特殊处理
  • ❌ 权值溢出：n 大、边权大时总权值超出 int，需用 long long
  • ❌ MST 唯一性误判：仅简单判同权边存在就认为不唯一（不严谨）

🚀 优化技巧

  • ✅ 提前 break：选够 n-1 条边立即退出，稀疏图效果显著
  • ✅ emplace_back：edges.emplace_back(u, v, w) 避免临时对象
  • ✅ 按大小合并：比按秩合并实现更简洁，效果等同
  • ✅ Lambda 排序：不重载 operator< 时用 Lambda 表达式
  • ✅ 边列表复用：Kruskal 可顺便输出 MST 边集，用于次小生成树等后续计算
🔴 血泪教训：比赛时最常见的错误是并查集编号从 0 开始还是从 1 开始搞混。建议统一使用1-indexed，初始化 fa.resize(n+1)。
