📖 知识精讲 — 多懒标记协同

同时支持加法 + 乘法

核心原则：先乘后加

对值 x，先乘 a 再加 b → a·x + b

再乘 c 再加 d → c·(a·x + b) + d = (a·c)·x + (b·c + d)

apply 函数（统一更新节点）

void apply(int p, int len, long long mu, long long ad) {
    sum[p] = (sum[p] * mu + ad * len) % P;
    mul[p] = (mul[p] * mu) % P;
    add[p] = (add[p] * mu + ad) % P;
    // 关键：原有的加法标记也要乘 mu！
}
【讲解】📖 知识精讲 — 多懒标记协同 本页要点（照着讲即可）： · 核心原则： 先乘后加 · 对值 x，先乘 a 再加 b → a·x + b · 再乘 c 再加 d → c·(a·x + b) + d = (a·c)·x + (b·c + d) 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。 本课大纲考点（可适时点题）：区间修改、多懒标记、权值线段树、线段树合并

📖 知识精讲 — 权值线段树

值域线段树 vs 下标线段树

叶子节点代表某个值的出现次数，而非数组元素

第 K 小查询（线段树上二分）

int kth(int p, int l, int r, int k) {
    if (l == r) return l;
    int mid = (l + r) >> 1;
    if (tree[lc[p]] >= k)
        return kth(lc[p], l, mid, k);
    else
        return kth(rc[p], mid+1, r, k - tree[lc[p]]);
}

适用场景

  • 全局第K小 / 第K大
  • 查询排名、前驱、后继
  • 动态开点处理 10⁹ 值域
【讲解】📖 知识精讲 — 权值线段树 本页要点（照着讲即可）： · 叶子节点代表 某个值的出现次数 ，而非数组元素 · 全局第K小 / 第K大 · 查询排名、前驱、后继 · 动态开点处理 10⁹ 值域 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

💻 代码模板 — 线段树合并 & 可持久化

线段树合并（动态开点）

int merge(int p, int q, int l, int r) {
    if (!p || !q) return p + q;     // 一方为空
    if (l == r) { cnt[p] += cnt[q]; return p; }
    lc[p] = merge(lc[p], lc[q], l, mid);
    rc[p] = merge(rc[p], rc[q], mid+1, r);
    pushup(p); return p;
}

可持久化（主席树）— 修改

int update(int pre, int l, int r, int x) {
    int p = ++tot; t[p] = t[pre];  // 复制节点
    if (l == r) { cnt[p]++; return p; }
    if (x <= mid) lc[p] = update(lc[pre], l, mid, x);
    else rc[p] = update(rc[pre], mid+1, r, x);
    pushup(p); return p;
}

每次修改只新建 O(log n) 个节点

⚠️ 易错点与优化技巧

  • ⚠ 多懒标记顺序 — 必须"先乘后加"，pushdown和update一致
  • ⚠ 加法标记被乘法影响 — add[p] = add[p] * mu + ad
  • ⚠ 动态开点空间 — 开到 操作数×log(值域)，约30~40倍
  • ⚠ 线段树合并不回溯 — 原树可能被破坏，必要时先复制
  • ✔ 离散化 + 权值树 — 减小值域，降低log因子
  • ✔ mid防溢出 — l + (r-l)/2 而非 (l+r)/2
  • ✔ 主席树静态区间K小 — 版本前缀和做差
【讲解】⚠️ 易错点与优化技巧 结合讲义《⚠️ 易错点与优化技巧》强调： · 多懒标记顺序：必须遵循"先乘后加"原则，乘法对加法标记也有影响 · 顺序一致性：pushdown 和 update 中的乘法/加法顺序必须一致 · 取模运算：多懒标记配合取模时，所有运算都需要取模 · 动态开点的空间：通常开到 操作数 × log(值域)，约 20~40 倍 · 线段树合并不回溯：合并后原树可能被修改，注意是否需要备份 幻灯片上可见要点： · ⚠ 多懒标记顺序 — 必须"先乘后加"，pushdown和update一致 · ⚠ 加法标记被乘法影响 — add[p] = add[p] * mu + ad · ⚠ 动态开点空间 — 开到 操作数×log(值域)，约30~40倍 · ⚠ 线段树合并不回溯 — 原树可能被破坏，必要时先复制 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。
