第 41 课

字符串哈希

String Hashing — 从 O(n) 到 O(1) 的子串判等

CSP-S 核心算法 BKDR Hash 双哈希防冲突

二分 + 哈希求 LCP · O(1) 子串查询 · 回文判断 · 字符串去重

📖 知识精讲：什么是字符串哈希？

字符串哈希的核心思想：将字符串映射为一个整数，使得相同的字符串映射到相同的整数，不同的字符串以极大概率映射到不同的整数。

BKDR Hash 函数

将字符串视为一个 base 进制数，逐字符计算：

hash(s) = (s[0]×baseⁿ⁻¹ + s[1]×baseⁿ⁻² + ... + s[n-1]) mod M

seed（base）选择

  • 常用质数：131 或 13331
  • 必须大于字符集大小（ASCII ≤ 127）
  • 经大量实践验证，冲突概率极低

模数选择

方案模数特点
自然溢出2⁶⁴代码极简，速度最快
单大质数1e9+7速度快，冲突小
双哈希1e9+7+1e9+9最安全，推荐

🔧 哈希函数设计：自然溢出 vs 双哈希

方案一：自然溢出（unsigned long long）

typedef unsigned long long ull; const ull BASE = 131; ull hash_str(const string& s) { ull h = 0; for (char c : s) h = h * BASE + c; // 自动对 2^64 取模 return h; }

✅ 代码最简洁 ，无需 % 运算
⚠️ 2^64 不是质数，可被特殊构造数据卡掉（anti-hash test）

方案二：双哈希（两个大质数）

const int MOD1 = 1e9+7, MOD2 = 1e9+9; const int BASE = 131; #define PLL pair<long long, long long> PLL hash_str(const string& s) { long long h1 = 0, h2 = 0; for (char c : s) { h1 = (h1 * BASE + c) % MOD1; h2 = (h2 * BASE + c) % MOD2; } return {h1, h2}; }
冲突概率 ≈ 1/(M1×M2) ≈ 10⁻¹⁸，在竞赛中几乎不可能发生冲突！CSP-S 推荐使用双哈希。

🧮 子串哈希 O(1) 公式推导

预处理前缀哈希与幂次

h[0] = 0 h[i] = (h[i−1] × base + s[i−1]) // i 从 1 到 n p[0] = 1, p[i] = p[i−1] × base

推导过程（以字符串 s = "abcde" 为例）

假设要查询子串 s[2..4] = "cde" 的哈希值：

h[5] = a×base⁴ + b×base³ + c×base² + d×base + e h[2] = a×base + b h[2] × base³ = a×base⁴ + b×base³ h[5] − h[2]×base³ = c×base² + d×base + e = hash("cde") ✓

通用公式

hash(l, r) = h[r+1] − h[l] × base^{r−l+1}

核心优势：预处理 O(n) 后，任意子串哈希可在 O(1) 时间内完成。

代码实现

ull get_hash(int l, int r) { // l, r 为 0-based 闭区间 return h[r+1] - h[l] * p[r-l+1]; }

💻 代码模板：StringHash 结构体

// ============ 自然溢出单哈希 ============ struct StringHash { int n; vector<ull> h, p; static const ull BASE = 131; StringHash(const string& s) { n = s.size(); h.resize(n+1, 0); p.resize(n+1, 1); for (int i = 0; i < n; i++) { h[i+1] = h[i] * BASE + s[i]; p[i+1] = p[i] * BASE; } } ull get(int l, int r) { // 子串 [l, r] return h[r+1] - h[l] * p[r-l+1]; } };

双哈希版本核心差异

struct DoubleHash { vector<long long> h1, h2, p1, p2; static const int MOD1 = 1e9+7, MOD2 = 1e9+9; pair<long long, long long> get(int l, int r) { long long v1 = (h1[r+1] - h1[l]*p1[r-l+1] % MOD1 + MOD1) % MOD1; long long v2 = (h2[r+1] - h2[l]*p2[r-l+1] % MOD2 + MOD2) % MOD2; return {v1, v2}; } };

📝 真题精练 1：字符串去重

题目：给定 N 个字符串，问有多少个不同的字符串。N ≤ 10⁴，总长度 ≤ 10⁶。

解题思路

  1. 对每个字符串计算 双哈希值
  2. 将哈希值对 (hash1, hash2) 存入 set
  3. set 的大小即为不同字符串的个数

AC 代码

#include <bits/stdc++.h> using namespace std; const int MOD1 = 1e9+7, MOD2 = 1e9+9, BASE = 131; pair<long long, long long> calc(const string& s) { long long h1=0, h2=0; for(char c:s){h1=(h1*BASE+c)%MOD1; h2=(h2*BASE+c)%MOD2;} return {h1,h2}; } int main() { ios::sync_with_stdio(false); cin.tie(nullptr); int N; cin>>N; set<pair<long long,long long>> st; while(N--) { string s; cin>>s; st.insert(calc(s)); } cout << st.size() << '\n'; }

⏱ 时间复杂度：O(Σ|s| + N log N)，空间 O(N)

📝 真题精练 2：最长回文子串

题目：给定字符串 s，求其最长回文子串的长度。|s| ≤ 10⁵。

算法：二分 + 正反哈希

  1. 预处理：正串哈希 H_forward 和反串哈希 H_reverse
  2. 枚举回文中心 i（奇数回文和偶数回文分开处理）
  3. 二分半径：若 H_forward[i−mid..i+mid] == H_reverse 对应区间，则回文成立

核心判断逻辑

// 奇数回文：中心 i，二分半径 mid if (fwd.get(i-mid, i+mid) == rev.get(n-1-(i+mid), n-1-(i-mid))) lo = mid; // 回文成立，尝试更大的半径 else hi = mid - 1; // 回文不成立，缩小半径 // 偶数回文：中心在 i 与 i+1 之间 if (fwd.get(i-mid+1, i+mid) == rev.get(n-1-(i+mid), n-1-(i-mid+1))) lo = mid;

⏱ 时间复杂度：O(n log n)
预处理 O(n) + 每个中心二分 O(log n)，共 n 个中心

扩展：更优的 O(n) 算法 — Manacher

Manacher 算法可以在 O(n) 时间内解决最长回文子串问题，但哈希 + 二分的思路更通用且容易实现，在 CSP-S 中已经足够。

⚠️ 易错点与优化技巧

常见错误

  • 模数选择不当：单用 1e9+7 仍可能被卡
  • 前缀下标混乱：h 数组从 1 开始，子串右端点需 +1
  • 负数取模：忘记 + MOD 再取模
  • 二分死循环：取上取整用 (lo+hi+1)/2
  • 自然溢出自信：CF 等平台广泛使用 anti-hash test

优化建议

  • 双哈希最安全：MOD1=1e9+7, MOD2=1e9+9
  • 随机 base：用 mt19937 随机生成，防止被针对
  • 大质数模数：998244353 也是好选择
  • pair 做 key：set 可直接用 pair，无需自定义哈希
  • 二分上界：hi 初始化为实际可能的最大值

随机化 base 示例

mt19937 rng(chrono::steady_clock::now().time_since_epoch().count()); const ull BASE = uniform_int_distribution<ull>(257, 1e9)(rng);
当取模为负数时，子串哈希公式必须写成：(h[r+1] - h[l]*p[r-l+1] % MOD + MOD) % MOD，否则可能得到错误结果！

🎯 本课小结

核心知识点要点复杂度
BKDR 哈希 base=131，将字符串视为 base 进制数 O(n) 预处理
自然溢出 ull 自动模 2⁶⁴，简洁但可能被卡 O(1) 查询
双哈希 MOD1+MOD2 同时计算，冲突概率 ≈ 0 O(1) 查询
子串哈希公式 hash[l,r] = h[r+1] − h[l]×base^{r−l+1} O(1)
二分 + 哈希 LCP、回文判断、字典序比较 O(log n)
哈希去重 双哈希 + set 统计不同字符串 O(N log N)

实践建议：CSP-S 中优先使用双哈希（1e9+7 + 1e9+9），确保万无一失。若时间紧迫可用自然溢出，但建议随机化 base。子串哈希的 O(1) 查询能力使其成为字符串问题的「瑞士军刀」。
