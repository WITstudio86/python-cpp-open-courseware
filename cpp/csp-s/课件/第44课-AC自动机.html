📖 知识精讲：AC 自动机概述

解决的问题

给定 N 个模式串 p₁, p₂, ..., pN 和一个文本串 T，要求找出每个模式串在文本串中的出现位置（或次数）。

为什么不直接用 KMP？

KMP 每次只能匹配一个模式串。对 N 个模式串分别 KMP，时间复杂度 O(N × |T|)，数据大了会 TLE。

AC 自动机 = Trie + fail 指针

  • Trie 树：存储所有模式串，每个节点代表一个前缀
  • fail 指针：指向当前节点最长后缀（该后缀也是某个模式串的前缀）

时间复杂度

步骤时间复杂度
构建 TrieO(∑|pᵢ|)
构建 fail 指针O(∑|pᵢ| × |Σ|)
匹配O(|T|)
总计O(∑|pᵢ| × 26 + |T|)
本质：AC 自动机是 KMP 在 Trie 树上的推广。KMP 的 next 数组是一维失配函数，fail 指针是二维的。

🔗 fail 指针的 BFS 构建

fail 指针的定义

设节点 u 表示的字符串为 s(u)，则 fail[u] 指向节点 v，满足：

  1. s(v) 是 s(u) 的 真后缀（不等于 s(u) 本身）
  2. s(v) 是某个模式串的前缀
  3. |s(v)| 最大（即最长真后缀）

BFS 构建算法

// 1. 将所有模式串先插入 Trie（略） void build() { queue<int> q; // 第一层：根节点的直接子节点 fail → 根 for (int c = 0; c < 26; c++) { if (son[0][c]) { fail[son[0][c]] = 0; q.push(son[0][c]); } } // 2. BFS 逐层构建 while (!q.empty()) { int u = q.front(); q.pop(); for (int c = 0; c < 26; c++) { int v = son[u][c]; if (v) { // 沿 fail 链向上查找 int f = fail[u]; while (f && !son[f][c]) f = fail[f]; fail[v] = son[f][c]; q.push(v); } } } }

⚡ Trie 图优化

优化的动机

普通 AC 自动机在匹配时，如果当前节点没有某个字符的子节点，需要通过 while 循环不断跳 fail 查找，可能退化。

Trie 图的核心

在构建 fail 的同时，将 Trie 树补全为一张图：
对于不存在的子节点 son[u][c]，设定 son[u][c] = son[fail[u]][c]

Trie 图版 build 函数

void build() { queue<int> q; for (int c = 0; c < 26; c++) { if (son[0][c]) { fail[son[0][c]] = 0; q.push(son[0][c]); } } while (!q.empty()) { int u = q.front(); q.pop(); for (int c = 0; c < 26; c++) { int v = son[u][c]; if (v) { fail[v] = son[fail[u]][c]; // 已在图中，直接取 q.push(v); } else { son[u][c] = son[fail[u]][c]; // 核心优化！ } } } }

匹配也变得简单

void query(const string &text) { int p = 0; for (char ch : text) { p = son[p][ch - 'a']; // 直接走！无需 while 循环 ans[p]++; // 只记录访问，不跳 fail } }
效果：匹配过程的时间复杂度从「可能退化」变为严格的 O(|T|)。
【讲解】⚡ Trie 图优化 结合讲义《四、Trie 图优化》强调： · 普通 AC 自动机在匹配时，如果当前节点没有某个字符的子节点，需要通过 while 循环不断跳 fail 指针查找，最坏情况下可能退化。 · Trie 图在构建 fail 指针的同时，将 Trie 树补全为一张图： · 对于节点 u 不存在字符 c 的子节点时，直接将 son[u][c] 指向 son[fail[u]][c] · 这样在匹配时，son[u][c] 总是有效，不需要 while 循环跳 fail · void build() { 幻灯片上可见要点： · 普通 AC 自动机在匹配时，如果当前节点没有某个字符的子节点，需要通过 while 循环不断跳 fail 查找，可能退化。 · 补全为一张图 · son[u][c] = son[fail[u]][c] 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

💻 完整代码模板

AC 自动机（Trie 图 + 拓扑排序优化）

const int N = 500010; int son[N][26], fail[N], cnt[N], ans[N], in[N], idx; void insert(const string &s, int id) { int p = 0; for (char ch : s) { int c = ch - 'a'; if (!son[p][c]) son[p][c] = ++idx; p = son[p][c]; } cnt[p] = id; // 记录是哪个模式串的结尾 } void build() { /* 见上一页 Trie 图优化版 */ } void topo() { // 拓扑排序统计出现次数 queue<int> q; for (int i = 1; i <= idx; i++) if (in[i] == 0) q.push(i); while (!q.empty()) { int u = q.front(); q.pop(); int v = fail[u]; ans[v] += ans[u]; if (--in[v] == 0) q.push(v); } }

使用流程

  1. insert 所有模式串 → 记录结尾节点
  2. build 构建 fail → BFS
  3. query 遍历文本串 → ans[p]++（不跳 fail）
  4. topo 拓扑排序 → 统计每个模式串的出现次数
【讲解】💻 完整代码模板 本页要点（照着讲即可）： · insert 所有模式串 → 记录结尾节点 · build 构建 fail → BFS · query 遍历文本串 → ans[p]++（不跳 fail） · topo 拓扑排序 → 统计每个模式串的出现次数 代码页节奏：先读懂输入输出 → 再走主流程 → 最后点出易错点（边界/类型/下标）。 可让学生预测下一行输出，再运行对照。

关键技巧

📊 拓扑排序优化详解

为什么需要拓扑排序？

fail 指针构成了一棵fail 树（根是 0，边从节点指向 fail 节点）。

在匹配过程中，我们只标记了当前到达的节点（ans[p]++），但没有计算 fail 链上的后缀匹配。

拓扑排序的作用

按 BFS 的逆序（即 fail 树的拓扑序），将子节点的 ans 值累加到父节点（fail 指向的节点）。
这样 ans[node] 就包含了所有以该节点为结尾的模式串的出现次数。

fail 树示意图

    ans[4] = 1       ans[3] = 2       ans[2] = 3
        |                |                |
      fail[4]        fail[3]          fail[2]
        |                |                |
        v                v                v
    fail[3] = 1     fail[2] = 0     fail[1] = 0

 拓扑序累加: ans[0] += ans[1] + ans[2]
             ans[1] += ans[3]
             ans[3] += ans[4]
时间复杂度：拓扑排序 O(节点数)，加上匹配 O(|T|)，总计 O(|T| + 节点数)，远优于跳 fail 的 O(|T| × 深度)。
【讲解】📊 拓扑排序优化详解 本页要点（照着讲即可）： · fail 指针构成了一棵 fail 树 （根是 0，边从节点指向 fail 节点）。 · fail 树 · 在匹配过程中，我们只标记了当前到达的节点（ans[p]++），但没有计算 fail 链上的后缀匹配。 · 时间复杂度： 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

📝 真题精练 2：不可重叠匹配

题目

给定文本串 T 和 N 个模式串，问文本串中最多能匹配多少个模式串，要求匹配位置不可重叠。
约束：模式串之间不可互相包含。

解题思路

  • 构建 AC 自动机
  • 遍历文本串，记录每个位置能匹配到的模式串（取最短的）
  • 使用贪心策略：按结束位置排序，选择不重叠的匹配

易错点回顾

  • 根节点的直接子节点 fail 指向根（0）
  • BFS 构建 fail 时注意边界（p 可能回到 0）
  • 匹配时跳 fail 可能 TLE → 用 Trie 图 + 拓扑排序
  • 数组大小要考虑模式串总长
