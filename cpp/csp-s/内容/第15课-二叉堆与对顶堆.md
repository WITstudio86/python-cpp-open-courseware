## 📖 知识精讲

### 一、二叉堆的结构与性质

二叉堆（Binary Heap）是一种**完全二叉树**，通常用数组实现（堆式存储，与线段树相同）。它是优先队列（Priority Queue）的经典实现方式，也是堆排序的基础数据结构。

**为什么需要堆？** 在很多算法问题中，我们需要反复地"取出当前最小/最大的元素，再插入新元素"。如果每次都用排序（O(n log n)），效率太低；如果用普通数组找最值（O(n)），也不够快。堆以 O(log n) 的插入和 O(log n) 的删除最值，完美平衡了这两个需求。

**分类**：
- **大根堆（Max-Heap）**：父节点的值 ≥ 子节点的值，根节点是全局最大值
- **小根堆（Min-Heap）**：父节点的值 ≤ 子节点的值，根节点是全局最小值

**数组实现**（下标从 1 开始，目的是方便父子节点计算）：
- 节点 i 的父节点：`i / 2`（等价于 `i >> 1`）
- 节点 i 的左子节点：`2i`（等价于 `i << 1`）
- 节点 i 的右子节点：`2i + 1`（等价于 `i << 1 | 1`）

**堆的两条性质**（以大根堆为例说明）：
1. **结构性质**：堆是一棵完全二叉树——除了最后一层可能不满外，其他各层都是满的，且最后一层的节点都靠左排列。这保证了堆在数组中紧凑存储，没有空洞。
2. **堆序性质**：对于任意节点 i，有 `heap[i] >= heap[2i]` 且 `heap[i] >= heap[2i+1]`。换句话说，从根到任意叶子的路径上，值是递减的。注意：堆序性质只约束父子之间，兄弟节点之间没有大小关系。

**堆的图示**（大根堆，插入顺序：3, 10, 5, 8, 2, 7）：

```
              10 (1)
             /      \
          8 (2)     7 (3)
         /   \      /
      3 (4) 2 (5) 5 (6)

数组表示：[0, 10, 8, 7, 3, 2, 5]
            ↑  ↑   ↑  ↑  ↑  ↑  ↑
           占位 1   2  3  4  5  6
```

注意：堆只保证父节点 ≥ 子节点，并不保证同一层的顺序。如节点 4（3）和节点 5（2）之间没有大小关系约束；同样，叶子节点 6（5）可能小于节点 5（2）的兄弟节点 4（3），这完全没问题。

### 二、核心操作详解

堆的两个最核心操作是**插入**和**删除堆顶**，它们分别使用**上浮（swim）**和**下沉（sink）**来恢复堆序性质。

#### 1. 插入操作（push）—— O(log n)

新元素加入到数组末尾（堆的最后一个位置），此时可能违反堆序性质。我们通过**上浮（swim）**将该元素逐步向上移动，直到满足堆序性质。

**算法思路**：新节点从底部开始，不断与父节点比较。如果比父节点大（大根堆），就与父节点交换位置，继续向上比较；如果比父节点小或已到达根节点，停止上浮。

```cpp
void push(int x) {
    heap[++size] = x;   // 1. 放到末尾
    int i = size;
    while (i > 1 && heap[i] > heap[i / 2]) {  // 2. 上浮
        swap(heap[i], heap[i / 2]);
        i /= 2;
    }
}
```

**上浮逐步演示**（向大根堆 [10, 8, 7, 3, 2, 5] 中插入 12）：

```
步骤1 — 将 12 放到末尾（位置 7）：
           10
          /  \
         8    7
        / \  / \
       3  2 5  12(×)  ← 12 > 父节点 7，违反堆序！

步骤2 — 12 上浮，与父节点 7 交换：
           10
          /  \
         8   12
        / \  / \
       3  2 5   7   ← 12 > 父节点 10，仍违反堆序！

步骤3 — 12 继续上浮，与父节点 10 交换：
           12
          /  \
         8   10
        / \  / \
       3  2 5   7   ← 12 已到根节点，完成！
```

每次上浮最多走 O(log n) 步（堆的高度），因此插入的时间复杂度为 O(log n)。

#### 2. 删除堆顶（pop）—— O(log n)

直接删除根节点会破坏完全二叉树的结构。标准做法是：**用最后一个元素替换根节点，删除末尾，然后对新根节点执行下沉（sink）操作**。

**算法思路**：新根节点从顶部开始，不断与较大的子节点比较。如果比子节点小，与较大的子节点交换（保证交换后堆序在局部成立），继续向下；如果比两个子节点都大或已到达叶子，停止下沉。

```cpp
void pop() {
    heap[1] = heap[size--];  // 1. 末尾替换根节点
    int i = 1;
    while (true) {
        int largest = i;
        int l = 2 * i, r = 2 * i + 1;
        if (l <= size && heap[l] > heap[largest]) largest = l;  // 与左子比较
        if (r <= size && heap[r] > heap[largest]) largest = r;  // 与右子比较
        if (largest == i) break;  // 堆序已恢复
        swap(heap[i], heap[largest]);
        i = largest;
    }
}
```

**下沉逐步演示**（从大根堆 [12, 8, 10, 3, 2, 5, 7] 中删除堆顶 12）：

```
步骤1 — 用末尾 7 替换根节点，删除末尾：
            7(×)
          /    \
         8     10
        / \   /  \
       3   2 5   [12]

步骤2 — 7 与子节点比较：左子 8 > 7，右子 10 > 8，选右子 10 交换：
           10
          /  \
         8    7(×)
        / \  /
       3  2 5        ← 7 > 左子 5，堆序在局部已恢复！
```

注意：下沉的关键是**选择较大的子节点进行交换**（大根堆），这样交换后局部堆序一定成立。如果选较小的子节点交换，可能交换后仍然违反堆序。

每次下沉最多走 O(log n) 步，因此删除堆顶的时间复杂度为 O(log n)。

#### 3. 堆化（heapify）—— O(n)

给定一个无序数组，如何快速建成一个堆？朴素做法是对每个元素依次调用 push，复杂度 O(n log n)。但有一个更高效的方法：**从后往前，对每个非叶子节点执行下沉操作**。

**为什么从 n/2 开始？** 对于大小为 n 的完全二叉树，编号 > n/2 的节点都是叶子节点（没有子节点），它们天然满足堆序性质。所以只需要下沉编号 ≤ n/2 的非叶子节点。

```cpp
void heapify() {
    for (int i = size / 2; i >= 1; i--) {
        // 对节点 i 执行下沉操作（同 pop 中的 sink）
    }
}
```

**复杂度为什么是 O(n) 而非 O(n log n)？** 虽然每个节点的下沉可能 O(log n)，但不同高度的节点数量差异巨大。具体分析：
- 高度为 h 的节点最多有 ⌈n / 2^(h+1)⌉ 个
- 每个这样的节点最多下沉 h 步
- 总操作次数 Σ(h × n / 2^(h+1)) = O(n)

这是一个经典的反直觉结论：自底向上的 heapify 可以在线性时间内完成。

### 三、堆排序（Heap Sort）—— O(n log n) 原地排序

堆排序是利用堆数据结构实现的排序算法，其核心优势是**原地排序**（不需要额外数组），空间复杂度 O(1)。

**算法步骤**：
1. **建堆**（heapify）：将数组原地调整为一个大根堆。O(n)
2. **循环提取**：重复以下操作 n-1 次 —— 将堆顶（当前最大值）与堆末尾元素交换，然后堆大小减 1，对新的堆顶执行下沉恢复堆序。O(n log n)
3. **最终结果**：如果使用的是大根堆，最终数组为升序（因为最大值依次被"沉淀"到数组末尾）

```cpp
void heap_sort(vector<int>& a) {
    int n = a.size() - 1;  // 假设下标从 1 开始
    // 1. 建堆
    for (int i = n / 2; i >= 1; i--) sink(i, n);
    // 2. 排序
    for (int i = n; i > 1; i--) {
        swap(a[1], a[i]);   // 堆顶（最大值）放到末尾
        sink(1, i - 1);     // 恢复堆序（堆大小为 i-1）
    }
}
```

**复杂度**：O(n log n)，不稳定排序。在实际应用中，堆排序的常数比快速排序大，但在"需要原地排序 + 稳定 O(n log n)"的场景下非常有用（如嵌入式系统内存受限时）。

### 四、对顶堆（Double Heap）—— 动态中位数维护

对顶堆是堆的一个经典高级应用，可以在 O(log n) 时间内插入元素、O(1) 时间内查询当前数据流的中位数。

**核心结构**：
- **左半部分：大根堆（MaxHeap）**—— 存储数据流中较小的一半元素。堆顶是左半部分的最大值（也就是整个数据流中位数偏左的那个值）
- **右半部分：小根堆（MinHeap）**—— 存储数据流中较大的一半元素。堆顶是右半部分的最小值

**图解对顶堆结构**（数据流：1, 5, 3, 8, 2, 9, 4）：

```
    左半部分（大根堆）        右半部分（小根堆）
   较小的数 → 堆顶最大      较大的数 → 堆顶最小
       [4]                    [5]
      /   \                  /   \
    [3]   [1]             [8]   [9]
    /
  [2]

   中位数 = 4（左堆顶，因为左堆比右堆多一个元素）
   如果元素总数为偶数：中位数 = (4 + 5) / 2 = 4.5
```

**维护不变式**（两个规则必须同时满足）：
1. **大小平衡**：MaxHeap.size() == MinHeap.size() 或 MaxHeap.size() == MinHeap.size() + 1（约定左堆可以比右堆多一个）
2. **值域分离**：MaxHeap 中的所有元素 ≤ MinHeap 中的所有元素（即 MaxHeap.top() ≤ MinHeap.top()）

**插入新元素 x 的三步法**：O(log n)

```cpp
void insert(int x) {
    // 第1步：决定放入哪个堆
    if (maxHeap.empty() || x <= maxHeap.top()) {
        maxHeap.push(x);    // 比左半部分的最大值还小 → 放左边
    } else {
        minHeap.push(x);    // 比左半部分的最大值大 → 放右边
    }
    // 第2步：平衡两个堆的大小
    if (maxHeap.size() > minHeap.size() + 1) {
        // 左堆太多了：把左堆的最大值移到右堆
        minHeap.push(maxHeap.top()); maxHeap.pop();
    } else if (minHeap.size() > maxHeap.size()) {
        // 右堆太多了：把右堆的最小值移到左堆
        maxHeap.push(minHeap.top()); minHeap.pop();
    }
    // 第3步：此时不变式已恢复
}
```

**对顶堆插入逐步演示**（以数据流 [5, 15, 1, 3] 为例）：

```
初始状态：MaxHeap={}, MinHeap={}

插入 5：
  → 左堆空，直接放入 MaxHeap
  状态：MaxHeap={5}, MinHeap={}

插入 15：
  → 15 > MaxHeap.top()(5)，放入 MinHeap
  → 平衡：MinHeap.size()(1) > MaxHeap.size()(1)? 不，都=1，无需调整
  状态：MaxHeap={5}, MinHeap={15}  ✓ 满足不变式

插入 1：
  → 1 ≤ MaxHeap.top()(5)，放入 MaxHeap
  → 平衡：MaxHeap.size()(2) > MinHeap.size()(1)+1? 不，2==2，无需调整
  状态：MaxHeap={5,1}, MinHeap={15}  ✓

插入 3：
  → 3 ≤ MaxHeap.top()(5)，放入 MaxHeap
  → 平衡：MaxHeap.size()(3) > MinHeap.size()(1)+1=2? 是！需要平衡
  → 将 MaxHeap.top()(5) 移到 MinHeap
  状态：MaxHeap={3,1}, MinHeap={5,15}  ✓
  中位数 = MaxHeap.top() = 3（共4个偶数，左堆顶即为较小中位数）
```

**查询中位数**：O(1)
- 若 MaxHeap.size() > MinHeap.size()：中位数 = MaxHeap.top()（总数为奇数，中位数在左堆堆顶）
- 否则（相等时）：中位数 = (MaxHeap.top() + MinHeap.top()) / 2.0（总数为偶数，取两堆顶的平均）

### 五、合并果子（Huffman 编码问题）

**问题描述**：有 n 堆果子，第 i 堆有 a[i] 个果子。每次可以合并任意两堆，代价为这两堆的重量之和。求将所有果子合并成一堆的最小总代价。

**为什么用贪心？** 直觉上，越早合并的堆在后续合并中会被反复计入代价。因此，我们应该优先合并最小的两堆——这正可以用小根堆高效实现。

**贪心策略正确性**：这是经典 Huffman 编码问题的等价变形。Huffman 的最优子结构性质保证了"每次取最小的两个合并"能得到全局最优解。

```cpp
long long min_cost(vector<int>& a) {
    priority_queue<int, vector<int>, greater<int>> pq;
    for (int x : a) pq.push(x);
    long long total = 0;
    while (pq.size() > 1) {
        int a = pq.top(); pq.pop();
        int b = pq.top(); pq.pop();
        total += a + b;      // 合并代价
        pq.push(a + b);      // 新堆放回
    }
    return total;
}
```

**复杂度**：O(n log n)。每次合并需要两次 pop 和一次 push，共 n-1 次合并。

**合并果子逐步演示**（果子堆：[1, 2, 9, 5, 3]）：

```
初始小根堆：[1, 2, 3, 5, 9]

第1次合并：取 1 和 2 → 代价 3 → 放入新堆 3
  堆变为：[3, 3, 5, 9]，累计代价 = 3

第2次合并：取 3 和 3 → 代价 6 → 放入新堆 6
  堆变为：[5, 6, 9]，累计代价 = 9

第3次合并：取 5 和 6 → 代价 11 → 放入新堆 11
  堆变为：[9, 11]，累计代价 = 20

第4次合并：取 9 和 11 → 代价 20 → 放入新堆 20
  堆变为：[20]，累计代价 = 40

答案为 40。
```

## 💻 代码模板

```cpp
// ========== 小根堆标准模板 ==========
class MinHeap {
private:
    vector<int> heap;
    int sz;

    void swim(int i) {
        while (i > 1 && heap[i] < heap[i / 2]) {
            swap(heap[i], heap[i / 2]);
            i /= 2;
        }
    }

    void sink(int i) {
        while (2 * i <= sz) {
            int j = 2 * i;
            if (j < sz && heap[j + 1] < heap[j]) j++;
            if (heap[i] <= heap[j]) break;
            swap(heap[i], heap[j]);
            i = j;
        }
    }

public:
    MinHeap() : heap(1), sz(0) {}  // 下标从 1 开始

    void push(int x) {
        heap.push_back(x);
        swim(++sz);
    }

    void pop() {
        heap[1] = heap[sz--];
        heap.pop_back();
        sink(1);
    }

    int top() { return heap[1]; }
    int size() { return sz; }
    bool empty() { return sz == 0; }
};
```

## ⚠️ 易错点与优化技巧

### 常见错误逐项详解

1. **下标从 1 开始** —— 堆的数组实现中，下标从 1 开始是为了父子节点计算的简洁：父节点 = i/2，子节点 = 2i 和 2i+1。如果从 0 开始，父节点变为 `(i-1)/2`，子节点变为 `2i+1` 和 `2i+2`，代码可读性下降且容易出错。竞赛中**强烈推荐从 1 开始**，在堆数组的索引 0 处放置一个占位值（或直接从 vector 的索引 1 开始使用）。

2. **sink 时选正确的子节点比较** —— 这是最易出错的地方：
   - 小根堆：选 **较小** 的子节点与当前节点比较，如果当前节点 ≤ 较小子节点，停止下沉
   - 大根堆：选 **较大** 的子节点与当前节点比较，如果当前节点 ≥ 较大子节点，停止下沉
   - 常见 bug：小根堆却选了较大的子节点交换，或反过来。会导致堆序性质被破坏，后续操作结果错误。

3. **对顶堆的平衡时机** —— 插入新元素后**必须立即**检查并调整两个堆的大小。如果先进行多次插入再平衡，中间状态可能违反不变式，导致后续插入判断错误（因为判断 `x <= maxHeap.top()` 依赖左堆顶是正确的最大值）。

4. **priority_queue 默认是大根堆** —— 这是 C++ STL 的设计选择。需要小根堆时，必须写全三个模板参数：`priority_queue<int, vector<int>, greater<int>>`。注意第三个参数是比较器类型，`greater<int>` 表示"更大的排后面"，从而堆顶是最小的。常见错误：只写 `priority_queue<int, greater<int>>`（缺少中间的容器类型参数），编译报错。

5. **堆排序是不稳定排序** —— 相同值的元素在堆排序后可能改变相对顺序。这是因为堆中的父子交换不保留同值元素的输入顺序。如果需要稳定排序，应选择归并排序或插入排序。

6. **手写堆 vs STL priority_queue 的选择** —— 大多数情况优先使用 STL。但在以下场景需要手写堆：
   - 需要删除非堆顶的某个特定元素（如 Dijkstra 中的 decrease-key 操作）
   - 需要遍历堆中所有元素进行检查
   - 需要 O(n) 的 heapify 操作但不想把数据复制两遍
   - 需要自定义更复杂的堆操作（如同时维护最大值和最小值）

7. **大根堆存负数变相实现小根堆技巧** —— 当只需要小根堆功能且不想写 `greater<int>` 时，可以将数值取负后存入默认大根堆。取 top 时再取反即可得到原最小值。这个方法在写代码很快的场合（如线上赛）非常实用。

8. **堆中元素的修改** —— priority_queue 不直接支持修改内部元素。如果需要修改，通常的做法是：
   - 记录修改，将修改后的新值 push 入堆
   - 使用一个 `vis[]` 数组标记已被"废弃"的旧值
   - 在 pop 时跳过已标记为废弃的元素
   - 这与 Dijkstra 的堆优化版本中处理"过期"节点是同一思路

9. **对顶堆查询中位数的精度** —— 如果数据是整数且总数为偶数，两个堆顶可能都是整数，中位数可能是 0.5 结尾的浮点数。注意使用 `double` 类型返回，避免整数除法丢精度。

10. **CF/竞赛中的对顶堆应用** —— 对顶堆也常用于维护"第 k 大/小的动态数据流"，只需调整两个堆的大小比例即可。例如维护第 k 小：让左堆始终保持 k 个元素，那么左堆堆顶就是第 k 小。

## 📝 真题精练

### 真题一：[CSP-S 经典] 动态中位数

**题目描述**：
依次读入一个整数序列。每当已经读入的整数个数为奇数时，输出已读入的整数的中位数。

**数据范围**：序列长度 M ≤ 10⁵

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false); cin.tie(0);
    int T; cin >> T;
    while (T--) {
        int id, m;
        cin >> id >> m;
        cout << id << " " << (m + 1) / 2 << '\n';
        priority_queue<int> maxHeap;                      // 小数部分
        priority_queue<int, vector<int>, greater<int>> minHeap; // 大数部分
        int cnt = 0;
        for (int i = 1; i <= m; i++) {
            int x; cin >> x;
            if (maxHeap.empty() || x <= maxHeap.top())
                maxHeap.push(x);
            else
                minHeap.push(x);
            // 平衡
            if (maxHeap.size() > minHeap.size() + 1) {
                minHeap.push(maxHeap.top()); maxHeap.pop();
            } else if (minHeap.size() > maxHeap.size()) {
                maxHeap.push(minHeap.top()); minHeap.pop();
            }
            // 奇数个时输出中位数
            if (i % 2 == 1) {
                cout << maxHeap.top();
                cnt++;
                if (cnt % 10 == 0) cout << '\n';
                else if (i != m) cout << " ";
            }
        }
        if (cnt % 10 != 0) cout << '\n';
    }
    return 0;
}
```

**复杂度分析**：O(M log M)。

### 真题二：[CSP-S 经典] 合并果子

**题目描述**：
有 n 堆果子，第 i 堆有 a[i] 个。每次合并任意两堆，代价为两堆重量之和。求将所有果子合并成一堆的最小总代价。

**数据范围**：n ≤ 10⁴

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false); cin.tie(0);
    int n; cin >> n;
    priority_queue<int, vector<int>, greater<int>> pq;
    for (int i = 0; i < n; i++) {
        int x; cin >> x;
        pq.push(x);
    }
    long long ans = 0;
    while (pq.size() > 1) {
        int a = pq.top(); pq.pop();
        int b = pq.top(); pq.pop();
        ans += a + b;
        pq.push(a + b);
    }
    cout << ans << '\n';
    return 0;
}
```

**复杂度分析**：O(n log n)。

### 真题三：[CSP-S 变体] 第 K 小的动态数据流

**题目描述**：
初始有一个空的数据结构，需要支持两种操作共 Q 次：
1. `1 x`：插入一个整数 x
2. `2 k`：查询当前所有已插入元素中，第 k 小的数是多少

保证查询时 k ≤ 当前元素个数。

**数据范围**：Q ≤ 2×10⁵，|x| ≤ 10⁹，k ≤ 10⁵

**解题思路**：
使用对顶堆的变体：保持大根堆（左堆）中有 k 个元素，则大根堆的堆顶就是第 k 小的元素。对于不同的 k 查询，需要动态调整两个堆的大小。

或者更通用的做法：使用平衡树（如 `__gnu_pbds::tree`），但堆的变体也能解决——维护大根堆始终保持所需大小，小根堆存放比第 k 小大的元素。

**AC 代码**（对顶堆变体，固定维护第 k 小）：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false); cin.tie(0);

    int Q; cin >> Q;
    priority_queue<int> maxHeap;                       // 存放较小的 k 个元素
    priority_queue<int, vector<int>, greater<int>> minHeap; // 存放较大的部分

    while (Q--) {
        int op; cin >> op;
        if (op == 1) {
            int x; cin >> x;
            // 先放入左堆
            maxHeap.push(x);
            // 左堆最多保持当前需要的 k 个（这里 k 由后续查询决定，因此先全部放入左堆也可以）
            // 但我们需要维持一边的大小：让左堆尽量小，把多余的移到右堆
            // 更通用的做法：始终将新元素放入左堆，然后如果左堆顶大于右堆顶，交换
        } else {
            int k; cin >> k;
            // 调整左堆大小恰好为 k
            while ((int)maxHeap.size() > k) {
                minHeap.push(maxHeap.top());
                maxHeap.pop();
            }
            while ((int)maxHeap.size() < k && !minHeap.empty()) {
                maxHeap.push(minHeap.top());
                minHeap.pop();
            }
            // 确保左堆顶 ≤ 右堆顶（交叉调整）
            while (!maxHeap.empty() && !minHeap.empty() && maxHeap.top() > minHeap.top()) {
                int a = maxHeap.top(); maxHeap.pop();
                int b = minHeap.top(); minHeap.pop();
                maxHeap.push(b);
                minHeap.push(a);
            }
            cout << maxHeap.top() << '\n';
        }
    }
    return 0;
}
```

**优化版**（维护第 k 小，k 可变）—— 更简洁的做法是使用 `__gnu_pbds::tree` 或离线 + 离散化 + 线段树/树状数组上二分。但在堆的课程中，对顶堆变体可以让同学们理解"两个堆控制大小关系"的核心思想。

**复杂度分析**：单次查询最坏 O(log n × 调整次数)。如果 k 变化不大（题目常有此约束），均摊效率很高。

## 🎯 本课小结

1. **堆 = 完全二叉树 + 堆序性质**：插入 O(log n)、删除堆顶 O(log n)、查询堆顶 O(1)。
2. **swim（上浮）与 sink（下沉）**：堆的两个原子操作。上浮用于插入后的调整（从底部向上升），下沉用于删除后的调整（从顶部向下降）。
3. **heapify 建堆是 O(n)**：从最后一个非叶子节点向前依次下沉，利用"底层的节点多但下沉步数少"的特性在线性时间内完成。
4. **堆排序**：原地 O(n log n) 排序算法，不稳定。分为建堆（O(n)）和依次提取（O(n log n)）两阶段。
5. **对顶堆**：大根堆（较小的一半）+ 小根堆（较大的一半），O(1) 查询中位数、O(log n) 插入。广泛用于数据流的中位数/第k小问题。
6. **合并果子 = Huffman 编码**：经典贪心 + 小根堆，每次合并最小的两堆。时间复杂度 O(n log n)。
7. **C++ STL**：`priority_queue<T>` 默认大根堆，`priority_queue<T, vector<T>, greater<T>>` 为小根堆。大多数情况优先使用 STL，特殊需求时手写堆。
8. **对顶堆扩展**：通过调整左右堆的大小比例，可以维护数据流的任意分位数（第 k 小、第 k 大等），是一个通用的动态排名数据结构。
