## 📖 知识精讲

### 一、AC 自动机解决的问题

AC 自动机（Aho-Corasick Automaton）用于解决**多模式串匹配**问题：

> 给定 N 个模式串 `p1, p2, ..., pn` 和一个文本串 `T`，要求找出每个模式串在文本串中出现的所有位置（或次数）。

如果使用 KMP 算法，需要对每个模式串分别匹配一次，时间复杂度为 `O(N × |T|)`（最坏情况下）。AC 自动机将所有模式串组织成一个 Trie 树 + fail 指针，实现一次性匹配所有模式串，时间复杂度为 `O(∑|pi| + |T| + 匹配次数)`。

### 二、AC 自动机的核心结构

AC 自动机 = **Trie 树** + **fail 指针**。

- **Trie 树**：存储所有模式串，每个节点代表一个前缀
- **fail 指针**：指向当前节点所表示字符串的**最长后缀**，且该后缀恰好是某个模式串的前缀

#### 2.1 fail 指针的直观理解

```
模式串: "he", "she", "his", "hers"

Trie 树构建后，fail 指针如下（简化示意）：

     root
    /  |  \
   h   s  h
  /    |    \
 e     h     i
/      |      \
r      e       s
|
s

fail 指向:
- she 的 'e' 的 fail 指向 he 的 'e'（因为 "he" 是 "she" 的后缀）
- hers 的 's' 的 fail 指向 his 的 's'（因为 "s" 是 "hers" 的后缀）
```

#### 2.2 fail 指针的数学定义

设节点 `u` 在 Trie 树中表示的字符串为 `s(u)`（从根节点到 `u` 的路径拼接）。

fail 指针 `fail[u]` 指向节点 `v`，满足：
1. `s(v)` 是 `s(u)` 的**真后缀**（即不等于 `s(u)` 本身）
2. `s(v)` 是某个模式串的前缀（即 `v` 在 Trie 树中存在）
3. `|s(v)|` 最大（即最长真后缀）

**类比 KMP：** `fail` 指针与 KMP 的 `next` 数组在思想上完全一致——都是找到最长相等前后缀。

### 三、fail 指针的 BFS 构建过程

#### 3.1 算法步骤

1. 将所有模式串插入 Trie 树（与普通 Trie 的 `insert` 完全相同）
2. 使用 BFS（队列）逐层构建 fail 指针
3. 对于根节点的直接子节点，fail 指向根节点（因为不存在非空的真后缀）
4. 对于其他节点 `u` 的子节点 `v`（字符为 `c`）：
   - 令 `f = fail[u]`
   - 向上查找：如果 `f` 有字符 `c` 的子节点，则 `fail[v] = son[f][c]`
   - 否则继续 `f = fail[f]`，直到找到或回到根节点

#### 3.2 核心代码（BFS 构建）

```cpp
void build() {
    // 第一层节点的 fail 全部指向根节点（0）
    queue<int> q;
    for (int c = 0; c < 26; c++) {
        if (son[0][c]) {
            fail[son[0][c]] = 0;
            q.push(son[0][c]);
        }
    }
    // BFS 逐层构建
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int c = 0; c < 26; c++) {
            int v = son[u][c];
            if (v) {
                // 向上寻找 fail 指针
                int f = fail[u];
                while (f && !son[f][c]) f = fail[f];
                fail[v] = son[f][c];
                q.push(v);
            }
        }
    }
}
```

#### 3.3 匹配过程

从根节点出发，对文本串的每个字符：

1. 如果当前节点有对应字符的子节点，则进入
2. 否则沿 fail 指针向上跳转，直到找到有该字符子节点的节点或回到根
3. 每到达一个节点，其 fail 链上的所有节点对应的模式串都是匹配的

```cpp
int query(const string &text) {
    int p = 0, res = 0;
    for (char ch : text) {
        int c = ch - 'a';
        while (p && !son[p][c]) p = fail[p];  // 沿 fail 跳转
        p = son[p][c];
        // 收集当前节点及其 fail 链上的所有匹配
        for (int t = p; t && cnt[t] != -1; t = fail[t]) {
            res += cnt[t];
            cnt[t] = -1;  // 标记已统计，避免重复
        }
    }
    return res;
}
```

### 四、Trie 图优化

#### 4.1 优化的动机

普通 AC 自动机在匹配时，如果当前节点没有某个字符的子节点，需要通过 `while` 循环不断跳 `fail` 指针查找，最坏情况下可能退化。

#### 4.2 Trie 图的构建

Trie 图在构建 fail 指针的同时，将 Trie 树补全为一张图：

- 对于节点 `u` 不存在字符 `c` 的子节点时，直接将 `son[u][c]` 指向 `son[fail[u]][c]`
- 这样在匹配时，`son[u][c]` 总是有效，不需要 while 循环跳 fail

```cpp
void build() {
    queue<int> q;
    for (int c = 0; c < 26; c++) {
        if (son[0][c]) {
            fail[son[0][c]] = 0;
            q.push(son[0][c]);
        }
        // 注意：这里不需要补全根节点的 son，因为 0 就是根
    }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int c = 0; c < 26; c++) {
            int v = son[u][c];
            if (v) {
                fail[v] = son[fail[u]][c];  // 简洁！因为 son 已被补全
                q.push(v);
            } else {
                son[u][c] = son[fail[u]][c];  // Trie 图优化：补全转移边
            }
        }
    }
}
```

**Trie 图匹配（无需 while 循环）：**

```cpp
int query(const string &text) {
    int p = 0, res = 0;
    for (char ch : text) {
        p = son[p][ch - 'a'];   // 直接走，son 保证有效
        for (int t = p; t && cnt[t] != -1; t = fail[t]) {
            res += cnt[t];
            cnt[t] = -1;
        }
    }
    return res;
}
```

### 五、拓扑排序优化：统计每个模式串的出现次数

#### 5.1 问题

在上述匹配过程中，如果我们需要统计每个模式串分别出现了多少次，直接沿 `fail` 链跳转会重复统计，时间复杂度变为 `O(|T| × max模式串长度)`，可能 TLE。

#### 5.2 拓扑排序优化

核心思想：**fail 指针构成了一棵树（fail 树）**，我们只需要在匹配时记录每个节点被访问的次数，最后通过拓扑排序（按 BFS 逆序）将子节点的计数向上累加到父节点（fail 指向的节点）。

```cpp
int ind[N];    // 入度数组（BFS 顺序）
int ans[N];    // 每个模式串的出现次数
int cnt[N];    // 模式串结尾标记

void query(const string &text) {
    int p = 0;
    for (char ch : text) {
        p = son[p][ch - 'a'];
        ans[p]++;  // 只记录当前节点的访问次数，不跳 fail
    }
}

void topo() {
    // 按 BFS 入队顺序的逆序处理（即 BFS 出队顺序的逆序）
    // idx 是 BFS 时最后入队的节点
    for (int i = idx; i >= 0; i--) {
        ans[fail[i]] += ans[i];  // 向 fail 指针方向累加
    }
    // 现在 ans[ node_id_of_pattern_k ] 即为模式串 k 的出现次数
}
```

**为什么是正确的？** 如果模式串 P 在文本串位置 j 处出现，那么 P 的所有后缀（对应 fail 链上的节点）也必然在位置 j 处出现。fail 指针指向最长后缀，拓扑排序能正确地将所有后缀的出现次数统计出来。

#### 5.3 时间复杂度

| 步骤 | 时间复杂度 |
|------|-----------|
| 构建 Trie | O(∑\|pi\|) |
| 构建 fail（BFS） | O(∑\|pi\| × \|Σ\|) |
| 匹配 | O(\|T\|) |
| 拓扑排序统计 | O(节点数) |
| **总计** | **O(∑\|pi\| × \|Σ\| + \|T\|)** |

### 六、AC 自动机与 KMP 的联系

| 概念 | KMP | AC 自动机 |
|------|-----|-----------|
| 模式串 | 单个模式串 | 多个模式串 |
| 前缀数据结构 | 一维数组 `next[]` | Trie 树 |
| 失配跳转 | `next[i]` (前缀函数) | `fail` 指针 |
| 失配目标 | 最长相等前后缀 | 最长后缀=某模式串前缀 |
| 时间复杂度 | O(\|P\| + \|T\|) | O(∑\|pi\| + \|T\|) |

**本质：** AC 自动机是 KMP 在 Trie 树上的推广。KMP 的 `next` 数组是一维的失配函数，AC 自动机的 `fail` 指针是二维（Trie 的每个节点都有一个失配指针）。

## 💻 代码模板

### 模板：AC 自动机（Trie 图优化 + 拓扑排序）

```cpp
const int N = 500010;  // 模式串总长度
int son[N][26], fail[N], cnt[N], ans[N], in[N];
int idx;

void insert(const string &s, int id) {
    int p = 0;
    for (char ch : s) {
        int c = ch - 'a';
        if (!son[p][c]) son[p][c] = ++idx;
        p = son[p][c];
    }
    cnt[p] = id;  // 记录模式串编号（或结尾标记）
}

void build() {
    queue<int> q;
    for (int c = 0; c < 26; c++) {
        if (son[0][c]) {
            fail[son[0][c]] = 0;
            q.push(son[0][c]);
        }
    }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int c = 0; c < 26; c++) {
            int v = son[u][c];
            if (v) {
                fail[v] = son[fail[u]][c];
                in[fail[v]]++;       // 拓扑排序用的入度
                q.push(v);
            } else {
                son[u][c] = son[fail[u]][c];  // Trie 图优化
            }
        }
    }
}

void query(const string &text) {
    int p = 0;
    for (char ch : text) {
        p = son[p][ch - 'a'];
        ans[p]++;  // 不跳 fail，只记录访问
    }
}

void topo() {
    queue<int> q;
    for (int i = 1; i <= idx; i++) {
        if (in[i] == 0) q.push(i);
    }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        int v = fail[u];
        ans[v] += ans[u];
        if (--in[v] == 0) q.push(v);
    }
}
```

## ⚠️ 易错点与优化技巧

| 问题 | 说明 | 解决方案 |
|------|------|----------|
| fail 根节点处理 | 根节点的直接子节点的 fail 指向根节点 | BFS 初始将所有 `son[0][c]` 入队，`fail` 设为 0 |
| 无限循环跳 fail | `while (f && !son[f][c])` 若无 `&& f` 可能死循环 | 一定加 `f` 的边界检查 |
| 跳 fail 导致 TLE | 每次匹配都跳 fail 链，最坏 O(\|T\| × max 串长) | 使用 Trie 图优化 + 拓扑排序统计 |
| 重复统计 | 同一模式串可能被多次计数 | 标记 `cnt[t] = -1` 或使用拓扑排序 |
| 字符集映射 | 不同题目的字符范围不同 | 根据题目调整 `son` 的第二维大小和映射函数 |
| 数组大小不足 | `son` 的 N 要考虑模式串总长 | `N = 模式串总长度 + 文本串长度`（保险起见） |

### 模式串出现次数统计对比

| 方法 | 适用场景 | 时间复杂度 |
|------|----------|-----------|
| 匹配时跳 fail 并标记 `-1` | 只关心出现了哪些模式串（不关心次数） | O(\|T\|) |
| 匹配时跳 fail 不标记 | 需要次数但数据小 | 最坏 O(\|T\| × max 串长) |
| 拓扑排序统计 | 需要精确次数且数据大 | O(\|T\| + 节点数) |

## 📝 真题精练

### 真题1：多模式串匹配 —— 每个模式串出现多少次

**【题目描述】**

给定 N 个模式串 `p1, p2, ..., pn` 和一个文本串 `T`，求每个模式串在文本串中出现的次数。

数据范围：`N ≤ 2 × 10^5`，`∑|pi| ≤ 2 × 10^5`，`|T| ≤ 2 × 10^6`。

**【输入格式】**

```
第一行：整数 N
接下来 N 行：每行一个模式串（仅包含小写字母）
最后一行：文本串 T
```

**【输出格式】**

```
N 行，每行输出对应模式串出现的次数
```

**【样例输入】**

```
5
a
aa
aaa
aaaa
aaaaa
aaabbaaab
```

**【样例输出】**

```
6
4
2
1
0
```

**【解题思路】**

1. 将所有模式串插入 Trie，记录每个模式串结尾的节点编号
2. 构建 fail 指针（Trie 图优化）
3. 遍历文本串匹配，对每个到达的节点 `ans[p]++`（不跳 fail）
4. 拓扑排序：`ans[fail[i]] += ans[i]`
5. 输出每个模式串结尾节点的 `ans` 值

**【参考代码见 `程序/lesson44_ac_automaton.cpp`】**

### 真题2：文本串中最多能匹配多少个模式串（不可重叠）

**【题目描述】**

给定一个文本串 T 和 N 个模式串，问在文本串中最多能匹配多少个模式串，要求匹配的位置不可重叠。

数据范围：`|T| ≤ 10^5`，`N ≤ 10^5`，`∑|pi| ≤ 10^5`。

约束：模式串不可被另一个模式串完全包含（即不会有"aa"和"a"同时出现这类情况）。

**【输入格式】**

```
第一行：整数 N
接下来 N 行：每行一个模式串
最后一行：文本串 T
```

**【输出格式】**

```
一个整数，表示最多能匹配的模式串数量
```

**【样例输入】**

```
3
ab
a
abcdef
abcde
```

**【样例输出】**

```
2
```

解释：可以在 `"abcde"` 的 `ab` 位置匹配 `"ab"`，在 `cde` 位置… 等等。实质是贪心选择每次匹配的最短模式串，且不重叠。

**【解题思路】**

本题变种：可转化为 AC 自动机上统计每个结尾位置的最佳选择。由于不可重叠且模式串不可互相包含，可以使用 AC 自动机匹配所有可能的结束位置，然后 DP 或贪心。

**简化做法：**
1. 构建 AC 自动机
2. 遍历文本串，记录每个位置能匹配的模式串（取最短的一个）
3. 贪心选择不重叠的匹配

**【参考代码见 `程序/lesson44_ac_automaton.cpp`】**
