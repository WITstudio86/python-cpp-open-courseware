## 一、二进制状态表示法

### 1.1 核心思想

状态压缩DP（State Compression DP，也称"状压DP"）的核心思想是：**用一个整数的二进制位来表示集合中每个元素"选或不选"的状态。**

例如，有3个元素 {0, 1, 2}，整数 `mask = 5`（二进制 `101`）表示选中了元素 0 和元素 2，没有选中元素 1。

| 十进制 | 二进制 | 含义（选中元素） |
|--------|--------|-------------------|
| 0 | 000 | 空集 {} |
| 1 | 001 | {0} |
| 2 | 010 | {1} |
| 3 | 011 | {0, 1} |
| 4 | 100 | {2} |
| 5 | 101 | {0, 2} |
| 6 | 110 | {1, 2} |
| 7 | 111 | {0, 1, 2} |

### 1.2 位运算基础回顾

在状态压缩DP中，以下位运算是最常用的操作：

```cpp
// 1. 检查第 i 位是否为 1
if (mask & (1 << i))  // mask 的第 i 位是 1

// 2. 将第 i 位置为 1
mask |= (1 << i);

// 3. 将第 i 位置为 0
mask &= ~(1 << i);

// 4. 翻转第 i 位
mask ^= (1 << i);

// 5. 获取最低位的 1 及其位置
int lowbit = mask & (-mask);  // lowbit = 最低位的 1 代表的值
int pos = __builtin_ctz(mask); // GCC 内置函数，最低位 1 的位置

// 6. 统计二进制中 1 的个数
int cnt = __builtin_popcount(mask);

// 7. 判断 mask 是否包含集合 sub
bool contains = (mask & sub) == sub;

// 8. 集合并集、交集
int union_set = mask1 | mask2;
int inter_set = mask1 & mask2;
```

### 1.3 状态压缩DP的适用条件

- **元素数量 n 通常较小**（n ≤ 20）：因为状态空间是 O(2^n)，n=20 时状态数约为 100 万
- **每个元素只有两种状态**（选/不选、访问/未访问等）
- **状态的转移只依赖于子集的状态**

**典型的时间复杂度：** O(n × 2^n) 或 O(n² × 2^n)

## 二、子集枚举技巧

### 2.1 枚举所有子集

枚举一个集合 mask 的所有子集（包括空集和 mask 本身）：

```cpp
// 枚举 mask 的所有子集
for (int sub = mask; ; sub = (sub - 1) & mask) {
    // sub 是 mask 的一个子集
    // 在此处理 sub
    if (sub == 0) break;
}
// 注意：上面的循环包含空集 sub=0，且会经过空集后退出
// 如果不希望处理空集，可以写：
// for (int sub = mask; sub; sub = (sub - 1) & mask) { ... }
```

**原理：** `(sub - 1) & mask` 会得到"比 sub 小的、且是 mask 子集的最大整数"。这是因为 `sub - 1` 会把 sub 最低位的 1 变 0，其后所有位变 1，再 `& mask` 保证仍然是 mask 的子集。

### 2.2 时间复杂度

枚举大小为 n 的全集（mask = 2^n - 1）的所有子集的子集，总复杂度为 **O(3^n)**。

这是因为每个元素有三种可能的状态：
- 不在 mask 中
- 在 mask 中但不在 sub 中
- 在 mask 中且在 sub 中

故总状态数为 3^n。

**对应CSP-S真题场景：** 当需要枚举一个状态的子集来进行转移时（如"互不侵犯"问题中枚举上一行的合法状态）。

## 三、TSP问题（旅行商问题）—— 最短Hamilton路径

### 3.1 问题描述

给定 n 个城市的带权完全图（或任意图），求从起点出发，**恰好访问每个城市一次**，最后到达终点的最短路径长度。这是经典的 **NP-hard 问题**。

在竞赛中，n 通常 ≤ 20，使用状态压缩DP可以在 O(n² × 2^n) 时间内求出精确解，这远超暴力搜索的 O(n!)。

### 3.2 状态设计

设 `dp[mask][i]` 表示：**已经访问过 mask 集合中的城市，当前停留在城市 i 的最短路径长度。**

- `mask`：一个 n 位二进制数，第 j 位为 1 表示城市 j 已被访问
- `i`：当前所在的城市编号（0 ≤ i < n）

**初始化：**
```cpp
// 从城市 i 出发（起点）
dp[1 << i][i] = 0;  // 其余为 INF (无穷大)
```

### 3.3 状态转移方程

对于状态 `dp[mask][i]`，考虑上一步是从城市 j 走到 i：

```
dp[mask][i] = min(dp[mask ^ (1<<i)][j] + dist[j][i])
```

其中：
- `mask ^ (1<<i)` 表示从 mask 中去掉城市 i（即到达 i 之前经过的城市集合）
- j 必须是 mask 中去掉 i 之后还在集合中的城市，即 `(mask ^ (1<<i)) & (1<<j) != 0`
- `dist[j][i]` 是从 j 到 i 的边权

**最终答案：** `min(dp[(1<<n)-1][i])`，其中 i 遍历所有城市（如果起点和终点没有特殊要求）。

如果指定终点为 n-1：答案为 `dp[(1<<n)-1][n-1]`。

### 3.4 转移顺序

按 mask 从小到大枚举（因为转移时 `mask ^ (1<<i)` 一定小于 `mask`，满足拓扑序）：

```cpp
for (int mask = 1; mask < (1 << n); mask++) {
    for (int i = 0; i < n; i++) {
        if (!(mask & (1 << i))) continue;       // i 必须在 mask 中
        int prev = mask ^ (1 << i);              // 去掉 i 后的集合
        for (int j = 0; j < n; j++) {
            if (!(prev & (1 << j))) continue;    // j 必须在 prev 中
            dp[mask][i] = min(dp[mask][i], dp[prev][j] + dist[j][i]);
        }
    }
}
```

### 3.5 时间复杂度分析

- 状态数量：O(n × 2^n)
- 每个状态的转移：O(n)
- 总复杂度：**O(n² × 2^n)**

对于 n=20：状态数约 20 × 10^6 = 2 × 10^7，转移约 4 × 10^8，在 1 秒左右刚好可以跑完（需要一定的常数优化）。

## 四、经典问题变体与扩展

### 4.1 棋盘类状压DP

在棋盘上放置棋子（国王、炮兵等），通常按**行**进行 DP。用 mask 表示当前行哪些列放置了棋子。

**核心步骤：**
1. 预处理所有"自身合法"的行状态（如：没有相邻的国王）
2. 预处理任意两个行状态之间的"兼容性"（上下行不冲突）
3. 逐行 DP：`dp[row][mask][cnt]`，其中 cnt 表示已放置的棋子数量

### 4.2 覆盖类状压DP

用 1×2 的骨牌覆盖棋盘，通常按**列**进行 DP。用 mask 表示当前列的哪些行被"伸出来"的骨牌占据。

**关键判断：** 两个相邻列的 mask 之间能否合法转移（需要检查空格是否为偶数等）。

### 4.3 排列类状压DP

求满足某种条件的排列数/最优排列。用 mask 表示已使用元素的集合，dp[mask] 表示已排列 mask 中元素的最优值。

## 五、真题精练

### 真题1：最短Hamilton路径

**【题目描述】**

给定一张 n 个点的带权无向图，点从 0 到 n-1 编号。求从起点 0 到终点 n-1 的最短 Hamilton 路径。

Hamilton 路径的定义：从 0 到 n-1 **不重不漏**地经过每个点恰好一次。

**【输入格式】**

第一行输入整数 n。
接下来 n 行，每行 n 个整数，其中第 i 行第 j 列的整数表示点 i 到 j 的距离（记为 `a[i][j]`）。
对于任意的 i, j，数据保证 `a[i][j] = a[j][i]` 且 `a[i][i] = 0`。

- 1 ≤ n ≤ 20
- 0 ≤ a[i][j] ≤ 10^7

**【输出格式】**

输出一个整数，表示最短 Hamilton 路径的长度。

**【样例输入】**
```
5
0 2 4 5 1
2 0 6 5 3
4 6 0 8 3
5 5 8 0 5
1 3 3 5 0
```

**【样例输出】**
```
18
```

**【解题思路】**

标准的状态压缩DP模板。`dp[mask][i]` 表示已经走过的城市集合为 mask（二进制第 j 位为 1 表示走过城市 j），当前在城市 i 的最短路径长度。

枚举顺序：从小到大枚举 mask，对于每个 mask 枚举当前城市 i 和上一个城市 j。

### 真题2：互不侵犯（SCOI2005）

**【题目描述】**

在 N×N 的棋盘里面放 K 个国王，使他们互不攻击，共有多少种摆放方案。

国王能攻击到它**上、下、左、右、左上、左下、右上、右下**八个方向上附近的各一个格子，共 8 个格子。

**【输入格式】**

一行两个整数 N, K。

- 1 ≤ N ≤ 9
- 0 ≤ K ≤ N²

**【输出格式】**

一个整数，表示方案数。

**【样例输入】**
```
3 2
```

**【样例输出】**
```
16
```

**【解题思路】**

**状态设计：** `dp[row][state][cnt]` 表示前 row 行，第 row 行的状态为 state，一共摆了 cnt 个国王的方案数。

**预处理：**
1. 枚举所有单行的合法状态（状态 state 中不能有相邻的 1，即 `state & (state << 1) == 0`）
2. 预处理每个状态的国王数量（即 `__builtin_popcount(state)`）
3. 预处理任意两个状态之间是否兼容（上下行不冲突）：
   - `state1 & state2 == 0`（不能在同一列）
   - `state1 & (state2 << 1) == 0`（不能在对角线）
   - `state1 & (state2 >> 1) == 0`（不能在对角线）

**转移方程：**
```
dp[row][cur][cnt] = sum(dp[row-1][prev][cnt - popcount(cur)])
```
其中 prev 和 cur 兼容。

**最终答案：** `sum(dp[N][state][K])`，对所有合法 state 求和。

时间复杂度：O(N × (合法状态数)² × K)，合法状态数远小于 2^N，当 N=9 时只有约 89 个。

> 详见 `/程序/lesson35_state_compression_dp_basic.cpp` 中的完整 AC 代码。

## 💻 代码模板

### 模板1：最短Hamilton路径（TSP标准模板）

这是状压DP的"Hello World"——考试中出现率极高的模板题。掌握了此模板，就掌握了状压DP的核心思维方式。

```cpp
// ========== 最短Hamilton路径 标准模板 ==========
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 20;
const int INF = 0x3f3f3f3f;

int n;
int dist[MAXN][MAXN];
int dp[1 << MAXN][MAXN];

int solve_hamilton() {
    // 1. 初始化：所有状态为 INF
    memset(dp, 0x3f, sizeof(dp));
    // 2. 起点：只访问了城市 0，当前在城市 0
    dp[1 << 0][0] = 0;
    // 3. 枚举所有 mask（按 mask 从小到大天然满足拓扑序）
    for (int mask = 1; mask < (1 << n); mask++) {
        for (int i = 0; i < n; i++) {
            if (!(mask & (1 << i))) continue;      // i 不在 mask 中
            int prev = mask ^ (1 << i);             // 去掉 i 后的集合
            for (int j = 0; j < n; j++) {
                if (!(prev & (1 << j))) continue;   // j 不在 prev 中
                dp[mask][i] = min(dp[mask][i], dp[prev][j] + dist[j][i]);
            }
        }
    }
    // 4. 答案：访问完所有城市，最终停在 n-1
    return dp[(1 << n) - 1][n - 1];
}
```

### 模板2：棋盘类状压DP标准框架

棋盘类问题（国王放置、炮兵阵地等）的通用框架：

```cpp
// ========== 棋盘状压DP 通用框架 ==========
const int MAXN = 10;
const int MAXK = 100;

int N, K;
long long dp[MAXN][1 << MAXN][MAXK];

vector<int> legal_state;        // 所有自身合法的行状态
vector<int> state_popcount;     // 每个状态的棋子数量

// Step 1: 预处理自身合法的行状态
void preprocess_row_states() {
    for (int state = 0; state < (1 << N); state++) {
        if (is_row_legal(state)) {
            legal_state.push_back(state);
            state_popcount.push_back(__builtin_popcount(state));
        }
    }
}

// Step 2: 判断两个行状态是否兼容
bool compatible(int prev_state, int cur_state) {
    // 同一列不能同时有棋子
    if (prev_state & cur_state) return false;
    // 对角线不能有冲突
    if (prev_state & (cur_state << 1)) return false;
    if (prev_state & (cur_state >> 1)) return false;
    return true;
}

// Step 3: DP 转移
long long solve_chessboard() {
    preprocess_row_states();
    int S = legal_state.size();

    // 第1行初始化
    for (int i = 0; i < S; i++) {
        int cnt = state_popcount[i];
        if (cnt <= K) dp[1][i][cnt] = 1;
    }

    // 逐行 DP
    for (int row = 2; row <= N; row++) {
        for (int i = 0; i < S; i++) {         // 当前行状态索引
            int cur_cnt = state_popcount[i];
            for (int j = 0; j < S; j++) {     // 上一行状态索引
                if (!compatible(legal_state[j], legal_state[i])) continue;
                int prev_cnt = state_popcount[j];
                for (int total = cur_cnt; total <= K; total++) {
                    dp[row][i][total] += dp[row-1][j][total - cur_cnt];
                }
            }
        }
    }

    // 统计答案
    long long ans = 0;
    for (int i = 0; i < S; i++) {
        ans += dp[N][i][K];
    }
    return ans;
}
```

## �️ 位运算速查表

以下是状态压缩DP中最常用的位运算操作总结。建议**熟记**这些操作，考场上无需推导直接使用。

| 操作 | 代码 | 说明 |
|------|------|------|
| 检查第 i 位是否为 1 | `mask & (1 << i)` | 结果为非0表示第i位是1 |
| 将第 i 位置为 1 | `mask \|= (1 << i)` | 不影响其他位 |
| 将第 i 位置为 0 | `mask &= ~(1 << i)` | 注意~的优先级 |
| 翻转第 i 位 | `mask ^= (1 << i)` | 0变1，1变0 |
| 获取最低位的1 | `mask & -mask` | lowbit 技巧 |
| 去掉最低位的1 | `mask & (mask - 1)` | Brian Kernighan算法 |
| 统计1的个数 | `__builtin_popcount(mask)` | GCC内置，O(1) |
| 获取最低位1的位置 | `__builtin_ctz(mask)` | count trailing zeros |
| 获取最高位1的位置 | `31 - __builtin_clz(mask)` | count leading zeros |
| 判断子集关系 | `(mask & sub) == sub` | sub是mask的子集 |
| 集合并集 | `mask1 \| mask2` | 两个集合的并 |
| 集合交集 | `mask1 & mask2` | 两个集合的交 |
| 集合差集 | `mask1 & ~mask2` | mask1减去mask2的元素 |
| 生成n位全1 | `(1 << n) - 1` | n个1的掩码 |
| 判断相邻位 | `state & (state << 1)` | 非0表示有相邻的1 |
| 判断是否为2的幂 | `(mask & (mask - 1)) == 0` | 掩码中只有1个1 |

**位运算优先级速记**（从高到低）：`~` > `<<` `>>` > `&` > `^` > `|` > `==` `!=` > `&&` `||`

**黄金法则**：所有涉及位运算的复杂表达式，一律加上括号。编译器不会怪你多加括号，但会因为你没加括号而出现难以调试的逻辑错误。

## 六、常见错误与注意事项

### 6.1 位运算优先级

**位运算的优先级低于比较运算符！** 这是最常见的踩坑点。

```cpp
// 错误写法 ❌
if (mask & 1 << i == 0)  // 实际是 mask & (1 << i == 0)，先算 ==

// 正确写法 ✅
if ((mask & (1 << i)) == 0)
if (!(mask & (1 << i)))
```

**优先级从高到低：** `~` > `<<` `>>` > `&` > `^` > `|` > `==` `!=`

**建议：** 凡是涉及位运算的表达式，都加上括号，不要依赖优先级记忆。

### 6.2 数组大小

```cpp
// dp 的大小是 [1 << n]，不是 [n]！
int dp[1 << 20];   // n ≤ 20 时需要约 100 万个 int

// 如果 dp 有两个维度：
int dp[1 << 20][20];  // 约 80 MB，注意内存限制
// 如果 n=20 且内存紧张，可以考虑使用 short 或者滚动数组
```

### 6.3 INF 的取值

INF 不要使用 `INT_MAX`，因为加法会溢出。推荐：
```cpp
const int INF = 0x3f3f3f3f;  // 约 1e9，且 memset 方便
memset(dp, 0x3f, sizeof(dp)); // 每个字节都是 0x3f
```

### 6.4 枚举顺序

**转移时 mask 必须从小到大枚举**（或使用记忆化搜索），因为 `mask ^ (1<<i)` 总是小于 `mask`（去掉了第 i 位），天然满足 DP 的拓扑序。

### 真题3：蒙德里安的梦想（骨牌覆盖状压DP）

**【题目描述】**

求把 N×M 的棋盘分割成若干个 1×2 的长方形（骨牌），有多少种不同的分割方案。

例如：当 N=2, M=3 时，共有 3 种方案。

**【输入格式】**

输入包含多组测试用例。每组测试用例占一行，包含两个整数 N 和 M。当 N=0, M=0 时表示输入终止。

- 1 ≤ N, M ≤ 11

**【输出格式】**

每组测试用例输出一个结果，每个结果占一行。

**【样例输入】**
```
1 2
1 3
1 4
2 2
2 3
2 4
2 11
4 11
0 0
```

**【样例输出】**
```
1
0
1
2
3
5
144
51205
```

**【解题思路】**

这是一道经典的**按列状压DP**（也可按行）。核心思想：用一个二进制数 mask 表示**当前列有哪些行被"伸出来"的骨牌占据**。

**状态设计思路**：
- 考虑从左到右逐列放置骨牌。一个 1×2 的骨牌可以横着放（占据当前列和下一列的同一行），也可以竖着放（占据当前列的两行）。
- `dp[col][mask]`：前 col 列已完全铺满，第 col+1 列**被伸出来的横骨牌占据**的行集合为 mask。
- 初始状态：`dp[0][0] = 1`（第0列没有任何摆放，也没有伸出来的骨牌）
- 答案：`dp[M][0]`（M列都放完了，第M+1列没有伸出来的，表示完美覆盖）

**转移条件**：从状态 `dp[col][mask]` 转移到 `dp[col+1][next_mask]`。需要判断在当前列的 mask 和 next_mask 约束下，能否合法摆放。关键判断：
1. mask 和 next_mask 不能有重叠（同一行不能被两个骨牌占据）
2. mask | next_mask 中，连续的空位必须是偶数个（竖骨牌占2行，所以空位必须成对）

**AC 代码**：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 12;

int N, M;
long long dp[1 << MAXN];     // 滚动数组优化
bool valid[1 << MAXN];       // valid[mask]: mask中的连续0是否都是偶数个

int main() {
    ios::sync_with_stdio(false); cin.tie(0);

    while (cin >> N >> M) {
        if (N == 0 && M == 0) break;

        // 预处理：哪些状态是"自身连续0为偶数"
        for (int mask = 0; mask < (1 << N); mask++) {
            int cnt = 0;       // 连续0的个数
            bool ok = true;
            for (int i = 0; i < N; i++) {
                if (mask & (1 << i)) {   // 这一行是1（有伸出来的骨牌）
                    if (cnt & 1) { ok = false; break; }  // 前面的连续0是奇数
                    cnt = 0;
                } else {
                    cnt++;
                }
            }
            if (cnt & 1) ok = false;   // 最后一段连续0也需要偶数
            valid[mask] = ok;
        }

        // DP初始化
        memset(dp, 0, sizeof(dp));
        dp[0] = 1;  // 第0列：没有任何伸出来的

        // 逐列DP
        for (int col = 1; col <= M; col++) {
            long long ndp[1 << MAXN] = {0};
            for (int prev = 0; prev < (1 << N); prev++) {
                if (dp[prev] == 0) continue;
                for (int cur = 0; cur < (1 << N); cur++) {
                    // cur: 当前列被横骨牌占据的情况（伸到下一列）
                    // prev: 上一列伸到当前列的情况
                    // 条件1: prev和cur不能有重叠
                    if (prev & cur) continue;
                    // 条件2: prev|cur的剩余空位（竖骨牌占位）必须是偶数连续段
                    if (valid[prev | cur]) {
                        ndp[cur] += dp[prev];
                    }
                }
            }
            memcpy(dp, ndp, sizeof(dp));
        }

        // 答案：M列填完，第M+1列没有伸出来的
        cout << dp[0] << '\n';
    }

    return 0;
}
```

**复杂度分析**：
- 状态数：O(2^N) 每列
- 转移：O(2^(2N)) 每列（两重循环枚举 prev 和 cur）
- 总复杂度：O(M × 4^N)，对于 N ≤ 11 是可行的
- 空间：滚动数组优化后 O(2^N)

**关键点总结**：
- 按列DP的视角：从"已经摆放好的列"向"下一列"转移
- `valid[mask]` 预处理是关键优化，避免了每次转移时重新判断
- 这也是"棋盘覆盖类"问题的通用模型——理解此题就掌握了骨牌覆盖类问题的核心
