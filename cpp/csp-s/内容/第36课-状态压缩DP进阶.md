## 一、轮廓线DP（插头DP入门）

### 1.1 什么是轮廓线DP

轮廓线DP（又称"插头DP"）是状态压缩DP的一个重要变体，用于解决**网格覆盖类**问题（如骨牌覆盖、路径覆盖等）。

**核心思想：** 在逐格（或逐列）递推的过程中，并不是保存整个棋盘的状态，而是只保存**当前处理格子的"轮廓线"**（即已处理区域和未处理区域的分界线）上的状态。

```
已处理区域  |  未处理区域
    ■ ■ ■  |  □ □ □
    ■ ■ ■  |  □ □ □
    ■ ■ ○  |  □ □ □    ← 轮廓线（○ 是当前格子）
          ↑
      轮廓线上的格子状态需要记录
```

对于 n × m 的网格，轮廓线上最多有 m（或 n）个格子，状态数最多为 2^m，远小于保存整个棋盘的 2^(n×m)。

### 1.2 轮廓线DP的基本框架

以逐格推进为例（按行、每行从左到右处理）：

```cpp
// dp[row][col][state] 或滚动数组优化
// state 用 m 位二进制表示轮廓线上哪些位置已被骨牌"伸出"

for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        for (int state = 0; state < (1 << m); state++) {
            // 根据 (i,j) 位置是否已被覆盖，决定转移
            // 转移1：如果未被覆盖，尝试横放骨牌
            // 转移2：如果未被覆盖，尝试竖放骨牌
            // 转移3：如果已被覆盖，直接跳过
        }
    }
}
```

### 1.3 轮廓线DP的常见应用

| 问题类型 | 状态表示 | 典型题目 |
|----------|----------|----------|
| 骨牌覆盖（1×2） | 每列的覆盖状态（bitmask） | 蒙德里安的梦想 |
| L形覆盖/Tetris | 轮廓线上格子的高度 | 插头DP经典题 |
| 哈密顿回路计数 | 插头配对信息 | 插头DP进阶 |
| 棋盘染色 | 当前行及上一行的状态 | 状压DP |

## 二、蒙德里安的梦想（骨牌覆盖经典问题）

### 2.1 问题描述

求把 N × M 的棋盘分割成若干个 1 × 2 的长方形（骨牌），有多少种方案。

例如，当 N=2, M=4 时，共有 5 种方案。

### 2.2 状态设计

我们**按列**进行 DP。一列一列地考虑。

设 `dp[col][state]` 表示：**处理完前 col 列后（即前 col 列已完全被骨牌覆盖），第 col 列有"伸出来"的骨牌的状态为 state 的方案数。**

- state 是一个 N 位二进制数，第 i 位为 1 表示第 col 列的第 i 行有一个**横向**骨牌伸到了第 col+1 列（即一个 1×2 的骨牌横跨了两列）。
- 这些"伸出"的格子连同第 col+1 列的同位置格子一起被一个横向骨牌覆盖。

### 2.3 状态转移（关键）

对于从第 col-1 列到第 col 列的转移，设：
- `prev`：第 col-1 列的"伸出"状态（伸到第 col 列）
- `cur`：第 col 列的"伸出"状态（伸到第 col+1 列）

**转移的合法性条件：**

1. **不能冲突：** `prev & cur == 0`，因为同一行的同一列不可能同时被两个骨牌（一个从前列伸来，一个伸向下列）占据。

2. **空格必须能用竖骨牌填满：** 考虑第 col 列中，哪些格子是空闲的（既没有被 prev 中的横向骨牌占据，也没有被 cur 中的横向骨牌占据）。这些空格必须用 1×2 的**竖骨牌**填满。

   空闲格子的状态：`free = (~(prev | cur)) & ((1 << N) - 1)`

   判断条件：free 的二进制表示中，连续的 0 的个数必须都是**偶数**（因为竖骨牌占 2 格，必须成对出现）。

   **简化判断：** `free` 中不能有奇数个连续的 0。即：将 free 按位分组，每组连续 0 的个数必须是偶数。

   等价条件：`free & (free << 1) == 0`？不对，这是一个常见的错误判断。正确做法是检查 free 是否可以被 2×1 的骨牌完全覆盖——即检查是否存在连续奇数个 0。

   **正确判据：** 预处理一个布尔数组 `st[state]`，表示状态 state 的所有连续 0 的段的长度是否都是偶数。这样转移时直接查表即可。

### 2.4 算法流程

```cpp
// Step 1: 预处理 st[] 数组
// st[state] = true 当且仅当 state 中所有连续0的段长为偶数
for (int state = 0; state < (1 << N); state++) {
    int cnt = 0;  // 连续0的个数
    bool ok = true;
    for (int i = 0; i < N; i++) {
        if (state >> i & 1) {
            if (cnt & 1) { ok = false; break; } // 奇数个连续0
            cnt = 0;
        } else {
            cnt++;
        }
    }
    if (cnt & 1) ok = false;  // 末尾的连续0
    st[state] = ok;
}

// Step 2: 预处理合法转移
// prev -> cur 合法当且仅当：
// (1) prev & cur == 0（不冲突）
// (2) st[prev | cur] == true（空格可被竖骨牌填满）
vector<int> trans[1 << N];
for (int prev = 0; prev < (1 << N); prev++) {
    for (int cur = 0; cur < (1 << N); cur++) {
        if ((prev & cur) == 0 && st[prev | cur]) {
            trans[prev].push_back(cur);
        }
    }
}

// Step 3: DP
memset(dp, 0, sizeof(dp));
dp[0][0] = 1;  // 第0列没有伸出，方案数为1
for (int col = 1; col <= M; col++) {
    for (int prev = 0; prev < (1 << N); prev++) {
        for (int cur : trans[prev]) {
            dp[col][cur] += dp[col-1][prev];
        }
    }
}

// 答案：处理完 M 列后，第 M 列没有任何骨牌伸出
cout << dp[M][0] << endl;
```

### 2.5 时间复杂度

- 预处理 st：O(2^N × N)
- 预处理 trans：O(2^N × 2^N)
- DP：O(M × 合法转移数)

当 N ≤ 11, M ≤ 11 时，2^N = 2048，完全可行。即使 N=11, M=11，总复杂度也在可接受范围内。

## 三、状压 + 概率DP / 期望DP

### 3.1 期望DP的基本概念

**期望DP** 是在状态转移中引入概率/期望的一种DP形式。通常用于解决以下类型的问题：

- 在随机过程中，求达到某个目标状态的**期望步数/期望收益**
- 每个状态有多个可能的转移方向，每个方向有一定的概率

### 3.2 状态设计

在状态压缩的期望DP中，典型的状态设计是：

```
dp[mask] = 从当前状态 mask 出发，达到目标状态还需要的最优期望值
```

**转移形式：**
```
dp[mask] = Σ(概率_i × 选择(新状态的最优值))
```

如果转移可能回到自身（自环），需要使用**高斯消元**或将自环项移项：
```
dp[mask] = p_self × dp[mask] + Σ(p_other × dp[other]) + cost
=> dp[mask] = (Σ(p_other × dp[other]) + cost) / (1 - p_self)
```

### 3.3 CSP-S 中的期望DP特点

在 CSP-S 级别，期望DP通常不会涉及复杂的高斯消元（那是NOI级别的内容）。常见的是：

1. **无环转移**：概率转移图是有向无环图（DAG），可以直接DP
2. **线性期望**：利用期望的线性性质，分别计算每个元素的贡献再求和
3. **全期望公式**：E[X] = Σ P(A_i) × E[X | A_i]

## 四、真题精练

### 真题1：蒙德里安的梦想

**【题目描述】**

求把 N × M 的棋盘分割成若干个 1 × 2 的长方形，有多少种方案。

**【输入格式】**

输入包含多组测试数据。
每组数据占一行，包含两个整数 N 和 M。
当输入 N=0, M=0 时，表示输入终止。

- 1 ≤ N, M ≤ 11

**【输出格式】**

每组数据输出一个结果，每个结果占一行。

**【样例输入】**
```
1 2
1 3
1 4
2 2
2 3
2 4
2 11
4 11
0 0
```

**【样例输出】**
```
1
0
1
2
3
5
144
51205
```

**【解题思路】**

采用按列的状压DP。核心要点：

1. `st[state]`：预处理每个列状态 state 是否合法（连续空格段长度均为偶数）
2. `dp[col][state]`：前 col 列铺满，第 col 列状态为 state 的方案数
3. 转移条件：`prev & cur == 0` 且 `st[prev | cur] == true`
4. 最终答案：`dp[M][0]`（最后没有骨牌伸出）

### 真题2：奖励关（期望DP + 状压）

**【题目描述】**

你正在玩一个游戏。游戏中有 n 种宝物，每种宝物有一个分值 p_i，以及一个"前提宝物集合" s_i（用二进制数表示），你需要先获得 s_i 中的所有宝物，才能选择获取宝物 i。

游戏规则：
- 系统会进行 K 轮
- 每轮系统会**等概率**随机抛出 n 种宝物中的一种（可能重复）
- 你可以选择**获取**（需要满足前提条件）或者**放弃**该宝物
- 每种宝物最多只能获取一次

求在**最优策略**下，期望获得的总分。

**【输入格式】**

第一行两个正整数 K 和 n，分别表示轮数和宝物种数。
接下来 n 行，每行描述一种宝物。其中第一个整数表示分值 p_i，后面若干个整数表示该宝物的前提宝物编号，以 0 结尾。

- 1 ≤ K ≤ 100
- 1 ≤ n ≤ 15
- 分值在 [-10^6, 10^6] 范围内（宝物分值为负时，最优策略可能是放弃）

**【输出格式】**

输出一个实数，保留 6 位小数，表示期望得分。

**【样例输入】**
```
1 2
1 0
2 1 0
```

(注：实际题目输入格式可能略有差异，以洛谷 P2473 为准)

**【样例输出】（示例）**
```
1.500000
```

**【解题思路】**

**状态设计：** `dp[mask]` 表示**已经收集了 mask 集合中的宝物**，在接下来的操作中（剩余轮数未知时），按最优策略能获得的期望最大总分。

实际上，由于轮数 K 会影响期望，通常有两种设计方式：

**方式一（正向，按轮数DP）：** `dp[round][mask]` = 经过 round 轮后，已收集 mask 的期望最大得分。这种写法简单直观。

**方式二（逆推，更常用）：** 从最后一轮向前推，`dp[round][mask]` = 从第 round 轮开始到结束，当前已收集 mask，能获得的期望最大得分。

**逆推转移方程：**
```
对于第 round 轮，枚举系统抛出的宝物 i（等概率 1/n）：
  如果 mask 已满足宝物 i 的前提条件（即 s_i ⊆ mask）：
    // 可以选择获取或者放弃
    best = max(dp[round+1][mask], dp[round+1][mask | (1<<i)] + p_i)
  否则（不满足前提条件）：
    // 只能放弃
    best = dp[round+1][mask]
  
  dp[round][mask] += best / n
```

**初始化：** `dp[K+1][mask] = 0`（第 K+1 轮及以后没有收益）

**最终答案：** `dp[1][0]`

由于采用逆推，不再需要考虑"最优策略"的决策——每次决策时未来状态已经算好了，直接取 max 即可。

**时间复杂度：** O(K × 2^n × n)，K ≤ 100，n ≤ 15，2^15 = 32768，总操作约 100 × 32768 × 15 ≈ 5 × 10^7，可以接受。

## 五、状压DP解题方法论总结

### 5.1 识别"状压DP可解"的信号

1. **题目中 n ≤ 20**，而暴力是 O(n!) 或 O(2^n × n!)
2. **每个元素"选/不选"**，且选择有顺序依赖
3. **棋盘规模小**（如 n, m ≤ 10），但覆盖/放置问题状态复杂
4. **集合的表示和操作**成为瓶颈

### 5.2 常见题型与模板

| 题型 | 状态设计 | 转移思路 |
|------|----------|----------|
| TSP/哈密顿路径 | dp[mask][last] | 枚举上一个节点 |
| 棋盘放置（国王/炮兵） | dp[row][state][cnt] | 按行转移，检查兼容性 |
| 骨牌覆盖（蒙德里安） | dp[col][state] | 按列转移，检查空格合法性 |
| 排列/分配 | dp[mask] | 枚举下一个加入的元素 |
| 期望DP + 状压 | dp[round][mask] | 逆推，枚举随机事件 |

### 5.3 优化技巧

1. **预处理合法状态和合法转移**：将状态检查（相邻位、兼容性）预先算好，避免在DP循环中重复计算
2. **使用 vector 存储合法后继**：`vector<int> trans[mask]` 存储 mask 可转移到的状态列表
3. **滚动数组优化空间**：如果 dp 有 "行/列" 维度，只保留当前和上一行
4. **使用 __builtin_popcount** 代替手动计数
5. **位运算替代布尔数组**：用掩码快速检查状态合法性

## 六、本节总结

| 知识点 | 核心技巧 | 典型复杂度 |
|--------|----------|------------|
| 轮廓线DP | 保存分界线状态，逐格/逐列递推 | O(nm × 2^min(n,m)) |
