## 知识精讲

### 一、大O表示法 (Big-O Notation)

#### 1.1 数学定义

设 \( f(n) \) 和 \( g(n) \) 是定义在正整数上的函数，其中 \( f(n) \) 表示算法的实际运行时间，\( g(n) \) 表示一个简单的参考函数。

- **大O (上界)**: \( f(n) = O(g(n)) \) 当且仅当存在正常数 \( c \) 和 \( n_0 \)，使得对于所有 \( n \ge n_0 \)，有 \( 0 \le f(n) \le c \cdot g(n) \)。
- **大Ω (下界)**: \( f(n) = \Omega(g(n)) \) 当且仅当存在正常数 \( c \) 和 \( n_0 \)，使得对于所有 \( n \ge n_0 \)，有 \( 0 \le c \cdot g(n) \le f(n) \)。
- **大Θ (紧确界)**: \( f(n) = \Theta(g(n)) \) 当且仅当 \( f(n) = O(g(n)) \) 且 \( f(n) = \Omega(g(n)) \)。

**直观理解**：
- O 描述的是"最坏不会超过" —— 增长率的上界
- Ω 描述的是"最好不会低于" —— 增长率的下界
- Θ 描述的是"恰好增长得一样快" —— 增长率的紧确界

#### 1.2 渐进分析中的常见操作

在分析复杂度时，我们遵循以下规则：

1. **忽略常数因子**：\( O(3n) = O(n) \)，\( O(100) = O(1) \)
2. **忽略低阶项**：\( O(n^2 + n) = O(n^2) \)，\( O(n^2 + n \log n) = O(n^2) \)
3. **加法法则**：\( O(f(n)) + O(g(n)) = O(\max(f(n), g(n))) \)
4. **乘法法则**：\( O(f(n)) \times O(g(n)) = O(f(n) \times g(n)) \)

### 二、最好/最坏/平均复杂度

#### 2.1 三种情况分析

| 情况 | 含义 | 分析方法 |
|------|------|----------|
| 最坏复杂度 (Worst Case) | 算法在所有可能输入中运行时间的最大值 | 构造最不利的输入，分析该输入下的操作次数 |
| 最好复杂度 (Best Case) | 算法在所有可能输入中运行时间的最小值 | 构造最有利的输入，分析该输入下的操作次数 |
| 平均复杂度 (Average Case) | 算法在所有可能输入上运行时间的期望值 | 假设输入的概率分布，计算运行时间的数学期望 |

**示例——线性搜索**：
- 最好情况：目标元素在第一个位置，\( O(1) \)
- 最坏情况：目标元素在最后一个位置或不存在，\( O(n) \)
- 平均情况：假设目标等概率出现在任意位置，期望比较次数为 \( \frac{n+1}{2} = O(n) \)

**示例——快速排序**：
- 最好情况：每次划分都均匀，\( O(n \log n) \)
- 最坏情况：数组已有序（若选第一个元素为基准），\( O(n^2) \)
- 平均情况：\( O(n \log n) \)

#### 2.2 CSP-S应试策略

在CSP-S考试中，我们通常关注**最坏情况复杂度**，因为它保证了算法在任何输入下都不会超时。但在实际选择算法时，快速排序的平均复杂度优秀，实际使用中通过随机化选基准来避免最坏情况。

### 三、递归复杂度分析与主定理

#### 3.1 递归树法

对于递推式 \( T(n) = a \cdot T(\frac{n}{b}) + f(n) \)，其中 \( a \) 是递归子问题的个数，\( b \) 是每个子问题规模的缩小因子，\( f(n) \) 是合并子问题结果的开销。

**递归树分析步骤**：
1. 画出递归树，根节点代价为 \( f(n) \)
2. 第 \( k \) 层有 \( a^k \) 个节点，每个节点代价为 \( f(\frac{n}{b^k}) \)
3. 总代价 = 所有层代价之和

#### 3.2 主定理 (Master Theorem)

对于递推式 \( T(n) = aT(\frac{n}{b}) + O(n^d) \)，其中 \( a \ge 1, b > 1, d \ge 0 \)：

**情况1**：若 \( d < \log_b a \)（递归调用开销占主导），则
\[ T(n) = O(n^{\log_b a}) \]

**情况2**：若 \( d = \log_b a \)（递归调用与合并开销平衡），则
\[ T(n) = O(n^d \log n) = O(n^{\log_b a} \log n) \]

**情况3**：若 \( d > \log_b a \)（合并开销占主导），则
\[ T(n) = O(n^d) \]

**实例验证**：
- 归并排序：\( T(n) = 2T(\frac{n}{2}) + O(n) \)，\( a=2, b=2, d=1 \)，\( \log_b a = 1 = d \)，属于情况2，\( T(n) = O(n \log n) \)
- 二分查找：\( T(n) = T(\frac{n}{2}) + O(1) \)，\( a=1, b=2, d=0 \)，\( \log_b a = 0 = d \)，属于情况2，\( T(n) = O(\log n) \)
- Strassen矩阵乘法：\( T(n) = 7T(\frac{n}{2}) + O(n^2) \)，\( a=7, b=2, d=2 \)，\( \log_2 7 \approx 2.81 > 2 \)，属于情况1，\( T(n) = O(n^{\log_2 7}) \approx O(n^{2.81}) \)

### 五、均摊复杂度 (Amortized Analysis)

#### 5.1 概念

均摊复杂度分析的是**一系列操作的平均时间**，即使单个操作可能很昂贵，但一系列操作的总体代价是可控的。

#### 5.2 三种分析方法

1. **聚合分析**：计算 n 次操作的总代价 \( T(n) \)，则均摊代价为 \( T(n)/n \)
2. **记账法**：为每次操作分配"存款"，昂贵的操作使用之前存储的存款
3. **势能法**：定义势能函数 \( \Phi \)，操作代价 = 实际代价 + 势能变化量

#### 5.3 经典例子：动态数组扩容

向动态数组（如C++的`vector`）末尾添加元素：
- 当数组满时，分配2倍大小的新数组，复制所有元素
- 单次扩容操作复杂度为 O(n)，但均摊复杂度为 O(1)

**证明**（聚合分析）：
- 假设从空数组开始，连续插入 n 个元素
- 扩容发生在容量为 1, 2, 4, 8, 16, ..., 2^k 时（其中 2^{k-1} < n ≤ 2^k）
- 总复制次数 = 1 + 2 + 4 + ... + 2^{k-1} < 2^k ≤ 2n
- n 次插入的总代价 = n (插入) + 2n (复制) ≤ 3n
- 均摊代价 = 3n / n = O(1)

## 代码模板

```cpp
/*
 * 时间复杂度分析模板
 * 功能：评估一段代码的时间复杂度
 * 使用方法：
 *   1. 将待测代码放入 measure() 函数中
 *   2. 运行程序，观察不同 n 值下的运行时间
 *   3. 根据增长趋势判断复杂度级别
 */
#include <bits/stdc++.h>
using namespace std;
using namespace chrono;

// 计时工具函数
template<typename Func>
double measure_time(Func f, int n) {
    auto start = high_resolution_clock::now();
    f(n);
    auto end = high_resolution_clock::now();
    duration<double> elapsed = end - start;
    return elapsed.count();
}

// ==================== 不同复杂度的算法实现 ====================

// O(log n) - 二分查找（非递归版）
int binary_search(vector<int>& arr, int target) {
    int l = 0, r = arr.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;  // 防止溢出
        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}

// O(log n) - 二分查找（递归版），递推式 T(n)=T(n/2)+O(1)
int binary_search_rec(vector<int>& arr, int l, int r, int target) {
    if (l > r) return -1;
    int mid = l + (r - l) / 2;
    if (arr[mid] == target) return mid;
    if (arr[mid] < target)
        return binary_search_rec(arr, mid + 1, r, target);
    else
        return binary_search_rec(arr, l, mid - 1, target);
}

// O(n log n) - 归并排序，递推式 T(n)=2T(n/2)+O(n)
void merge(vector<int>& arr, int l, int mid, int r) {
    vector<int> tmp(r - l + 1);
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) {
        if (arr[i] <= arr[j]) tmp[k++] = arr[i++];
        else tmp[k++] = arr[j++];
    }
    while (i <= mid) tmp[k++] = arr[i++];
    while (j <= r) tmp[k++] = arr[j++];
    for (int p = 0; p < k; p++) arr[l + p] = tmp[p];
}

void merge_sort(vector<int>& arr, int l, int r) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    merge_sort(arr, l, mid);
    merge_sort(arr, mid + 1, r);
    merge(arr, l, mid, r);
}

// O(n^2) - 冒泡排序
void bubble_sort(vector<int>& arr) {
    int n = arr.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                swap(arr[j], arr[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // 优化：提前终止
    }
}

// O(2^n) - 递归求解斐波那契数列（低效版）
int fibonacci_rec(int n) {
    if (n <= 1) return n;
    return fibonacci_rec(n - 1) + fibonacci_rec(n - 2);
}

// O(n) - 迭代求解斐波那契数列
int fibonacci_iter(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}

// O(log n) - 快速幂（矩阵快速幂求斐波那契）
using ll = long long;
const ll MOD = 1e9 + 7;

void mat_mul(ll a[2][2], ll b[2][2]) {
    ll c[2][2] = {{0, 0}, {0, 0}};
    for (int i = 0; i < 2; i++)
        for (int j = 0; j < 2; j++)
            for (int k = 0; k < 2; k++)
                c[i][j] = (c[i][j] + a[i][k] * b[k][j]) % MOD;
    memcpy(a, c, sizeof(c));
}

void mat_pow(ll a[2][2], int n) {
    ll res[2][2] = {{1, 0}, {0, 1}};  // 单位矩阵
    while (n) {
        if (n & 1) mat_mul(res, a);
        mat_mul(a, a);
        n >>= 1;
    }
    memcpy(a, res, sizeof(res));
}

ll fibonacci_log(int n) {
    if (n <= 1) return n;
    ll a[2][2] = {{1, 1}, {1, 0}};
    mat_pow(a, n - 1);
    return a[0][0];
}
```

## 易错点与优化技巧

### 常见错误

1. **混淆 log 的底数**：在大O表示法中，\( O(\log_2 n) = O(\log_3 n) = O(\log n) \)，因为换底公式 \( \log_a n = \frac{\log_b n}{\log_b a} \)，常数因子被忽略。所以写 \( O(\log n) \) 即可，无需指定底数。

2. **误判嵌套循环的复杂度**：
   ```cpp
   // 这不是 O(n^2)！
   for (int i = 0; i < n; i++)
       for (int j = i; j < n; j += i + 1)  // 内层循环次数递减
           // ...
   ```
   需要实际计算内层循环的执行次数之和。

3. **忽略递归的复杂度**：递归函数不仅考虑递归深度，还要考虑每层的工作量。如`fibonacci_rec(5)`有15次调用，复杂度为O(2^n)，而不是O(n)。

4. **STL操作的复杂度**：务必记住常用STL操作的复杂度：
   - `vector::push_back`：均摊 O(1)
   - `vector::insert(iterator, val)`：O(n)
   - `set/map::insert`：O(log n)
   - `unordered_set/unordered_map::insert`：均摊 O(1)，最坏 O(n)
   - `sort`：O(n log n)
   - `nth_element`：O(n)
   - `priority_queue::push/pop`：O(log n)

### 优化技巧

1. **二分查找用 `mid = l + (r - l) / 2`** 而非 `(l + r) / 2`，避免整数溢出。

2. **使用 `lower_bound` / `upper_bound`** 替代手写二分查找，代码更简洁且不易出错。

3. **输入数据的范围决定了可选算法**：
   - n ≤ 10：可用 O(n!) 的枚举全排列
   - n ≤ 20：可用 O(2^n) 的状态压缩DP
   - n ≤ 100：可用 O(n^3) 的 Floyd 算法
   - n ≤ 5000：可用 O(n^2) 的DP
   - n ≤ 10^5：可用 O(n log n) 的排序或二分
   - n ≤ 10^6：需要 O(n) 或 O(n log n) 且常数较小的算法
   - n ≥ 10^7：只能 O(n)，且要注意输入输出优化

## 真题精练

### 题目1：时间复杂度判断

**【题目描述】**

给定一个长度为 \( n \) 的整数数组 \( a_1, a_2, \dots, a_n \)，你需要处理 \( q \) 次操作，每次操作为以下两种之一：

1. `1 x`：在数组中查找元素 \( x \) 是否存在，若存在输出其下标（任意一个即可），否则输出 `-1`。
2. `2 l r k`：将下标在 \( [l, r] \) 范围内的所有元素加上 \( k \)，然后输出该范围内元素的最大值。

请分析以下两种实现方案的时间复杂度，并判断在 \( n, q \le 10^5 \) 的数据范围下哪种方案可行。

- **方案A**：
  - 查询操作：线性扫描数组查找 \( x \)
  - 修改操作：遍历 \( [l, r] \) 更新每个元素，再遍历求最大值

- **方案B**：
  - 查询操作：使用 `unordered_map` 记录每个值的所有出现位置
  - 修改操作：使用线段树维护区间加和区间最大值

**【时间复杂度分析】**

**方案A**：
- 单次查询：O(n)
- 单次修改：O(n)（遍历更新 O(n) + 遍历求最大值 O(n) = O(n)）
- 总复杂度：O(q × n)，最坏为 \( 10^5 \times 10^5 = 10^{10} \)，不可行。

**方案B**：
- 单次查询：O(1)（哈希表查找）
- 单次修改（区间加会导致元素值变化，需要更新哈希表）：若只考虑线段树的区间操作，单次修改 O(log n)，但维护哈希表需要额外处理。
- 实际上这题的正解是使用**线段树**维护区间最大值，并用**平衡树或线段树**维护每个值的位置集合，整体复杂度 O((n+q) log n)，在 \( 10^5 \) 范围内可行。

**【AC代码】**

本题的核心是分析复杂度，不需要完整实现。但给出线段树维护区间加和区间最大值的模板：

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

const int MAXN = 100005;
ll tree[MAXN * 4], lazy[MAXN * 4];
int n, q;

void push_up(int rt) {
    tree[rt] = max(tree[rt << 1], tree[rt << 1 | 1]);
}

void push_down(int rt, int l, int r) {
    if (lazy[rt]) {
        int mid = (l + r) >> 1;
        tree[rt << 1] += lazy[rt];
        tree[rt << 1 | 1] += lazy[rt];
        lazy[rt << 1] += lazy[rt];
        lazy[rt << 1 | 1] += lazy[rt];
        lazy[rt] = 0;
    }
}

void build(int rt, int l, int r, vector<ll>& a) {
    if (l == r) { tree[rt] = a[l]; return; }
    int mid = (l + r) >> 1;
    build(rt << 1, l, mid, a);
    build(rt << 1 | 1, mid + 1, r, a);
    push_up(rt);
}

void update(int rt, int l, int r, int ql, int qr, ll val) {
    if (ql <= l && r <= qr) {
        tree[rt] += val;
        lazy[rt] += val;
        return;
    }
    push_down(rt, l, r);
    int mid = (l + r) >> 1;
    if (ql <= mid) update(rt << 1, l, mid, ql, qr, val);
    if (qr > mid) update(rt << 1 | 1, mid + 1, r, ql, qr, val);
    push_up(rt);
}

ll query(int rt, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return tree[rt];
    push_down(rt, l, r);
    int mid = (l + r) >> 1;
    ll res = LLONG_MIN;
    if (ql <= mid) res = max(res, query(rt << 1, l, mid, ql, qr));
    if (qr > mid) res = max(res, query(rt << 1 | 1, mid + 1, r, ql, qr));
    return res;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n >> q;
    vector<ll> a(n + 1);
    for (int i = 1; i <= n; i++) cin >> a[i];
    build(1, 1, n, a);
    while (q--) {
        int op, l, r; ll k;
        cin >> op >> l >> r;
        if (op == 1) {
            cin >> k;
            update(1, 1, n, l, r, k);
        } else {
            cout << query(1, 1, n, l, r) << '\n';
        }
    }
    return 0;
}
```

【复杂度分析】
- 建树：O(n)
- 单次更新/查询：O(log n)
- 总复杂度：O((n + q) log n)，适用于 n, q ≤ 10^5

### 题目2：多重循环复杂度分析

**【题目描述】**

小K在准备CSP-S考试时，写下了以下两段代码。请分别分析它们的时间复杂度（用大O表示法表示），并对于每个代码段，指出当 \( n = 10^5 \) 时能否在 1 秒内运行完成（假设计算机每秒执行 \( 10^8 \) 次基本操作）。

**代码段1**：
```cpp
int ans = 0;
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j += i) {
        ans++;
    }
}
```

**代码段2**：
```cpp
int ans = 0;
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j *= 2) {
        for (int k = 1; k <= j; k++) {
            ans++;
        }
    }
}
```

**【题目分析】**

**代码段1分析**：

内层循环 `j` 的步长为 `i`，对于每个固定的 `i`，内层循环执行 \( \left\lfloor \frac{n}{i} \right\rfloor \) 次。

总执行次数：
\[ \sum_{i=1}^{n} \left\lfloor \frac{n}{i} \right\rfloor \approx n \sum_{i=1}^{n} \frac{1}{i} = n \cdot H_n \]

其中 \( H_n \) 是调和数，\( H_n = 1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n} \approx \ln n + \gamma \approx O(\log n) \)。

因此总复杂度为 \( O(n \log n) \)。

当 \( n = 10^5 \) 时，操作次数约为 \( 10^5 \times \ln(10^5) \approx 10^5 \times 11.5 \approx 1.15 \times 10^6 \)，远小于 \( 10^8 \)，**可以在1秒内完成**。

**代码段2分析**：

最内层循环执行 `j` 次 (`k` 从 1 到 `j`)。

中层循环：`j = 1, 2, 4, 8, ..., 2^p`（其中 \( 2^p \le i < 2^{p+1} \)）。

对于固定的 `i`，中层循环有 \( \lfloor \log_2 i \rfloor + 1 \) 次迭代，每次迭代最内层执行 `j = 2^t` 次。

对于固定的 `i`，总执行次数：
\[ \sum_{t=0}^{\lfloor \log_2 i \rfloor} 2^t = 2^{\lfloor \log_2 i \rfloor + 1} - 1 < 2i \]

因此对于固定的 `i`，内两层共执行 O(i) 次。

总复杂度：
\[ \sum_{i=1}^{n} O(i) = O(n^2) \]

准确计算：对于每个 `i`，操作次数约为 \( 2 \times 2^{\lfloor \log_2 i \rfloor} - 1 \approx O(i) \)，总复杂度为 \( O(n^2) \)。

当 \( n = 10^5 \) 时，操作次数约为 \( \frac{n^2}{2} \approx 5 \times 10^9 \)，远超 \( 10^8 \)，**无法在1秒内完成**。

**【AC代码】**

验证上述分析的测试程序：

```cpp
#include <bits/stdc++.h>
using namespace std;
using ll = long long;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    // 代码段1：O(n log n) 验证
    int n = 100000;
    ll cnt1 = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= n; j += i) {
            cnt1++;
        }
    }
    cout << "代码段1操作次数: " << cnt1 << '\n';
    // 理论值: n * H_n ≈ 100000 * 12.09 ≈ 1,209,000

    // 代码段2：O(n^2) 验证（n 较小时测试）
    n = 5000;
    ll cnt2 = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= i; j *= 2) {
            for (int k = 1; k <= j; k++) {
                cnt2++;
            }
        }
    }
    cout << "代码段2操作次数(n=" << n << "): " << cnt2 << '\n';
    // 理论值: 约 2*n^2/2 = n^2 = 25,000,000

    return 0;
}
```

【复杂度分析】
- 代码段1：O(n log n)，适合 \( n \le 10^7 \)
- 代码段2：O(n²)，仅适合 \( n \le 5000 \)

## 本课小结

1. **大O表示法**是分析算法效率的核心工具，我们关注的是输入规模趋于无穷时的渐进行为。
2. **主定理**提供了分析分治递归算法复杂度的通用方法，记住三种情况的条件。
3. **常见复杂度级别**：O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)。
4. **均摊分析**帮助我们理解某些操作序列的平均代价，最典型的是动态数组的扩容。
5. **CSP-S应试核心**：根据数据范围推断期望的复杂度级别，选择合适的算法。
