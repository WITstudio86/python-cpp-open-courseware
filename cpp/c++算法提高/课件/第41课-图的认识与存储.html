图的认识与存储

一、图是什么？

定义：图（Graph）由 顶点集 V 和 边集 E 组成，记作 G = (V, E)。它是描述事物之间"关系"的强大工具。

朋友圈关系图（无向图）

[小明] ─────────── [小红] │ │ │ │ [小刚] ─────────── [小丽] │ │ [小强] V = {小明, 小红, 小刚, 小丽, 小强} E = {(小明,小红), (小明,小刚), (小红,小丽), (小刚,小丽), (小刚,小强)}

现实世界中的图

场景顶点 = ?边 = ?
社交网络用户好友关系 / 关注关系
道路地图城市 / 路口公路
网页链接网页超链接
电路板电子元件导线
航班网络机场航线
核心思想：万事万物皆可抽象为"顶点 + 关系"，图论就是研究这种关系网络的数学分支。

二、图的分类

类型特点生活举例
无向图边没有方向，(u,v) = (v,u)微信好友（互为好友）
有向图边有方向，u → v ≠ v → u微博关注（A 关注 B，B 不一定关注 A）
带权图边上带有"权重"数值城市间距离（公里）
无权图边只表示存在/不存在简单的好友关系

有向图 vs 无向图

无向图（对称） 有向图（单向） A ─── B A ──→ B │ │ │ │ │ │ ↓ ↓ C ─── D C ←── D

带权图示例

北京 ──1200km──→ 上海 │ │ 300km 500km │ │ 南京 ──300km──→ 杭州
记忆口诀：无向如镜子（互相对称），有向如单行道（单向通行），带权如导航（有距离数字）。

三、邻接矩阵存储

核心：用一个 二维数组 graph[N][N] 表示图。
graph[i][j] = 1 表示有边，graph[i][j] = 0 表示无边。
无向图的邻接矩阵是 对称的：graph[i][j] == graph[j][i]

存储示意图

图结构: 邻接矩阵 graph[4][4]: 1 ─── 2 1 2 3 4 │ ╱ ┌───────┐ │ ╱ 1│0 1 0 1│ 3 2│1 0 1 0│ │ 3│0 1 0 1│ 4 4│1 0 1 0│ └───────┘

代码实现

const int MAXN = 101;
int graph[MAXN][MAXN];   // 邻接矩阵

// 添加无向边
void addEdge(int u, int v) {
    graph[u][v] = 1;
    graph[v][u] = 1;       // 对称赋值！
}

// 查询：O(1) 判断两点是否相邻
bool hasEdge(int u, int v) {
    return graph[u][v] == 1;
}
优点缺点
实现简单直观空间 O(V²)，稀疏图浪费严重
查询边 O(1)遍历邻居需 O(V)
修改边方便无法存储重边
适用场景：顶点数 ≤ 500，边比较稠密，或需要频繁判断"两点是否相邻"。

四、邻接表存储

核心：为每个顶点维护一个 邻居列表。
使用 vector<int> adj[N]，adj[u] 存储 u 的所有邻居。

存储示意图

图结构: 邻接表: 1 ─── 2 adj[1] = {2, 4} │ ╱ adj[2] = {1, 3} │ ╱ adj[3] = {2, 4} 3 adj[4] = {1, 3} │ 4

代码实现

#include <vector>
using namespace std;

const int MAXN = 101;
vector<int> adj[MAXN];    // 邻接表

void addEdge(int u, int v) {
    adj[u].push_back(v);
    adj[v].push_back(u);
}

// 遍历 u 的所有邻居
for (int v : adj[u]) {
    cout << v << " ";
}
优点缺点
空间 O(V+E)，稀疏图友好查询边需 O(degree)
遍历邻居高效 O(degree)删除边稍麻烦
天然支持重边实现稍复杂
适用场景：绝大多数实际问题！顶点数大、边稀疏时首选邻接表。

五、链式前向星（进阶）

本质：邻接表的 数组高效实现，用单向链表模拟邻接表，是算法竞赛中的常用选择。

核心数据结构

struct Edge {
    int to;       // 边的终点
    int next;     // 下一条边的索引（链表指针）
    int w;        // 边权（可选）
} edge[MAXM];

int head[MAXN];  // head[u] 指向从 u 出发的第一条边
int cnt = 0;     // 边计数器

加边操作（头插法）

void addEdge(int u, int v, int w) {
    cnt++;
    edge[cnt].to = v;
    edge[cnt].w = w;
    edge[cnt].next = head[u];  // 新边指向之前的"第一条边"
    head[u] = cnt;             // head 指向新边
}

遍历邻居

for (int i = head[u]; i != -1; i = edge[i].next) {
    int v = edge[i].to;   // 邻居顶点
    int w = edge[i].w;    // 边的权重
}
优点：无 vector 开销，常数极小，速度快于邻接表。
缺点：实现相对复杂，需要理解链表插入逻辑。
什么时候用：参加算法竞赛、追求极致性能时使用。

六、三种存储方式总结

复杂度对比

操作邻接矩阵邻接表 (vector)链式前向星
存储空间O(V²)O(V + E)O(V + E)
添加边O(1)O(1) 均摊O(1)
删除边O(1)O(degree)不直接支持
查询边 (u,v)O(1)O(degree)O(degree)
遍历 u 的邻居O(V) ❌O(degree)O(degree)
实现难度★☆☆☆☆★★☆☆☆★★★☆☆

如何选择？

场景推荐方式原因
V ≤ 500，边稠密邻接矩阵O(1)查边，简单
V 较大，边稀疏邻接表空间 O(V+E)，遍历快
频繁判断两点相邻邻接矩阵O(1) 快速
只关心遍历/搜索邻接表每条边访问一次
算法竞赛链式前向星常数最小
本课核心收获：
1. 图 G = (V, E) 是描述"关系"的自然数学工具
2. 邻接矩阵 → 稠密图 / 小规模 / 需要快速查边
3. 邻接表 → 稀疏图 / 大规模 / 遍历边
4. 链式前向星 → 竞赛用、性能极致
5. 选存储方式的核心依据：图的稠密程度和需要的操作
