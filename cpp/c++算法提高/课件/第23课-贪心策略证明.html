交换论证法 —— 证明贪心正确性的利器

核心思想

假设存在一个最优解 OPT，但它和我们的贪心解不一样。 我们一步一步地把 OPT "改造"成贪心解，每次改造都不会让结果变差。 最终 OPT 变成了贪心解，说明贪心解就是最优解！

┌──────────────────────────────────────────────────────────┐ │ 交换论证五步法 │ │ │ │ ① 假设存在一个最优解 OPT │ │ ② 找到 OPT 中第一个与贪心解不同的选择位置 │ │ ③ 在此位置用贪心选择替换 OPT 的选择 │ │ ④ 证明替换后结果不差（≤ 原 OPT） │ │ ⑤ 重复②-④，直到 OPT 变成贪心解 │ │ │ │ 结论：贪心解 ≥ OPT ≥ 贪心解 → 贪心解 = OPT！ │ └──────────────────────────────────────────────────────────┘

生活类比

书架整理的故事：
朋友说他的书架排列方式是最优的。你走到他的书架前，把第一本"放错位置"的书按你的方式重新摆放，问他："现在是不是比刚才更好（至少不更差）？"他点头。你一本本改过去，最后他的书架和你的一模一样——你的排列方式就是最优的！

归纳法补充

数学归纳法框架：
基础步骤：第一次贪心选择一定存在于某个最优解中。
归纳步骤：若前 k 步贪心选择正确，则第 k+1 步也正确。
结论：贪心算法的每一步都正确 → 贪心解 = 最优解。
【讲解】交换论证法 —— 证明贪心正确性的利器 结合讲义《二、交换论证法——"换一下也不会更好"》强调： · 交换论证（Exchange Argument）是贪心证明中最常用、最直观的方法。它的核心思路是这样的： · 第一步：假设存在一个"最优解"，但它和我们的贪心解不同。 · 第二步：我们在这个"最优解"中找到第一个和贪心选择不一致的地方。 · 第三步：在这个不一致的地方，用贪心选择去"替换"最优解中的选择，证明替换后的结果不会变得更差。 · 第四步：经过有限次这样的替换后，最优解被逐步"改造"成了贪心解，而每次改造都没有让结果变差。 幻灯片上可见要点： · 假设存在一个 最优解 OPT ，但它和我们的贪心解 不一样 。 我们一步一步地把 OPT "改造"成贪心解， 每次改造都不会让结果变差 。 最终 OPT 变成了贪心解，说明贪心解就是最优解！ · 最优解 OPT · 每次改造都不会让结果变差 · 书架整理的故事： 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。 本课大纲考点（可适时点题）：交换论证、归纳法简易证明

排队接水 —— 排序贪心 + 交换论证

问题描述

N 个人在一个水龙头前排队接水，每人需要 tᵢ 分钟。
求一种排队顺序，使所有人的等待时间之和最小。

接水时间
[3, 1, 2]
→
贪心排序后
[1, 2, 3]
→
最小等待: 4

贪心策略

策略：按接水时间从小到大排序，让接水快的人先接。
直觉：如果接水慢的人排在前面，他后面的每个人都要多等很久！

交换论证证明

假设最优顺序中 A 在 B 前面，但 t(A) > t(B) 交换 A 和 B 的位置 ┌──────────────────────────────────────┐ │ ... → A(慢) → ... → B(快) → ... │ ← 交换前 │ ... → B(快) → ... → A(慢) → ... │ ← 交换后 └──────────────────────────────────────┘ 交换后： - A前面的人：等待时间不变 - B后面的人：等待时间不变（总接水时间未变） - A与B之间的人：等待时间都减少 t(A)-t(B) > 0 → 总等待时间严格减少！ → 原顺序不可能是最优的 ✗ 结论：任何最优排列中，接水时间短的人必须在前面 ✓
【讲解】排队接水 —— 排序贪心 + 交换论证 结合讲义《排队接水——排序贪心》强调： · using namespace std; · // 结构体：记录每个人的编号和接水时间 · struct Person { · int id; // 编号（输入顺序） · int time; // 接水所需时间 幻灯片上可见要点： · N 个人在一个水龙头前排队接水，每人需要 tᵢ 分钟。 求一种排队顺序，使 所有人的等待时间之和最小 。 · 所有人的等待时间之和最小 · 从小到大排序 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

排队接水 —— 代码实现

核心代码（C++）

struct Person {
    int id;    // 原始编号
    int time;  // 接水时间
};

bool cmp(Person a, Person b) {
    return a.time < b.time;  // 按时间升序
}

long long minWaitingTime(Person p[], int n) {
    sort(p, p + n, cmp);  // 贪心核心：排序

    long long totalWait = 0;
    long long prefixSum = 0;  // 前缀和

    for (int i = 0; i < n; i++) {
        totalWait += prefixSum;         // 当前人的等待时间
        prefixSum += p[i].time;         // 累加接水时间
    }

    return totalWait;
}

样例测试

输入
n = 5
t = [3, 6, 1, 4, 2]
排序后
[1, 2, 3, 4, 6]
顺序: 3 5 1 4 2
输出
最少等待: 22
复杂度：O(n log n) 时间（排序瓶颈），O(n) 空间
【讲解】排队接水 —— 代码实现 讲义提要：| 操作 | 时间复杂度 | 说明 | |------|-----------|------| | 排序 | O(n log n) | 使用 sort 对 n 个人按接水时间排序 | | 计算等待时间 | O(n) | 一次遍历计算前缀和 | | **总时间复杂度** | **O(n log n)** | 排序是瓶颈 | | **空间复杂度** | **O(n)** | 存储 n 个人的信息 | 本页要点（照着讲即可）： · 复杂度： 代码页节奏：先读懂输入输出 → 再走主流程 → 最后点出易错点（边界/类型/下标）。 可让学生预测下一行输出，再运行对照。

合并果子 —— 优先队列贪心 + 归纳法

问题描述

有 n 堆果子，每次合并任意两堆，合并代价 = 两堆重量之和。
求合并成一堆的最小总代价（本质是哈夫曼编码问题）。

贪心策略

策略：每次选取最小的两堆进行合并，合并后的新堆放回去，继续重复。
工具：优先队列（最小堆），每次 O(log n) 取最小的两个元素。

归纳法证明思路

基础（n=2）： 只有两堆 → 只有一种合并方式 → 显然最优 ✓ 归纳： 设最小两堆为 a 和 b。 用交换论证证明：存在最优方案，a 和 b 是第一次合并的。 如果最优方案中先合并的不是 a 和 b，则可以用 a 和 b 替换，证明总代价不增加（因为 a 和 b 最小，最先合并 对总代价贡献最小）。 合并 a 和 b 后 → 问题变为 n-1 堆子问题 由归纳假设 → 子问题贪心最优 → 整体最优 ✓

合并果子 —— 代码与合并树

核心代码

#include <queue>
using namespace std;

int minMergeCost(int piles[], int n) {
    // 最小堆：greater<int> 使堆顶是最小元素
    priority_queue<int, vector<int>, greater<int>> pq;

    for (int i = 0; i < n; i++) pq.push(piles[i]);

    int totalCost = 0;
    while (pq.size() > 1) {
        int a = pq.top(); pq.pop();  // 最小
        int b = pq.top(); pq.pop();  // 次小
        int merged = a + b;
        totalCost += merged;
        pq.push(merged);          // 放回新堆
    }
    return totalCost;
}

合并树可视化（样例：[1, 2, 3, 4, 5]）

15 ← 最终一堆 / \ 6 9 / \ / \ 3 3 4 5 / \ 1 2 步骤1: 1+2=3 (代价+3) 步骤2: 3+3=6 (代价+6) 步骤3: 4+5=9 (代价+9) 步骤4: 6+9=15(代价+15) 总代价: 3+6+9+15 = 33
复杂度：O(n log n) 时间，O(n) 空间
每一步堆操作 O(log n)，共 n-1 步。

本课小结 —— 贪心证明的核心方法

交换论证

  • 假设存在更优解 OPT
  • 找到第一个与贪心不同的位置
  • 用贪心选择替换
  • 证明替换后结果不差
  • 重复直到 OPT = 贪心解

归纳法

  • 基础步骤：第一步贪心选择正确
  • 归纳步骤：若前 k 步正确
    则第 k+1 步也正确
  • 结论：每一步都正确
    → 贪心解 = 最优解

策略：按时间升序排序
证明：交换论证
关键点：快的人在前
复杂度：O(n log n)

证明：归纳法+交换论证
