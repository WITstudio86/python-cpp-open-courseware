选择排序 —— 算法框架与代码

算法框架（伪代码）
for i = 0 到 n-2: // 共 n-1 轮 minIndex = i // 假设arr[i]最小 for j = i+1 到 n-1: // 扫描未排序部分 if arr[j] < arr[minIndex]: minIndex = j // 发现更小的，更新 if minIndex != i: 交换 arr[i] 和 arr[minIndex] // 放到前面
// 完整的选择排序函数（升序） void selectionSort(int arr[], int n) { for (int i = 0; i < n - 1; i++) { // 第1步：在未排序区间 arr[i..n-1] 中找最小值 int minIndex = i; for (int j = i + 1; j < n; j++) { if (arr[j] < arr[minIndex]) { minIndex = j; } } // 第2步：将最小值交换到 arr[i] if (minIndex != i) { int temp = arr[i]; arr[i] = arr[minIndex]; arr[minIndex] = temp; } } }

关键技巧：

  • minIndex 记录的是最小值的位置（索引），不是值本身
  • 内层循环结束后才交换——每轮最多只交换一次
  • if (minIndex != i) 避免自己和自己交换（优化）

选择排序 vs 冒泡排序

对比维度冒泡排序选择排序
核心操作 比较 相邻 两个元素，逆序就交换 扫描 整个 未排序区间，选出最小值后交换
每轮结果 最大的元素"冒泡"到末尾 最小的元素"浮"到最前面
交换次数 每次比较都可能交换（最多 ~n²/2 次） 每轮最多1次（共 n-1 次）
比较次数 ~n²/2 次（可提前终止） 固定 ~n²/2 次（无论如何）
稳定性 稳定 ✓ 不稳定 ✗
适用场景 数据基本有序时效率高 交换代价高时更优（如大文件）
稳定性说明

对于 [5a, 3, 5b, 2]（5a和5b是两个相等的5）：

冒泡排序 → [2, 3, 5a, 5b]（相等元素保持原序，稳定）

选择排序 → 第1轮2和5a交换 → [2, 3, 5b, 5a]（5a和5b顺序变了，不稳定）

小结：如果交换代价很高（比如对硬盘上的大文件排序），选择排序比冒泡排序更合适——因为交换次数少得多。如果数据基本有序，冒泡排序加上提前终止标志会更快。

【讲解】选择排序 vs 冒泡排序 本页要点（照着讲即可）： · 核心操作 · 每轮结果 · 交换次数 · 比较次数 · 适用场景 · 对于 [5a, 3, 5b, 2] （5a和5b是两个相等的5）： 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

应用：找第k小的数

选择排序有一个巧妙的特性：第 i 轮刚好把第 i+1 小的数放到 arr[i]。利用这一点，只需执行 k 轮就能找到第 k 小的数！

数组 [7, 2, 9, 1, 5]，找 第3小 的数（k=3） 第1轮：在 [7,2,9,1,5] 中找最小 → 1，与arr[0]交换 → [1, 2, 9, 7, 5] 第2轮：在 [2,9,7,5] 中找最小 → 2，已在arr[1] → [1, 2, 9, 7, 5] 第3轮：在 [9,7,5] 中找最小 → 5，与arr[2]交换 → [1, 2, 5, 7, 9] arr[2] = 5 就是第3小的数 ✓
// 只执行 k 轮选择排序，找到第k小的数 int kthSmallest(int arr[], int n, int k) { for (int i = 0; i < k; i++) { // 只做k轮 int minIndex = i; for (int j = i + 1; j < n; j++) { if (arr[j] < arr[minIndex]) minIndex = j; } if (minIndex != i) { int temp = arr[i]; arr[i] = arr[minIndex]; arr[minIndex] = temp; } } return arr[k - 1]; // arr[k-1] 就是第k小的数 }

效率分析：

  • 时间复杂度：O(k × n)，当 k 较小时比完整排序快
  • 如果 k = 1，就是找最小值（1轮）；如果 k = n，等于完整排序
  • 此题也可以用 sort() 后输出 arr[k-1]，但选择排序思路体现了算法的灵活运用
【讲解】应用：找第k小的数 结合讲义《五、选择排序的巧妙应用：找第k小的数》强调： · 选择排序有一个非常巧妙的应用场景：如果我只想找到数组中**第k小的数**，而不需要对整个数组排序，那么只需要进行 k 轮选择即可！ · 这是因为选择排序每一轮都把当前未排序部分的最小值找到并放到正确位置。第1轮找到第1小的数，第2轮找到第2小的数……第k轮找到第k小的数。 · 例如：arr = [7, 2, 9, 1, 5]，找第3小的数（k=3） · 第1轮：在 [7,2,9,1,5] 中选最小值1，放到第1位 → [1, 2, 9, 7, 5] · 第2轮：在 [2,9,7,5] 中选最小值2，放到第2位 → [1, 2, 9, 7, 5]（已在位置） 幻灯片上可见要点： · 选择排序有一个巧妙的特性： 第 i 轮刚好把第 i+1 小的数放到 arr[i] 。利用这一点，只需执行 k 轮就能找到第 k 小的数！ · 第 i 轮刚好把第 i+1 小的数放到 arr[i] · 效率分析： · 时间复杂度： O(k × n) ，当 k 较小时比完整排序快 讲解时放慢关键术语；用 1 个生活类比 + 1 个反例加深印象。

本课小结

选择排序三要素

1. 外层循环 — 控制轮次，i 从 0 到 n-2（共 n-1 轮）

2. 内层循环 — 扫描未排序区间，找到最小值的位置

3. 交换操作 — 将最小值放到本轮的目标位置 arr[i]

要点说明
时间复杂度O(n²)，无论数据初始状态如何
空间复杂度O(1)，原地排序，不需要额外数组
交换次数n-1 次（每轮最多1次），比冒泡排序少得多
稳定性不稳定——跨距离交换可能打乱相等元素顺序
拓展应用找第k小的数——只需k轮选择即可

核心思想回顾：

"每次都从剩下的里面挑最小的，放到前面去。"——这就是选择排序的全部奥义。

这个"选最小"的思想，在后续学习的贪心算法、优先队列等知识中还会反复出现，是算法思维的重要基石。
