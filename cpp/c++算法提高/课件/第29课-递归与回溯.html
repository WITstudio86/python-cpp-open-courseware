试探与回溯 —— 走迷宫式的搜索策略

核心思想 像走迷宫一样，遇到死路就退回来换条路
经典框架 选择 → 试探 → 递归 → 撤销
关键优化 剪枝 —— 提前排除不可能的分支
经典问题 八皇后、组合输出、全排列

生活中的回溯：
走迷宫时，每到一个岔路口用粉笔做标记，选一条路走。遇到死胡同就沿着标记退回来，擦掉标记，换另一条路——这就是回溯！

什么是回溯？—— 走迷宫比喻

回溯法的本质

深度优先搜索 (DFS)
对解空间树进行深度优先遍历，一条路走到底再看其他分支。
状态维护 + 撤销
做选择时记录状态，返回时恢复状态。这是回溯区别于普通DFS的关键。

代码模板

void backtrack(参数) {
    if (满足终止条件) {
        记录/输出解;        // 找到一组解！
        return;
    }

    for (遍历所有候选选择) {
        if (选择合法) {        // ← 剪枝在这里发生
            做选择;              // ② 试探
            backtrack(新参数);    // ③ 递归
            撤销选择;            // ④ 撤销 ★ 关键步骤
        }
    }
}
为什么必须"撤销选择"？
如果不撤销，上一次选择的"脚印"会污染下一条分支。就像走迷宫时，如果你不擦掉之前做的标记，新的路径会被旧标记干扰，可能错过正确的出口。撤销保证了每次探索都是从"干净"的状态开始。

八皇后问题 —— 经典回溯例题

问题规则

  • 8×8 棋盘放 8 个皇后
  • 皇后可以攻击：同行、同列、同对角线
  • 要求任意两个皇后互不攻击
  • 问有多少种放置方法？
答案：92 种解法
实际探索约 2057 个节点
远小于 8! = 40320

数据结构

int pos[8];
// pos[i] = 第i行皇后在哪一列
// 天然保证"每行一个皇后"

冲突检查

// 同列：
pos[i] == col

// 对角线：
abs(row-i) == abs(col-pos[i])
// 行差 = 列差 → 同一条对角线

剪枝优化 —— 回溯法的效率关键

什么是剪枝？

在搜索过程中，如果发现当前选择不可能导出合法解，就立即放弃这个分支，不再继续深入搜索。

没有剪枝

o / | \ o o o ← 全部探索 /|\ /|\ /|\ o o o o o o o o ... 探索量：8! = 40320

有剪枝

o / | \ o o ✗ ← 提前排除！ /|\ /|\ o o ✗ o o ... 探索量：约 2057 个节点

八皇后中的剪枝策略

策略 检查时机 效果
同列剪枝 放置新皇后时立即检查 排除同列冲突分支
对角线剪枝 放置新皇后时立即检查 排除对角线冲突分支
组合剪枝 剩余可选不够时 避免无效深层递归
剪枝口诀： "能早剪就早剪，能剪深就剪深" —— 越早发现分支不可行，节省的计算量越大！

组合输出 + 本课总结

组合输出问题

从 1~n 中选 r 个数，输出所有组合

// n=5, r=3 的输出：
1 2 3   1 2 4   1 2 5
1 3 4   1 3 5   1 4 5
2 3 4   2 3 5   2 4 5
3 4 5
// 共 C(5,3) = 10 种
通过 start 参数保证递增，避免重复组合

组合回溯模板

void dfs(int start, int depth) {
    if (depth == r) {  输出; return; }
    for (int i = start; i <= n; i++) {
        // 剪枝：剩余不够
        if (n-i+1 < r-depth) break;
        comb[depth] = i;        // 选
        dfs(i+1, depth+1);      // 递归
        // 自动撤销（被覆盖）
    }
}
