二分答案 + 贪心验证 · 解决"最小化最大值"问题

专题：查找与二分
核心：二分 + 贪心

🔍 二分答案 + 贪心验证 原理

核心思想

在可能的答案区间上进行二分搜索，每次用 check() 函数判断当前猜测是否可行，从而逐步缩小范围，找到最优解。

关键前提：答案必须具有单调性——存在一个分界点，一侧全部可行，另一侧全部不可行。

流程图解

开始：设定搜索范围 [left, right]
↓
计算中点 mid = (left + right) / 2
↓
check(mid) 是否可行？
✓ 可行
↓
记录 ans = mid
尝试更小 → right = mid - 1
✗ 不可行
↓
需要更大 → left = mid + 1
↓
left > right？→ 输出 ans，结束

贪心验证策略

对于数列分段类问题，check(limit) 使用贪心策略：

  • 从左到右扫描，尽量把元素放入当前段
  • 当前段和超过 limit 时，新起一段
  • 统计总段数，判断是否 ≤ M

💻 check() 函数设计 & 二分框架

check() 函数（贪心验证）

bool check(long long limit) { int segments = 1; // 当前段数，至少1段 long long sum = 0; // 当前段内的元素和 for (int i = 0; i < n; i++) { if (a[i] > limit) return false; // 单元素超限 if (sum + a[i] > limit) { // 当前段装不下 segments++; // 新起一段 sum = a[i]; // 重置当前段和 } else { sum += a[i]; // 加入当前段 } } return segments <= m; // 段数不超过M则可行 }

二分答案框架

long long left = max_elem, right = total_sum; // 确定上下界 long long ans = right; while (left <= right) { long long mid = left + (right - left) / 2; if (check(mid)) { ans = mid; // mid 可行，记录答案 right = mid - 1; // 尝试更小的上限 } else { left = mid + 1; // mid 不可行，需要更大的 } } cout << ans << endl;

复杂度

时间：O(n log S) — check() O(n) × 二分 O(log S)
空间：O(n) — 存储输入数组

🏋️ 例题：数列分段 —— 逐步推演

输入：N = 5, M = 3, 数列 = [4, 2, 4, 5, 1]

二分范围：left = 5（最大元素）, right = 16（总和）

  • 1
    mid = (5 + 16) / 2 = 10
    check(10)：贪心扫描 → [4,2,4], [5,1] → 段数 = 2 ≤ 3
    ✓ 可行 → ans = 10, right = 9
  • 2
    mid = (5 + 9) / 2 = 7
    check(7)：贪心扫描 → [4,2], [4], [5], [1] → 段数 = 4 > 3
    ✗ 不可行 → left = 8
  • 3
    mid = (8 + 9) / 2 = 8
    check(8)：贪心扫描 → [4,2], [4], [5,1] → 段数 = 3 ≤ 3
    ✓ 可行 → ans = 8, right = 7
  • 4
    mid = (8 + 7) / 2 = 7 — left(8) > right(7)，搜索结束
    最终答案：ans = 6（回顾：当 mid=6 时可行，之前已记录）

最优方案：[4, 2] (6) + [4] (4) + [5, 1] (6) → 最大段和 = 6

通过仅 3 次 check() 调用（log₂ 11 ≈ 3.5）就锁定了答案，而暴力需要尝试 12 种可能的答案值。

🏋️ 例题2：月度开销

输入：N = 7, M = 5, 开销 = [100, 400, 300, 100, 500, 101, 400]

二分范围：left = 500（单天最大）, right = 1901（总开销）

check(mid) 验证过程（以 mid = 500 为例）

// check(500)：逐天扫描，贪心分组 // 第1月: 100+400=500 ✓ (再加300→800>500，换月) // 第2月: 300+100=400 ✓ (再加500→900>500，换月) // 第3月: 500 ✓ (再加101→601>500，换月) // 第4月: 101 ✓ (再加400→501>500，换月) // 第5月: 400 ✓ // 月份数 = 5 ≤ M=5 → mid=500 可行 ✓

继续二分，尝试 mid = (500+500)/2 = 500 附近更小的值...
发现 mid = 499 时，第3天 500 > 499，直接不可行。
最优答案：500

最优划分：[100,400] [300,100] [500] [101] [400]

各月开销：500, 400, 500, 101, 400 → 最大 = 500

解题三步走

  1. 定界：确定二分上下界（下界 = 单元素最大，上界 = 总和）
  2. 验证：写 check(mid) 函数——贪心统计所需段数
  3. 搜索：二分框架套用——可行往左缩，不可行往右扩

拓展思考：如果问题改成“最大化最小值”（比如：把 N 个物品分给 M 个人，让得到最少物品的人得到尽可能多），check() 的判定逻辑会如何变化？

二分答案的威力，在于用 O(log n) 的代价，将“最优解搜索”转化为“可行性判定”
