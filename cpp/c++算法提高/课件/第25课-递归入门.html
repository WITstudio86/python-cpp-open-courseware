什么是递归？

递归（Recursion）是一种程序设计技巧，指一个函数在定义中直接或间接地调用自身。

生活中的递归例子：

  • 套娃——打开一个套娃，里面还有一个小一号的套娃，直到最小的那个。
  • 镜子对镜子——两面镜子相对放置，会看到无限嵌套的影像。
  • 讲故事——"从前有座山，山里有座庙，庙里有个老和尚在讲故事，讲的什么故事呢？从前有座山……"
  • 文件夹嵌套——文件夹里面可以有文件夹，一层一层嵌套下去。

在计算机科学中，递归是解决具有自相似结构问题的利器。一个问题如果可以分解为更小的同类子问题，就可以用递归来解决。

递归三要素
①
终止条件
明确"什么时候停下来"
否则会陷入无限递归
→ 导致栈溢出（Stack Overflow）
②
递归公式
明确"问题如何缩小"
将大问题转化为更小的同类问题
→ 每次递归都向终止条件靠近
③
递归调用
明确"函数如何调用自己"
用更小的参数调用自身
→ 将子问题的结果组合为原问题的解

记忆口诀：

递归三要素，一个不能少 —— 结束有终点，递推有公式，自己调用自己！

阶乘递归 —— 最经典的递归例子

定义：n! = n × (n-1) × (n-2) × ... × 1，特别地 0! = 1

递归公式：n! = n × (n-1)! ，终止条件：n == 0 时返回 1

int factorial(int n) { cm">// 终止条件：0的阶乘为1 if (n == 0) return 1; cm">// 递归公式：n! = n * (n-1)! return n * factorial(n - 1); }
factorial(3) │ ├─→ 3 * factorial(2) │ │ │ ├─→ 2 * factorial(1) │ │ │ │ │ ├─→ 1 * factorial(0) │ │ │ │ │ │ │ └─→ 返回 1 ← 终止条件！ │ │ │ │ │ └─→ 返回 1 * 1 = 1 │ │ │ └─→ 返回 2 * 1 = 2 │ └─→ 返回 3 * 2 = 6
斐波那契递归 —— 兔子数列

斐波那契数列：1, 1, 2, 3, 5, 8, 13, 21, ...

递推公式：F(n) = F(n-1) + F(n-2)，F(1)=1, F(2)=1

int fib(int n) { cm">// 终止条件：前两项都是1 if (n == 1 || n == 2) return 1; cm">// 递归：F(n) = F(n-1) + F(n-2) return fib(n - 1) + fib(n - 2); }
fib(5) / \ fib(4) fib(3) / \ / \ fib(3) fib(2) fib(2) fib(1) / \ (1) (1) (1) fib(2) fib(1) (1) (1) → fib(5) = fib(4)+fib(3) = 3+2 = 5

⚠️ 注意：朴素递归求斐波那契有大量重复计算（如fib(2)算了3次），时间复杂度高达O(2ⁿ)。后续课程会学习用记忆化搜索来优化。

递归调用栈 —— 背后的魔法

计算机使用调用栈（Call Stack）来管理函数调用。每次函数调用都会在栈上压入一个"栈帧"，存储函数的参数、局部变量和返回地址。

以 factorial(3) 为例的调用栈变化：
factorial(0) → 返回 1
↑ 返回 ↑
factorial(1) → 等待 1×(结果) → 返回 1
↑ 返回 ↑
factorial(2) → 等待 2×(结果) → 返回 2
↑ 返回 ↑
factorial(3) → 等待 3×(结果) → 返回 6
↑ 调用 ↑
main()

调用时向下生长（压栈），返回时向上收缩（弹栈）

递归的优缺点总结
✅ 优点❌ 缺点
代码简洁、优雅，思路清晰 函数调用有开销，效率可能较低
天然适合处理树、图等递归结构 深度过大可能导致栈溢出
与数学归纳法思维一致，易于证明 可能产生大量重复计算
是分治、回溯等高级算法的基础 调试相对困难，需要追踪调用链
"将复杂问题简单化"的思维模式 某些问题递归转迭代需要额外技巧

💡 核心经验：能递归解决的问题，一定是能分解为更小同类子问题的问题。
