核心问题：在互不重叠的条件下，从 N 个区间中选出尽可能多的区间

算法原理：为什么按结束时间排序？

问题场景

有 N 个活动，每个活动有一个开始时间 s[i] 和一个结束时间 f[i]。 同一时刻只能进行一个活动。目标：选出尽可能多的互不重叠的活动。

可能的策略对比

策略一：按开始时间排序
选开始最早的活动？不对——如果一个活动从 8:00 持续到 20:00，选它之后就再也选不了别的了。
策略二：按持续时间排序
选最短的活动？也不对——短活动可能卡在中间，把两个本来可以都选的长活动破坏了。
策略三：按结束时间排序
选结束最早的活动，然后从剩余活动中选开始时间 >= 已选结束时间的活动。结束越早，留给后面的时间越多！

算法步骤

  1. 将所有活动（区间）按结束时间从小到大排序
  2. 初始化：选中第一个活动，记录 lastEnd = 第一个活动的结束时间
  3. 遍历剩余活动：如果 当前活动.start >= lastEnd，则选中它，更新 lastEnd
  4. 选出的活动数量即为答案

正确性证明：交换论证

交换论证（Exchange Argument）

设最优解 OPT 中结束最早的活动为 A，贪心选出的第一个活动为 B。由于 B 是全局结束最早的，必有 f[B] ≤ f[A]。 在 OPT 中把 A 换为 B，因为 B 结束得更早（或一样早），不会与 OPT 中后续活动产生冲突，所以替换后仍为可行解，且活动数量不变。 重复此过程，可以将 OPT 完全转换为贪心解，证明贪心解也是最优的。

代码实现：区间调度贪心算法

核心思路：struct 存储区间 + sort 自定义比较 + 贪心遍历选择

C++ 区间调度 — 完整实现 
// 定义区间结构体
struct Interval {
    int start;  // 开始时间
    int end;    // 结束时间
};

// 自定义比较函数：按结束时间从小到大排序
bool cmp(Interval a, Interval b) {
    return a.end < b.end;  // 结束时间早的排在前面
}

// 贪心选择最大不重叠区间数
int maxNonOverlap(Interval arr[], int n) {
    // 第一步：按结束时间排序
    sort(arr, arr + n, cmp);

    // 第二步：贪心选择
    int count = 1;               // 至少选第一个
    int lastEnd = arr[0].end;   // 最后一个已选活动的结束时间

    for (int i = 1; i < n; i++) {
        if (arr[i].start >= lastEnd) {  // 不重叠
            count++;
            lastEnd = arr[i].end;     // 更新最后结束时间
        }
    }

    return count;
}

时间复杂度

O(N log N) — 排序是瓶颈
贪心遍历只须 O(N)

空间复杂度

O(N) — 存储 N 个区间
可原地排序做到 O(1) 额外空间

关键细节

端点恰好相接（start == end）
不算重叠，可以同时选

本课小结：区间调度问题

1

核心策略

按结束时间从小到大排序，贪心地选择不重叠的区间

2

正确性证明

交换论证：结束最早的区间给后面留出最多的空间，可以用它替换最优解中的第一个

3

实现技巧

struct 存储区间 + sort 自定义比较函数 + 维护 lastEnd 变量

4

复杂度

O(N log N)，排序是瓶颈
遍历选择只需线性时间

5

经典应用

活动选择、会议安排
