⚙️ 二分答案的两种模式

模式一：求最大值

check 序列: [✓ ✓ ✓ ✓ ✓ | ✗ ✗ ✗ ✗] ↑ 找最后一个 ✓ 的位置 写法要点: if check(mid): ans = mid left = mid + 1 ← 向右 else: right = mid - 1 适用: 砍树(最大高度) 跳石头(最大最小距离)

模式二：求最小值

check 序列: [✗ ✗ ✗ ✗ | ✓ ✓ ✓ ✓ ✓] ↑ 找第一个 ✓ 的位置 写法要点: if check(mid): ans = mid right = mid - 1 ← 向左 else: left = mid + 1 适用: 最小化最大值的 问题(如分配任务)

标准代码框架

// 求最大值框架 —— 找最后一个满足 check 的位置
long long left = L, right = R, ans = L;
while (left <= right) {
    long long mid = left + (right - left) / 2;  // 防溢出
    if (check(mid)) {
        ans = mid;        // 记录可行解
        left = mid + 1;   // 尝试更大 → 向右搜索
    } else {
        right = mid - 1;  // 不可行 → 向左缩小
    }
}
// ans 就是最终答案！
⚠ 关键：mid 计算用 left + (right - left) / 2，防止 (left+right) 溢出

🏋️ 例题1：砍树问题

问题描述

有 n 棵树，需要获得至少 M 米木材。电锯设在高度 H，高于 H 的部分被砍下。求 最大的 H 使得木材足够。

图解砍树过程

—— H=15
砍5米
树1: 20m
未砍
树2: 15m
10<15
树3: 10m
砍2米
树4: 17m
H=15 时：木材 = (20-15) + 0 + 0 + (17-15) = 5 + 0 + 0 + 2 = 7 米 ≥ M=7 ✓

check 函数设计

// 判断电锯高度 H 能否获得至少 M 米木材
bool check(long long H) {
    long long total = 0;
    for (int i = 0; i < n; i++) {
        if (tree[i] > H) total += tree[i] - H;
        if (total >= M) return true;  // 提前返回优化
    }
    return total >= M;
}
// 求最大值模式：check(true) → left=mid+1，check(false) → right=mid-1

🏋️ 例题2：跳石头问题

问题描述

起点到终点距离 L=25，中间有 n=5 块石头。移除至多 M=2 块，求最小间距的最大值。

可视化：d=4 时的 check 过程

起点(0)        石2          石11         石14         石17         石21       终点(25)
  ●─────────────●────────────●────────────●────────────●────────────●───────────●

prev=0
  │            2-0=<4           11-0≥4               14-11=<4         17-11≥4           21-17≥4        25-21≥4
  │           移除✗(1)    保留✓ prev→11    移除✗(2)    保留✓ prev→17    保留✓ prev→21    ✓

总移除 = 2 块 ≤ M=2 → check(4) = true ✓

check 函数设计

// 判断能否在移除 ≤ M 块石头的情况下，使相邻间距 ≥ d
bool check(int d) {
    int removed = 0;      // 已移除石头数
    int prev = 0;         // 上一块保留石头位置(起点=0)
    for (int i = 1; i <= n; i++) {
        if (rock[i] - prev < d) {
            removed++;        // 太近，移除这块石头
            if (removed > M) return false;
        } else {
            prev = rock[i];   // 距离够，保留并更新 prev
        }
    }
    if (L - prev < d) removed++;  // 检查终点
    return removed <= M;
}
贪心策略：从左到右扫描，遇到距离不够的就移除当前石头（而不是前一块），因为保留更靠左的石头能给后面留出更多空间。这个策略是 最优 的！

📊 效率对比与复杂度分析

线性枚举 vs 二分答案

方法 答案范围 10^3 答案范围 10^6 答案范围 10^9
线性枚举 约 1000 次 约 10^6 次 ❌ 10^9 次 ❌❌
二分答案 约 10 次 ✓ 约 20 次 ✓ 约 30 次 ✓✓
log₂(10^9) ≈ 30，这就是二分答案的威力！

二分答案的时间复杂度公式

┌──────────────────────────────────────────────────┐ │ T = O( log₂(R) × T_check ) │ │ │ │ R = 答案范围大小（如 0 ~ 10^9） │ │ T_check = 单次判定函数的时间（如砍树 O(n)） │ │ │ │ 空间复杂度：O(1) —— 只需要几个变量！ │ └──────────────────────────────────────────────────┘
对比总结：
  • 暴力枚举：要尝试答案范围内的 每一个值 → O(R × T_check)
  • 二分答案：只需尝试 log₂(R) 个值 → O(log R × T_check)
  • 当 R=10^9 时，速度提升约 3000万倍！从"不可能"到"瞬间完成"！

🎯 check 函数设计心法

check 是二分答案的"灵魂"，设计好 check 就成功了 80%

设计四步法

  1. 明确问题："如果答案是 mid，是否满足题目要求？"
  2. 模拟计算：按题目规则，以 mid 为参数计算结果
  3. 比较判断：结果是否 ≥（或 ≤）题目要求？
  4. 验证单调：确保 mid 变化时，可行性只拐一次弯

常见错误

  • ❌ check 函数逻辑写反了
  • ❌ 单调性判断错误
  • ❌ 边界条件未处理好
  • ❌ 数据类型溢出（用 long long！）
  • ❌ 忘记提前退出优化

📝 本课小结

✅ 核心收获

  • 二分答案 = 判定 + 二分查找
  • 把"求最优解"变成"判断可行"
  • check 函数是算法的灵魂
  • 必须确保单调性前提成立
  • 两种模式：求最大 / 求最小

📋 应用场景特征

  • 题目问"最大值最小"或"最小值最大"
  • 答案在一个连续范围内
  • 存在单调的可行/不可行分界
  • check 函数可以在较短时间内计算
