## 📖 算法讲解

### 一、贪心算法为什么要证明？

在之前几节课中，我们学习了许多贪心算法：找零钱、活动选择、区间覆盖、部分背包……贪心算法看起来总是很简单——每一步都做"当前看起来最好的选择"，最后就得到了全局最优解。

但问题来了：**凭什么"局部最优"一定能通向"全局最优"？** 并不是所有问题都适用贪心策略。比如在 01 背包问题中，如果按照"单位价值最高"来贪心，就会得到错误答案。

**贪心策略的证明，就是回答一个问题：“为什么我这样做一定是对的？”** 只有经过严格证明的贪心策略，我们才能放心地在竞赛中使用它。本课将介绍两种最适合中小学生的贪心证明方法：交换论证和归纳法。

### 二、交换论证法——"换一下也不会更好"

交换论证（Exchange Argument）是贪心证明中最常用、最直观的方法。它的核心思路是这样的：

**第一步**：假设存在一个"最优解"，但它和我们的贪心解不同。

**第二步**：我们在这个"最优解"中找到第一个和贪心选择不一致的地方。

**第三步**：在这个不一致的地方，用贪心选择去"替换"最优解中的选择，证明替换后的结果不会变得更差。

**第四步**：经过有限次这样的替换后，最优解被逐步"改造"成了贪心解，而每次改造都没有让结果变差。

**第五步**：结论——贪心解至少和最优解一样好，所以贪心解本身就是最优解！

这就像什么呢？想象你和朋友各自整理了一套书。朋友的书架排列方式和你不一样，但他坚持说他的排列方式是最优的。你就走到他的书架前，把第一本放错位置的书按照你的方式重新摆放，然后问他："现在是不是比刚才更好（或者至少不更差）？"他不得不点头。你一本一本地改过去，最后他的书架变得和你一模一样——而他每次都承认没有变差。所以你的排列方式就是最优的！

### 三、归纳法——"第一步对了，后面每一步也都对"

数学归纳法是另一种常用的证明方法，特别适合那些每一步都做"局部最优选择"的贪心策略。

归纳法证明贪心的基本框架：

**基础步骤**：证明第一次贪心选择一定存在于某个最优解中。也就是说，存在一个最优解，它的第一步和我们的贪心选择相同。

**归纳步骤**：假设前 k 步的贪心选择都包含在某个最优解中，证明第 k+1 步的贪心选择也一定包含在某个最优解中（可能是原最优解调整后的另一个最优解）。

**结论**：由归纳原理，贪心算法的每一步选择都正确，贪心解等于最优解。

归纳法的巧妙之处在于：它把"证明一整套策略都正确"这个大问题，拆解成了"证明每一步都正确"的小问题。就像爬楼梯，只要证明你能跨出第一步，而且每跨一步后都能继续跨下一步，那无论楼梯有多少级，你都能爬到顶。

### 四、两个经典证明实例

**实例1：排队接水问题**。策略是按接水时间从小到大排序。为什么？

假设存在一个最优顺序，但前面有人接水时间更长。我们把那个"接水时间长的"和后面"接水时间短的"交换位置。交换后，中间所有人的等待时间都减少了（因为两个人在前面的人接水更快了），而其他位置的人等待时间不变。所以交换后的总等待时间减少了——这说明"时间长的在前"不可能是最优的！因此，按时间升序排列就是最优策略。

**实例2：合并果子问题**。策略是每次选最小的两堆合并。为什么？

假设有一定数量的果子堆。在任何情况下，最小的两堆必须被合并。如果最优解第一步不是合并最小的两堆，我们可以把最优解中涉及的合并操作进行调整——把不是最小的两堆的合并替换为合并最小的两堆，可以证明总代价不会增加。这就是哈夫曼编码的贪心选择性质的证明思路。

### 五、中小学生如何思考贪心证明

对于参加信息学竞赛的中小学生来说，不需要写出严密到每一行的数学证明。在考试或比赛中，可以用以下方式来"说服自己"贪心是对的：

1. **举反例测试**：想一些特殊数据，手动验证贪心策略是否能得到正确结果。如果找不到反例，贪心策略大概率是对的。

2. **"换一下试试"**：尝试把手算的最优解的某一步换成贪心选择，看看结果会不会变差。如果不差，那贪心就没问题。

3. **归纳思维**：问自己——"第一次这样选对吗？选了之后，剩下的子问题还能用同样的策略吗？"如果答案是肯定的，那贪心策略通常有效。

4. **画图辅助**：用图形、表格或故事来辅助理解。比如排队问题可以想象真实排队场景——让动作慢的人站前面，所有人都会等更久，这显然不合理。

## 💻 代码实现

### 排队接水——排序贪心

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// 结构体：记录每个人的编号和接水时间
struct Person {
    int id;   // 编号（输入顺序）
    int time; // 接水所需时间
};

// 比较函数：按接水时间升序排列
bool cmp(Person a, Person b) {
    return a.time < b.time;
}

// 排队接水：n个人，每人接水时间为t[i]
// 返回最小总等待时间
long long minWaitingTime(Person p[], int n) {
    // 关键：按接水时间从小到大排序（贪心选择）
    sort(p, p + n, cmp);

    long long totalWait = 0;  // 总等待时间
    long long currentSum = 0; // 前i个人的接水时间之和（前缀和）

    for (int i = 0; i < n; i++) {
        // 第i个人的等待时间 = 前面所有人的接水时间之和
        totalWait += currentSum;
        // 更新前缀和：加上当前这个人的接水时间
        currentSum += p[i].time;
    }

    return totalWait;
}
```

### 合并果子——优先队列贪心

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

// 合并果子：n堆果子，每次合并任意两堆，代价为两堆之和
// 求合并成一堆的最小总代价
int minMergeCost(int piles[], int n) {
    // 使用优先队列（最小堆），每次取出最小的两堆
    // greater<int> 使优先队列成为小顶堆
    priority_queue<int, vector<int>, greater<int>> pq;

    // 将所有果子堆入队
    for (int i = 0; i < n; i++) {
        pq.push(piles[i]);
    }

    int totalCost = 0; // 总代价

    // 当堆数 > 1 时，继续合并
    while (pq.size() > 1) {
        // 取出最小的两堆
        int a = pq.top(); pq.pop();
        int b = pq.top(); pq.pop();

        // 合并这两堆，代价为 a + b
        int merged = a + b;
        totalCost += merged;

        // 将合并后的新堆放回队列
        pq.push(merged);
    }

    return totalCost;
}
```

## 📊 复杂度分析

### 排队接水

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 排序 | O(n log n) | 使用 sort 对 n 个人按接水时间排序 |
| 计算等待时间 | O(n) | 一次遍历计算前缀和 |
| **总时间复杂度** | **O(n log n)** | 排序是瓶颈 |
| **空间复杂度** | **O(n)** | 存储 n 个人的信息 |

### 合并果子

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 建堆 | O(n) | 将所有元素入优先队列 |
| 每次合并 | O(log n) | 优先队列的 push/pop 操作 |
| 合并次数 | n-1 次 | 每合并一次堆数减1 |
| **总时间复杂度** | **O(n log n)** | (n-1) × O(log n) |
| **空间复杂度** | **O(n)** | 优先队列存储最多 n 个元素 |

两种算法的瓶颈都在排序或堆操作上，都是 O(n log n) 级别，对于 n ≤ 10^5 的数据完全可以胜任。

## 🏋️ 经典例题

### 例题1：排队接水

**题目描述**：有 n 个人在一个水龙头前排队接水，每个人接水需要的时间为 t₁, t₂, ..., tₙ（单位：分钟）。所有人的等待时间之和等于每个人等待时间的总和。请找出一种排队顺序，使得总的等待时间最小。

例如：有 3 个人，接水时间分别为 3、1、2。如果按 [3, 1, 2] 的顺序排队，第一个人等待 0 分钟，第二个人等待 3 分钟（等第一个人接完），第三个人等待 3+1=4 分钟。总等待时间 = 0+3+4 = 7 分钟。但如果按 [1, 2, 3] 的顺序，总等待时间 = 0+1+(1+2) = 4 分钟。

**输入格式**：
- 第一行一个整数 n（1 ≤ n ≤ 1000），表示人数
- 第二行 n 个整数，第 i 个整数表示第 i 个人的接水时间 tᵢ（1 ≤ tᵢ ≤ 1000）

**输出格式**：
- 第一行输出最优排队顺序（按输入编号输出）
- 第二行输出最小的总等待时间

**样例输入**：
```
5
3 6 1 4 2
```

**样例输出**：
```
3 5 1 4 2
20
```

**贪心策略证明（交换论证）**：
- **策略**：按接水时间从小到大排序
- **证明**：假设存在一个最优排队顺序，其中某个人 A 排在某个人 B 前面，但 A 的接水时间 t_A > t_B。现在我们把 A 和 B 交换位置。交换后，排在 A 和 B 后面的人的等待时间不变。排在 A 前面的人的等待时间也不变。唯一变化的是 A 和 B 各自的等待时间以及 A、B 之间的人（如果有的话）的等待时间。交换后，这中间所有人的等待时间都减少了 (t_A - t_B) > 0。因此总等待时间减少，说明原来"时间长的在前"的顺序不可能是最优的。所以最优顺序一定是按时间升序排列。

### 例题2：合并果子

**题目描述**：在一个果园里，多多已经将所有的果子打了下来，并按不同种类分成了 n 堆。多多决定把所有的果子合并成一堆。每一次合并，多多可以把两堆果子合并到一起，消耗的体力等于这两堆果子的重量之和。可以看出，所有的果子经过 n-1 次合并之后，就只剩下一堆了。多多在合并果子时总共消耗的体力等于每次合并所消耗体力之和。请设计合并顺序，使体力消耗最少。

例如：有 3 堆果子，重量分别为 1、2、9。可以先将 1 和 2 合并，新堆重量为 3，消耗体力 3。再将新堆 3 和 9 合并，得到 12，消耗体力 12。总消耗 = 3 + 12 = 15。

**输入格式**：
- 第一行一个整数 n（1 ≤ n ≤ 10000），表示果子的堆数
- 第二行 n 个整数，表示每堆果子的重量（均为正整数，不超过 20000）

**输出格式**：一个整数，即最小的体力消耗值

**样例输入**：
```
3
1 2 9
```

**样例输出**：
```
15
```

**贪心策略证明（归纳法简述）**：
- **策略**：每次选取最小的两堆进行合并（使用最小堆实现）
- **证明思路**：这个问题等价于哈夫曼编码问题。可以用归纳法证明：设所有堆中最小的两堆重量为 a 和 b。我们可以证明存在一个最优合并方案，其中 a 和 b 是第一次合并的两堆。如果最优方案中 a 和 b 不是最先合并的，可以通过调整合并顺序，使 a 和 b 最先合并，且总代价不增加。将 a 和 b 合并后，问题变为 n-1 堆（其中一堆是新合并的 a+b）的子问题，由归纳假设，贪心策略在子问题上也最优。因此贪心策略整体最优。

### 📝 提高题

#### 提高题1：最小总和问题

**题目描述**：给定 N 个正整数，每次可以从中取出两个数 a 和 b，将它们替换为 a+b，同时获得分数 a+b。重复此操作直到剩下一个数。求能获得的总分数的最小值。这实际上就是合并果子问题的另一种描述。

**输入格式**：第一行一个整数 N（1 ≤ N ≤ 10000）。第二行 N 个整数（不超过 20000）。

**输出格式**：一个整数，表示最小总分数。

**样例输入**：
```
4
4 3 2 6
```

**样例输出**：
```
30
```

**样例解释**：合并 2+3=5（代价 5），剩下 [4,5,6]；合并 4+5=9（代价 9），剩下 [6,9]；合并 6+9=15（代价 15），总数只剩 1 个。总代价 = 5+9+15 = 30。

**请写出交换论证的证明过程（不需要代码）**：

### 📝 挑战题

#### 挑战题1：独木舟

**题目描述**：有 N 个人要乘独木舟过河。每只独木舟最多载两人，且载重不超过 C。第 i 个人的体重为 w[i]。求最少需要多少只独木舟。

**输入格式**：第一行两个整数 N 和 C（1 ≤ N ≤ 10000, 1 ≤ C ≤ 20000）。第二行 N 个整数 w[i]（1 ≤ w[i] ≤ C）。

**输出格式**：一个整数，表示最少需要的独木舟数量。

**样例输入**：
```
4 10
7 2 4 6
```

**样例输出**：
```
3
```

**样例解释**：按体重排序 [2, 4, 6, 7]。最轻的 2 和最重的 7 配对（9 ≤ 10，可共乘），最轻剩 4 和最重剩 6 配对（10 ≤ 10，可共乘）。共 2 只船？等等，2+7=9，4+6=10，刚好 2 只船。但样例输出是 3？让我重新算……哦，4 个人：[2,4,6,7]。2+7=9 过，4+6=10 过，确实 2 只。应该把样例改一下。

**修正样例输入**：
```
5 10
7 2 8 4 6
```

**修正样例输出**：
```
3
```

**样例解释**：排序 [2, 4, 6, 7, 8]。2+8=10 过（舟1），4+7=11>10，4 单独（舟2），6+7=13>10，最后 7 和 6 配对？不对，4 单过后剩 [6,7]：6+7=13>10，所以 7 单独、6 单独？不对……按照贪心策略：2+8=10（舟1），4+7=11>10 所以 4 单独（舟2），6+7=13>10 所以 6 单独（舟3），7 单独（舟4）。这样是 4 只。不对，重新想。

应该是：2+8=10（舟1），4+7=11>10 放不下，4+6=10（舟2），剩下 7 单独（舟3），共 3 只。让我把解释改对。

**正确的样例解释**：排序 [2, 4, 6, 7, 8]。贪心策略（最轻+最重配）：2+8=10≤10，配一对（舟1）；4+7=11>10，4 太重配 7，4+6=10≤10，配一对（舟2）；剩下 7 单独（舟3）。共 3 只。

#### 基础题1 参考代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int n, t[1005];
    cin >> n;
    for (int i = 0; i < n; i++) cin >> t[i];
    sort(t, t + n);

    long long totalWait = 0, sum = 0;
    for (int i = 0; i < n; i++) {
        totalWait += sum;
        sum += t[i];
    }
    cout << totalWait << endl;
    return 0;
}
```

#### 提高题2 参考答案（证明，非代码）

**交换论证证明**：

假设最优排列中，存在两个相邻的任务 A（运行时间 a）和 B（运行时间 b），A 排在 B 前面但 a > b。

设 A 和 B 前面所有任务的总时间为 S，A 和 B 后面所有任务的总时间为 T（后面有 K 个任务）。

交换前总等待时间：
- A 等待 S，B 等待 S+a，后面的 K 个任务额外等待 a+b
- 交换前总等待 = S + (S+a) + K×(a+b) + 后面 K 个任务内部的等待

交换后（B 在 A 前）总等待时间：
- B 等待 S，A 等待 S+b，后面的 K 个任务额外等待 b+a
- 交换后总等待 = S + (S+b) + K×(b+a) + 后面 K 个任务内部的等待

交换前后差值 = (S+a) - (S+b) = a - b > 0（因为 a > b）。说明交换后等待时间减少了。

**结论**：若存在"运行时间长的排在运行时间短的前面"的情况，交换它们一定能减少总等待时间。因此最优排列中，运行时间一定非递减排列。

#### 挑战题1 参考代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    int n, C, w[10005];
    cin >> n >> C;
    for (int i = 0; i < n; i++) cin >> w[i];
    sort(w, w + n);

    int boats = 0;
    int left = 0, right = n - 1;
    while (left <= right) {
        if (left == right) {
            boats++;  // 只剩一个人
            break;
        }
        if (w[left] + w[right] <= C) {
            left++;   // 最轻的上船
            right--;  // 最重的上船
        } else {
            right--;  // 最重的太重，自己坐一艘
        }
        boats++;
    }
    cout << boats << endl;
    return 0;
}
```

## 📝 本课小结

本节课我们学习了贪心策略的证明方法。贪心算法虽然思路简单，但"为什么贪心是对的"这个问题并不简单。我们介绍了两种适合中小学生的证明方法：

1. **交换论证**：假设存在更优解，用贪心选择去替换，证明结果不会变差。这是最直观的证明方法，适合大多数贪心问题。

2. **归纳法**：先证明第一步贪心选择正确，再证明如果前 k 步正确则第 k+1 步也正确。适合那些具有明确"最优子结构"的问题。

我们还通过两个经典例题——**排队接水**（排序贪心）和**合并果子**（优先队列贪心）——展示了如何将证明方法和代码实现结合起来。排队接水用交换论证证明了"按时间升序排列最优"，合并果子用归纳法+交换论证证明了"每次选最小两堆合并最优"。

记住：在竞赛中，找到贪心策略后花几分钟做个"换一下试试"的验证，往往就能避免因为贪心策略错误而导致的大面积失分。贪心不难，证明也不难，关键是养成"先想清楚再写代码"的好习惯。
