# 第45课：算法综合实战（一）—— 枚举+贪心+二分

## 🎯 学习目标

- **掌握多种算法的综合运用**：学会如何在一道题目中同时运用枚举、贪心和二分查找三种算法，理解它们之间如何相互配合
- **培养算法选择思维**：面对实际问题时能够分析问题特征，选择最合适的算法策略，理解"先排序再贪心"、"二分答案+贪心验证"等经典组合模式
- **提升代码综合能力**：通过综合题目的练习，锻炼将不同算法模块化、组合化编写的能力，能够独立完成从问题分析到代码实现的完整流程

## 📖 算法回顾

### 枚举算法（暴力法）

枚举是一种最直观的算法思想：把所有可能的情况一一列举出来，判断哪些满足条件，哪些不满足条件，从而找到答案。枚举的核心三要素是**枚举对象**（你要枚举什么）、**枚举范围**（从哪里枚举到哪里）和**检验条件**（什么样的枚举结果是有效的）。

例如：判断一个数 n 是否为质数，可以枚举 2 到 sqrt(n) 之间的所有整数，看是否能整除 n。

枚举的优点是**简单直观、不容易出错**，适合初学者；缺点是当数据范围较大时，时间复杂度会很高。通常情况下，n ≤ 1000 时可以考虑暴力枚举，n 更大时就需要结合其他算法进行优化。

### 贪心算法

贪心算法的核心思想是：在每一步选择中都采取当前状态下最优的选择，希望通过局部最优解来达到全局最优解。贪心算法最重要的步骤是**证明贪心策略的正确性**——并不是所有问题都能用贪心解决，只有当问题具有"贪心选择性质"和"最优子结构"时才能使用。

经典贪心例题包括：**硬币找零**（每次选面额最大的硬币）、**活动安排**（每次选结束时间最早的活动）、**排队接水**（接水时间短的人先接）等。

贪心的优点是**实现简单、效率高**（通常 O(n log n) 以内）；缺点是需要严格的证明，很多看似能用贪心的问题实际上需要动态规划来解决。

### 二分查找

二分查找（二分答案）是处理**单调性问题**的利器。当我们需要在一个有序的范围（答案区间）内找到满足条件的最大/最小值时，可以使用二分查找将时间复杂度从 O(n) 降到 O(log n)。

二分查找的关键在于：
- **确定答案的上下界**（left 和 right）
- **写出 check(mid) 函数**，判断 mid 是否满足条件
- **根据 check 结果调整区间**：如果 mid 满足，缩小左边界（找更大的）；如果不满足，缩小右边界（找更小的）

典型应用场景：**最大值最小化**或**最小值最大化**问题。例如：切割绳子使得每段最长、分巧克力使得每人得到最大面积等。

## 💻 综合技巧

### 如何选择正确的算法？

面对一道综合题时，可以按照以下思路进行分析：

1. **观察数据规模**：如果 n ≤ 20，可能可以使用暴力枚举或状态压缩；如果 n ≤ 10^5，通常需要 O(n log n) 的算法，考虑排序+贪心或二分
2. **分析问题单调性**：如果问题具有"越大越容易满足"或"越小越容易满足"的单调性，优先考虑二分答案
3. **寻找局部最优**：如果每一步都可以独立地做出最优选择而不影响后续决策，贪心可能是正确的
4. **模块化思考**：将一个问题拆分为"验证部分"和"搜索部分"，验证部分用贪心，搜索部分用二分

### 常见综合模式

| 模式 | 说明 | 典型题目 |
|------|------|----------|
| 二分答案 + 贪心验证 | 二分搜索答案，用贪心判断是否可行 | 切割绳子、分巧克力 |
| 排序 + 贪心 | 先排序使问题有序化，再贪心选择 | 最优配对、活动安排 |
| 枚举 + 剪枝优化 | 枚举所有可能，用条件提前排除 | 部分组合问题 |

### 算法选择决策树

面对一道算法题，可以按照下面的决策流程判断该用什么算法或算法组合：

```

                      ┌────────▼─────────┐

                         │  分巧克力)   │        │是        │否
                         └──────────────┘  ┌────▼───┐ ┌──▼────────┐
                                           │排序+   │ │考虑动态   │
                                           │贪心    │ │规划/高级  │
                                           │(如最优 │ │数据结构   │
                                           │配对)   │ │           │
                                           └────────┘ └───────────┘
```

**决策要点速查表**：

| 题目特征 | 推荐算法 | 关键判断依据 |
|----------|----------|-------------|
| 答案域连续且单调 | 二分答案 + 贪心验证 | check(mid) 能在 O(N) 或 O(N log N) 内完成 |
| 数据通过排序后可局部最优选择 | 排序 + 贪心 | 排序后相邻/就近贪心，需能证明正确性 |
| N ≤ 20，需要穷举所有方案 | 枚举 / 回溯 / 状态压缩 | 搜索空间 ≤ 2^20 ≈ 10^6，可接受 |
| N ≤ 10^5，无明显单调性 | 排序 + 扫描线 / 双指针 | 有序化后线性扫描 |
| N > 10^5，涉及区间/前缀 | 前缀和 / 差分 / 线段树 | 需要 O(log N) 级别的查询/更新 |

记住口诀：**"数据小用枚举，单调用二分，有序用贪心，都不行想DP"**。对于本课的综合题目，最常见的组合就是"二分答案 + 贪心验证"——二分负责在答案域上高效搜索，贪心负责快速判断当前候选答案是否可行。

## 🏋️ 经典例题

### 例题1：切割绳子

#### 题目描述

有 N 条绳子，它们的长度分别为 L₁, L₂, ..., Lₙ。如果从它们中切割出 K 条长度相同的绳子，这 K 条绳子每条最长能有多长？答案保留两位小数。

**注意**：绳子可以不用全部用完，每条绳子切割后剩余的部分不能再拼接使用。

#### 输入格式

```
第一行：两个正整数 N 和 K，用空格隔开
第二行：N 个正实数，表示 N 条绳子的长度（单位：米）
```

#### 输出格式

```
一个实数，表示切割出的 K 条绳子的最大长度，保留两位小数
```

#### 样例输入

```
4 11
8.02 7.43 4.57 5.39
```

#### 样例输出

```
2.00
```

#### 算法思路

这是一个经典的**二分答案 + 贪心验证**问题。

- **二分搜索**：答案（绳子长度）具有单调性——如果长度为 x 可以切出 ≥ K 条，那么所有小于 x 的长度也都可以。因此我们可以二分搜索最大的 x。
- **贪心验证**：对于给定的长度 mid，每条绳子能贡献的段数 = floor(Lᵢ / mid)，将所有绳子的贡献相加，如果 ≥ K 则 mid 可行。

### 解题步骤推导

下面我们逐步推导这道题的完整思考过程。

**第一步：问题分析**

题目要求"K 条绳子每条最长能有多长"，设答案为 x，则有如下关系：
- 每条原绳能切出的段数 = floor(Lᵢ / x)
- 总段数要求：∑ floor(Lᵢ / x) ≥ K

当 x 越大时，每条绳子能切出的段数越少，总段数也越少。这意味着**答案 x 具有单调性**：如果某个长度 x 可行（能切出 ≥ K 条），那么所有 ≤ x 的长度也都可行。反之，如果 x 不可行，那么所有 ≥ x 的长度也都不可行。这种"可行区间连续"的性质，正是二分答案适用的标志。

**第二步：确定二分边界**

- **下界（left）**：绳子的长度不能是负数，最短可能的结果是 0（当完全切不出时）。因此 left = 0。
- **上界（right）**：单条绳子的长度就是上限，因为任何切割得到的段都不可能比原绳长。取所有绳子中最长的那条，即 right = max(Lᵢ)。
- **精度控制**：题目要求保留两位小数，二分在实数域上需要设定精度 epsilon。通常取比题目要求多 2~3 个数量级，这里取 EPS = 1e-5，确保结果精确到小数点后两位。

**第三步：check 函数设计**

check(mid) 的核心逻辑是验证"当每段长度为 mid 时，能否切出至少 K 段"。对于每条绳子 Lᵢ，它能贡献的段数为 floor(Lᵢ / mid)——注意这里是向下取整，因为绳头剩余的部分不能拼接。将所有贡献相加得到总段数 cnt，判断 cnt ≥ K 即可。check 函数的时间复杂度为 O(N)。

**第四步：二分迭代过程**

- 如果 check(mid) 为 true，说明 mid 可行，但我们还想找更大的答案，于是将 left 移到 mid（left = mid），继续在右半区搜索。
- 如果 check(mid) 为 false，说明 mid 太大了，切不出足够的段数，于是将 right 移到 mid（right = mid），在左半区搜索。
- 当 right - left ≤ EPS 时，区间已经足够小，left 即为所求的最大可行长度。

**第五步：复杂度分析对比**

| 解法 | 时间复杂度 | 说明 |
|------|-----------|------|
| 暴力枚举 | O(N × 10^d)，d 为精度位数 | 从 0.00 到 maxLen，每次步进 0.01，对于每条绳子都要计算一次，不可接受 |
| 二分答案 | O(N × log(M/EPS)) | 每次 check O(N)，二分迭代约 log₂(10^5) ≈ 17 次，可轻松应对 N ≤ 10^5 |

通过这五步推导，我们可以清晰地看到二分答案如何将原本指数级/多项式级高复杂度的枚举问题优化到对数级，这正是二分答案的强大之处。

#### 参考代码

```cpp
#include <iostream>
#include <cstdio>   // printf 需要
#include <cmath>    // floor 等数学函数（本题未直接用，保留备用）
using namespace std;

const int MAXN = 10005;    // 最大绳子数量
const double EPS = 1e-5;   // 实数二分精度：比输出精度(0.01)多3个数量级
double len[MAXN];           // 存储每条绳子的长度
int n, k;                   // n条绳子，需要切出k段

// check(mid)：贪心验证当前长度mid是否可行
// 核心逻辑：遍历每条绳子，统计能切出的段数，判断总数是否≥k
bool check(double x) {
    int cnt = 0;
    for (int i = 0; i < n; i++) {
        // (int)强制转换实现向下取整（等价于 floor）
        // 每条绳子能切出 floor(len[i] / x) 段
        cnt += (int)(len[i] / x);
    }
    return cnt >= k; // 总数够k段则mid可行
}

int main() {
    // ---- 1. 输入 ----
    cin >> n >> k;
    double maxLen = 0;       // 记录最长绳子，作为二分上界
    for (int i = 0; i < n; i++) {
        cin >> len[i];
        if (len[i] > maxLen) maxLen = len[i]; // 动态更新最大值
    }

    // ---- 2. 实数二分搜索 ----
    // 答案区间：[0, maxLen]，在实数域上二分
    double left = 0, right = maxLen;
    while (right - left > EPS) {     // 区间宽度小于EPS时停止
        double mid = (left + right) / 2; // 取区间中点
        if (check(mid)) {
            left = mid;   // mid可行 → 尝试更大的长度，收缩左边界
        } else {
            right = mid;  // mid不可行 → 长度太大，收缩右边界
        }
    }
    // 循环结束后，left是满足条件的最大长度（精确到EPS）

    // ---- 3. 输出 ----
    printf("%.2f\n", left); // 保留两位小数输出
    return 0;
}
```

### 例题2：最优配对

#### 题目描述

给定 2N 个整数，将它们两两配对，得到 N 对。要求每对中两个数之差的绝对值之和最小，输出这个最小值。

#### 输入格式

```
第一行：一个正整数 N（1 ≤ N ≤ 1000）
第二行：2N 个整数 a₁, a₂, ..., a₂ₙ
```

#### 输出格式

```
一个整数，表示最小差值之和
```

#### 样例输入

```
3
1 3 4 6 7 9
```

#### 样例输出

```
4
```

**样例解释**：最佳配对方案为 (1,3)、(4,6)、(7,9)，差值分别为 2、2、2，总和为 6。

> 注：若配成 (1,4)、(3,6)、(7,9)，差值为 3+3+2=8，不是最优。

#### 算法思路

这是一个典型的**排序 + 贪心**问题。

- 首先将 2N 个数从小到大排序
- 贪心策略：将相邻的两个数配对，即第 1 个和第 2 个、第 3 个和第 4 个……这样配对
- 为什么正确？假设 a ≤ b ≤ c ≤ d，那么 (a,b)+(c,d) ≤ (a,c)+(b,d) 且 ≤ (a,d)+(b,c)

#### 参考代码

```cpp
#include <iostream>
#include <algorithm> // sort 需要
using namespace std;

const int MAXN = 2005; // 2*N最大为2000，多开一点防止越界
int a[MAXN];            // 存储2N个整数

int main() {
    // ---- 1. 输入 ----
    int n;
    cin >> n;
    int m = 2 * n;       // 总共有2N个数
    for (int i = 0; i < m; i++) {
        cin >> a[i];
    }

    // ---- 2. 排序：贪心配对的前提 ----
    // 只有排序后，"相邻配对最优"的性质才成立
    // sort的时间复杂度为O(m log m)，使用快速排序的变种
    sort(a, a + m);

    // ---- 3. 贪心配对 ----
    // 策略：a[0]与a[1]配对，a[2]与a[3]配对，以此类推
    // 每对的差值为a[i+1] - a[i]（因为已排序，后面的一定≥前面的）
    int ans = 0;
    for (int i = 0; i < m; i += 2) { // 步长为2，每次处理一对
        ans += a[i + 1] - a[i];       // 相邻两数之差即为该对代价
    }

    // ---- 4. 输出 ----
    cout << ans << endl;
    return 0;
}
```

### 为什么贪心是正确的

"排序后相邻配对"这个贪心策略看起来直观，但我们需要严格证明它的正确性。下面用数学归纳法和反证法给出证明。

**方法一：数学归纳法**

设排序后的数组为 a₁ ≤ a₂ ≤ ... ≤ a₂ₙ。我们要证明配对方案 a₁-a₂, a₃-a₄, ..., a₂ₙ₋₁-a₂ₙ 是最优的。

**归纳基础**（n = 1）：只有两个数时，唯一的配对方式就是相邻配对，显然最优。

**归纳假设**：假设对于 2(n-1) 个数，相邻配对策略是最优的。

**归纳步骤**：考虑 2n 个数。首先考虑最小的数 a₁，它必须与某个数配对。假设 a₁ 与 aₖ（k > 2）配对，那么 a₂ 只能与另一个数（比如 aⱼ）配对。根据绝对值不等式：
- (a₂ - a₁) + (aₖ - aⱼ) ≤ (aₖ - a₁) + (a₂ - aⱼ)

左边是将 a₁ 与 a₂ 配对、aⱼ 与 aₖ 配对的结果，右边是原始方案。由于左边 ≤ 右边，将 a₁ 和 a₂ 配对不会使总代价变大。因此 a₁ 的最优配对对象就是 a₂。

去掉 a₁ 和 a₂ 后，剩余 2(n-1) 个数保持有序，根据归纳假设，相邻配对是最优的。归纳完成。

**方法二：反证法（更直观）**

假设存在一种最优配对方案不是相邻配对，则必然存在两对 (a, c) 和 (b, d)，其中 a ≤ b ≤ c ≤ d（排序后），即"交叉配对"。计算两种方案的代价：
- 交叉配对代价 = (c - a) + (d - b)
- 调整为相邻配对 = (b - a) + (d - c)

差值 = [(c - a) + (d - b)] - [(b - a) + (d - c)]
     = c - a + d - b - b + a - d + c
     = 2(c - b)

由于 c ≥ b，所以差值 ≥ 0，即**交叉配对的代价 ≥ 相邻配对的代价**。因此任何含有交叉的方案都可以通过调整为相邻配对来不增加（通常减小）总代价。反复调整直到没有交叉，即得到排序后相邻配对的方案。这说明相邻配对方案确实是最优的。

**关键结论**：在数轴上有序点之间，"不交叉"的配对方案总是优于或等于任何含有交叉的方案。这个性质保证了排序后贪心配对的正确性，也是解决一类"最优配对"问题的核心思想。

### 例题3：分巧克力

#### 题目描述

儿童节那天有 K 位小朋友到小明家做客。小明拿出了珍藏已久的巧克力招待小朋友们。小明一共有 N 块巧克力，其中第 i 块是 Hᵢ × Wᵢ 的方格组成的长方形。

为了公平起见，小明需要从这 N 块巧克力中切出 K 块分给小朋友们。切出的巧克力必须是**正方形**（边长必须是整数），且**大小相同**。小朋友们都希望得到的巧克力尽可能大，你能帮小明计算出最大的边长是多少吗？

**注意**：每块巧克力只能切，不能拼接。例如一块 6×5 的巧克力可以切出 6 块 2×2 的巧克力（3 × 2 = 6），剩余的部分不能再利用。

#### 输入格式

```
第一行：两个整数 N 和 K（1 ≤ N, K ≤ 10^5）
接下来 N 行：每行两个整数 Hᵢ 和 Wᵢ（1 ≤ Hᵢ, Wᵢ ≤ 10^5）
```

#### 输出格式

```
一个整数，表示切出的正方形巧克力的最大边长
```

#### 样例输入

```
2 10
6 5
5 6
```

#### 样例输出

```
2
```

**样例解释**：两块巧克力分别为 6×5 和 5×6。如果边长为 2，每块 6×5 可以切出 floor(6/2) × floor(5/2) = 3×2 = 6 块，两块共 12 块 ≥ 10，满足要求。边长为 3 时，每块切出 floor(6/3) × floor(5/3) = 2×1 = 2 块，共 4 块 < 10，不满足。因此最大边长为 2。

#### 算法思路

这道题是典型的**二分答案 + 贪心验证**问题，与"切割绳子"属于同一模式。

- **二分搜索**：答案（边长）具有单调性——如果边长为 x 可以切出 ≥ K 块，那么所有小于 x 的边长也都可行。因此可以在 [1, max(H, W)] 范围内二分搜索最大的 x。由于边长必须是整数，二分在整数域上进行。
- **贪心验证**：对于给定的边长 mid，每块巧克力能切出的正方形数量 = floor(Hᵢ / mid) × floor(Wᵢ / mid)。注意这里是两个维度分别向下取整后相乘——因为切出来的正方形既要满足宽度也要满足高度。将所有巧克力贡献的数量相加，如果 ≥ K 则 mid 可行。

**为什么是二分答案？** 判断标准有两个：
1. 答案具有单调性：边长增大 → 切出的块数减少，反之亦然
2. 验证函数 check(mid) 可以高效（O(N)）实现

**与切割绳子的区别**：
- 切割绳子是"一维"问题：每条绳子贡献 floor(Lᵢ / mid) 段
- 分巧克力是"二维"问题：每块巧克力贡献 floor(Hᵢ / mid) × floor(Wᵢ / mid) 块
- 但两者的核心框架完全一致：二分答案 + O(N) 贪心验证

#### 参考代码

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int n, k;
int h[MAXN], w[MAXN]; // h[i]和w[i]分别表示第i块巧克力的高度和宽度

// 贪心验证：判断能否切出k块边长为x的正方形巧克力
bool check(int x) {
    long long cnt = 0; // 注意使用long long防止溢出
    for (int i = 0; i < n; i++) {
        // 每块巧克力在两个维度上分别能切出多少段，相乘得到总块数
        cnt += (long long)(h[i] / x) * (w[i] / x);
        if (cnt >= k) return true; // 提前返回，优化性能
    }
    return cnt >= k;
}

int main() {
    cin >> n >> k;
    int maxSide = 0;
    for (int i = 0; i < n; i++) {
        cin >> h[i] >> w[i];
        // 二分上界：最长的边长不可能超过任何一块巧克力的最长边
        maxSide = max(maxSide, max(h[i], w[i]));
    }

    // 二分搜索最大边长（整数二分）
    int left = 1, right = maxSide;
    int ans = 0;
    while (left <= right) {
        int mid = left + (right - left) / 2; // 防止整数溢出
        if (check(mid)) {
            ans = mid;     // 记录当前可行解
            left = mid + 1; // 尝试更大的边长
        } else {
            right = mid - 1; // 边长太大，缩小
        }
    }

    cout << ans << endl;
    return 0;
}
```

**代码讲解**：
1. **check 函数中使用 long long**：N 和边长最大可达 10^5，每块巧克力最多切出 10^10 量级的块数，int 会溢出，必须用 long long。
2. **提前返回优化**：当 cnt ≥ k 时立即返回 true，避免不必要的遍历，在大数据量下可显著提升性能。
3. **整数二分模板**：与切割绳子的实数二分不同，整数二分使用 left ≤ right 的循环条件，并显式记录 ans。mid 的计算使用 `left + (right - left) / 2` 防止 left + right 溢出。
4. **边界初始化**：left 从 1 开始（边长至少为 1），right 取所有巧克力长宽的最大值。

## 📊 复杂度分析

| 题目 | 算法组合 | 时间复杂度 | 空间复杂度 |
|------|----------|------------|------------|
| 切割绳子 | 二分答案 + 贪心验证 | O(N · log M)，M 为长度范围/精度 | O(N) |
| 最优配对 | 排序 + 贪心配对 | O(N log N) | O(N) |
| 分巧克力 | 二分答案 + 贪心验证 | O(N · log M)，M 为最大边长 | O(N) |

**各题复杂度详解**：

- **切割绳子**：二分查找在实数域上迭代约 log₂(M / EPS) ≈ 17~20 次，每次 check 需要 O(N) 遍历所有绳子，总体 O(N log M)。空间上只需存储 N 条绳子的长度数组。
- **最优配对**：排序使用快速排序，时间复杂度 O(N log N)；贪心配对只需 O(N) 单次遍历 2N 个数。总体 O(N log N)，其中 N 为配对数。空间上存储 2N 个整数。
- **分巧克力**：二分查找在整数域 [1, maxSide] 上迭代约 log₂(10^5) ≈ 17 次，每次 check 遍历 N 块巧克力，O(N)。但 check 内部做乘积运算可能涉及大数，需要注意使用 long long。总体 O(N log M)，其中 M 为最大边长。空间上存储 N 块巧克力的长宽。

**三种解法的对比总结**：

| 比对维度 | 切割绳子 | 最优配对 | 分巧克力 |
|----------|---------|---------|---------|
| 核心算法 | 二分+贪心 | 排序+贪心 | 二分+贪心 |
| 问题维度 | 一维线性 | 一维配对 | 二维面积 |
| 二分域 | 实数（有精度要求） | 不需要二分 | 整数（无精度问题） |
| 贪心验证 | 每绳段数 = Lᵢ/mid | 相邻配对 | 每块数量 = (Hᵢ/mid)×(Wᵢ/mid) |
| 易错点 | EPS 精度控制 | 排序后才能贪心 | 乘积用 long long，防溢出 |

从对比可以看出，"二分答案 + 贪心验证"是本课最核心的综合模式。切割绳子是它的实数版本，分巧克力是它的整数+二维版本。而最优配对则展示了另一种常见模式："排序使数据有序化 + 贪心选择"。掌握这三种模式的判断标准和实现技巧，就能应对大多数中等难度的算法综合题。

### 挑战题

#### 练习4：路灯问题（二分 + 贪心）

**题目描述**：笔直的公路上有 N 盏路灯，第 i 盏路灯的位置为 P[i]（已按升序排列），照明半径为 R（所有路灯相同）。现在需要确定最小的半径 R，使得整条公路（从位置 0 到位置 L）的每一个位置至少被一盏路灯照亮。

**输入格式**：
```
第一行：两个整数 N L（1 ≤ N ≤ 100000，1 ≤ L ≤ 10^9）
第二行：N 个整数 P[1]..P[N]（0 ≤ P[i] ≤ L，已升序排列）
```

**输出格式**：
```
一个整数，表示满足条件的最小半径（结果向上取整）
```

**样例输入**：
```
3 10
0 4 9
```

**样例输出**：
```
5
```

**样例解释**：半径 R=5 时，路灯0照亮 [0,5]，路灯4照亮 [0,9]，路灯9照亮 [4,14]，整条路从 0 到 10 全覆盖。R=4 时路灯0照 [0,4]，路灯4照 [0,8]，路灯9照 [5,13]，覆盖了 [0,13] 全覆盖。实际 R=2 时：灯0照 [0,2]，中间 [2,2] 有覆盖（灯 4 照 [2,6]），所以... 通过二分可精确求得最小 R。

### 练习题参考答案

#### 练习1参考代码

```cpp
#include <iostream>
using namespace std;

int a[100005];

int main() {
    int N, Q;
    cin >> N >> Q;
    for (int i = 1; i <= N; i++) cin >> a[i];

    while (Q--) {
        int x;
        cin >> x;
        int left = 1, right = N, ans = -1;
        while (left <= right) {
            int mid = (left + right) / 2;
            if (a[mid] == x) { ans = mid; break; }
            else if (a[mid] < x) left = mid + 1;
            else right = mid - 1;
        }
        cout << ans << endl;
    }
    return 0;
}
```

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

struct Activity {
    int s, e;
    bool operator<(const Activity& o) const {
        return e < o.e;  // 按结束时间升序
    }
} a[100005];

int main() {
    int N;
    cin >> N;
    for (int i = 0; i < N; i++)
        cin >> a[i].s >> a[i].e;

    sort(a, a + N);

    int ans = 1, last = a[0].e;
    for (int i = 1; i < N; i++) {
        if (a[i].s >= last) {
            ans++;
            last = a[i].e;
        }
    }
    cout << ans << endl;
    return 0;
}
```

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
int P[MAXN];
int N, L;

bool check(int R) {
    double covered = 0;
    for (int i = 0; i < N; i++) {
        if (P[i] - R > covered) return false;
        covered = P[i] + R;
    }
    return covered >= L;
}

int main() {
    cin >> N >> L;
    for (int i = 0; i < N; i++) cin >> P[i];

    int left = 0, right = L, ans = L;
    while (left <= right) {
        int mid = (left + right) / 2;
        if (check(mid)) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }
    cout << ans << endl;
    return 0;
}
```

## 📝 本课小结

1. **二分答案 + 贪心验证**是解决"最大值最小化"或"最小值最大化"问题的经典组合，关键在于判断问题是否具有单调性
2. **排序 + 贪心**适用于可以通过排序使问题变得有序然后进行贪心选择的场景，如配对、区间覆盖等问题
3. 面对综合题时，**先分析数据规模和数据特征**，再决定使用哪种算法组合，不要盲目套用模板
4. 将复杂问题拆分为"验证"和"搜索"两个阶段，分别用不同的算法解决，是应对综合题的有效策略
