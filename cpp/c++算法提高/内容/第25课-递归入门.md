# 第25课：递归入门——函数调用自己

## 🎯 学习目标

## 📖 算法讲解

### 一、什么是递归？

递归（Recursion）是程序设计中一种强大的编程技巧。简单来说，**递归就是函数自己调用自己**。

让我们从一个生活中的例子来理解递归：假设你在排队，你想知道自己是第几个人。你不需要从头数起，只需要问前面一个人："你是第几个？"，然后在他的答案上加 1。前面的人也用同样的方法问他前面的人，一直问到队伍最前面的第一个人（他知道自己是第 1 个）。这个"不断向前问，直到触底反弹"的过程，就是递归思想的生动写照。

在计算机科学中，递归是一种将复杂问题分解为更小的同类问题来解决的方法。一个擅用递归的程序员，就像手持一面魔镜——镜子中映出镜子，层层叠叠，直到触及最深处那个简单的答案。

### 二、递归三要素

设计递归函数时，必须明确三个要素。缺少任何一个，递归要么死循环，要么逻辑错误。

```
┌──────────────────────────────────────────────────────────────────┐
│                      递归算法三要素                               │
├──────────────────────────────────────────────────────────────────┤
│  1. 终止条件（Base Case）                                        │
│     →  递归什么时候停止？到了最简情况，直接返回答案              │
│                                                                  │
│  2. 递推关系（Recurrence Relation）                              │
│     →  大问题和小问题之间有什么联系？如何将大问题拆成小问题？    │
│                                                                  │
│  3. 递归调用（Recursive Call）                                   │
│     →  在函数体中调用自身，向终止条件靠近                        │
└──────────────────────────────────────────────────────────────────┘
```

还是用排队的例子：

- **终止条件**：如果前面没有人，那么我是第 1 个
- **递推关系**：我是第几个 = 前面的人是第几个 + 1
- **递归调用**：问前面的人"你是第几个？"

### 三、调用栈——递归背后的秘密

要真正理解递归，必须明白"调用栈"（Call Stack）的工作原理。每当一个函数被调用时，计算机会在内存中分配一块空间（称为"栈帧"），用来保存函数的参数、局部变量和返回地址。递归调用层层深入，栈帧就层层叠加。

以计算 `factorial(4)` 为例，来看调用栈的压入与弹出过程：

```
调用过程（压栈）                    返回过程（弹栈）
═══════════════════               ═══════════════════

factorial(4) 入栈                  factorial(4) 得到 4*6 = 24 返回
│  n = 4                                  ↑
│  调用 factorial(3)              factorial(3) 得到 3*2 = 6 返回
│  │  n = 3                              ↑
│  │  调用 factorial(2)          factorial(2) 得到 2*1 = 2 返回
│  │  │  n = 2                          ↑
│  │  │  调用 factorial(1)      factorial(1) 得到 1*1 = 1 返回
│  │  │  │  n = 1                      ↑
│  │  │  │  调用 factorial(0)  factorial(0) 到达终止条件 → 返回 1
│  │  │  │  │  n = 0
│  │  │  │  │  return 1  ← 终止条件！
│  │  │  │  └─────────────────────────────┘
│  │  │  └─────────────────────────────────┘
│  │  └─────────────────────────────────────┘
│  └─────────────────────────────────────────┘
└─────────────────────────────────────────────┘

栈空间增长方向 →→→→→→→→→→          ←←←←←←←←←← 栈空间收缩方向
```

当我们调用 `factorial(4)` 时：
1. `factorial(4)` 发现 n ≠ 0，于是调用 `factorial(3)`，自己"等待"结果
2. `factorial(3)` 调用 `factorial(2)`，继续向下
3. 一直到达 `factorial(0)`，满足终止条件 n == 0，直接返回 1（不再递归）
4. `factorial(1)` 得到结果 1，计算 1×1=1，返回
5. `factorial(2)` 得到结果 1，计算 2×1=2，返回
6. 逐层向上返回，最终 `factorial(4)` 得到 24

**关键点**：如果没有终止条件，栈帧会不断堆叠直到内存耗尽——这就是著名的"栈溢出"（Stack Overflow）。

### 四、阶乘的递归树

阶乘 n! 的定义：n! = n × (n-1) × (n-2) × ... × 2 × 1，且 0! = 1。

用递归实现阶乘时，递推关系非常清晰：

```
factorial(n) = n × factorial(n-1)      当 n > 0 时
factorial(n) = 1                       当 n = 0 时（终止条件）
```

递归树：

```
                    factorial(4)
                         │
                   返回 4 × factorial(3)
                              │
                        返回 3 × factorial(2)
                                   │
                             返回 2 × factorial(1)
                                        │
                                  返回 1 × factorial(0)
                                             │
                                        返回 1（终止！）
```

从树底往回"攀爬"，每一层用本层的 n 乘以子树返回的值，就能得到最终结果。

### 五、斐波那契数列的递归树

斐波那契数列的定义：第一项和第二项都是 1，从第三项开始，每一项等于前两项之和。

```
fib(1) = 1                            （终止条件）
fib(2) = 1                            （终止条件）
fib(n) = fib(n-1) + fib(n-2)          （n ≥ 3 时的递推关系）
```

数列前几项：1, 1, 2, 3, 5, 8, 13, 21, 34, ...

计算 `fib(5)` 的递归树：

```
                              fib(5)
                         ┌──────┴──────┐
                      fib(4)         fib(3)
                   ┌─────┴─────┐   ┌───┴───┐
                fib(3)      fib(2) fib(2) fib(1)
              ┌───┴───┐      │      │      │
           fib(2)  fib(1)    1      1      1
             │       │
             1       1
```

树中 fib(3) 被重复计算了 2 次，fib(2) 被重复计算了 3 次。这说明**简单的递归可能产生大量重复计算**——这也是斐波那契递归效率低下的原因（我们会在后续课程中用记忆化搜索来优化）。

### 六、递归 vs 循环

| 比较维度 | 递归 | 循环 |
|---------|------|------|
| 代码简洁度 | 代码短，逻辑清晰（如斐波那契） | 代码稍长，但直接 |
| 空间开销 | 每层递归占用栈空间，空间复杂度高 | 只用常数空间 |
| 运行效率 | 函数调用有开销，且可能重复计算 | 通常更快 |
| 适用场景 | 树形结构、分治问题、回溯搜索 | 线性迭代问题 |

**选择建议**：当问题具有天然的"自相似性"（如树形结构、分治问题）时，递归是优雅且高效的选择；当问题是简单的线性迭代时，循环往往更直接。两种方法没有绝对的好坏，关键是看问题本身的结构。

## 💻 代码实现

```cpp
#include <iostream>
using namespace std;

// ===== 阶乘的递归实现 =====
// 递推关系：factorial(n) = n * factorial(n-1)
// 终止条件：n == 0 时返回 1
long long factorial(int n) {
    // 终止条件（Base Case）
    if (n == 0) {
        return 1;
    }
    // 递推关系 + 递归调用
    return n * factorial(n - 1);
}

// ===== 斐波那契数列的递归实现 =====
// 递推关系：fib(n) = fib(n-1) + fib(n-2)
// 终止条件：n == 1 或 n == 2 时返回 1
long long fibonacci(int n) {
    // 终止条件（两个终止条件！）
    if (n == 1 || n == 2) {
        return 1;
    }
    // 递推关系 + 两次递归调用
    return fibonacci(n - 1) + fibonacci(n - 2);
}

// ===== 用递归打印自然数 1 到 n =====
// 展示递归顺序的重要性
void print1toN(int n) {
    if (n == 0) return;              // 终止条件
    print1toN(n - 1);                // 先递归
    cout << n << " ";                // 回归时打印，输出 1 2 3 ... n
}

void printNto1(int n) {
    if (n == 0) return;              // 终止条件
    cout << n << " ";                // 先打印
    printNto1(n - 1);                // 再递归，输出 n ... 3 2 1
}

int main() {
    // 测试阶乘
    int n1 = 5;
    cout << "factorial(" << n1 << ") = " << factorial(n1) << endl;
    // 输出：factorial(5) = 120

    // 测试斐波那契
    int n2 = 10;
    cout << "fibonacci(" << n2 << ") = " << fibonacci(n2) << endl;
    // 输出：fibonacci(10) = 55

    // 演示递归顺序
    cout << "打印 1 到 5：";
    print1toN(5);
    cout << endl;

    cout << "打印 5 到 1：";
    printNto1(5);
    cout << endl;

    return 0;
}
```

## 📊 复杂度分析

**阶乘递归（factorial）：**
- 时间复杂度：O(n)，递归调用 n 次，每次执行常数时间的乘法运算
- 空间复杂度：O(n)，递归深度为 n，调用栈需要存储 n 个栈帧

**斐波那契递归（fibonacci）：**
- 时间复杂度：O(2ⁿ)，每次调用会产生两个新的递归调用，形成一棵二叉树
  - 具体来说，计算 fib(n) 的调用次数约等于 fib(n+1) - 1（可用数学归纳法证明）
  - 当 n=40 时，调用次数约为 1.65 亿次——已经非常慢了！
- 空间复杂度：O(n)，递归树的最大深度为 n（沿着最左侧的路径 fib(n) → fib(n-1) → ... → fib(1)）

**为什么斐波那契递归这么慢？**

```
fib(5) 调用了 fib(4) 和 fib(3)
fib(4) 又调用了 fib(3) 和 fib(2)
fib(3) 被计算了 2 次
fib(2) 被计算了 3 次
fib(1) 被计算了 2 次
```

大量子问题被重复计算，这是朴素递归的典型缺陷。我们将在后续的"动态规划"课程中学习如何用"记忆化搜索"来避免重复计算，将时间复杂度降至 O(n)。

## 🏋️ 经典例题

### 例题1：阶乘计算（递归实现）

**题目描述**：输入一个整数 n（0 ≤ n ≤ 20），计算 n 的阶乘。阶乘的定义：n! = n × (n-1) × (n-2) × ... × 2 × 1，特别地，0! = 1。

**输入格式**：一行，一个整数 n。

**输出格式**：一行，一个整数，表示 n! 的值。

**样例输入**：
```
5
```

**样例输出**：
```
120
```

**解题思路**：

阶乘问题非常适合用递归来解决，因为它的定义本身就具有递归结构：
- n! = n × (n-1)!，这是一个典型的"用更小规模的同类问题来表示当前问题"的模式
- 终止条件：0! = 1

递归调用链：factorial(5) → factorial(4) → factorial(3) → factorial(2) → factorial(1) → factorial(0)，触底后逐层返回计算结果。

**题解代码**：
```cpp
#include <iostream>
using namespace std;

// 递归计算阶乘
// 递推关系：fact(n) = n * fact(n-1)，n > 0
// 终止条件：fact(0) = 1
long long fact(int n) {
    if (n == 0) {           // 终止条件
        return 1;
    }
    return n * fact(n - 1); // 递推关系 + 递归调用
}

int main() {
    int n;
    cin >> n;

    long long ans = fact(n);
    cout << ans << endl;

    return 0;
}
```

### 例题2：斐波那契数列第n项

**题目描述**：斐波那契数列是这样一个数列：1, 1, 2, 3, 5, 8, 13, 21, 34, ...。从第 3 项开始，每一项都等于前两项之和。给定一个整数 n（1 ≤ n ≤ 30），请输出斐波那契数列的第 n 项。

**输入格式**：一行，一个整数 n。

**输出格式**：一行，一个整数，表示斐波那契数列的第 n 项。

**样例输入**：
```
7
```

**样例输出**：
```
13
```

**解题思路**：

斐波那契数列的数学定义：

```
fib(1) = 1            ← 终止条件1
fib(2) = 1            ← 终止条件2
fib(n) = fib(n-1) + fib(n-2)    ← 递推关系（n ≥ 3）
```

注意：斐波那契数列有两个终止条件（第 1 项和第 2 项都是 1），这与阶乘只有一个终止条件不同。忽略任何一个终止条件都会导致无限递归。

**为什么 n 限制在 30 以内？**

本题限制 n ≤ 30 是因为朴素递归的斐波那契算法时间复杂度是 O(2ⁿ)。当 n=30 时，递归调用次数约为 fib(31) - 1 ≈ 1,346,269 次（约 134 万次），还可以在时限内完成。但如果是 n=50，调用次数将达到约 200 亿次，程序会运行极其缓慢甚至假死。

在后面的课程中，我们会学习如何用"记忆化搜索"将时间复杂度优化到 O(n)，轻松处理 n=50 甚至更大的情况。

**题解代码**：
```cpp
#include <iostream>
using namespace std;

// 递归计算斐波那契数列第 n 项
// 递推关系：fib(n) = fib(n-1) + fib(n-2)，n ≥ 3
// 终止条件：fib(1) = 1, fib(2) = 1
long long fib(int n) {
    // 两个终止条件
    if (n == 1 || n == 2) {
        return 1;
    }
    // 递推关系 + 两次递归调用
    return fib(n - 1) + fib(n - 2);
}

int main() {
    int n;
    cin >> n;

    long long ans = fib(n);
    cout << ans << endl;

    return 0;
}
```

```cpp
#include <iostream>
using namespace std;

// 练习1：递归求阶乘
long long factorial(int n) {
    if (n == 0) return 1;           // 终止条件
    return n * factorial(n - 1);    // 递推关系
}

// 练习2：递归输出 1 到 n
void print1toN(int n) {
    if (n == 0) return;             // 终止条件
    print1toN(n - 1);               // 先递归
    cout << n << " ";               // 回归时输出
}

// 练习3：递归求斐波那契第 n 项
long long fib(int n) {
    if (n == 1 || n == 2) return 1; // 两个终止条件

}

// 练习4：递归求各位数字之和
int digitSum(int n) {
    if (n == 0) return 0;                     // 终止条件
    return (n % 10) + digitSum(n / 10);       // 递推关系
}

// 练习5：递归求最大公约数（辗转相除法）
int gcd(int a, int b) {
    if (b == 0) return a;           // 终止条件
    return gcd(b, a % b);           // 递推关系
}

int main() {
    // 测试练习1
    cout << "阶乘: " << factorial(5) << endl;       // 120

    // 测试练习2
    cout << "1到5: ";

    // 测试练习5

    return 0;
}
```

## 📝 本课小结

本节课我们进入了递归算法的世界。递归的核心思想是"函数调用自己"，通过将大问题分解为规模更小的同类问题来求解。设计递归函数时必须牢牢把握三个要素：**终止条件**（递归什么时候停下来）、**递推关系**（大问题和小问题之间的数学联系）和**递归调用**（向终止条件迈进的每一步）。

我们深入理解了调用栈的工作原理——递归的层层深入对应着栈帧的层层叠加，当终止条件触发时，结果从栈底逐层向上返回。通过阶乘和斐波那契数列的递归树，我们直观地看到了递归的执行过程，也认识到了朴素递归可能带来的重复计算问题。同一条递归语句，写在不同位置（递归调用前或后），输出的顺序会截然相反，这体现了递归"触底反弹"的执行顺序。

记住这句话：**递推关系是灵魂，终止条件是保障，递归调用是躯干。** 三者缺一不可，缺了递推关系代码无法推进，缺了终止条件程序就会栈溢出，缺了递归调用就成了普通函数。掌握了递归思想，你就拥有了解决树形结构、分治策略、回溯搜索等大量高级算法的基础武器！

下一节课，我们将探索更多经典的递归问题，包括汉诺塔和辗转相除法，进一步感受递归的优雅与力量。
