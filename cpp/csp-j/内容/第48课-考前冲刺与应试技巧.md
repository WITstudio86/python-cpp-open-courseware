## 📖 知识精讲

### 一、考试策略：先易后难与时间分配

CSP-J考试时长为2小时，共4道题目，每道题满分100分，总分400分。合理的做题策略是拿高分的关键。首先，拿到试卷后不要急于编码，花5分钟通读全部题目，初步判断每道题的难度。CSP-J的题目难度大致呈递增趋势，但并非绝对——有时第二题可能比第一题更简单，这取决于个人知识储备。通读之后，按照"先易后难"的原则排序：优先做自己最有把握的题目，确保基础分到手。时间分配建议为每道题30分钟，留出机动时间应对突发情况。具体来说，对简单题（如模拟题）控制在20分钟内完成编码与调试；中等难度题（如贪心、二分）用30分钟；难题（如搜索、动态规划初步）用35-40分钟。如果一道题思考超过10分钟仍无明确思路，应立即跳过，先做后面的题目。全部做完后再回头攻克难题，此时心态更放松，往往能豁然开朗。

CSP-J采用部分分机制，每道题有多个测试点，即使不能满分也要尽量拿部分分。以下是一些实用的部分分策略：

```cpp
// 部分分策略示例：对于不会做的题，先写朴素暴力拿小数据分
#include <bits/stdc++.h>
using namespace std;

int main() {
    freopen("problem.in", "r", stdin);
    freopen("problem.out", "w", stdout);
    
    int n;
    cin >> n;
    
    // 子任务1：n <= 10，直接暴力枚举
    if (n <= 10) {
        // 暴力做法，保证正确但复杂度高
        int ans = 0;
        // ... 暴力枚举逻辑
        cout << ans << endl;
        return 0;
    }
    
    // 子任务2：大数据的特殊情况
    // 如果不会正解，输出一个合理的特殊值
    // 例如输出 n 或 0，可能蒙对几个测试点
    cout << n << endl;
    
    return 0;
}
```

### 二、代码调试技巧

在考场中，调试能力往往比编码能力更重要——几乎没有人能一遍写出完全正确的代码。最基础的调试方法是**打印调试法**：在关键位置用`cout`或`cerr`输出中间变量的值，观察程序运行状态。注意正式提交时必须删除或注释掉所有调试输出，否则会被判为"输出格式错误"。更推荐使用`cerr`而非`cout`进行调试打印，因为`cerr`输出到标准错误流，不会影响`freopen`的文件输出。

```cpp
// 打印调试法示例
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, a[100005];
    cin >> n;
    for (int i = 1; i <= n; i++) cin >> a[i];
    
    int sum = 0;
    for (int i = 1; i <= n; i++) {
        sum += a[i];
        // 调试打印：观察每次累加后的sum值
        cerr << "i=" << i << ", a[i]=" << a[i] << ", sum=" << sum << endl;
    }
    
    cout << sum << endl;
    return 0;
}
```

**assert断言**是另一种高效的调试手段，用于在运行时验证程序假设是否成立。例如，在处理数组下标时，可以用`assert(idx >= 0 && idx < N)`来确保下标不越界。如果断言失败，程序会立即终止并报告错误位置，帮助我们快速定位问题。

```cpp
#include <cassert>
// assert断言调试
int a[1005];
void setValue(int idx, int val) {
    assert(idx >= 0 && idx < 1005);  // 断言下标合法
    a[idx] = val;
}
```

**小数据对拍**是最可靠的调试方法。原理是：用暴力程序（保证正确但效率低）和你的优化程序同时运行大量随机小数据，比较两者的输出是否一致。如果发现不一致，就用该组数据去调试你的程序。

**二分错误定位法**适用于代码较长、不知道哪里出错的情况。将代码分成两半，在中间位置加入一个`return 0;`，运行程序看前半部分是否正确。通过不断缩小范围，可以快速定位到出错的代码段。这种方法在考场时间紧张时尤其高效——与其盯着代码干看十分钟，不如用二分法两分钟内找到Bug所在。

### 三、常见陷阱与防范

**数组越界**是CSP-J中最常见的错误之一。C++不会检查数组下标是否合法，访问越界位置会导致未定义行为：可能恰好读到合法内存而"看起来正常"，也可能直接RE（运行时错误）。防范方法是：声明数组时统一开大10-20个元素，访问时注意下标从0还是1开始，循环边界条件仔细检查。

```cpp
// 数组越界防范示例
const int MAXN = 100005;  // 比题目最大数据多开5-10个
int a[MAXN];

int main() {
    int n;
    cin >> n;
    // 安全：确保n <= MAXN - 5
    for (int i = 1; i <= n; i++) {
        cin >> a[i];  // 下标从1开始，最大为n
    }
    // 访问a[n+1]？危险！如果n=MAXN-1就会越界
    return 0;
}
```

**未初始化变量**是另一个隐蔽的错误。C++中局部变量（包括数组）的初始值是未定义的，可能是任意值。全局变量和静态变量会自动初始化为0，但局部变量不会。养成声明变量时立即初始化的好习惯：`int ans = 0;`、`bool flag = false;`。此外，`memset`只能将数组设为0或-1（按字节赋值），不要用它来初始化其他值。

**int溢出**在涉及乘法、阶乘、大范围求和时极易发生。int的范围约为±21亿，当计算结果超出这个范围时会发生"回绕"，得到错误的负数或小数值。CSP-J中很多题目的答案需要取模（如对1e9+7取模），此时中间的乘法运算`a * b % MOD`可能先溢出再取模。防范方法：涉及乘法时使用`long long`，或者使用`1LL * a * b % MOD`的技巧。

```cpp
// int溢出防范
const int MOD = 1e9 + 7;

// 错误写法：a*b可能溢出int
int wrong_multiply(int a, int b) {
    return (a * b) % MOD;  // a*b先按int计算，可能溢出
}

// 正确写法
int correct_multiply(int a, int b) {
    return (1LL * a * b) % MOD;  // 1LL强制转为long long
}
```

**多组数据未清零**是初学者极易犯的错误。当一道题有多组测试数据时，如果在处理每组数据之前不清零数组和变量，上一组的残留数据会影响当前组的结果。使用`memset`可以快速清零数组，但要确保在每个测试用例开始时调用。

**freopen文件输入输出**是CSP-J的硬性要求：程序必须从`.in`文件读取输入，将结果写入`.out`文件。如果忘记写`freopen`，或者文件名写错（如`problem.in`写成`problem.txt`），程序将无法读取任何数据，直接输出0或乱码，导致0分。建议将freopen作为代码模板的第一行，养成习惯。

### 四、心态调整：遇到难题的处理方法

考场上遇到不会做的题是常态，即使是获奖选手也几乎不可能满分。关键在于心态管理和应对策略。当发现一道题没有明确思路时，首先深呼吸，告诉自己"我不会，别人也不一定会"，避免因为一题的卡壳影响整场考试的心态。然后按以下步骤处理：第一，重新审题，确认没有误解题意——可以用样例手动模拟一遍理解题目要求；第二，思考能否用暴力枚举拿部分分——CSP-J的前几个测试点数据规模通常很小，暴力足以通过；第三，考虑特殊性质——子任务描述中通常会标注特殊条件（如"保证数组已排序"、"保证图为链"），针对这些特殊性质写专门的代码；第四，如果实在没有任何思路，尝试输出`0`、`-1`或者输入数据的某个特征值，有时能碰对个别测试点。记住：CSP-J是看总分的，一道题失分不代表整场失败。保持冷静，把会做的题目做对，就是胜利。

### 五、考场注意事项

考前一天务必准备好以下物品：准考证（打印2份，一份备用）、身份证或户口本、黑色签字笔、2B铅笔、橡皮。不需要带草稿纸，考场会统一发放。编程环境方面，务必提前了解考点使用的编译器版本（通常为Dev-C++ 5.11或CodeBlocks，编译器为MinGW GCC），如果有条件，考前用相同的环境练习几次，熟悉IDE的快捷键和调试功能。考试过程中，每写完一道题就立即保存，并在本地运行样例测试。建一个专门的文件夹存放所有代码文件，文件名严格按照题目要求命名（通常为题目英文名，如`candy.cpp`、`live.cpp`）。提交前再次检查：freopen是否写对、文件名是否匹配、调试输出是否已删除、数组大小是否足够。最后，留出至少5分钟用于全部代码的最后检查和备份——将代码文件夹复制一份到桌面或U盘，防止意外丢失。

## ⚠️ 易错点

### 1. freopen 忘记写或写错导致 0 分

这是CSP-J中最"冤枉"的0分原因。freopen是文件重定向函数，必须写在`main`函数最前面，在任何输入输出操作之前。常见的错误有：文件名拼写错误（`problem.in`写成`problem.txt`或`problme.in`）、路径写错（多加路径前缀）、格式字符串写错（`"r"`和`"w"`写反）。更隐蔽的错误是：只写了输入freopen而忘记输出freopen，导致所有输出写到终端而非文件，评测机读不到输出文件判0分。还有些同学在调试时注释掉了freopen，提交时忘记恢复。

**正确写法**：
```cpp
freopen("candy.in", "r", stdin);   // 文件名严格与题目一致
freopen("candy.out", "w", stdout); // 两个都要写，缺一不可
```

**自检方法**：提交前在main函数最后加一行`fclose(stdout);`，如果程序异常终止说明freopen有问题。

### 2. 多组数据忘记初始化

当题目包含多组测试数据（常见格式为第一行输入T，后续T组数据）时，如果不在每组数据开始前重置变量，上一组数据的值会"污染"当前组的结果。需要注意的是，不仅数组需要清零，普通变量（如计数器、答案变量、标记数组）也要重新赋值。一个典型的错误是在循环外声明`int ans = 0;`，然后在循环内累加，循环条件应该是每组重置而非累加。

**正确写法**：
```cpp
int T; cin >> T;
while (T--) {
    int ans = 0;  // 每组数据重新声明并初始化为0
    memset(vis, 0, sizeof(vis));  // 标记数组清零
    // ... 处理逻辑
    cout << ans << endl;
}
```

### 3. int 溢出，何时用 long long

int的最大值约为2.1×10^9（即21亿），当数据范围超过这个值时必须使用long long（最大值约9.2×10^18）。需要特别注意的溢出场景：计算阶乘（13!已经超出int范围）、两个大int相乘（50000×50000=2.5×10^9已溢出）、累加求和（n=10^5个10^5求和=10^10溢出）、二分答案中的`mid = (l + r) / 2`在l和r很大时也可能溢出（虽然long long通常安全，但更推荐`mid = l + (r - l) / 2`）。CSP-J中建议：只要涉及乘法、前缀和、答案可能较大（通常数据范围标注|a_i|≤10^5且n≤10^5），就直接使用long long，空间通常足够（8字节vs4字节，100000个元素差400KB）。

```cpp
// 安全的写法
long long a[100005];     // 输入数据直接用long long
long long sum = 0;
for (int i = 1; i <= n; i++) {
    sum += a[i];         // long long累加，安全
}
long long product = 1LL * a[i] * b[i];  // 乘法前强制转换
```

### 4. 数组大小计算错误

很多同学在估算数组大小时只看题目给出的n范围，忽略了以下因素：n可能取到最大值+1（循环边界写`i<=n`时访问a[n]）、空间换时间的算法需要额外存储（如前缀和、差分数组、线段树4倍空间）、邻接表存图双向边需要2倍空间、字符串需要存`\0`结束符。CSP-J中常用的"多加5个"原则：`const int MAXN = 100000 + 5;`。对于不确定大小的数组（如动态规划的维度），先在纸上计算清楚再写代码。

**错误示例**：题目n≤100000，写了`int a[100000];`，但循环是`for(int i=1; i<=n; i++)`访问a[n]，当n=100000时a[100000]越界。
**正确示例**：`int a[100005];`，始终多开5-10个元素。

### 5. STL 使用不当

STL虽然方便，但使用不当会导致TLE（超时）或MLE（超内存）。常见问题有：

- **vector频繁push_back导致多次扩容**：知道数据规模时用`reserve()`预分配空间，或直接用数组。
- **map/unordered_map的常数因子较大**：能用数组下标解决的（如值域<10^7）优先用数组，map用于值域很大但元素数量较少的情况。CSP-J中如果发现map导致TLE，考虑改用`pair`数组+排序+二分模拟map。
- **stack/queue未判空就取top/front**：访问前一定要用`empty()`判断，否则RE。
- **string的`+`操作在循环中效率低**：大量拼接时使用`+=`或`stringstream`。

```cpp
// 避免反复扩容
vector<int> v;
v.reserve(100000);  // 预分配空间

// 安全访问栈/队列
if (!s.empty()) {
    int top = s.top();
    s.pop();
}
```

### 6. 文件输入输出调试问题

在本地IDE中使用freopen后，程序从文件读取输入，终端上看不到任何提示，不熟悉时会以为程序卡死了。这是正常现象——程序在等待文件输入，不会在控制台显示"请输入n"。因此本地调试时需要手动创建一个与freopen指定文件名相同的`.in`文件（如`candy.in`），在其中写入测试数据。另一种调试策略是在代码中使用条件编译：定义一个`LOCAL`宏，本地运行时从标准输入读取，提交时改为freopen。

```cpp
#define LOCAL 1  // 本地调试设为1，提交时改为0

int main() {
#if LOCAL
```

### 题目一：CSP-J 2021 分糖果

- **题目来源**：CSP-J 2021 第一轮（入门组）T1
- **题目简述**：有n个小朋友围成一圈分糖果，从第L个小朋友开始，到第R个小朋友结束（包含L和R）。每个小朋友分到的糖果数量等于其编号除以n的余数。问获得糖果最多的小朋友分到多少糖果。
- **考察知识点**：数学推导、取模运算的边界分析、O(1)思维题
- **易错点分析**：这道题看似简单但有不少同学写复杂了。核心在于理解：分到的糖果数是编号对n取模的结果，最大值理论上是n-1。如果区间[L, R]足够长（跨过了一个完整的模n周期），答案就是n-1；否则答案就是R % n。判断"足够长"的条件是：L % n + (R - L) >= n - 1 或者 L / n != R / n。很多同学用暴力循环L到R拿部分分，但R-L可能达到10^9，暴力会TLE。事实上这题O(1)的数学解法才是正解，关键在于发现从L开始，只要L到R之间有任何一个数模n等于n-1，答案就是n-1。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    freopen("candy.in", "r", stdin);
    freopen("candy.out", "w", stdout);
    
    long long n, L, R;
    cin >> n >> L >> R;
    
    // 如果区间跨过了一个完整周期，答案就是 n-1
    if (L / n != R / n || R - L >= n - 1) {
        cout << n - 1 << endl;
    } else {
        // 否则最大值就是 R % n
        cout << R % n << endl;
    }
    
    fclose(stdin);
    fclose(stdout);
    return 0;
}
```

### 题目二：CSP-J 2020 直播获奖

- **题目来源**：CSP-J 2020 第二轮 T2
- **题目简述**：NOI2130直播中，每评测完一名选手就评出一次获奖分数线。获奖分数线定义为：将所有已评测选手的成绩从高到低排序，取前w%（w=计划获奖率）名中的最低分。如果前w%名中有非整数，则向上取整。输出每次评测后的获奖分数线。
- **考察知识点**：桶排序（计数排序）、实时维护前w%大的元素、分数值域较小（0-600）
- **易错点分析**：这题如果用sort每轮都排一次序，n可达10^5，O(n^2logn)会超时。关键在于观察到分数范围只有0-600，可以使用桶排序（计数数组）。维护一个大小为601的桶，每次加入新成绩后，从600分向下累加人数，直到累加人数 ≥ 要求的获奖人数，当前分数即为分数线。注意向上取整的计算：计划获奖人数 = ceil(已评测人数 × w / 100)，可以直接用整数运算 `(cnt * w + 99) / 100` 实现向上取整。还有同学忘记每次都要重新从高到低扫描桶，而是试图增量更新结果导致逻辑错误。

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAX_SCORE = 600;

int bucket[MAX_SCORE + 5];  // 桶数组，下标表示分数

int main() {
    freopen("live.in", "r", stdin);
    freopen("live.out", "w", stdout);
    
    int n, w;
    cin >> n >> w;
    
    for (int i = 1; i <= n; i++) {
        int score;
        cin >> score;
        bucket[score]++;  // 将当前分数放入桶中
        
        // 计算计划获奖人数：ceil(i * w / 100)
        int plan = max(1, i * w / 100);  // C++整数除法向下取整
        // 由于题目要求向上取整，需要特殊处理
        int need = (i * w + 99) / 100;   // 向上取整
        if (need < 1) need = 1;
        
        // 从高到低累加，找到分数线
        int cnt = 0;
        int line = 0;
        for (int s = MAX_SCORE; s >= 0; s--) {
            cnt += bucket[s];
            if (cnt >= need) {
                line = s;
                break;
            }
        }
        
        cout << line << " ";
    }
    cout << endl;
    
    fclose(stdin);
    fclose(stdout);
    return 0;
}
```

### 题目三：CSP-J 2019 公交换乘

- **题目来源**：CSP-J 2019 第二轮 T2
- **题目简述**：小明乘坐公共交通出行。乘坐地铁可以获得一张优惠券，优惠券在获取后45分钟内有效，可以用于乘坐公交车（票价不超过优惠券面额时免费，否则需要补差价）。优惠券按获得时间排序，用最接近过期的优惠券优先使用。给定小明的出行记录（类型、票价、时间），计算总花费。
- **考察知识点**：队列模拟、时间窗口滑动、贪心（使用最早可获得且面额足够的优惠券）
- **易错点分析**：这是典型的队列模拟题，但有两个关键细节容易被忽略。第一，优惠券有45分钟有效期，需要维护一个滑动窗口——每次处理公交车时，先把队列中过期的优惠券弹出。第二，选择优惠券时需要使用"面额足够且最早获得"的那张，即从队头开始扫描，选择第一张面额≥当前公交票价的有效优惠券。很多同学直接用队列的front()而不检查面额是否足够，或者用优先队列增加了不必要的复杂度。另外，时间是int范围内，但总花费可能超出int（最多10^5次出行，每次票价最多1000，总计10^8在int范围内，但用long long更稳妥）。

```cpp
#include <bits/stdc++.h>
using namespace std;

struct Ticket {
    int price;  // 面额
    int time;   // 获得时间
    bool used;  // 是否已使用
};

vector<Ticket> tickets;  // 模拟队列，保存所有未使用且未过期的优惠券
int head = 0;            // 队列头指针（最早未过期的票）

int main() {
    freopen("transfer.in", "r", stdin);
    freopen("transfer.out", "w", stdout);
    
    int n;
    cin >> n;
    
    long long total = 0;
    
    for (int i = 1; i <= n; i++) {
        int type, price, t;
        cin >> type >> price >> t;
        
        if (type == 0) {
            // 地铁：付全款，获得优惠券
            total += price;
            tickets.push_back({price, t, false});
        } else {
            // 公交车：尝试使用优惠券
            // 1. 先清除过期的优惠券（移动head指针）
            while (head < tickets.size() && t - tickets[head].time > 45) {
                head++;
            }
            
            // 2. 扫描有效优惠券，找第一张面额足够的
            bool found = false;
            for (int j = head; j < tickets.size(); j++) {
                if (!tickets[j].used && tickets[j].price >= price) {
                    tickets[j].used = true;
                    found = true;
                    break;
                }
            }
            
            if (!found) {
                total += price;  // 无可用优惠券，付全款
            }
            // 用了优惠券则免费，total不增加
        }
    }
    
    cout << total << endl;
    
    fclose(stdin);
    fclose(stdout);
    return 0;
}
```

### 题目四：CSP-J 2022 乘方

- **题目来源**：CSP-J 2022 第一轮 T1
- **题目简述**：给定两个正整数a和b，计算a^b的值。如果a^b > 10^9，则输出-1；否则输出a^b的具体值。
- **考察知识点**：幂运算、溢出判断、快速幂思想、循环中的提前终止
- **易错点分析**：这道题的难度在于正确判断溢出。直接调用`pow(a, b)`会使用浮点数运算，精度不足且可能出错。正确做法是用循环逐次相乘，每次乘法后检查是否超过10^9。特别注意a=1时的特殊情况——1的任何次方都是1，不需要循环b次（b可能很大，如10^9，循环会超时）。另外需要使用long long存储中间结果，因为10^9是安全的，但2^30≈10^9，2^31就超过了。检查溢出的代码也很关键：不能在乘法之后和limit比较（如果乘完溢出变成负数，比较结果不可预测），而应该在乘法之前判断——如果当前结果已经大于limit/a，那么再乘a必然超过limit。

```cpp
#include <bits/stdc++.h>
using namespace std;

const long long LIMIT = 1000000000LL;  // 10^9

int main() {
    freopen("pow.in", "r", stdin);
    freopen("pow.out", "w", stdout);
    
    long long a, b;
    cin >> a >> b;
    
    // 特判：a=1时结果恒为1
    if (a == 1) {
        cout << 1 << endl;
        fclose(stdin);
        fclose(stdout);
        return 0;
    }
    
    long long ans = 1;
    for (long long i = 1; i <= b; i++) {
        // 在乘法之前检查：如果 ans > LIMIT / a，乘完必定超10^9
        if (ans > LIMIT / a) {
            cout << -1 << endl;
            fclose(stdin);
            fclose(stdout);
            return 0;
        }
        ans *= a;
    }
    
    cout << ans << endl;
    
    fclose(stdin);
    fclose(stdout);
    return 0;
}
```
