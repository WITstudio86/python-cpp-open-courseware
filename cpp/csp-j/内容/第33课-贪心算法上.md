## 📖 知识精讲

### 一、什么是贪心算法

贪心算法（Greedy Algorithm）是一种在每一步选择中都采取当前状态下最优（最有利）的选择，从而希望导致结果是全局最优的算法策略。贪心算法的核心思想可以用一句话概括：**"每一步都做到最好，最终就能得到最好的结果。"**

但需要注意，贪心算法并不是对所有问题都能得到整体最优解。能使用贪心算法解决的问题必须满足两个关键性质：

1. **贪心选择性质**：问题的整体最优解可以通过一系列局部最优选择（即贪心选择）来达到。也就是说，不需要"后悔"或回溯，每一步的选择都是不可撤销的。这是贪心算法区别于回溯法的根本特征。

2. **最优子结构性质**：问题的最优解包含其子问题的最优解。即一个大问题的最优解可以由其子问题的最优解组合而成。这个性质也是动态规划所要求的，但贪心算法以更高效的方式利用了它。

在 CSP-J 考试中，贪心算法是高频考点，尤其常见于活动选择、区间调度、硬币找零等问题。掌握贪心算法的关键在于：**能够判断一个问题是否适合用贪心，并能设计出正确的贪心策略。**

### 二、贪心策略的设计步骤

设计贪心算法一般遵循以下四个步骤：

第一步：**分析问题，确定候选集合**。明确所有可能的选择是什么。例如在活动选择问题中，候选集合就是所有尚未被排除的活动。

第二步：**设计贪心策略**。确定按照什么标准来进行选择。这是最关键的一步——策略设计错误，整个算法就会失效。常见的策略有：按某个属性从小到大排序后依次选择、按某个属性从大到小排序后依次选择、按某种比值（如性价比）排序后依次选择。

第三步：**证明贪心策略的正确性**。在比赛中，不需要严格的数学证明，但至少要能用"反证法"或"替换法"在头脑中验证策略的合理性。如果找不到反例，策略很可能是正确的。

第四步：**实现算法**。贪心算法的实现通常非常简洁，大部分情况是"排序 + 一次遍历"的模式。时间复杂度通常由排序决定，为 O(n log n)。

让我们通过一个例子来理解这个流程。假设你面前有一排硬币（1元、5元、1元、10元、1元），你每次可以从两端取一枚硬币，目标是取得的总金额最大。这个问题的贪心策略是什么？答案是：每次比较两端的硬币，取面额更大的那一枚。这个策略是否正确？是的——因为无论你取哪一枚，剩下的硬币序列仍然是原序列的一个子序列，问题具有最优子结构性质。

再考虑一个反例：硬币排列为 [1, 100, 10, 1]。如果贪心取两端较大的，第一次取1（右端1和左端1一样，随便取一个），对手会取100，最终你的总额是1+10=11；但如果你第一次取左端1，对手可能取右端1，然后你就能取到100，总额是101。这说明上述贪心策略是错误的！这个例子充分说明了**贪心策略需要慎重设计并验证**。

### 三、经典问题一：活动选择问题（区间调度）

**问题描述**：有 n 个活动，每个活动有一个开始时间 s[i] 和结束时间 f[i]。同一时间只能参加一个活动，且每个活动一旦开始就必须完整参加。问最多能参加多少个活动？

**贪心策略**：按照**结束时间从小到大**排序，每次选择结束时间最早且与已选活动不冲突的活动。

为什么按结束时间排序是正确的？因为选择结束时间最早的活动，可以为后面留出尽可能多的时间空间。我们可以用"替换法"来证明：假设最优解中第一个活动不是结束最早的，我们可以把最优解中的第一个活动替换为结束最早的那个活动——替换后不减少活动数量，因此结束最早的活动一定属于某个最优解。

下面演示一个具体例子：

```
活动编号：   1    2    3    4    5    6
开始时间：   1    3    0    5    8    5
结束时间：   4    5    6    7    9    9

按结束时间排序后：
活动编号：   1    2    3    4    6    5
开始时间：   1    3    0    5    5    8
结束时间：   4    5    6    7    9    9

贪心过程（lastEnd 表示上一个选中活动的结束时间）：
初始：lastEnd = 0，ans = 0
活动1 [1,4]：start=1 >= lastEnd=0，选中。lastEnd=4，ans=1
活动2 [3,5]：start=3 < lastEnd=4，冲突，跳过
活动3 [0,6]：start=0 < lastEnd=4，冲突，跳过
活动4 [5,7]：start=5 >= lastEnd=4，选中。lastEnd=7，ans=2
活动6 [5,9]：start=5 < lastEnd=7，冲突，跳过
活动5 [8,9]：start=8 >= lastEnd=7，选中。lastEnd=9，ans=3

最终选择了活动1、4、5，共3个活动。
```

该算法的时间复杂度为 O(n log n)（由排序决定），空间复杂度为 O(n)。如果使用动态规划解决同样的问题，时间复杂度会是 O(n²)，空间复杂度 O(n)。由此可见贪心算法的高效性。

**区间调度问题的常见变种及对应策略**：

- **最多区间选择**（本问题）：按结束时间升序排序，选择不冲突的区间。这是最经典的变种，对应"活动选择"问题。
- **最少区间覆盖**（用最少的区间覆盖目标线段）：按开始时间升序排序，每次选择能覆盖当前左端点且右端点最远的区间。对应"区间覆盖"问题。
- **区间选点**（用最少的点使得每个区间内至少有一个点）：按结束时间升序排序，每次在未覆盖区间的右端点放置一个点。对应"种树问题"。
- **移除最少区间使剩余区间不重叠**：等价于"最多区间选择"，答案是 n - 最多可选区间数。

在 CSP-J 考试中，这四种变种都可能出现，但核心都是**根据具体需求选择合适的排序标准**。请务必把每种变种都练习一遍。

### 四、经典问题二：硬币找零问题

**问题描述**：给定不同面额的硬币和一个总金额，计算可以凑成总金额所需的最少硬币个数。如果无法凑出，返回 -1。

**贪心策略**：每次选择面额最大且不超过剩余金额的硬币。

以人民币硬币面额（1元、5元、10元、20元、50元、100元）为例，找零 87 元的过程如下：

```
剩余 87 元 → 面额 50 ≤ 87，选 1 枚 50 元 → 剩余 37 元
剩余 37 元 → 面额 20 ≤ 37，选 1 枚 20 元 → 剩余 17 元
剩余 17 元 → 面额 10 ≤ 17，选 1 枚 10 元 → 剩余  7 元
剩余  7 元 → 面额  5 ≤  7，选 1 枚  5 元 → 剩余  2 元
剩余  2 元 → 面额  1 ≤  2，选 2 枚  1 元 → 剩余  0 元

最少硬币数：1 + 1 + 1 + 1 + 2 = 6 枚
```

**重要警示：贪心策略并非对所有硬币系统都正确！**

考虑硬币面额为 {1, 3, 4}，找零 6 元的情况：
- 贪心策略：先选 4 元（最大 ≤ 6），剩余 2 元 → 选 1 元 × 2 → 共 3 枚硬币
- 实际最优解：选 3 元 × 2 → 共 2 枚硬币

贪心给出了 3 枚的错误答案，而最优解是 2 枚！这个反例充分说明了硬币找零问题中贪心策略的局限性。

人民币硬币面额（1、5、10、20、50、100）之所以能用贪心，是因为它满足"规范硬币系统"（canonical coin system）的性质——每个面额都是前面某些面额的整数倍，且贪心选择不会导致"死胡同"。

**CSP-J 考试中的应对策略**：题目没有明确说明面额规律时，如果金额和面额数量都不大（如金额 ≤ 10000，面额数 ≤ 10），最安全的做法是使用动态规划（完全背包）来求解。DP 的做法是：设 dp[i] 表示凑出金额 i 所需的最少硬币数，则 dp[i] = min(dp[i], dp[i - coins[j]] + 1)。

### 五、贪心算法与其它算法的对比

理解贪心算法与其它经典算法的区别，有助于在考试中正确选择解题策略：

| 对比维度 | 贪心算法 | 动态规划 | 回溯/枚举 |
|---------|---------|---------|----------|
| 选择方式 | 每步选当前最优，不回溯 | 考虑所有子问题，记录每个状态的最优值 | 穷举所有可能的解 |
| 正确性 | 需要证明（不一定最优） | 理论上保证最优 | 保证最优 |
| 时间复杂度 | 通常 O(n log n) | 通常 O(n²) 或 O(nW) | 通常指数级 |
| 空间复杂度 | 通常 O(1) 或 O(n) | 通常 O(n) 或 O(n²) | 通常 O(n)（递归栈） |
| 适用条件 | 贪心选择性 + 最优子结构 | 最优子结构 + 子问题重叠 | 无特殊限制 |
| CSP-J 典型题 | 活动选择、排队接水、最优装载 | 01背包、LIS、数字三角形 | 全排列、N皇后 |

**判断是否使用贪心的四步法**：

1. **分析问题规模**：如果 n ≤ 20，直接用回溯/枚举，不需要考虑贪心；
2. **检查贪心选择性质**：尝试构造反例，如果找不到反例，贪心可能有效；
3. **设计贪心策略**：确定排序标准（按哪个属性排序，升序还是降序）；
4. **用样例验证**：在小数据和边界数据上测试，确认策略可行。

### 六、CSP-J 常见贪心题型总结

1. **活动选择/区间调度**：给定若干区间，选择最多的互不重叠区间。策略是按**结束时间**升序排序，依次选择不冲突的区间。时间复杂度 O(n log n)。

2. **排队接水**：n 个人排队接水，每人需要 t[i] 时间，求最小的总等待时间。策略是按**接水时间**升序排序（短作业优先）。时间复杂度 O(n log n)。

3. **最优装载**：有 n 个物品和一艘载重为 C 的船，每个物品重 w[i]，求最多能装多少个物品。策略是按**重量**升序排序，依次装入直到超重。时间复杂度 O(n log n)。

4. **区间覆盖**：用最少的给定区间覆盖目标区间 [L, R]。策略是按**左端点**升序排序，每次选择能覆盖当前左端点且右端点最远的区间。时间复杂度 O(n log n)。

5. **删数问题**：从一个高精度整数中删除 k 位数字，使剩余数字组成的数最小。策略是从左到右扫描，删除第一个比右边大的数字（即删除"山峰"），重复 k 次。可用单调栈优化到 O(n)。

6. **合并果子（哈夫曼编码）**：n 堆果子，每次合并两堆的代价为两堆重量之和，求最小总代价。策略是每次选择最小的两堆合并，使用优先队列（小根堆 priority_queue）实现。时间复杂度 O(n log n)。

## 💻 代码模板

### 模板一：活动选择问题（区间调度）完整模板

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;

struct Activity {
    int start, end;
} a[MAXN];

// 按结束时间升序排序——贪心策略的核心
bool cmp(Activity x, Activity y) {
    return x.end < y.end;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> a[i].start >> a[i].end;
    }
    
    // 第1步：按结束时间排序
    sort(a, a + n, cmp);
    
    // 第2步：贪心选择
    int ans = 1;               // 至少选第一个活动
    int lastEnd = a[0].end;    // 上一个选中活动的结束时间
    
    for (int i = 1; i < n; i++) {
        if (a[i].start >= lastEnd) {  // 当前活动与已选活动不冲突
            ans++;
            lastEnd = a[i].end;
        }
    }
    
    cout << ans << endl;
    return 0;
}
```

### 模板二：硬币找零通用模板（贪心版，仅适用于规范硬币系统）

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

// 硬币找零——贪心策略
// 注意：仅当硬币面额系统为"规范硬币系统"时保证最优
// coins 数组需按面额从大到小排序
int greedyCoinChange(int coins[], int m, int amount) {
    int count = 0;
    for (int i = 0; i < m; i++) {
        if (amount >= coins[i]) {
            int num = amount / coins[i];     // 尽可能多用当前面额
            count += num;
            amount -= num * coins[i];        // 减去已使用的金额
        }
        if (amount == 0) break;
    }
    if (amount > 0) return -1;  // 无法凑出
    return count;
}

int main() {
    int coins[] = {100, 50, 20, 10, 5, 1};  // 人民币面额，从大到小
    int m = 6;
    int amount;
    cin >> amount;
    
    int ans = greedyCoinChange(coins, m, amount);
    cout << ans << endl;
    return 0;
}
```

### 模板三：硬币找零通用模板（DP版，保证正确）

```cpp
#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;

const int INF = 0x3f3f3f3f;
const int MAX_AMOUNT = 10005;

int dp[MAX_AMOUNT];  // dp[i] = 凑出金额 i 所需的最少硬币数

int dpCoinChange(int coins[], int m, int amount) {
    memset(dp, 0x3f, sizeof(dp));
    dp[0] = 0;
    
    for (int i = 1; i <= amount; i++) {
        for (int j = 0; j < m; j++) {
            if (i >= coins[j]) {
                dp[i] = min(dp[i], dp[i - coins[j]] + 1);
            }
        }
    }
    return dp[amount] == INF ? -1 : dp[amount];
}

int main() {
    int coins[] = {1, 3, 4};  // 非规范硬币系统，贪心会出错
    int m = 3;
    int amount;
    cin >> amount;
    
    int ans = dpCoinChange(coins, m, amount);
    cout << ans << endl;
    return 0;
}
```

### 模板四：区间覆盖问题模板

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;

struct Interval {
    int left, right;
} a[MAXN];

// 按左端点升序排序
bool cmp(Interval x, Interval y) {
    return x.left < y.left;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n, targetL, targetR;
    cin >> n >> targetL >> targetR;
    for (int i = 0; i < n; i++) {
        cin >> a[i].left >> a[i].right;
    }
    
    sort(a, a + n, cmp);
    
    int ans = 0;
    int currentR = targetL;  // 当前已覆盖到的右边界
    int i = 0;
    
    while (currentR < targetR) {
        int maxR = currentR;
        // 在所有左端点 <= currentR 的区间中，选右端点最大的
        while (i < n && a[i].left <= currentR) {
            maxR = max(maxR, a[i].right);
            i++;
        }
        if (maxR == currentR) {  // 无法继续延伸，无解
            ans = -1;
            break;
        }
        ans++;
        currentR = maxR;
    }
    
    cout << ans << endl;
    return 0;
}
```

## ⚠️ 易错点

- **易错点1：排序标准选错。** 在活动选择问题中，最常见的错误是按开始时间排序或按区间长度排序。正确的做法是按结束时间排序。建议在写代码前先用纸笔推演一个小样例，确认排序标准是否正确，不要想当然地选择排序字段。例如，给定区间 [1,10]、[2,4]、[5,6]，如果按开始时间排序会先选 [1,10]，导致只能选1个活动；而按结束时间排序会选 [2,4] 和 [5,6]，得到2个活动的最优解。

- **易错点2：贪心策略并非总是正确。** 硬币找零问题是典型的"贪心不一定正确"的例子——{1,3,4}面额找零6元时贪心给出3枚的错误答案（最优为2枚）。在 CSP-J 考试中，如果题目没有明确说明可以安全使用贪心，应优先考虑动态规划。判断方法是：尝试构造反例，如果面额不满足"大面额是小面额的整数倍"的规律，贪心很可能失效。

- **易错点3：区间覆盖问题中忘记处理无解情况。** 当所有给定区间都无法完全覆盖目标区间时，程序应输出 -1。很多同学只写了正常流程，忽略了 `maxR == currentR` 的无解判断，导致部分测试点失分。无解还可能发生在目标区间本身为 [0,0] 或所有区间都在目标区间之外的情况下。

- **易错点4：cmp 比较函数写错导致排序异常。** C++ 的 sort 要求 cmp 函数满足严格弱序。常见错误是写 `return a.end <= b.end`（多了等号），这会导致运行时错误或排序结果不确定。务必写成严格小于 `return a.end < b.end`。

- **易错点5：贪心选择后忘记更新状态。** 在贪心循环中，选中一个活动后必须更新 `lastEnd`（或等价的状态变量）。忘记更新会导致后续判断全部基于错误的参照点，最终答案可能偏大或偏小。建议在每次选中后立即更新状态变量，并保持命名清晰（如 lastEnd、currentR 等）。

## 📝 真题精练

### 题目一：活动选择（CSP-J 风格模拟题）

**【题目描述】**
学校有 n 个社团申请使用礼堂，每个社团申请的使用时间段为 [s_i, f_i)（左闭右开区间，即 f_i 时刻礼堂已空闲）。同一时间礼堂只能被一个社团使用。请你编写程序计算最多能安排多少个社团使用礼堂。

**【输入格式】**
第一行一个整数 n（1 ≤ n ≤ 100000），表示社团数量。
接下来 n 行，每行两个整数 s_i 和 f_i（0 ≤ s_i < f_i ≤ 10^9），表示第 i 个社团申请使用的开始时间和结束时间。

**【输出格式】**
输出一个整数，表示最多能安排的社团数量。

**【样例输入】**
```
6
1 4
3 5
0 6
5 7
8 9
5 9
```

**【样例输出】**
```
3
```

**【样例解释】**
可以选择 [1,4)、[5,7)、[8,9) 三个社团，数量为 3，是所有可行方案中的最大值。

**【AC 代码】**
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;

struct Activity {
    int start, end;
} a[MAXN];

bool cmp(Activity x, Activity y) {
    return x.end < y.end;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> a[i].start >> a[i].end;
    }
    
    sort(a, a + n, cmp);
    
    int ans = 1;
    int lastEnd = a[0].end;
    for (int i = 1; i < n; i++) {
        if (a[i].start >= lastEnd) {
            ans++;
            lastEnd = a[i].end;
        }
    }
    
    cout << ans << endl;
    return 0;
}
```

### 题目二：排队接水（CSP-J 风格模拟题）

**【题目描述】**
有 n 个人在一个水龙头前排队接水，第 i 个人接满水需要 t_i 分钟。请安排一个排队顺序，使得 n 个人的**总等待时间**最小，并输出最小的总等待时间。

**等待时间的定义**：第 i 个人的等待时间 = 从 0 时刻开始到他接满水所经过的总时间（即前面所有人的接水时间之和加上自己的接水时间）。所有 n 个人的等待时间之和即为总等待时间。

**【输入格式】**
第一行一个整数 n（1 ≤ n ≤ 100000），表示人数。
第二行 n 个整数 t_1, t_2, ..., t_n（1 ≤ t_i ≤ 10000），表示每个人接水所需的时间。

**【输出格式】**
输出一个整数，表示最小的总等待时间。

**【样例输入】**
```
4
3 1 4 2
```

**【样例输出】**
```
20
```

**【样例解释】**
按接水时间从小到大排序：1、2、3、4。
- 第 1 个人完成时间 = 1
- 第 2 个人完成时间 = 1 + 2 = 3
- 第 3 个人完成时间 = 3 + 3 = 6
- 第 4 个人完成时间 = 6 + 4 = 10
总等待时间 = 1 + 3 + 6 + 10 = 20。

如果按原顺序 3、1、4、2 接水，总等待时间 = 3 + 4 + 8 + 10 = 25，大于 20。

**【AC 代码】**
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;

int t[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    cin >> n;
    for (int i = 0; i < n; i++) {
        cin >> t[i];
    }
    
    // 贪心策略：按接水时间升序排序（短作业优先）
    sort(t, t + n);
    
    long long totalWait = 0;   // 注意使用 long long，防止溢出
    long long currentTime = 0; // 当前累计时间
    
    for (int i = 0; i < n; i++) {
        currentTime += t[i];         // 第 i 个人完成接水的时间
        totalWait += currentTime;    // 累加到总等待时间
    }
    
    cout << totalWait << endl;
    return 0;
}
```

### 题目三：最优装载（CSP-J 风格）

**【题目描述】**  
有一艘船载重上限为 C，有 n 件货物，第 i 件重量为 w_i。每件最多装一次，问最多能装多少件？

**【输入格式】**  
第一行：n C（1 ≤ n ≤ 1e5，1 ≤ C ≤ 1e9）  
第二行：n 个正整数 w_i（1 ≤ w_i ≤ 1e9）

**【输出格式】**  
最多件数。

**【样例输入】**
```
5 10
3 2 7 1 4
```

**【样例输出】**
```
4
```

**【策略】** 按重量升序，能装就装（轻的优先，件数最多）。

**【AC 代码】**
```cpp
#include <iostream>
#include <algorithm>
using namespace std;

const int MAXN = 100005;
long long w[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    int n;
    long long C;
    cin >> n >> C;
    for (int i = 0; i < n; i++) cin >> w[i];
    sort(w, w + n);
    int ans = 0;
    long long sum = 0;
    for (int i = 0; i < n; i++) {
        if (sum + w[i] <= C) {
            sum += w[i];
            ans++;
        } else break;  // 后面更重，装不下
    }
    cout << ans << endl;
    return 0;
}
```

**注意**：若问的是**价值最大**且每件有价值，则不是简单按重量，可能要按价值/重量或直接 DP（01 背包），本课只讨论“件数最多”的纯重量贪心。

| 问题 | 排序关键字 | 扫描时决策 | 典型输出 |
|------|------------|------------|----------|
| 最多不重叠区间 | 右端点升序 | 不冲突则选 | 个数 |
| 移除最少重叠 | 同上 | n − 最多不重叠 | 个数 |
| 区间选点 | 右端点升序 | 右端点放点 | 点数 |
| 区间覆盖 | 左端点升序 | 覆盖当前点且右端最远 | 区间数或 -1 |
| 排队接水 | 时间升序 | 累加等待 | 总等待 |
| 最优装载（件数） | 重量升序 | 能装就装 | 件数 |

### 区间选点再讲一遍

给定 n 个闭区间，在数轴上选尽量少的点，使每个区间至少含一个点。

**策略**：按右端点排序；若当前区间尚未被已有点覆盖，则在其右端点放一个点。

```cpp
// a[i] = {L, R}，按 R 升序
sort(a, a + n, [](auto x, auto y){ return x.second < y.second; });
int ans = 0;
long long last = -2e18;  // 上一个点的位置
for (int i = 0; i < n; i++) {
    if (a[i].first > last) {   // 未被覆盖
        last = a[i].second;    // 放在右端点
        ans++;
    }
}
```

### 证明思路速记（替换法）

对“按结束时间选活动”：  
设贪心选的第一个活动为 g，某最优解第一个为 o。若 g≠o，则用 g 替换 o 后仍合法且数量不少，故存在以 g 开头的最优解。归纳即可。

### 何时不要贪心

1. 需要考虑“将来更大收益”的全局权衡（如一般背包价值最大）。  
2. 硬币系统非规范。  
3. 能构造出明确反例。  
4. 状态依赖复杂，更像 DP。

## 🎯 本课小结

- 贪心算法的核心是**每一步做出当前最优的选择**，并希望这些局部最优能推导出全局最优
- 贪心算法能正确求解的问题必须满足**贪心选择性质**和**最优子结构性质**
- 活动选择问题是贪心算法的经典应用，策略是按**结束时间**升序排序，依次选择不冲突的活动，时间复杂度 O(n log n)
- 硬币找零问题中，贪心策略并非总是最优——面额不满足规范硬币系统时需要使用动态规划
- 区间覆盖问题使用不同的贪心策略：按**左端点**排序，每次选能覆盖当前左端点且右端点最远的区间
- 设计贪心算法的一般流程：分析候选集合 → 设计贪心策略 → 验证正确性 → 编码实现
- CSP-J 中贪心常与排序结合，代码量通常很少，但难点在于**判断能否使用贪心**和**设计正确的贪心策略**
- 排队接水、最优装载等问题也都可以用排序+贪心高效解决
- 常见的排序标准选错和 cmp 函数写错是考试中的高频失分点，务必重视
- 区间选点、最多不重叠、最少覆盖三类题排序关键字不同，考前对照表再过一遍
