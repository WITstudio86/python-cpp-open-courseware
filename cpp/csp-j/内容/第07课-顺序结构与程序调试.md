## 📖 知识精讲

### 一、顺序结构：程序的默认执行方式

顺序结构是三种基本控制结构之一（另两种是分支与循环）。**只要没有分支、循环、函数跳转，语句就严格按照书写顺序从第一行执行到最后一行。**

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 10;           // ① 先执行：a 变为 10
    int b = 20;           // ② 再执行：b 变为 20
    int c = a + b;        // ③ 使用①②的结果：c = 30
    cout << c << endl;    // ④ 输出 30
    return 0;             // ⑤ 结束
}
```

**顺序结构的四个本质特点**：

1. **一次执行**：每条语句按顺序执行一次（除非被跳转改写流程）。
2. **结果依赖**：后面语句可以安全使用前面语句已经算好的结果。
3. **严格先后**：前一条语句“做完”后，才会开始后一条。
4. **默认方式**：C++ 的默认控制流就是顺序；分支/循环是对默认流的“改写”。

可以把顺序结构想象成流水线：

```
输入 → 计算1 → 计算2 → 计算3 → 输出
         ↑ 每一步都依赖上一步的结果
```

竞赛题里大量“读入—处理—输出”的主程序骨架，本质上就是顺序结构：

```cpp
int main() {
    // 1. 读入
    int a, b;
    cin >> a >> b;

    // 2. 处理（顺序计算）
    int sum = a + b;
    int prod = a * b;

    // 3. 输出
    cout << sum << " " << prod << endl;
    return 0;
}
```

### 二、C++ 语句分类（读程基础）

想读懂顺序结构，必须先认清“什么是一条语句”。

#### 1. 声明语句

```cpp
int a;                 // 声明但未初始化（局部变量值未定义）
int b = 10;            // 声明并初始化（推荐）
double x = 3.14, y;    // 同一类型可连续声明
const int N = 100;     // 常量声明
```

#### 2. 表达式语句

以分号结尾的表达式：

```cpp
a = b + c;             // 赋值表达式语句
cout << a;             // 输出也是表达式语句
a++;                   // 自增表达式语句
(void)0;               // 合法但无意义
```

#### 3. 控制语句

改变执行顺序的语句：`if`、`for`、`while`、`switch`、`return`、`break`、`continue`、`goto`。

本课先聚焦顺序；下一课起进入分支。

#### 4. 空语句

单独一个分号：

```cpp
;                      // 空语句：什么也不做
while (cin >> x);      // 危险写法：循环体是空语句
if (a > 0);            // 危险写法：if 后面是空语句
```

空语句在语法上合法，却是逻辑错误重灾区。

#### 5. 复合语句（代码块）

用花括号 `{ }` 把多条语句包成“一条语句”：

```cpp
{
    int t = a;
    a = b;
    b = t;
}
```

复合语句在 if/for/while 中极为重要：没有花括号时，控制语句只“管”后面紧跟的那一条语句。

### 三、变量的生命周期与顺序赋值

顺序结构里，最容易算错的不是运算符，而是**“某时刻变量到底是多少”**。

#### 1. 赋值是“覆盖”不是“复制关系永久绑定”

```cpp
int a = 3;
int b = a;   // b 拿到当前 a 的值 3
a = 10;      // 改 a 不会自动改 b
// 现在 a=10, b=3
```

很多人误以为 `b = a` 建立了“永久相等关系”，其实只是把当时的值拷过去。

#### 2. 右值先算，再写入左值

```cpp
int a = 5, b = 3;
a = a + b;   // 先算右边 5+3=8，再写入 a
```

#### 3. 交换的两种标准写法

**方法 A：临时变量（最稳妥，考试首选）**

```cpp
int t = x;
x = y;
y = t;
```

**方法 B：加减法（了解即可，有溢出风险）**

```cpp
x = x + y;
y = x - y;
x = x - y;
```

**方法 C：异或（了解即可）**

```cpp
x = x ^ y;
y = x ^ y;
x = x ^ y;
```

CSP-J 读程题常让你跟踪交换过程，务必会画变量表。

### 四、程序错误的四大类型

竞赛评测反馈通常对应以下错误类型。理解它们，才能知道该看编译器、运行结果还是逻辑。

#### 1. 编译错误（Compile Error, CE）

程序还没生成可执行文件就失败了。常见原因：

| 报错信息（片段） | 含义 | 常见原因 |
|------------------|------|----------|
| `expected ';' before ...` | 缺分号 | 上一行漏写 `;` |
| `was not declared in this scope` | 未声明 | 变量/函数名写错，或用前未定义 |
| `expected '}' at end of input` | 缺右花括号 | `{` `}` 不成对 |
| `expected primary-expression` | 表达式残缺 | 运算符两边缺操作数 |
| `invalid conversion` / `cannot convert` | 类型不匹配 | 把字符串赋给 int 等 |
| `redeclaration` | 重复声明 | 同名变量重复定义 |

**例：缺分号**

```cpp
int a = 10   // 缺分号
int b = 20;  // 编译器可能在这一行报错！
```

注意：报错行号有时指“发现错误的位置”，真正问题可能在上一行。

#### 2. 链接错误（Link Error）

各 .cpp 单独编译通过，但合在一起时找不到符号。

常见情况：

- 调用了只有声明没有定义的函数；
- 多个文件里定义了同名全局变量/函数（重复定义）；
- 写了 `main` 却拼错成 `mian`（有时表现为入口找不到）。

CSP-J 单文件题目中链接错误较少，但“函数只声明不定义”会在本地练习中出现。

#### 3. 运行时错误（Runtime Error, RE）

程序能启动，但执行中崩溃或被系统终止。

| 类型 | 示例 | 说明 |
|------|------|------|
| 除零 | `int x = 5 / 0;` | 整数除零 |
| 数组越界 | `a[10]` 但只开了 `a[10]`（下标 0~9） | 访问非法下标 |
| 段错误 | 解引用空指针、写只读区 | 非法内存访问 |
| 栈溢出 | 过深递归 | 后续递归课会详讲 |
| 断言失败 | `assert(false)` | 调试断言触发 |

#### 4. 逻辑错误（Wrong Answer, WA）

最麻烦：能编译、能跑完，但输出不对。

常见根因：

- 算法本身错；
- 边界条件没处理（n=0、负数、最大值）；
- 整数除法截断；
- `=` 与 `==` 混用；
- 输出格式多空格、少换行；
- 调试输出忘删，导致“答案多了几行”。

### 五、调试方法精讲

#### 1. 输出调试法（竞赛最实用）

在关键位置打印变量与流程标记：

```cpp
int main() {
    int a, b;
    cin >> a >> b;
    cerr << "[DEBUG] a=" << a << ", b=" << b << endl;  // 建议用 cerr

    int c = a + b;
    cerr << "[DEBUG] c=" << c << endl;

    cout << c << endl;  // 正式输出只走 cout
    return 0;
}
```

**为什么推荐 `cerr`？**

- `cout` 是标准输出，会被评测当成答案；
- `cerr` 是标准错误流，本地可见，部分评测环境不会把它当答案（但考试仍建议最终删干净）。

**可开关调试宏模板：**

```cpp
#define DEBUG

#ifdef DEBUG
#define dbg(x) cerr << #x << " = " << (x) << endl
#else
#define dbg(x)
#endif

int main() {
    int a = 3, b = 5;
    dbg(a);
    dbg(b);
    dbg(a + b);
    return 0;
}
```

提交前：注释掉 `#define DEBUG`，或直接删除全部调试语句。

#### 2. 断点调试法（IDE 精查逻辑）

适用于 Dev-C++、Code::Blocks、VS Code + gdb、CLion 等。

**标准步骤：**

1. 在可疑行左侧点一下，出现红点——这就是**断点**；
2. 以调试模式运行（常见快捷键 F5）；
3. 程序运行到断点处暂停；
4. 打开**监视/变量窗口**，查看当前所有局部变量；
5. **单步跳过**（Step Over）：执行当前行，不进入函数内部；
6. **单步进入**（Step Into）：进入函数内部继续调；
7. **继续**（Continue）：跑到下一个断点；
8. 对比“实际值”和“心算预期值”。

**调试时重点看什么？**

- 变量值是否符合当前步骤的预期；
- 是否走进了你以为会走的分支；
- 循环次数是否正确；
- 数组下标是否越界；
- 累加器是否从正确初值开始。

#### 3. 二分隔离与对拍（进阶意识）

长代码可用中间标记 `cerr << "here\n";` 二分缩小 bug 范围；算法题后续还会用「暴力程序 vs 待测程序」对拍。本课先建立“对比预期”的意识即可。

### 六、程序阅读（读程）系统方法

CSP-J 有大量“阅读程序，写输出”题。顺序结构读程是基础功。

#### 五步法

1. **概览**：看输入输出、有无循环/分支、大致在算什么；
2. **找关键变量**：谁会变？谁是累加器？谁是中间量？
3. **逐行模拟**：像 CPU 一样执行，不要跳读；
4. **制作变量追踪表**：每执行一条关键语句，更新一列表格；
5. **还原输出**：严格按 `cout` 顺序与格式写答案。

#### 变量追踪表模板

对代码：

```cpp
int a = 3, b = 5;
a = a + b;
b = a - b;
a = a - b;
cout << a << " " << b << endl;
```

| 步骤 | 语句 | a | b | 说明 |
|------|------|---|---|------|
| 0 | 初始 | 3 | 5 | 声明初始化 |
| 1 | `a=a+b` | 8 | 5 | 3+5=8 |
| 2 | `b=a-b` | 8 | 3 | 8-5=3 |
| 3 | `a=a-b` | 5 | 3 | 8-3=5 |
| 4 | 输出 | 5 | 3 | 输出 `5 3` |

结论：这是交换。

#### 读程常见陷阱

1. **整数除法**：`7/2` 是 3，不是 3.5；
2. **自增夹在表达式里**：先用后加 / 先加后用必须分清；
3. **赋值链**：`a=b=c=1` 从右往左；
4. **中间值被覆盖**：后面用到的是“新值”，不是初始值；
5. **输出格式**：空格、换行、是否有多余字符。

### 七、常见编译错误速查

| 现象 | 常见原因 | 对策 |
|------|----------|------|
| `expected ';'` | 上一行缺分号 | 检查报错行与上一行 |
| `was not declared` | 未声明/拼写错 | 先声明再使用 |
| `expected '}'` | 花括号不成对 | 成对书写、编辑器高亮 |
| 类型转换失败 | 如 `int x="hi"` | 类型匹配 |
| 中文标点 | 全角 `；` `（` | 英文标点重打 |
| `void main` | 非标准入口 | 使用 `int main` |

### 八、提交前 / 查 WA 清单

1. 样例能否手算通过；2. 边界 0/1/最大；3. 是否该用 `long long`；  
4. 是否整数除法踩坑；5. 累加器是否初始化；6. 输出格式；  
7. 调试输出是否删净；8. 是否读错题意。

## 💻 代码模板

### 模板 1：可开关调试输出模板

```cpp
#include <iostream>
using namespace std;

// 提交时注释下一行，关闭全部调试输出
#define DEBUG

#ifdef DEBUG
#define dbg(x) cerr << "[DEBUG] " << #x << " = " << (x) << endl
#else
#define dbg(x) do {} while (0)
#endif

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int a, b;
    cin >> a >> b;
    dbg(a);
    dbg(b);

    long long sum = 1LL * a + b;
    dbg(sum);

    cout << sum << '\n';
    return 0;
}
```

**使用要点：**

- 开发阶段打开 `DEBUG`，观察中间量；
- 正式提交关闭 `DEBUG`；
- 调试信息走 `cerr`，正式答案走 `cout`。

### 模板 2：变量追踪 / 顺序模拟模板

```cpp
#include <iostream>
#include <iomanip>
using namespace std;

// 打印一行变量状态，便于手算对照
void print_state(const char* step, int a, int b, int c) {
    cout << left << setw(12) << step
         << " a=" << setw(4) << a
         << " b=" << setw(4) << b
         << " c=" << setw(4) << c << endl;
}

int main() {
    int a = 3, b = 7, c = 4;
    print_state("init", a, b, c);

    a = b - a;
    print_state("a=b-a", a, b, c);

    b = c * a;
    print_state("b=c*a", a, b, c);

    c = b + a;
    print_state("c=b+a", a, b, c);

    cout << "final output: " << c << endl;  // 20
    return 0;
}
```

竞赛中保持「读入 / 处理 / 输出」分区，出错时更容易定位。

## ⚠️ 易错点

1. **调试输出忘记删除**  
   本地看结果没错，提交却 WA。原因往往是多打印了 `debug:` 或中间变量。  
   **对策**：用 `#ifdef DEBUG` 统一管理；提交前全文搜索 `DEBUG`、`cerr`、`cout << "debug`。

2. **局部变量未初始化就参与运算**  
   ```cpp
   int s;
   s = s + 10;   // s 的初值是垃圾值
   ```  
   **对策**：累加器写 `int s = 0;`，最值按题意初始化。

3. **把“报错行”当成“出错行”**  
   缺分号、缺括号时，编译器常在下一行报错。  
   **对策**：报错行附近上下各看 3~5 行。

4. **空语句导致“条件失效”**  
   ```cpp
   if (x > 0);
       cout << "positive\n";  // 总会执行
   ```  
   **对策**：if/for/while 后不要随手打分号。

5. **顺序赋值误用旧值/新值**  
   ```cpp
   a = b;
   b = a;   // 想交换？其实两个都变成原 b
   ```  
   **对策**：交换必须用临时变量（或标准算法 `swap`）。

6. **整数除法隐藏在复合表达式中**  
   ```cpp
   int a = 5;
   cout << a / 2 * 2;  // 结果是 4，不是 5
   ```  
   **对策**：读程时每遇到 `/` 先问“两边是不是都是整数”。

7. **中文标点与不可见字符**  
   从 PDF/网页复制样例代码时引入全角符号。  
   **对策**：标点全部用英文输入法重打关键符号。

## 📝 真题精练

### 题目1：多变量顺序追踪（读程）

**题目描述**：阅读下列程序，写出运行结果。

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 3, b = 7, c = 4;
    a = b - a;
    b = c * a;
    c = b + a;
    cout << c << endl;
    return 0;
}
```

**分析过程（变量追踪表）**：

| 步骤 | 语句 | a | b | c | 说明 |
|------|------|---|---|---|------|
| 0 | 初始 | 3 | 7 | 4 | |
| 1 | `a = b - a` | 4 | 7 | 4 | 7-3=4 |
| 2 | `b = c * a` | 4 | 16 | 4 | 4×4=16 |
| 3 | `c = b + a` | 4 | 16 | 20 | 16+4=20 |
| 4 | `cout << c` | | | | 输出 20 |

**答案**：`20`

**AC 验证代码：**

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 3, b = 7, c = 4;

    a = b - a;  // a = 4
    b = c * a;  // b = 16
    c = b + a;  // c = 20

    cout << c << endl;  // 20
    return 0;
}
```

**考点**：顺序赋值、新值覆盖旧值、读程制表。

### 题目2：交换变量并判断功能（读程 + 调试意识）

**题目描述**：下列程序运行后的输出是什么？它实现了什么功能？

```cpp
#include <iostream>
using namespace std;

int main() {
    int x = 15, y = 8;
    int t = x;
    x = y;
    y = t;
    cout << x << " " << y << endl;
    return 0;
}
```

**分析过程**：

1. 初始：`x=15, y=8`
2. `t = x` → `t=15`（保存原 x）
3. `x = y` → `x=8`
4. `y = t` → `y=15`
5. 输出：`8 15`

功能：用临时变量交换 `x` 与 `y`。

**答案**：`8 15`（两变量交换）

**AC 验证代码：**

```cpp
#include <iostream>
using namespace std;

int main() {
    int x = 15, y = 8;

    // 标准三步交换
    int t = x;
    x = y;
    y = t;

    cout << x << " " << y << endl;  // 8 15
    return 0;
}
```

**对比错误写法（调试案例）：**

```cpp
// 错误：没有临时变量
x = y;   // x 变成 8，原 15 丢失
y = x;   // y 也变成 8
// 结果: 8 8
```

**考点**：顺序执行下的数据覆盖、临时变量的必要性。

### 题目3（巩固）：带整数除法的顺序计算

**题目描述**：写出输出结果。

```cpp
#include <iostream>
using namespace std;

int main() {
    int a = 10, b = 3, c;
    c = a / b;
    a = a + c;
    b = a % b + c;
    cout << a << " " << b << " " << c << endl;
    return 0;
}
```

**分析：**

| 步骤 | 语句 | a | b | c |
|------|------|---|---|---|
| 初始 | | 10 | 3 | ? |
| `c=a/b` | | 10 | 3 | 3 | 整数除法 10/3=3 |
| `a=a+c` | | 13 | 3 | 3 | 10+3=13 |
| `b=a%b+c` | | 13 | 4 | 3 | 13%3+3=1+3=4 |

**答案**：`13 4 3`

## 🎯 本课小结

### 核心知识点回顾

| 知识点 | 要点 |
|--------|------|
| 顺序结构 | 默认自上而下逐条执行，后句依赖前句结果 |

### 考试建议

1. **读程题**：宁可慢，也要画变量表；心算容易在第 3、4 步串值。
2. **编程题 WA**：先删调试输出，再查样例与边界，再用 `cerr` 看中间量。
3. **CE**：先看报错信息关键词（semicolon / declared / token），再看上一行。
4. **养成习惯**：写完先手算一组数据，再运行对照；这就是最小成本的调试。
5. 下一课将进入 **if-else 分支**，顺序结构会被条件跳转改写——但读程制表的方法完全通用。
