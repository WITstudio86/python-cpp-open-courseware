## 📖 知识精讲

### 1. 什么是递归

递归（Recursion）是一种编程技巧，指的是一个函数在它的函数体内直接或间接地调用自身。递归这个名字本身就暗示了它的含义——「递」是传递、递推的过程，「归」是回归、返回的过程。就像你站在两面镜子中间，你会在镜子中看到无数个自己，每一个自己都在做相同的动作。

一种非常形象的比喻是**俄罗斯套娃**。打开一个套娃，里面有一个更小的套娃；再打开这个更小的套娃，里面还有一个更小的。这个过程一直持续，直到你遇到那个最小的、打不开的实心套娃为止。然后你开始逆向操作：把最小的放回次小的，次小的放回第三小的……最终恢复到最初那个最大的套娃。递归函数的工作原理与之如出一辙：不断地调用更小规模的自己，直到遇到不能再拆分的「原子问题」，然后逐层返回结果。

让我们从一个简单的递归倒计时程序来直观体会递归：

```cpp
#include <iostream>
using namespace std;

void countdown(int n) {
    if (n <= 0) {                   // 递归边界：不能再继续了
        cout << "发射！" << endl;
        return;
    }
    cout << n << " ";               // 递：输出当前数字
    countdown(n - 1);               // 递：把更小的子问题交给下一层
    cout << n << " ";               // 归：返回来时再输出一次
}

int main() {
    countdown(3);
    return 0;
}
// 输出：3 2 1 发射！1 2 3
```

这段代码的输出非常耐人寻味。「3 2 1 发射！」出现在「递」的阶段，函数不断调用自身，每次把 n 减 1，直到 n 变成 0 触发边界条件。而「1 2 3」出现在「归」的阶段，每一层调用结束后，执行调用点之后的代码。很多初学者会误以为递归函数调用完毕后就直接结束了，实际上，调用完毕后控制权会回到调用者的下一行代码继续执行——这个「归」的过程正是递归的精妙之处。

递归函数的核心优势在于它能够用简洁的代码表达具有自相似结构的问题。对于那些天然具有「大问题可以分解为结构相同的小问题」特性的场景，递归往往是最自然、最直观的解法。比如树的遍历、图的搜索、分治算法等，递归几乎是不可或缺的。

### 2. 递归三要素

任何一个正确的递归函数，都必须同时具备以下三个要素。缺一不可，否则要么无限递归导致栈溢出，要么得到错误结果。

**要素一：递归边界（Base Case）**

递归边界是递归函数的「出口」，是问题规模缩小到不能再小时直接返回的条件。没有递归边界，函数就会像一辆没有刹车的汽车，永远停不下来。在编写递归函数时，我们要问自己一个问题：问题的最小规模是什么？此时答案是多少？这个答案就是递归边界的返回值。

```cpp
// 递归边界示例
if (n == 0) return 1;       // 0的阶乘为1
if (n <= 1) return n;       // 斐波那契第0项为0，第1项为1
if (n <= 0) return;         // 倒计时到0就停止
```

**要素二：递归关系式（Recursive Relation）**

递归关系式描述了「大问题」和「小问题」之间的关系。它告诉我们，当前问题的答案可以通过哪些更小子问题的答案推导出来。这个关系式在数学上也称为「递推公式」。写代码时，我们需要把数学上的递推公式翻译成函数调用表达式。

```cpp
// 递归关系式示例
return n * factorial(n - 1);     // n! = n × (n-1)!
return fib(n - 1) + fib(n - 2);  // fib(n) = fib(n-1) + fib(n-2)
```

**要素三：参数变化方向（Parameter Convergence）**

每一次递归调用，参数都必须朝着递归边界的方向移动。换句话说，递归调用的参数必须比当前参数「更接近」边界条件。通常表现为参数不断减小（如 n-1、n-2），直到达到边界值。如果参数的变化方向偏离了边界（比如 n+1 而边界是 n==0），就会导致无限递归。

```cpp
// 正确的参数变化：向边界靠近
int factorial(int n) {
    if (n == 0) return 1;            // 边界
    return n * factorial(n - 1);     // 参数递减，向0靠近
}

// 错误的参数变化：背离边界
int bad(int n) {
    if (n == 0) return 1;
    return bad(n + 1);               // 参数递增，永远到不了0！
}
```

三个要素是一个有机的整体：边界决定了停止条件，关系式决定了计算逻辑，参数变化决定了程序能否终止。三个要素缺一不可，任何一个处理不当都会导致程序出错。

### 3. 阶乘的递归实现

阶乘是入门递归最经典的问题。n 的阶乘（记作 n!）定义为从 1 到 n 的所有整数的乘积。其数学定义为：

- 0! = 1（递归边界）
- n! = n × (n-1)! （递归关系）

我们先给出完整的 C++ 实现：

```cpp
#include <iostream>
using namespace std;

long long factorial(int n) {
    if (n == 0) return 1;                  // 递归边界
    return n * factorial(n - 1);            // 递归关系 + 参数递减
}

int main() {
    int n;
    cin >> n;
    cout << factorial(n) << endl;
    return 0;
}
```

现在我们来逐步追踪 `factorial(5)` 的执行过程，这是理解递归最关键的一步。我们用 ASCII 图来画调用栈（Call Stack）的变化：

```
【递的过程——逐层深入】
执行 factorial(5)
  │  5 * factorial(4)，factorial(4) 还没计算，需要等待
  │  执行 factorial(4)
  │    │  4 * factorial(3)，factorial(3) 还没计算
  │    │  执行 factorial(3)
  │    │    │  3 * factorial(2)，factorial(2) 还没计算
  │    │    │  执行 factorial(2)
  │    │    │    │  2 * factorial(1)，factorial(1) 还没计算
  │    │    │    │  执行 factorial(1)
  │    │    │    │    │  1 * factorial(0)，factorial(0) 还没计算
  │    │    │    │    │  执行 factorial(0)
  │    │    │    │    │    │  到达递归边界！n==0，直接返回 1
  │    │    │    │    │    │
【归的过程——逐层返回】
  │    │    │    │    │  ← factorial(0) 返回 1
  │    │    │    │    │  factorial(1) 计算：1 * 1 = 1，返回 1
  │    │    │    │    │
  │    │    │    │  ← factorial(1) 返回 1
  │    │    │    │  factorial(2) 计算：2 * 1 = 2，返回 2
  │    │    │    │
  │    │    │  ← factorial(2) 返回 2
  │    │    │  factorial(3) 计算：3 * 2 = 6，返回 6
  │    │    │
  │    │  ← factorial(3) 返回 6
  │    │  factorial(4) 计算：4 * 6 = 24，返回 24
  │    │
  │  ← factorial(4) 返回 24
  │  factorial(5) 计算：5 * 24 = 120，返回 120

最终结果：120
```

观察这个过程，你会发现一个有趣的事实：在「递」的阶段，没有任何一个函数能够计算出最终结果——它们都在「等待」更小规模问题的答案。只有当 `factorial(0)` 直接返回 1 后，等待链才被打破，「归」的阶段开始逐层计算并返回。理解这个「等待-返回」的机制，是掌握递归的第一道坎。

### 4. 斐波那契数列

斐波那契数列的定义本身就是一个递归定义：

- fib(0) = 0, fib(1) = 1
- fib(n) = fib(n-1) + fib(n-2)，其中 n ≥ 2

**实现一：朴素递归**

```cpp
#include <iostream>
using namespace std;

long long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

这个实现非常简洁，几乎是把数学定义直接翻译成了代码。但它有一个严重的性能问题：大量重复计算。以 fib(5) 为例，来看看函数调用的树形结构：

```
                  fib(5)
                 /      \
            fib(4)      fib(3)
           /     \      /     \
       fib(3)  fib(2) fib(2) fib(1)
       /    \   /   \   /   \
   fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
   /    \
fib(1) fib(0)
```

你会发现 fib(3) 被计算了 2 次，fib(2) 被计算了 3 次。随着 n 的增大，重复计算的数量呈指数增长。朴素的递归斐波那契的时间复杂度是 O(2^n)——这意味着计算 fib(50) 可能需要宇宙的寿命那么长！空间复杂度为 O(n)，这是递归调用栈的深度。

**实现二：记忆化搜索（Memoization）**

既然重复计算是问题的根源，我们可以用一个数组把已经计算过的结果「记住」，下次用到时直接查表即可。

```cpp
#include <iostream>
#include <vector>
using namespace std;

const int N = 100;
long long memo[N];  // 记忆数组，初始化为 -1 表示未计算

long long fib_memo(int n) {
    if (n <= 1) return n;                  // 递归边界
    if (memo[n] != -1) return memo[n];     // 如果已经算过，直接返回
    return memo[n] = fib_memo(n - 1) + fib_memo(n - 2);  // 算完后存起来
}

int main() {
    fill(memo, memo + N, -1);  // 初始化所有位置为 -1
    int n;
    cin >> n;
    cout << fib_memo(n) << endl;
    return 0;
}
```

加上记忆化后，每个 n 最多被计算一次，时间复杂度骤降至 O(n)，空间复杂度为 O(n)。这是一个巨大的飞跃——从指数到线性，让计算 fib(50) 变得瞬间完成。

**实现三：迭代（递推）**

从递归定义出发，我们也可以完全不用递归，从底向上递推计算：

```cpp
#include <iostream>
using namespace std;

long long fib_iter(int n) {
    if (n <= 1) return n;
    long long a = 0, b = 1, c;
    for (int i = 2; i <= n; i++) {
        c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

迭代版本的时间复杂度是 O(n)，空间复杂度是 O(1)——只用两个变量就搞定了。对于线性递推问题，迭代往往比递归更高效，因为递归存在函数调用开销和栈空间消耗。但递归代码更直观、更贴近数学定义。选择哪个取决于具体场景和你对代码可读性的要求。

### 5. 递归调用栈

理解递归调用栈（Call Stack）是学习递归的必经之路。每当一个函数被调用时，操作系统会在内存中为它分配一块称为「栈帧」（Stack Frame）的空间，用于存储该函数的局部变量、参数地址以及返回地址（即调用结束后应该回到哪里继续执行）。

递归函数的特点是会多次调用自身，每一次调用都会创建一个新的栈帧压入调用栈。栈是一种后进先出（LIFO）的数据结构，这正好匹配递归的执行模式——最后进入的调用最先返回。

让我们以 factorial(3) 为例，可视化调用栈的变化：

```
初始状态（main 调用 factorial(3)）：
┌────────────┐
│ factorial  │  ← 栈顶：当前执行的函数
│   n = 3    │
├────────────┤
│   main()   │  ← 栈底
└────────────┘

factorial(3) 调用 factorial(2)，新栈帧压入：
┌────────────┐
│ factorial  │
│   n = 2    │
├────────────┤
│ factorial  │
│   n = 3    │  等待 factorial(2) 返回
├────────────┤
│   main()   │
└────────────┘

factorial(2) 调用 factorial(1)，新栈帧压入：
┌────────────┐
│ factorial  │
│   n = 1    │
├────────────┤
│ factorial  │
│   n = 2    │
├────────────┤
│ factorial  │
│   n = 3    │
├────────────┤
│   main()   │
└────────────┘

factorial(1) 调用 factorial(0)，新栈帧压入：
┌────────────┐
│ factorial  │
│   n = 0    │  ← 到达边界，直接返回 1
├────────────┤
│ factorial  │
│   n = 1    │
├────────────┤
│ factorial  │
│   n = 2    │
├────────────┤
│ factorial  │
│   n = 3    │
├────────────┤
│   main()   │
└────────────┘

factorial(0) 返回，栈帧弹出。factorial(1) 拿到结果 1，计算 1*1=1，返回并弹出：
┌────────────┐
│ factorial  │
│   n = 2    │
├────────────┤
│ factorial  │
│   n = 3    │
├────────────┤
│   main()   │
└────────────┘

以此类推，栈帧逐层弹出，直到回到 main，调用栈为空。
```

栈帧的压入对应「递」的过程，栈帧的弹出对应「归」的过程。栈的大小取决于递归的深度。如果递归过深（比如递归层数达到几万甚至几十万），调用栈可能会溢出（Stack Overflow）——没错，那个著名的程序员问答网站的名字就是由此而来。在 C++ 中，默认的栈空间通常是几 MB，这意味着递归深度一般不应超过几万层。对于深度递归问题，可以考虑使用迭代或者手动模拟栈来避免栈溢出。

### 6. 递归与迭代对比

递归和迭代（循环）是解决问题的两种基本方式。它们各有所长，没有绝对的优劣之分。

| 对比维度 | 递归 | 迭代 |
|----------|------|------|
| 代码简洁性 | 代码精炼，与数学定义高度一致 | 需要手动维护循环变量和状态 |
| 可读性 | 对于具有自相似结构的问题非常直观 | 对于简单线性问题更直观 |
| 时间复杂度 | 朴素递归可能产生指数级复杂度 | 通常为 O(n) |
| 空间复杂度 | O(n)（调用栈深度） | 通常 O(1) |
| 栈溢出风险 | 深度递归可能导致栈溢出 | 无调用栈，无此风险 |
| 适用场景 | 树、图的遍历，分治，回溯 | 简单线性递推，遍历数组 |

选择指南：如果问题的结构天然是递归的（例如树的深度优先遍历、快速排序、归并排序、汉诺塔），用递归写出来的代码往往比迭代版本清晰得多。如果只是一个简单的线性递推（如阶乘、斐波那契），迭代通常更高效。如果递归深度过大（超过 10^5 层），应当避免使用递归。如果在赛事中需要权衡代码正确性和性能，优先保证正确性——写对的递归远比写错的迭代好。

### 7. 递归思维训练

学习递归最难的地方往往不是语法，而是思维方式。初学者习惯于用循环的眼光看世界，让他们用「自己调用自己」的方式来思考，需要一次思维模式的转变。以下几个练习可以帮助你培养递归思维：

**第一步：寻找自相似结构。** 面对一个问题时，问自己：这个问题能否分解为规模更小的同类子问题？如果可以，那么递归就有了用武之地。例如：求数组的和 = 第一个元素 + 剩余元素的和；反转字符串 = 最后一个字符 + 剩余部分的反转；求最大公约数 = gcd(b, a % b)。

**第二步：确定最小子问题的答案。** 也就是说，当问题规模小到不能再分时，答案是什么？这就是递归边界。数组为空时和为 0，字符串为空时反转也是空字符串，gcd(a, 0) = a。

**第三步：写出递推关系式。** 用数学语言（或伪代码）描述「当前答案」与「子问题答案」之间的关系。这个过程就是找递归关系式。

**第四步：假设子问题已被正确求解。** 这是递归思维中最关键的一种「信念」——在编写递归代码时，你要假设 `f(n-1)` 已经正确地返回了问题的解。你不需要去想 `f(n-1)` 内部是怎么做的，你只需要关心「如果 `f(n-1)` 是对的，那么 `f(n)` 应该怎么算」。这种「信任子调用」的心态能帮助你从无限嵌套的细节中跳出来，专注于当前这一层逻辑。

**第五步：验证参数收敛。** 确保每一次递归调用都让问题规模减小，最终一定会到达边界条件。

举个例子：求一个正整数 n 的各位数字之和。自相似结构：n 的数字之和 = n 的最后一位 + (n 去掉最后一位后的数字之和)。边界：n < 10 时，数字和就是 n 本身。递推式：digitSum(n) = (n % 10) + digitSum(n / 10)。验证收敛：每次 n 除以 10，位数减少 1，最终 n 会变成一位数，触发边界。代码顺理成章：

```cpp
int digitSum(int n) {
    if (n < 10) return n;
    return (n % 10) + digitSum(n / 10);
}
```

一旦你熟练掌握了这种五步思维法，递归就不再神秘，而是变成了一种自然的问题分解工具。

## 💻 代码模板

### 模板1：阶乘（递归 + 迭代）

```cpp
#include <iostream>
using namespace std;

// 方法一：递归实现
// 时间复杂度 O(n)，空间复杂度 O(n)（调用栈深度）
long long factorial_recursive(int n) {
    if (n == 0) return 1;                  // 递归边界：0! = 1
    return n * factorial_recursive(n - 1); // 递归关系：n! = n * (n-1)!
}

// 方法二：迭代实现
// 时间复杂度 O(n)，空间复杂度 O(1)
long long factorial_iterative(int n) {
    long long result = 1;
    for (int i = 1; i <= n; i++) {
        result *= i;
    }
    return result;
}

int main() {
    int n;
    cout << "请输入 n（n <= 20，避免溢出）：";
    cin >> n;
    cout << "递归结果：" << factorial_recursive(n) << endl;
    cout << "迭代结果：" << factorial_iterative(n) << endl;
    return 0;
}
```

### 模板2：斐波那契（三种实现）

```cpp
#include <iostream>
#include <cstring>
using namespace std;

const int MAXN = 100;
long long memo[MAXN];

// 方法一：朴素递归
// 时间复杂度 O(2^n)，空间复杂度 O(n)
// 缺点：大量重复计算，n > 40 就非常慢了
long long fib_naive(int n) {
    if (n <= 1) return n;
    return fib_naive(n - 1) + fib_naive(n - 2);
}

// 方法二：记忆化递归（自顶向下）
// 时间复杂度 O(n)，空间复杂度 O(n)
// 优点：代码结构类似朴素递归，但无重复计算
long long fib_memo(int n) {
    if (n <= 1) return n;                  // 递归边界
    if (memo[n] != -1) return memo[n];     // 已计算，直接查表
    return memo[n] = fib_memo(n - 1) + fib_memo(n - 2);  // 计算并存储
}

// 方法三：迭代递推（自底向上）
// 时间复杂度 O(n)，空间复杂度 O(1)
// 优点：无递归开销，最优的空间效率
long long fib_iterative(int n) {
    if (n <= 1) return n;
    long long a = 0, b = 1, c;
    for (int i = 2; i <= n; i++) {
        c = a + b;  // fib(i) = fib(i-1) + fib(i-2)
        a = b;      // a 变为下一轮的 fib(i-2)
        b = c;      // b 变为下一轮的 fib(i-1)
    }
    return b;
}

int main() {
    memset(memo, -1, sizeof(memo));  // 初始化记忆数组

    int n;
    cout << "请输入 n（n <= 90，避免溢出）：";
    cin >> n;

    if (n <= 40) {
        cout << "朴素递归：fib(" << n << ") = " << fib_naive(n) << endl;
    } else {
        cout << "朴素递归：n 过大，跳过（太慢了）" << endl;
    }
    cout << "记忆化递归：fib(" << n << ") = " << fib_memo(n) << endl;
    cout << "迭代递推：fib(" << n << ") = " << fib_iterative(n) << endl;
    return 0;
}
```

## ⚠️ 易错点

### 易错点1：忘记写递归边界

这是最常见的递归错误。没有边界的递归函数会无限调用自身，直到栈溢出。

```cpp
// 错误代码：没有递归边界
int factorial_wrong(int n) {
    return n * factorial_wrong(n - 1);  // 永远也不会停！
}

// 正确代码：先写边界
int factorial_correct(int n) {
    if (n == 0) return 1;               // 边界在前
    return n * factorial_correct(n - 1);
}
```

**解决方法：** 编写任何递归函数时，第一行就写边界条件。养成「先写出口，再写逻辑」的习惯。

### 易错点2：参数未向边界收敛

即使写了边界条件，如果递归调用时参数没有向边界靠拢，仍然会死循环。

```cpp
// 错误代码：参数远离边界（n 越来越大，永远到不了 0）
int wrong_converge(int n) {
    if (n == 0) return 1;
    return n * wrong_converge(n + 1);   // 应该是 n - 1！
}

// 另一个常见错误：在错误的方向上递归
int wrong_direction(int n) {
    if (n > 100) return n;              // 边界是 n > 100
    return wrong_direction(n - 1);      // n 在减小，永远到不了 > 100！
}
```

**解决方法：** 明确参数的变化方向，确保每一步都会离边界更近。可以用纸笔手动模拟两三步来验证。

### 易错点3：递归返回值未正确传递

初学者容易在递归调用后忘记把返回值继续向上返回，导致最外层拿到的是不确定的值。

```cpp
// 错误代码：递归调用的返回值没有被返回
int factorial_wrong(int n) {
    if (n == 0) return 1;
    factorial_wrong(n - 1);             // 调用了，但返回值被丢弃！
    // 函数没有 return 语句，返回的是未定义的值
}

// 另一种错误：返回了，但没有关联当前层的结果
int factorial_wrong2(int n) {
    if (n == 0) return 1;
    n * factorial_wrong2(n - 1);        // 算了但没 return
}

// 正确代码
int factorial_correct(int n) {
    if (n == 0) return 1;
    return n * factorial_correct(n - 1);
}
```

**解决方法：** 调用递归函数后，一定要用 `return` 把计算结果（或基于它的运算结果）返回给上一层。如果你的编译器开启了 -Wall 警告，会提示「control reaches end of non-void function」。

### 易错点4：递归深度过大导致栈溢出

C++ 默认的栈空间约为 8MB（Windows 下通常只有 1~2MB），意味着递归深度过大时会触发栈溢出（Stack Overflow / Segmentation Fault）。

```cpp
// 错误场景：递归 10 万层，大概率栈溢出
void dfs_wrong(int n) {
    if (n == 0) return;
    dfs_wrong(n - 1);
}

int main() {
    dfs_wrong(100000);  // 栈溢出！程序崩溃
    return 0;
}
```

**解决方法：**
- 如果递归深度可能超过几千层，改用迭代写法。
- 对于必须用递归的深度搜索问题（如树、图），检查数据范围。如果数据范围允许递归，则放心使用；否则考虑手动用 `stack` 容器模拟递归。
- 在 Windows 平台，可以在编译时使用 `-Wl,--stack,16777216` 来增大栈空间（例如增大到 16MB）。但这不是通用方案，比赛中慎用。
- 将递归改写为「尾递归」形式（某些编译器会优化，但 C++ 标准不保证）。

## 📝 真题精练

### 题目1：递归求和

**题目描述：**
给定一个正整数 n（1 ≤ n ≤ 10000），请使用递归函数计算 1 + 2 + 3 + … + n 的值。要求必须使用递归实现，不得使用循环或等差数列公式。

**输入格式：**
一行一个正整数 n。

**输出格式：**
一行一个整数，表示 1 到 n 的和。

**样例1：**
输入：
```
5
```
输出：
```
15
```
解释：1 + 2 + 3 + 4 + 5 = 15。

**样例2：**
输入：
```
100
```
输出：
```
5050
```
解释：1 到 100 的和，经典的高斯求和。

**AC 代码：**

```cpp
#include <iostream>
using namespace std;

// 递归求和：sum(n) = n + sum(n-1)，边界 sum(1) = 1
long long sum_recursive(int n) {
    if (n == 1) return 1;                   // 递归边界
    return n + sum_recursive(n - 1);        // 递推关系
}

int main() {
    int n;
    cin >> n;
    cout << sum_recursive(n) << endl;
    return 0;
}
```

**复杂度分析：**
- 时间复杂度：O(n)，共递归调用 n 层，每层执行 O(1) 运算。
- 空间复杂度：O(n)，递归调用栈深度为 n。

**思考题：** 如果 n 达到 100000，这段代码还能正常运行吗？为什么？应该怎么解决？（提示：考虑递归深度与栈溢出，以及用迭代改写。）

### 题目2：递归求数字位数

**题目描述：**
给定一个正整数 n（1 ≤ n ≤ 10^9），请使用递归函数计算 n 的十进制位数。例如 12345 的位数为 5，100 的位数为 3。要求必须使用递归实现。

**输入格式：**
一行一个正整数 n。

**输出格式：**
一行一个整数，表示 n 的十进制位数。

**样例1：**
输入：
```
12345
```
输出：
```
5
```
解释：12345 是一个五位数。

**样例2：**
输入：
```
100
```
输出：
```
3
```
解释：100 是一个三位数，注意前导 0 不计入位数，但输入保证是正整数，无前导 0。

**AC 代码：**

```cpp
#include <iostream>
using namespace std;

// 递归求位数：digitCount(n) = 1 + digitCount(n/10)，边界 n < 10 时返回 1
int digitCount(int n) {
    if (n < 10) return 1;                   // 递归边界：一位数
    return 1 + digitCount(n / 10);          // 递推关系：去掉最后一位，位数加 1
}

int main() {
    int n;
    cin >> n;
    cout << digitCount(n) << endl;
    return 0;
}
```

**复杂度分析：**
- 时间复杂度：O(log n)，每次递归 n 缩小为原来的十分之一，递归深度等于 n 的位数。
- 空间复杂度：O(log n)，递归调用栈深度等于 n 的位数，对于 n ≤ 10^9 最多 10 层，完全不会栈溢出。

**变式思考：** 如果题目要求计算二进制中 1 的个数，递归边界和递推关系应该如何修改？（提示：边界 n == 0 返回 0；递推关系 (n & 1) + countOne(n >> 1)。）

## 🎯 本课小结

- 递归是函数调用自身的编程技巧，包含「递」（深入）和「归」（返回）两个阶段
- 递归三要素：递归边界（终止条件）、递归关系式（递推公式）、参数收敛（向边界趋近）——三者缺一不可
- 阶乘是递归的经典入门例题：边界 0! = 1，关系式 n! = n × (n-1)!
- 斐波那契的朴素递归时间复杂度高达 O(2^n)，通过记忆化搜索可优化至 O(n)，迭代版本更可达到 O(1) 空间
- 递归调用栈是理解递归的关键：每次调用压入一个栈帧，返回时弹出；深度过大可能导致栈溢出
- 递归与迭代各有优劣：递归代码简洁直观，适合树/图/分治等结构化问题；迭代高效且无栈溢出风险
- 培养递归思维的五步法：找自相似结构 → 定最小子问题答案 → 写递推关系式 → 信任子调用 → 验证参数收敛
- 编写递归函数时，边界条件永远放在最前面，确保每次递归让问题规模减小，返回值必须正确传递
