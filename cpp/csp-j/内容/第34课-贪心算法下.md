## 📖 知识精讲

### 一、排序 + 贪心组合策略

在上一课中，我们看到活动选择、排队接水等问题都遵循一个共同的模式：**先排序，再贪心**。这个模式是 CSP-J 考试中贪心算法最主流的考察形式，也是解决大部分贪心问题的通用框架。

**排序 + 贪心的标准流程**：

```
输入数据 → 按某种属性排序（关键步骤）→ 依次处理（贪心选择）→ 输出结果
```

排序的目的在于**把所有候选方案按照一定的优先级排列**，然后我们就可以放心地从优先级最高的方案开始选择，不必回头考虑。这就是"贪心"二字的本质——排序替我们完成了"当前最优"的判断。

常见的排序标准有以下几种：

1. **按数值大小排序**（升序/降序）：适用于排队接水（升序，短作业优先）、最优装载（升序，轻的物品优先装）。
2. **按区间端点排序**：适用于活动选择（按结束时间升序）、区间覆盖（按开始时间升序）。
3. **按比值/性价比排序**：适用于部分背包问题。虽然 CSP-J 考纲中没有完全背包，但"按性价比排序"的思想是通用的。
4. **无需排序，直接使用堆（priority_queue）**：适用于需要动态维护最小（或最大）元素的场景，如合并果子、数据流中的中位数等。

**为什么排序能简化贪心的正确性证明？**

假设我们按属性 P 升序排序后进行贪心选择。如果存在一个最优解，且该解中第一个选择的元素不是 P 最小的，我们可以将最优解中 P 最小的元素与第一个选择的元素交换位置——由于 P 更小意味着"更优"（或至少不更差），交换后不会使解变差。因此，P 最小的元素一定属于某个最优解。这种证明方法称为"交换论证法"（Exchange Argument），是贪心证明的核心工具。

**注意**：并非所有的贪心问题都需要排序。例如硬币找零问题中，面额数组天然就是有序的（从大到小）。但绝大多数 CSP-J 级别的贪心问题都会涉及排序步骤。

让我们通过一个综合示例来巩固排序+贪心的思维模式。考虑"最优装载问题"：有 n 个物品，每个物品重量为 w[i]，船的最大载重为 C。求最多能装多少个物品。贪心策略是：按重量升序排序，从最轻的装到最重的，直到总重量超过 C。这个策略之所以正确，是因为如果最优解中装了一个较重的物品而非一个较轻的物品，我们可以用较轻的物品替换它（不增加总重量还可能减少），从而得到同样多或更多的物品数量。

### 二、哈夫曼编码思想与合并果子问题

**哈夫曼编码**是一种用于数据压缩的经典算法，由 David Huffman 在 1952 年提出。其核心思想十分朴素：**出现频率越高的字符，编码越短；出现频率越低的字符，编码越长**。这样可以使得编码后的总长度最小。

哈夫曼编码的构造过程使用了一种典型的贪心策略：**每次从待处理的权值集合中取出最小的两个，将它们合并为一个新的节点（新节点的权值为两子节点权值之和），并将新节点放回集合**。重复此过程直到集合中只剩下一个节点。这个不断合并最小元素的过程，在 CSP-J 中对应着经典的**"合并果子"问题**。

**合并果子问题描述**：

有 n 堆果子，第 i 堆有 a_i 个果子。每次可以选择两堆果子合并为一堆，合并的代价为两堆果子数量之和。求将所有果子合并为一堆的最小总代价。

**为什么贪心是正确的？**

考虑合并过程中的第一次合并：如果我们选择最小的两堆合并，可以证明总代价不会比选择其他两堆合并更大。直觉上，较早合并的果堆会在后续的合并中被多次计入代价——越小的堆越应该被"多次合并"（即较早合并），以减少累计代价。

更严格的证明思路如下：假设最优解中第一次合并了 a 和 b（不是最小的两堆），而最小的两堆是 x 和 y。由于 x ≤ a 且 y ≤ b，所以 x + y ≤ a + b。如果将 a 和 b 替换为 x 和 y 作为第一次合并，总代价不会增加。通过归纳法可以证明，每次选最小的两个合并总能得到最优解。

**实现方法：使用优先队列（小根堆）**

由于每次需要动态地获取最小的两个元素并插入新元素，使用 `priority_queue<int, vector<int>, greater<int>>`（小根堆）是最佳选择。STL 的 priority_queue 默认是大根堆，若要使用小根堆，需要指定比较器为 `greater<int>`。

合并果子的核心代码如下：

```cpp
priority_queue<int, vector<int>, greater<int>> pq;  // 小根堆
for (int i = 0; i < n; i++) {
    int x; cin >> x;
    pq.push(x);
}

long long totalCost = 0;
while (pq.size() > 1) {
    int a = pq.top(); pq.pop();    // 取最小
    int b = pq.top(); pq.pop();    // 取第二小
    int sum = a + b;               // 合并代价
    totalCost += sum;
    pq.push(sum);                  // 新堆放回队列
}
cout << totalCost << endl;
```

这个算法的时间复杂度为 O(n log n)，其中每次推送/弹出堆顶元素的时间为 O(log n)，共执行约 n 次合并操作。空间复杂度为 O(n)（堆的大小）。

**合并果子与 dp 石子合并的区别**：

需要与区间 DP 中的"石子合并"问题区分。合并果子允许任意选择两堆合并（不要求相邻），因此使用贪心（哈夫曼编码思想）即可。而石子合并问题要求合并相邻的两堆，不满足贪心选择性质，必须使用区间 DP。二者的区别在于：合并果子是**全局选择**（任意两堆），石子合并是**局部选择**（只能相邻），前者可用贪心，后者必须 DP。

**优先队列的三种声明方式**：

```cpp
// 1. 大根堆（默认）：priority_queue<int> pq;
// 2. 小根堆（方式一）：priority_queue<int, vector<int>, greater<int>> pq;
// 3. 小根堆（方式二，取负值）：priority_queue<int> pq; pq.push(-x);
```

在 CSP-J 考试中，建议使用方式一（显式小根堆），代码清晰不易出错。方式三虽然写法简洁，但要注意负数处理和 int 溢出风险。

### 三、删数问题

**问题描述**：给定一个 n 位正整数（可能很大，以字符串形式给出），从中删除 k 个数字（k < n），使剩余的数字按原顺序组成的正整数最小。输出这个最小的剩余整数（需去除前导零）。

**贪心策略**：从左到右扫描每一位数字，如果当前数字比它右边的数字大，则删除当前数字（即删除"山峰"——第一个下降沿之前的顶点）。重复这个过程 k 次。如果扫描完一轮都找不到"山峰"（即整个序列是非递减的），则删除最后一个数字。

**为什么这个策略有效？**

考虑两个相邻的数字位置 i 和 i+1：
- 如果 a[i] > a[i+1]，删除 a[i] 会使剩余的数变小（高位变小了）
- 如果 a[i] ≤ a[i+1]，保留 a[i] 更好，因为 a[i] 不比 a[i+1] 大

因此，第一次应该删除最左边的"山峰"位置（满足 a[i] > a[i+1]），删除后相当于该位置被右边更小的数字取代，整个数变小了。重复这个过程 k 次即可。

**算法优化：单调栈**

朴素的实现需要扫描 k 轮，时间复杂度为 O(kn)。当 k 和 n 都很大时（如 n ≤ 10^5），可以使用**单调栈**优化到 O(n)：

维护一个单调递增栈，遍历每个数字时，如果栈顶元素大于当前数字且还有删除名额（k > 0），则弹出栈顶。遍历完成后，如果 k > 0，从末尾继续删除。最后处理前导零并输出结果。

单调栈版本的代码模板如下：

```cpp
string removeKdigits(string num, int k) {
    string stk;  // 用 string 模拟栈
    for (char c : num) {
        while (!stk.empty() && stk.back() > c && k > 0) {
            stk.pop_back();
            k--;
        }
        stk.push_back(c);
    }
    // 如果 k 还有剩余，从末尾删除
    while (k > 0 && !stk.empty()) {
        stk.pop_back();
        k--;
    }
    // 去除前导零
    int start = 0;
    while (start < stk.size() && stk[start] == '0') start++;
    if (start == stk.size()) return "0";
    return stk.substr(start);
}
```

这个单调栈解法是 CSP-J 考试中的高频考点，必须熟练掌握。关键点在于：单调栈中维护的是一个**非递减序列**，每次遇到一个比栈顶小的数字时，如果还有删除名额，就删除栈顶（即删除一个"山峰"）。

### 四、最优装载问题

**问题描述**：有 n 个物品，每个物品重量为 w[i]（物品不可分割），以及一艘载重上限为 C 的船。求最多能装多少个物品上船。

**贪心策略**：按重量从小到大排序，依次装载，直到不能继续装入为止。

这是最简单的贪心问题之一。因为每个物品的"价值"等同（都是"1个物品"），所以重量越轻的物品"性价比"越高——用最少的载重换取 1 个物品。排序后依次装入即可。

**为什么不用考虑 DP？** 因为每个物品的"价值"都一样（都是 1），我们只需要最大化数量，而不需要考虑"不同价值"的情况。如果物品有不同的价值（即 0-1 背包问题），则必须使用 DP，因为此时贪心策略（按性价比排序）无法保证全局最优。

```cpp
sort(w, w + n);  // 按重量升序排序
int count = 0;
long long sum = 0;  // 注意用 long long
for (int i = 0; i < n; i++) {
    if (sum + w[i] <= C) {
        sum += w[i];
        count++;
    } else {
        break;  // 后面的更重，更不可能装入
    }
}
cout << count << endl;
```

时间复杂度 O(n log n)，空间复杂度 O(1)（不计输入数组）。注意总重量可能超过 int 范围，需要使用 `long long`。

### 五、贪心算法与动态规划的对比与选择

这是 CSP-J 考试中非常重要的一个判断能力：**给定一个问题，应该用贪心还是 DP 来解？**

| 对比维度 | 贪心算法 | 动态规划 |
|---------|---------|---------|
| 选择方式 | 每步选当前最优，决策不可撤销 | 考虑所有可能的子问题，记录每个状态的最优解 |
| 正确性保证 | 需要额外证明（不一定最优） | 数学上保证最优（只要状态定义正确） |
| 时间复杂度 | 通常 O(n log n) 或 O(n) | 通常 O(n²) 到 O(n³)，有时更高 |
| 空间复杂度 | 通常 O(1) 或 O(n) | 通常 O(n) 到 O(n²) |
| 适用条件 | 贪心选择性质 + 最优子结构 | 最优子结构 + 子问题重叠 |
| CSP-J 典型题 | 活动选择、合并果子、最优装载 | 01背包、LIS、数字三角形 |

**选择贪心还是 DP 的判断流程图**：

```
给定一个问题
    ↓
数据范围 n ≤ 20？ → 是 → 直接用回溯/枚举（保证正确）
    ↓ 否
能想到一个"看起来合理"的贪心策略？
    ↓ 是
能构造出反例吗？
    ↓ 否（找不到反例）
用样例验证，答案正确？
    ↓ 是
使用贪心！O(n log n)
    
    如果找不到贪心策略，或者找到了反例，
    或者样例不通过 → 使用 DP
```

**具体判断技巧**：

1. **看问题是否具有"不可分割性"**：0-1 背包中物品不能分割，贪心失效，必须 DP。而部分背包（物品可分割，虽然 CSP-J 不考）就可以用贪心。

2. **看选择是否有"顺序约束"**：合并果子没有顺序约束，可用贪心；石子合并要求相邻，必须 DP。

3. **看是否有"性价比"概念**：最优装载中所有物品价值相同，贪心有效；0-1 背包中价值不同，贪心失效。

4. **看数据范围**：如果 n 很大（如 10^5），DP 的 O(n²) 可能超时，贪心 O(n log n) 是唯一选择。此时贪心策略可能非常隐蔽，需要仔细思考。

5. **"删数问题"的启示**：删数问题看起来像"选择保留哪些数字"（类似组合优化），但实际可以用贪心（单调栈）解决。这说明某些看似需要 DP 的问题，实际存在巧妙的贪心策略。

**实战策略**：在 CSP-J 复赛中，如果有明确的贪心策略且通过样例，优先使用贪心（代码简洁不易出错）。如果不确定贪心是否正确，或者数据范围允许 DP，使用 DP 更安全——毕竟"正确的 DP 胜过不确定的贪心"。

## 💻 代码模板

### 模板一：合并果子（哈夫曼编码 / 小根堆）

```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    cin >> n;
    
    // 小根堆：priority_queue<类型, 容器, 比较器>
    priority_queue<int, vector<int>, greater<int>> pq;
    
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        pq.push(x);
    }
    
    long long totalCost = 0;  // 注意用 long long 防溢出
    
    while (pq.size() > 1) {
        int a = pq.top(); pq.pop();
        int b = pq.top(); pq.pop();
        int sum = a + b;
        totalCost += sum;
        pq.push(sum);
    }
    
    cout << totalCost << endl;
    return 0;
}
```

### 模板二：删数问题（单调栈优化版）

```cpp
#include <iostream>
#include <string>
using namespace std;

string removeKdigits(string num, int k) {
    string stk;  // 用 string 模拟单调栈
    
    for (char c : num) {
        // 栈顶 > 当前数字，且还有删除名额 → 弹栈

            stk.pop_back();
            k--;
        }
        stk.push_back(c);
    }
    
    // 如果 k 还有剩余（整个序列已是非递减的），从末尾删除
    while (k > 0 && !stk.empty()) {
        stk.pop_back();
        k--;
    }
    
    // 去除前导零
    int start = 0;
    while (start < (int)stk.size() && stk[start] == '0') {
        start++;
    }
    
    if (start == (int)stk.size()) {
        return "0";  // 全为零
    }
    
    return stk.substr(start);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string num;
    int k;
    cin >> num >> k;
    
    cout << removeKdigits(num, k) << endl;
    return 0;
}
```

### 模板四：删数问题（朴素版，用于理解原理）

```cpp
#include <iostream>
#include <string>
using namespace std;

// 朴素版：逐次删除"山峰"
string removeKdigitsSimple(string num, int k) {
    for (int t = 0; t < k; t++) {
        bool found = false;
        for (int i = 0; i < (int)num.size() - 1; i++) {
            if (num[i] > num[i + 1]) {  // 找到"山峰"
                num.erase(i, 1);        // 删除第i位
                found = true;
                break;
            }
        }
        if (!found) {
            num.pop_back();  // 整个序列非递减，删末尾
        }
    }
    
    // 去除前导零
    int start = 0;
    while (start < (int)num.size() && num[start] == '0') start++;
    if (start == (int)num.size()) return "0";
    return num.substr(start);
}

int main() {
    string num;
    int k;
    cin >> num >> k;
    cout << removeKdigitsSimple(num, k) << endl;
    return 0;
}
```

## ⚠️ 易错点

- **易错点1：合并果子中使用大根堆而非小根堆。** STL 的 `priority_queue` 默认是大根堆，如果直接声明 `priority_queue<int> pq`，每次取出的将是最大值而非最小值，导致答案错误。务必声明为 `priority_queue<int, vector<int>, greater<int>> pq;` 来使用小根堆。考试时如果忘记语法，可以使用"取负值"的技巧：每次 push 时传入负数，pop 后取绝对值。

- **易错点2：删数问题未处理前导零。** 删除 k 位数字后，剩余的数字可能有前导零（如 "10200" 删 1 位得到 "0200"）。必须去除前导零，且当结果为空字符串时要输出 "0"。很多同学忘记处理前导零或边界情况导致 WA。

- **易错点3：删数问题中 k 的剩余处理。** 使用单调栈优化后，如果整个字符串遍历完毕但 k 仍大于 0（说明原序列是非递减的，如 "12345"，一个山峰都没有），应直接从末尾删除剩余的 k 位。忘记这一步会导致错误。

- **易错点4：最优装载的数据溢出。** 物品重量 w[i] 最高可达 10^9，n 可达 10^5，总重量累计可达 10^14，远超 int 范围。务必使用 `long long` 来存储累计总重量，否则会发生溢出发导致判断错误。

- **易错点5：贪心与 DP 的混淆。** 合并果子问题是贪心（任意合并），石子合并是区间 DP（只能合并相邻的）。两种问题描述相似但解法完全不同。在 CSP-J 考试中，一定要仔细阅读题目条件，确认是否有"相邻"的约束。切勿看到"合并"二字就直接套用合并果子的模板。

- **易错点6：删数问题的单调栈方向错误。** 删数问题中的"山峰"是指 `num[i] > num[i+1]`，即前一个大于后一个时删除前一个。有些同学会错误地删除 `num[i] < num[i+1]` 的情况（即删"山谷"），这会使剩余数字变大。记住口诀："遇山删峰，让后面的小数字提前"。

### 题目一：合并果子（CSP-J 真题风格）

**【题目描述】**
在一个果园里，多多已经将所有的果子打了下来，而且按果子的不同种类分成了 n 堆，第 i 堆有 a_i 个果子。多多决定把所有的果子合成一堆。

每一次合并，多多可以把两堆果子合并到一起，消耗的体力等于两堆果子的重量之和。可以看出，所有的果子经过 n-1 次合并之后，就只剩下一堆了。多多在合并果子时总共消耗的体力等于每次合并所耗体力之和。

因为还要花大力气把这些果子搬回家，所以多多在合并果子时要尽可能地节省体力。假定每个果子重量都为 1，请你设计一个合并次序方案，使多多耗费的体力最少，并输出这个最小的体力耗费值。

**【输入格式】**
第一行一个整数 n（1 ≤ n ≤ 10000），表示果子的堆数。
第二行 n 个整数 a_i（1 ≤ a_i ≤ 20000），表示每堆果子的数量。

**【输出格式】**
输出一个整数，表示最小的体力耗费值。

**【样例输入】**
```
3
1 2 9
```

**【样例输出】**
```
15
```

**【样例解释】**
方案一：先合并 1 和 2（体力 3），再合并 3 和 9（体力 12），总体力 = 3 + 12 = 15。
方案二：先合并 2 和 9（体力 11），再合并 1 和 11（体力 12），总体力 = 11 + 12 = 23。
最优方案为方案一，耗费 15 体力。

**【AC 代码】**
```cpp
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    int n;
    cin >> n;
    
    // 小根堆
    priority_queue<int, vector<int>, greater<int>> pq;
    
    for (int i = 0; i < n; i++) {
        int x;
        cin >> x;
        pq.push(x);
    }
    
    long long totalCost = 0;
    
    while (pq.size() > 1) {
        int a = pq.top(); pq.pop();
        int b = pq.top(); pq.pop();
        int sum = a + b;
        totalCost += sum;
        pq.push(sum);
    }
    
    cout << totalCost << endl;
    return 0;
}
```

### 题目二：删数问题（CSP-J 真题风格）

**【题目描述】**
键盘输入一个高精度的正整数 n（不超过 250 位），去掉其中任意 k 个数字后剩下的数字按原左右次序将组成一个新的非负整数。编程对给定的 n 和 k，寻找一种方案使得剩下的数字组成的新数最小。

**【输入格式】**
第一行输入一个高精度正整数 n（以字符串形式给出，长度不超过 250）。
第二行输入一个整数 k（0 < k < n 的长度）。

**【输出格式】**
输出一个整数，表示删除 k 个数字后最小的剩余整数。如果结果是 0，输出 0。注意无需输出前导零。

**【样例输入】**
```
175438
4
```

**【样例输出】**
```
13
```

**【样例解释】**
删除 4 个数字的过程（朴素版逐步删除"山峰"）：
原数：175438
第1次删 7（1[7]5438 中7 > 5）→ 15438
第2次删 5（1[5]438 中5 > 4）→ 1438
第3次删 4（1[4]38 中4 > 3）→ 138
第4次删 8（13[8] 中8 > 末尾？序列非递减，删末尾）→ 13
最终结果：13

**【AC 代码】**
```cpp
#include <iostream>
#include <string>
using namespace std;

string removeKdigits(string num, int k) {
    string stk;
    
    for (char c : num) {
        while (!stk.empty() && stk.back() > c && k > 0) {
            stk.pop_back();
            k--;
        }
        stk.push_back(c);
    }
    
    // 删除剩余的 k 位
    while (k > 0 && !stk.empty()) {
        stk.pop_back();
        k--;
    }
    
    // 去除前导零
    int start = 0;
    while (start < (int)stk.size() && stk[start] == '0') {
        start++;
    }
    
    if (start == (int)stk.size()) {
        return "0";
    }
    
    return stk.substr(start);
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(0);
    
    string num;
    int k;
    cin >> num >> k;
    
    cout << removeKdigits(num, k) << endl;
    return 0;
}
```

## 🎯 本课小结

- **排序 + 贪心**是 CSP-J 中最主流的贪心考题模式，核心步骤为：分析排序标准 → 排序 → 一次遍历选择
- **合并果子问题**使用哈夫曼编码思想，每次取最小的两个合并，用 `priority_queue`（小根堆）实现，时间复杂度 O(n log n)
- **删数问题**的贪心策略是"删除第一个山峰"（`num[i] > num[i+1]` 则删除 num[i]），可用单调栈优化到 O(n)
- **最优装载问题**是最简单的贪心问题之一，按重量升序排序后依次装载，注意累计重量使用 `long long` 防溢出
- **贪心 vs DP 的判断流程**：先看数据范围，尝试设计贪心策略并构造反例，如果找不到反例且通过样例则使用贪心；如果贪心不确定或数据范围允许，使用 DP 更稳妥
- 优先队列的三种声明方式：大根堆（默认）、小根堆（`greater<int>`）、取负值法。在考试中建议使用显式小根堆
- 贪心算法的代码通常很短，但**难在策略设计**。建议考前多练习各种贪心题型，积累策略设计经验
