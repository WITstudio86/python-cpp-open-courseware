一、贪心算法核心思想

核心定义：贪心算法在每一步选择中都采取当前状态下最优的选择（局部最优），从而希望导致结果是全局最优的算法策略。

两个关键性质（缺一不可）

  • 贪心选择性质：整体最优解可以通过一系列局部最优选择来达到。每一步选择不需回溯，不可撤销。
  • 最优子结构性质：问题的最优解包含其子问题的最优解。这是贪心和DP的共同基础。

贪心策略设计四步骤

  1. 分析问题，确定候选集合（所有可能的选择）
  2. 设计贪心策略（按什么标准选择——这是最关键的一步）
  3. 验证正确性（尝试构造反例，找不到反例则策略可能正确）
  4. 实现算法（通常是排序 + 一次遍历，O(n log n)）
⚠️ 注意：贪心并不总是正确的！必须先判断问题是否满足贪心选择性质和最优子结构性质，再决定是否使用贪心。

二、经典问题：活动选择（区间调度）

📌 问题：有 n 个活动，每个活动有开始时间 s[i] 和结束时间 f[i]。同一时间只能参加一个活动。最多能参加多少个活动？

贪心策略：按结束时间升序排序

// 核心贪心代码 int greedySelect(Activity a[], int n) { sort(a, a + n, cmp); // 按结束时间升序 int ans = 1; int lastEnd = a[0].end; for (int i = 1; i < n; i++) { if (a[i].start >= lastEnd) { // 不冲突 ans++; lastEnd = a[i].end; } } return ans; }
变种问题排序标准贪心策略复杂度
最多区间选择按结束时间 ↑选不冲突的区间O(n log n)
最少区间覆盖按开始时间 ↑选延伸最远的区间O(n log n)
区间选点按结束时间 ↑在右端点放置点O(n log n)
移除最少区间按结束时间 ↑n - 最多可选数O(n log n)
🎯 考试技巧：区间类问题最重要的是选对排序标准。建议写代码前先用纸笔推演小样例，确认排序标准正确。

三、硬币找零问题

贪心策略：每次选最大面额（仅适用于规范硬币系统）

// 贪心法 —— 仅适用人民币等规范硬币系统 int coinChange(int coins[], int m, int amount) { int count = 0; for (int i = 0; i < m; i++) { count += amount / coins[i]; // 尽可能多用 amount %= coins[i]; // 剩余金额 } return (amount == 0) ? count : -1; }
⚠️ 重要反例：硬币面额 {1, 3, 4}，找零 6 元
贪心：4+1+1 = 3 枚（错误！）
最优：3+3 = 2 枚（DP 得出）
→ 面额不满足规范硬币系统时，贪心会失效！
🎯 考试应对：如果题目未明确说明面额规律，且数据范围不大（金额 ≤ 10000），请优先使用动态规划（完全背包），保证正确性。
// DP法（完全背包）—— 保证正确 int dp[MAX_AMOUNT]; memset(dp, 0x3f, sizeof(dp)); dp[0] = 0; for (int i = 1; i <= amount; i++) for (int j = 0; j < m; j++) if (i >= coins[j]) dp[i] = min(dp[i], dp[i - coins[j]] + 1);

四、真题精练

📝 题目一：活动选择
题目：有 n 个社团申请使用礼堂，时间段为 [s_i, f_i)，同一时间只能一个社团使用。求最多能安排多少个社团。
输入：第一行 n (1 ≤ n ≤ 100000)，接下来 n 行每行两个整数 s_i, f_i。
输出：一个整数，表示最多能安排的社团数。
样例输入：
6
1 4
3 5
0 6
5 7
8 9
5 9
样例输出：3
📝 题目二：排队接水
题目：n 个人排队接水，第 i 人需 t_i 分钟。求最小总等待时间（每个人的完成时间之和）。
输入：第一行 n，第二行 n 个整数 t_i。
样例输入：4 \n 3 1 4 2
样例输出：20 （排序后 1,2,3,4，完成时间 1,3,6,10，总和 = 20）
🎯 解题关键：两道题都使用排序 + 贪心模式。题目一按结束时间排序，题目二按接水时间排序。注意题目二中总等待时间可能超过 int 范围，需使用 long long。

五、易错点 + 本课小结

⚠️ 五大易错点

  • 排序标准选错：活动选择应按结束时间排序，而非开始时间或区间长度。写代码前先用纸笔验证。
  • 贪心并非总是正确：硬币找零中 {1,3,4} 面额时贪心失效。不明确时优先用 DP。
  • 忘记无解判断：区间覆盖中当 maxR == currentR 时表示无法继续，应输出 -1。
  • cmp 函数写错：必须写 return a.end < b.end（严格小于），不能写成 <=。
  • 数据溢出：排队接水的总等待时间可能很大，务必使用 long long。
