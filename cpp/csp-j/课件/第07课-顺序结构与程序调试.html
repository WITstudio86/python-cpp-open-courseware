一、顺序结构：程序的默认执行方式

只要没有分支、循环、函数跳转，语句就严格按照书写顺序从上到下逐条执行。

int main() { int a = 10; // ① 先执行：a 变为 10 int b = 20; // ② 再执行：b 变为 20 int c = a + b; // ③ 使用①②结果：c = 30 cout << c << endl; // ④ 输出 30 return 0; // ⑤ 结束 }
四个本质特点
  1. 一次执行：每条语句按序执行一次
  2. 结果依赖：后句可用前句已算好的结果
  3. 严格先后：前句做完才开始后句
  4. 默认方式：分支/循环是对默认流的“改写”
竞赛主程序骨架
// 1. 读入 cin >> a >> b; // 2. 处理（顺序计算） int sum = a + b; // 3. 输出 cout << sum << endl;
【讲解】顺序结构是三种基本控制结构之一。流水线类比：输入→计算1→计算2→输出。

二、C++ 语句分类（读程基础）

1. 声明语句
int a; // 未初始化（危险） int b = 10; // 推荐 const int N = 100;
2. 表达式语句
a = b + c; cout << a; a++;
3. 控制语句

if for while switch return break continue

改变执行顺序；本课先聚焦顺序

4. 空语句 & 5. 复合语句
; // 空语句：什么也不做 if (a > 0); // 危险！if 后空语句 { t=a; a=b; b=t; } // 复合：多条当一条
空语句是逻辑错误重灾区：if (x>0); 或 while(cin>>x); 语法合法，但语义常与预期相反。
【讲解】认清“什么是一条语句”。复合语句在 if/for 中极为重要：无花括号时只管后面紧跟的一条。

三、变量赋值与交换（顺序中的关键）

赋值是“覆盖”，不是永久绑定

int a = 3; int b = a; // b 拿到当时的 3 a = 10; // 改 a 不会自动改 b // 现在 a=10, b=3

右值先算，再写入左值：a = a + b; 先算右边再写 a。

标准三步交换（考试首选）

int t = x; x = y; y = t;

了解：加减法 / 异或交换有溢出或可读性风险，考试优先临时变量。

错误交换：x = y; y = x; — 第一句后 x 已变成 y，原 x 丢失，结果两个都是原 y。 像“两杯水交换需要第三个空杯子”。
【讲解】顺序结构里最容易算错的是“某时刻变量到底是多少”。CSP-J 读程常让你跟踪交换。

四、程序中的四类错误

1. 编译错误 (CE)

语法错误、类型不匹配、未声明。编译阶段发现。

expected ';' / was not declared / cannot convert

2. 链接错误 (LE)

函数声明未定义、缺少库。undefined reference to 'xxx'

3. 运行时错误 (RE)

除零、数组越界、空指针、栈溢出、段错误。

4. 逻辑错误 (WA)

能编译能跑完但结果不对——最难排查，靠读程与变量表。

报错片段含义对策
expected ';' before缺分号查报错行与上一行
was not declared未声明/拼写错先声明再使用
expected '}' at end缺右花括号成对书写
segmentation fault段错误/越界查下标与指针
技巧：先修第一个错误（后面常是连锁反应）。报错行号有时指“发现位置”，真正问题可能在上一行。
【讲解】理解错误类型才能知道该看编译器、运行结果还是逻辑。

五、程序调试方法

方法一：输出调试法（竞赛最实用）

cin >> a >> b; cerr << "[DEBUG] a=" << a << endl; int c = a + b; cerr << "[DEBUG] c=" << c << endl; cout << c << endl; // 正式答案走 cout

推荐 cerr：标准错误流，减少污染标准答案输出。提交前仍建议删净。

方法二：断点调试法

  1. 行左侧单击设断点（红点）
  2. 调试运行（常见 F5）
  3. 断点处暂停
  4. 监视/变量窗口看当前值
  5. Step Over 单步；Step Into 进函数
  6. Continue 跑到下一断点
  7. 对比“实际值”与“预期值”

调试时重点关注

  • 变量值是否符合预期？何时偏离？
  • 是否走进预期分支？循环次数与边界？
  • 累加器初值、数组下标、表达式中间结果
【讲解】长代码可用 cerr<<"here" 二分隔离 bug。对拍意识本课先建立“对比预期”。

六、程序阅读（读程）五步法

  1. 概览：输入输出、有无循环/分支、大致在算什么
  2. 找关键变量：谁会变？谁是累加器？谁是中间量？
  3. 逐行模拟：像 CPU 一样执行，不要跳读
  4. 制作变量追踪表：每执行关键语句，更新一列表格
  5. 还原输出：严格按 cout 顺序与格式写答案

变量追踪表示例（加减法交换）

int a = 3, b = 5; a = a + b; b = a - b; a = a - b; // 最终 a=5, b=3
步骤语句ab说明
0初始35声明初始化
1a=a+b853+5=8
2b=a-b838-5=3
3a=a-b538-3=5
读程口诀：一步一更新，绝不跳步心算。陷阱：整数除法、自增、赋值链、新值覆盖旧值、输出格式。
【讲解】CSP-J 大量“阅读程序写输出”题。顺序结构读程是基础功。

七、代码模板：可开关调试输出

#include <iostream> using namespace std; // 提交时注释下一行，关闭全部调试输出 #define DEBUG #ifdef DEBUG #define dbg(x) cerr << "[DEBUG] " << #x << " = " << (x) << endl #else #define dbg(x) do {} while (0) #endif int main() { int a, b; cin >> a >> b; dbg(a); dbg(b); long long sum = 1LL * a + b; dbg(sum); cout << sum << '\n'; // 正式答案 return 0; }
竞赛最佳实践：调试信息走 cerr / dbg，正式答案走 cout。提交前注释 #define DEBUG，全文搜索 DEBUG / cerr。
【讲解】配套程序 lesson07 中 demo04 即此技巧。保持读入/处理/输出分区便于定位。

十、真题练习二：交换变量读程

题目：下列程序输出什么？实现了什么功能？

int x = 15, y = 8; int t = x; x = y; y = t; cout << x << " " << y << endl;
步骤代码xyt
初始声明158?
①t = x15815
②x = y8815
③y = t81515

答案：8 15（用临时变量完成两变量交换）

错误写法：x=y; y=x; → 结果 8 8，原 x 丢失。
【练习】对应 lesson07 exam02。强调临时变量必要性。

十二、提交前 / 查 WA 清单

提交前 8 问
  1. 样例能否手算通过？
  2. 边界 0 / 1 / 最大值？
  3. 是否该用 long long？
  4. 是否整数除法踩坑？
  5. 累加器是否初始化？
  6. 输出格式（空格/换行）？
  7. 调试输出是否删净？
  8. 是否读错题意？
查 CE 关键词
  • semicolon → 分号
  • declared → 声明/拼写
  • token / primary-expression → 表达式残缺
  • conversion → 类型
  • void main → 改为 int main

写完先手算一组数据，再运行对照——最小成本调试。

下一课预告：第 8 课 if-else 分支——顺序结构会被条件跳转改写，但读程制表的方法完全通用。
【讲解】WA 先删调试输出，再查样例与边界，再用 cerr 看中间量。
