🃏 部分分策略（"骗分"技巧）

许多题目有部分分设计——允许针对部分数据范围编写专门代码，不需要完美解决也能拿分。

1
暴力枚举小数据（常见 20-30 分）

当 n ≤ 10 时用 O(n!) 暴力，n ≤ 100 时用 O(n³)。针对不同数据范围写分支代码。

int main() { int n; cin >> n; if (n <= 10) { // 暴力全排列 O(n!) — 拿小数据满分 } else if (n <= 1000) { // O(n^2) 算法 — 拿中等数据满分 } else { // O(n log n) 最优算法 } }
2
特殊情况的特判（常见 5-15 分）

n=1、全部相同、单调递增/递减等边界情况单独处理。

3
打表法（适合输入范围小的题）

提前计算所有可能答案，程序中直接查表输出。适合 n ≤ 10 的斐波那契、阶乘等问题。

4
输出固定值碰运气

完全不会的题，输出 0、-1、n 等常见答案，有时能碰中 1-2 个测试点。

💡 骗分不是"骗"，是竞赛策略
很多省份的 CSP-J 第二轮三等奖线在 80-120 分。即使第3、4题不会，只要第1题满分 + 第2题大部分分 + 第3、4题的部分分，也能拿到不错的奖项。

🔧 模拟题解题模板

核心思路：按规则一步步模拟，注意细节

📅 日期模拟模板

// 闰年判断 bool isLeap(int y) { return (y%4==0 && y%100!=0) || y%400==0; } // 年月日 → 总天数（基准法） long long totalDays(int y,int m,int d){ long long total = 0; for(int i=1;i<y;i++) total += isLeap(i)?366:365; for(int i=1;i<m;i++) total += daysOfMonth(y,i); total += d; return total; } // 日期差 = totalDays(d2) - totalDays(d1)

🔢 高精度加法模板

string add(string a, string b) { string res = ""; int carry = 0; int i = a.size()-1, j = b.size()-1; while (i>=0 || j>=0 || carry) { int sum = carry; if(i>=0) sum += a[i--]-'0'; if(j>=0) sum += b[j--]-'0'; res += sum%10 + '0'; carry = sum/10; } reverse(res.begin(),res.end()); return res; }
⚠️ 模拟题易错点
• 闰年判断：能被4整除但不能被100整除或能被400整除
• 月份天数：2月平年28天，闰年29天
• 日期进位：日超→月+1，月超13→年+1
• 高精度进位：循环条件要包含 carry != 0

🔍 枚举优化 & 贪心模板

枚举优化三大思路

  1. 减少枚举维度：通过等式关系消去一重循环。如三数之和：枚举两个数，第三个用 target-a[i]-a[j] 二分查找，O(n³) → O(n² log n) → O(n²)
  2. 缩小枚举范围：利用题目的约束条件（大小关系、奇偶性）缩小上下界
  3. 剪枝：发现当前分支不可能产生更优解，立即跳过

贪心算法：区间调度模板

struct Activity { int start, end; }; bool cmp(Activity a, Activity b) { return a.end < b.end; } int maxActivities(Activity a[], int n) { sort(a, a+n, cmp); // 按结束时间排序 int count = 0, lastEnd = -1; for (int i = 0; i < n; i++) { if (a[i].start >= lastEnd) { count++; lastEnd = a[i].end; } } return count; }
✅ 适合贪心的问题
• 区间调度（按结束时间排序）
• 哈夫曼编码
• 部分背包（物品可分割）
• 最小生成树 Kruskal
❌ 不适合贪心的问题
• 01 背包（需动态规划）
• 最长路径
• 旅行商问题
• 大多数"选或不选"类问题

🎯 二分答案模板

核心思想

将"求满足条件的最大值/最小值"转化为"判断某个值是否满足条件"。前提：问题的判定函数具有单调性。

求最大值模板

int left = minVal, right = maxVal; int ans = left; while (left <= right) { int mid = left + (right-left)/2; if (check(mid)) { ans = mid; left = mid + 1; // 尝试更大 } else { right = mid - 1; } }

适用场景：砍树求最高锯子、最大化最小值

求最小值模板

int left = minVal, right = maxVal; int ans = right; while (left <= right) { int mid = left + (right-left)/2; if (check(mid)) { ans = mid; right = mid - 1; // 尝试更小 } else { left = mid + 1; } }

适用场景：最小化最大值、最小化代价

经典例题：砍树问题

n 棵树高度 h_i，需要至少 M 木材。锯子高度越高，砍下的木材越少（单调性）。求满足条件下的最高锯子高度。

// check(H): 判断H高度是否能获得≥M木材 bool check(int H) { long long total = 0; for (int i = 0; i < n; i++) if (h[i] > H) total += h[i] - H; return total >= M; } // 时间复杂度: O(n log maxH)
⚠️ 二分答案死循环排查
更新区间时，确保 mid 的计算方式是 left + (right-left)/2（防溢出），并且 left 和 right 的更新方向正确（一个用 mid±1，另一个用 mid）。

📋 模拟题示例：日期差值计算

题目：给定两个日期 "YYYY-MM-DD"，计算相差天数。
输入：2024-01-01 / 2024-01-10    输出：9
// 核心思路：转换为"公元1年1月1日"起的累计天数，再相减 bool isLeap(int y) { return (y%4==0&&y%100!=0) || y%400==0; } int daysOfMonth(int y, int m) { int d[]={0,31,28,31,30,31,30,31,31,30,31,30,31}; if(m==2 && isLeap(y)) return 29; return d[m]; } long long totalDays(int y, int m, int d) { long long total = 0; for(int i=1; i<y; i++) total += isLeap(i)?366:365; for(int i=1; i<m; i++) total += daysOfMonth(y, i); total += d; return total; } // 日期差 = totalDays(y2,m2,d2) - totalDays(y1,m1,d1)
💡 基准日法优势：统一处理所有跨年、跨月、闰年情况，代码简洁不易出错。注意使用 long long 存储大年份的累计天数，避免溢出。

📋 枚举 & 贪心示例

枚举优化：三数之和为零

// 排序 + 双指针：O(n²) sort(a, a+n); for (int i=0; i<n-2; i++) { if (a[i] > 0) break; // 剪枝：最小的数>0，不可能和为0 int left = i+1, right = n-1; while (left < right) { int sum = a[i] + a[left] + a[right]; if (sum == 0) return true; else if (sum < 0) left++; else right--; } }

朴素 O(n³) → 排序+双指针 O(n²)，n=1000 时可接受（约 10⁶ 运算）。

贪心：活动选择（区间调度）

// 贪心策略：每次选结束时间最早的不冲突活动 // 步骤：① 按结束时间排序 ② 遍历选不冲突的活动 sort(a, a+n, [](auto& x,auto& y){return x.end<y.end;}); int count=0, lastEnd=-1; for(int i=0;i<n;i++) { if(a[i].start >= lastEnd) { count++; lastEnd=a[i].end; } }

时间复杂度 O(n log n)。证明方法：交换论证——最优解中第一个活动一定是结束时间最早的。

记忆口诀：贪心看结束，枚举少一维，二分要单调，模拟重细节。

🗂️ CSP-J 第二轮四大题型总结

1. 模拟题

特征：规则明确，按步骤实现
典型：日期计算、字符串处理
关键：细心读题，注意边界
复杂度：通常 O(n) 或 O(1)
第1题高频

2. 枚举题

特征：需要遍历搜索空间
典型：三数之和、子集枚举
优化：排序+双指针、剪枝
复杂度：O(n²) 通常可接受
第2题高频

3. 贪心题

特征：局部最优→全局最优
典型：区间调度、活动选择
关键：证明贪心正确性
复杂度：O(n log n)（常需排序）
第2-3题高频

4. 二分答案

特征：单调性判定问题
典型：砍树、最小化最大值
关键：check 函数设计
复杂度：O(n log V)
第3-4题高频
