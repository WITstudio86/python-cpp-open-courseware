CLI 程序的四大组件

一个典型的 CLI 程序包含四个核心组件，它们像齿轮一样协同工作：

🚀 程序启动
▼
📋 显示菜单（showMenu）
▼
👤 用户输入选择（cin >> choice）
▼
⚙️ 执行对应功能（switch）
▼ ↻ 循环
🔚 退出程序（choice == 0）

四大组件：

  • 菜单显示 — 告诉用户有哪些选项
  • 输入读取 — 获取用户的选择
  • 功能分发 — 根据选择执行不同操作
  • 主循环 — 不断重复，直到用户选择退出

主循环：do-while 的天然优势

do-while 循环的特点：先执行一次循环体，再检查条件。这非常适合菜单程序——菜单至少要显示一次！

int main() { int choice; do { showMenu(); // 1. 显示菜单 cin >> choice; // 2. 获取用户选择 switch (choice) { // 3. 分发功能 case 1: addTask(); break; case 2: viewTasks(); break; case 0: cout << "再见！"; break; default: cout << "无效选择！"; } } while (choice != 0); // 4. 选0才退出 return 0; }
循环类型执行顺序最少执行次数适用场景
while (条件) { }先判断，再执行0 次可能一次都不需要执行
do { } while (条件);先执行，再判断1 次至少执行一次（菜单！）

switch 分支 —— 功能路由器

switch 语句像一个路由器，根据用户输入的数字把程序引导到对应的功能函数。

switch (choice) { // choice 是用户输入的数字 case 1: addTask(); // 选1 → 执行添加任务 break; // ★ 别忘了 break！ case 2: viewTasks(); // 选2 → 执行查看任务 break; case 0: cout << "再见！"; // 选0 → 退出 break; default: // 其他数字 → 无效 cout << "❌ 无效选择！"; }
⚠️ 易错点：每个 case 末尾的 break 极易忘记！如果漏掉 break，程序会"穿透"到下一个 case，导致执行了不该执行的功能。

switch vs if-else：当需要根据一个变量的多个具体值来判断时，switch 比写一长串 if-else 更清晰、更高效。

用户输入处理 —— cin 与 getline 的配合

CLI 程序中处理用户输入有三种常见方式：

// 方式1：读取整数（用于菜单选择） int choice; cin >> choice; // 方式2：读取一行文字（用于任务标题，可含空格） string title; cin.ignore(); // ★ 先清空缓冲区！ getline(cin, title); // 再读取整行 // 方式3：读取单个字符（用于 y/n 确认） char confirm; cin >> confirm;

⚠️ 关键陷阱：cin >> 后面的"幽灵换行符"

这是 CLI 编程中最常见的 Bug！当 cin >> 读取整数后，输入缓冲区中会残留一个换行符 `\n`。如果紧接着使用 getline()，它会把这个换行符当作"一行"读走，导致用户输入被跳过！

用户输入：1 [回车] 缓冲区内容：'1' '\n' ↑ ↑ cin>>choice cin.ignore() 读取了 '1' 丢弃了 '\n' ← 不丢弃的话 getline 会读到空行！

✅ 正确做法：在 cin >> 之后、getline() 之前，加一句 cin.ignore();

int choice; cin >> choice; cin.ignore(); // ★ 清空残留的换行符 string title; getline(cin, title); // 现在可以正常读取了！
💡 记忆口诀：整数读完留换行，ignore 清空不害怕！

增量开发 —— 先搭骨架，再充血肉

软件开发中有一个重要原则：增量开发（Incremental Development）。先把整体骨架跑起来，再逐步添加功能。这样可以：

  • 及早发现问题（骨架运行正常 ≠ 逻辑正确）
  • 每一步都有可以运行的版本
  • 降低调试难度（出问题知道是刚加的代码导致的）
// 占位函数 —— 先让程序能编译运行 void addTask() { cout << " [功能开发中] 添加任务功能将在第2课实现！" << endl; } void viewTasks() { cout << " [功能开发中] 查看任务功能将在第2课实现！" << endl; }
