# 第47节：游戏博览会

## 教学目标

- 学生能够自信地展示自己的游戏作品
- 学生能够清晰地讲解游戏的设计思路和技术实现
- 学生能够欣赏他人作品并给予建设性反馈
- 学生在互评中互相学习、共同进步
- 培养学生的表达与展示能力
- 培养学生给予和接受反馈的能力
- 培养学生的代码审美素养

---

## 时间分配（60分钟）

| 环节 | 时间 | 内容 |
|------|------|------|
| 开场介绍 | 3分钟 | 说明展示规则、流程和评价标准 |
| 作品展示 | 40分钟 | 每组5+2分钟（约6-7组） |
| 自由试玩 | 12分钟 | 互相试玩、交流心得 |
| 投票与总结 | 5分钟 | 投票最佳作品、老师总结 |

---

## 教学内容

### 一、开场介绍（3分钟）

**教师开场白（参考）：**

> 同学们，今天我们迎来了一个特别的课堂——**游戏博览会**！过去的几节课，每个小组都投入了大量心血，设计、编码、调试，做出了属于自己的游戏作品。今天，我们不再敲代码，而是做一件同样重要的事情：**展示、分享和互相学习**。
>
> 在真正的游戏行业中，做出一款好游戏只是第一步，**怎么让别人知道你的游戏好、怎么讲清楚你的设计思路**，同样关键。今天每个小组有 **5分钟演示 + 2分钟问答**，请认真准备，也请观众认真观看。
>
> 展示结束后，我们有**自由试玩时间**，大家可以亲自体验同学的作品。最后我们会**投票选出最佳游戏**！

**明确规则（打在屏幕上/写在黑板）：**

1. 每组 **5分钟演示** + **2分钟问答**
2. 演示内容包括：游戏名称、玩法介绍、设计亮点、技术难点、心得体会
3. 观众需填写 **反馈表**（每人至少给2个小组写反馈）
4. 自由试玩时，互相尊重、有序体验
5. 每人一票，投给你最喜欢的游戏

---

### 二、作品展示环节（40分钟）

#### 展示流程

```
每组展示时间：5分钟演示 + 2分钟问答 = 7分钟/组
40分钟 ≈ 5-6组展示（根据班级人数调整）
```

#### 时间控制策略

- **教师担任计时员**：使用计时器投屏，让学生能看到剩余时间
- **4分钟时提示**："还剩1分钟"
- **5分钟时提示**："时间到，请进入问答环节"
- **7分钟时提示**："感谢这一组，请下一组准备"

#### 演示者 checklist（提前发给学生）

在演示时，请务必讲清楚以下几点：

1. **游戏名字和一句话介绍**
   - "我们的游戏叫《XXX》，是一款XXX类型的游戏"
2. **怎么玩（操作方式）**
   - 键盘控制？鼠标点击？展示操作键位
3. **游戏的核心玩法**
   - 玩家目标是什么？怎么算赢？怎么算输？
4. **一个设计亮点**
   - 你们最得意的一个设计或功能是什么？
5. **一个技术难点**
   - 实现过程中遇到的最大困难是什么？怎么解决的？
6. **心得体会**
   - 做这个游戏最大的收获是什么？

#### Q&A 引导问题（教师备用）

如果观众没有问题，教师可以引导提问：

- "你觉得这个游戏最难做的是哪部分？"
- "如果再加一个功能，你会加什么？"
- "这个游戏的灵感来自哪里？"
- "有没有什么想做但没做出来的功能？"

#### 展示顺序安排

建议按以下方式排序（避免冷场）：

1. 自愿优先 → 让准备好的小组先上
2. 或者抽签决定 → 增加趣味性
3. 或者按座位顺序 → 最简单

---

### 三、自由试玩时间（12分钟）

#### 组织方式

- 每个小组在自己的电脑上打开游戏
- 其他同学**自由走动**，去试玩感兴趣的游戏
- 每个游戏旁放一张**反馈便利贴**，试玩者写下简短评价

#### 教师角色

- 巡视观察，拍照记录
- 与学生交流试玩感受
- 确保每个游戏都有人试玩（避免冷落任何一组）
- 控制音量，保持有序

#### 试玩引导问题

鼓励学生在试玩时思考：

- 这个游戏好玩吗？为什么？
- 操作顺手吗？
- 画面看起来怎么样？
- 有没有什么让人惊喜的地方？
- 如果是我，我会怎么改进？

---

### 四、投票与总结（5分钟）

#### 投票方式

- 每人一票（不能投自己组）
- 投票方式可选：
  - **举手投票**：最直接
  - **贴纸投票**：每人一个小贴纸，贴在喜欢的游戏海报上
  - **匿名纸条**：写下来投进投票箱
  - **在线投票**：用班级群投票小程序

#### 奖项设置（建议多维度，让更多组获得认可）

| 奖项 | 评选标准 |
|------|----------|
| 最佳游戏奖 | 综合体验最好 |
| 最佳创意奖 | 玩法最新颖 |
| 最佳代码奖 | 代码结构最清晰 |
| 最佳美术奖 | 画面最好看 |
| 最佳展示奖 | 讲解最精彩 |
| 最受欢迎奖 | 获得最多投票 |

#### 教师总结要点

1. **肯定努力**：每个完成作品的小组都值得掌声
2. **回顾亮点**：举例1-2个印象深刻的作品/功能
3. **共性建议**：从代码质量、用户体验、创意方面给出整体建议
4. **展望未来**：编程是一项长期技能，今天的每一行代码都是成长

## 评价维度与标准

### 教师评分维度（参考）

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 创意 | 25% | 游戏概念是否新颖？是否有原创性？ |
| 完成度 | 25% | 游戏是否能正常运行？功能是否完整？ |
| 代码质量 | 20% | 代码结构是否清晰？变量命名是否规范？是否有注释？ |
| 展示表达 | 20% | 讲解是否清晰流畅？是否能回答提问？团队合作如何？ |
| 用户体验 | 10% | 操作是否顺手？界面是否友好？ |

### 评分等级参考

- **A (优秀, 90-100)**：游戏完整、创意突出、展示精彩、代码清晰
- **B (良好, 80-89)**：游戏可玩、有一定创意、展示清楚
- **C (合格, 70-79)**：游戏基本完成、展示基本清楚
- **D (待改进, <70)**：游戏未完成或存在严重问题

## 教师主持要点

### 会前准备

- [ ] 准备计时器（投屏可见）
- [ ] 打印反馈表（每人2-3份）
- [ ] 准备投票工具（贴纸/纸条/小程序）
- [ ] 准备奖项（奖状/小奖品）
- [ ] 确认每组游戏能正常运行
- [ ] 安排展示顺序
- [ ] 准备相机拍照记录

### 会中注意

- **营造轻松氛围**：这是庆祝，不是考试。多用鼓励性语言
- **控制节奏**：严格计时，但不催促。如果某组讲得好可以适当放宽
- **引导互动**：观众没提问时，教师主动提问暖场
- **给予即时反馈**：每组展示后给予简短正面点评
- **关注边缘学生**：确保每个学生都有参与感，不受冷落

### 会后跟进

- 拍照发班级群
- 收集反馈表，整理后发给各小组
- 总结常见问题，后续课程中针对性讲解
- 鼓励学生继续完善作品

---

## 备用方案

### 如果展示时间不够

- 将演示时间压缩为 3+1 分钟
- 或将部分小组的展示安排在下次课

### 如果某组游戏无法运行

- 让学生口头演示设计思路和代码
- 请其他同学帮忙排查问题（变成Debug教学）

### 如果学生过于紧张

- 老师站在旁边辅助讲解
- 让同组另一位同学补充
- 简化要求："不用都讲，挑一个最想说的点就好"

---

## 课程小结

本节是纯粹的展示活动课，不涉及新的编程知识。核心目标是：

1. **让学生获得成就感** — 看到自己的作品被展示和认可
2. **培养表达与沟通能力** — 学会用清晰的语言讲解技术内容
3. **培养反馈素养** — 学会给予和接受建设性反馈
4. **激发持续学习的动力** — 看到同学的优秀作品，获得新的灵感

> "编程不只是写给机器看的，也是写给人看的；游戏不只是自己玩的，更是让别人玩的。"
