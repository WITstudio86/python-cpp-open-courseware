#### 2.2 水管对设计（8分钟）

**上下水管 + 固定间隙**：

```
        屏幕顶部 (y=0)
        ┌─────────────┐
        │  上水管      │  ← 从顶部延伸到间隙上沿
        │  (矩形)     │
        │            │
        └─────────────┘  ← gap_y（间隙上沿）
        
        ╔═════════════╗  ← GAP_SIZE（间隙，小鸟穿过的空间）
        ║   间隙      ║     固定150像素
        ╚═════════════╝  
        
        ┌─────────────┐  ← gap_y + GAP_SIZE（间隙下沿）
        │  下水管      │
        │  (矩形)     │  ← 从间隙下沿延伸到底部
        │            │
        └─────────────┘
        屏幕底部 (y=HEIGHT)
```

**关键代码**：

```python
GAP_SIZE = 150  # 上下水管之间的间隙（固定）

# 生成一对水管
gap_y = random.randint(100, HEIGHT - 100 - GAP_SIZE)  # 间隙的y坐标（随机偏移）

# 上水管：从顶部(0) 到 间隙上沿(gap_y)
top_pipe = pygame.Rect(pipe_x, 0, PIPE_WIDTH, gap_y)

# 下水管：从间隙下沿(gap_y + GAP_SIZE) 到 底部(HEIGHT)
bottom_pipe = pygame.Rect(pipe_x, gap_y + GAP_SIZE, PIPE_WIDTH, HEIGHT - gap_y - GAP_SIZE)
```

**要点说明**：
- `GAP_SIZE` 是固定的，保证小鸟总能穿过（只要玩家操作正确）
- `gap_y` 是随机的——这就是游戏难度的来源！间隙有时靠上，有时靠下
- 随机范围 `(100, HEIGHT - 100 - GAP_SIZE)` 保证了间隙不会太靠近顶部或底部
- 一对水管共享同一个 x 坐标和 gap_y，它们是一个整体

**管道数据存储方式**：

```python
# 每个管道对存储为一个列表：[top_pipe_rect, bottom_pipe_rect, scored]
# scored 标记这对水管是否已经被计过分
pipes.append([top_pipe, bottom_pipe, False])
```

#### 2.3 碰撞检测（7分钟）

Flappy Bird 中有**三种**碰撞会导致死亡：

**碰撞 1：小鸟撞水管**

```python
# 为小鸟创建一个 Rect 用于碰撞检测
bird_rect = pygame.Rect(bird_x - BIRD_RADIUS, bird_y - BIRD_RADIUS,
                         BIRD_RADIUS * 2, BIRD_RADIUS * 2)

# 遍历所有水管对，检查碰撞
for pipe_pair in pipes:
    top_pipe, bottom_pipe, scored = pipe_pair
    if bird_rect.colliderect(top_pipe) or bird_rect.colliderect(bottom_pipe):
        game_state = "game_over"  # 小鸟死亡！
```

> **讲解要点**：`colliderect()` 是上节学过的碰撞检测方法，这里只需要对上下水管分别检测即可。只要碰到任何一个，游戏就结束。

**碰撞 2：小鸟撞地面**

```python
if bird_y + BIRD_RADIUS >= HEIGHT:  # 小鸟底部超出窗口
    game_state = "game_over"
```

**碰撞 3：小鸟撞天空**

```python
if bird_y - BIRD_RADIUS <= 0:  # 小鸟顶部超出窗口
    bird_y = BIRD_RADIUS       # 或者直接死亡
    bird_vy = 0                # 停止上升
```

> **设计选择**：有两种处理方式——方案A：撞天花板直接死亡；方案B：撞天花板只是挡住不让飞出。这里我们采用方案A（死亡），因为这样更刺激，和原版Flappy Bird一致。

**汇总——死亡条件**：

```python
def check_death(bird_rect, pipes):
    """检查小鸟是否死亡，返回 True/False"""
    # 1. 撞水管
    for top_pipe, bottom_pipe, _ in pipes:
        if bird_rect.colliderect(top_pipe) or bird_rect.colliderect(bottom_pipe):
            return True
    # 2. 撞地面
    if bird_rect.bottom >= HEIGHT:
        return True
    # 3. 撞天空
    if bird_rect.top <= 0:
        return True
    return False
```

#### 2.4 过管计分逻辑（4分钟）

**核心思路**：小鸟的**左边缘**越过了水管的**右边缘**，且这对水管还没有被计过分 → 得分+1。

```
  ┌─────┐
  │水管 │  pipe.right ──→  ← bird.left
  │     │                       ┌──┐
  │     │                       │鸟│
  └─────┘                       └──┘
  
  当 bird.left > pipe.right 时，说明小鸟已经飞过了这对水管
```

**关键代码**：

```python
for pipe_pair in pipes:
    top_pipe, bottom_pipe, scored = pipe_pair
    # 条件1：小鸟的左边缘超过了水管的右边缘
    # 条件2：这对水管还没有被计过分
    if bird_rect.left > top_pipe.right and not scored:
        score += 1
        pipe_pair[2] = True  # 标记为"已计分"，防止重复加分
```

> **为什么要 `scored` 标记？** —— 如果不标记，每一帧小鸟的 `left` 都大于 `pipe.right`，分数会在一秒内变成60！加上标记后，每对水管只加一次分。

**计分时机详解**：

```
帧1: bird.left=95, pipe.right=100  → 还没过，不加分
帧2: bird.left=98, pipe.right=97   → 刚过！scored=False → 加分！scored=True
帧3: bird.left=101, pipe.right=94  → 已过，但scored=True → 不加分 ✓
帧4: bird.left=104, pipe.right=91  → 已过，但scored=True → 不加分 ✓
```

#### 2.6 游戏状态机（3分钟）

游戏有两种状态，用 `game_state` 变量来控制：

```python
game_state = "playing"  # 初始状态：游戏中

# 游戏主循环中：
if game_state == "playing":
    # 更新小鸟位置、水管位置
    # 检测碰撞 → 如果死亡，切换到 game_over
    # 检测过管 → 加分
    pass
elif game_state == "game_over":
    # 显示 Game Over 画面
    # 等待玩家按下空格键 → 重置游戏，切换到 playing
    pass
```

**状态转换图**：

```
  ┌──────────┐  碰撞/出界   ┌───────────┐
  │ playing  │ ────────────→ │ game_over │
  │          │               │           │
  └──────────┘ ←──────────── └───────────┘
        ↑      按下空格键重置        │
        └────────────────────────────┘
```

> **为什么需要状态机？** —— 如果不用状态机，Game Over 之后小鸟还在下落、分数还在变，画面就很混乱。状态机让程序的逻辑清晰分离。

## 💡 常见问题与解决

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 分数一秒钟变成好几百 | 没有用 `scored` 标记防止重复计分 | 每对水管加 `scored` 标记，计分后设为 `True` |
| 小鸟"卡"在水管里反复碰撞 | 死亡后小鸟还在水管区域内 | 死亡后立即切换到 `game_over` 状态，停止更新 |
| 碰撞检测不灵敏/穿模 | 小鸟的 Rect 没有每帧更新 | 确保 `bird_rect` 在碰撞检测前用最新的 `bird_x`、`bird_y` 重新创建 |
| Game Over 后按键没反应 | 事件处理中只在 `playing` 状态检测空格 | 在 `game_over` 状态也添加空格检测 |
| 重新开始后分数不清零 | 重置时忘了重置 `score` 变量 | 在重置函数中 `score = 0` |
| 水管间隙位置太极端 | `gap_y` 随机范围设置不合理 | 确保 `gap_y` 范围在 `[50, HEIGHT - 50 - GAP_SIZE]` 内 |
| 最高分不更新 | 比较逻辑写错或没有在死亡时比较 | 确保在 `game_state` 变为 `game_over` 时执行 `if score > high_score: high_score = score` |
| 小鸟一直往上飞出屏幕 | 空格键按住不放，连续触发上升 | 使用 `pygame.KEYDOWN` 事件（不是 `get_pressed()`），每次按下只触发一次 |
| 水管生成太快/太慢 | 生成间隔帧数设置不合适 | 调整 `pipe_spawn_timer` 的阈值（建议 60~100 帧） |
