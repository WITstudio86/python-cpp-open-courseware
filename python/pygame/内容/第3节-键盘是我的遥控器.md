### 一、导入（5分钟）

#### 1.1 从生活场景引入

同学们，你们玩过遥控车吗？你按下遥控器上的"前进"按钮，车子就向前跑；你松开按钮，车子就停下来。这个过程看起来很简单，但你想过一个问题吗——**车子是怎么"知道"你按了哪个按钮的？**

遥控器会发射一个信号，车子接收到信号后，就知道"哦，主人让我前进"，然后执行前进的动作。

游戏程序也是一样的道理！当你按下键盘上的方向键时，你的电脑会发送一个信号给游戏程序。这个信号，在 Pygame 里有一个专门的名字，叫做——**事件（Event）**。

#### 1.2 什么是事件？

"事件"这个词听起来有点抽象，但其实它就在我们身边。举几个例子：

- 你按了一下门铃 → **"门铃被按下"事件发生了** → 屋里的人来开门
- 你点击了手机屏幕上的图标 → **"屏幕被点击"事件发生了** → APP 启动
- 你在游戏中按了空格键 → **"空格键被按下"事件发生了** → 角色跳起来

简单来说：**事件 = 发生的事情。游戏程序就是不停地"听"有没有事件发生，然后做出对应的反应。**

#### 1.3 本节课我们要做什么？

今天我们要做一个"键盘遥控器"——用方向键来控制一个矩形在屏幕上自由移动，就像遥控一辆小车一样！而且我们要给小矩形加上"围栏"，让它不能跑出窗口，就像遥控车不能穿墙一样。

我们先来看一下最终效果的核心逻辑：

```
重复执行：
    看看有没有人按了键？
    如果有 → 是哪个键？
        是左键 → 矩形向左移
        是右键 → 矩形向右移
        是上键 → 矩形向上移
        是下键 → 矩形向下移
    如果矩形碰到边界 → 停下来，不许出去！
    把矩形画到屏幕上
```

### 二、核心讲解（25分钟）

#### 2.1 事件循环——游戏的"耳朵"

上一节课我们写过一个让窗口不自动关闭的代码，还记得吗？

```python
running = True
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
```

这段代码里藏着本节课最重要的一个概念：**事件循环**。

`pygame.event.get()` 就像一个**快递员**，它会把游戏运行期间发生的所有事件（键盘按下、鼠标点击、窗口关闭等等）收集起来，装在一个"事件列表"里交给我们。然后我们用 `for event in ...` 一个一个地检查这些事件。

想象一下：你的游戏是一个"服务台"，`pygame.event.get()` 是排队的人群。你需要逐一接待每个人，问清楚他们有什么事（判断事件类型），然后处理他们的问题。

**代码结构如下：**

```python
while running:                          # 游戏主循环
    for event in pygame.event.get():    # 取出所有事件，逐个检查
        if event.type == pygame.QUIT:   # 如果是"关闭窗口"事件
            running = False             # 就退出循环，结束游戏
        if event.type == pygame.KEYDOWN:# 如果是"按键被按下"事件
            # 在这里处理键盘操作
            pass
```

> **小提示**：`pygame.QUIT` 是一个特殊的事件类型，它代表用户点击了窗口右上角的关闭按钮。如果不处理这个事件，窗口就关不掉，程序也不会结束。

#### 2.2 KEYDOWN 事件——检测"单次按键"

当用户按下键盘上的任意一个键时，Pygame 就会生成一个 `KEYDOWN` 事件。

`KEYDOWN` 的意思是 **"键被按下去的那一瞬间"**。就好像有人敲门，"咚"的那一声就是 KEYDOWN 事件。

在 `KEYDOWN` 事件中，我们可以通过 `event.key` 来知道具体是哪个键被按下了。Pygame 给每个键都起了一个名字，就是所谓的"键常量"：

| 键盘按键 | Pygame 常量 | 含义 |
|----------|-------------|------|
| ← 左方向键 | `pygame.K_LEFT` | Key Left |
| → 右方向键 | `pygame.K_RIGHT` | Key Right |
| ↑ 上方向键 | `pygame.K_UP` | Key Up |
| ↓ 下方向键 | `pygame.K_DOWN` | Key Down |
| 空格键 | `pygame.K_SPACE` | Key Space |

**完整的方向键处理代码：**

```python
import pygame
import sys

pygame.init()
screen = pygame.display.set_mode((800, 600))
pygame.display.set_caption("键盘遥控器")

# 矩形的初始位置
x = 400
y = 300
rect_width = 50
rect_height = 50

clock = pygame.time.Clock()
running = True

while running:
    # 事件处理
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_LEFT:
                x -= 10  # 向左移动 10 像素
                print("向左走！")
            if event.key == pygame.K_RIGHT:
                x += 10  # 向右移动 10 像素
                print("向右走！")
            if event.key == pygame.K_UP:
                y -= 10  # 向上移动 10 像素
                print("向上走！")
            if event.key == pygame.K_DOWN:
                y += 10  # 向下移动 10 像素
                print("向下走！")

    # 绘制
    screen.fill((255, 255, 255))
    pygame.draw.rect(screen, (0, 128, 255), (x, y, rect_width, rect_height))
    pygame.display.update()
    clock.tick(60)

pygame.quit()
sys.exit()
```

**运行试试看！** 你会发现一个有趣的现象：每按一下方向键，矩形只移动一小格（10 像素）。如果你按住方向键不放，矩形并不会持续移动——因为 `KEYDOWN` 事件只在键**刚按下去的那一瞬间**触发一次。

这就引出了一个问题：如果我想要按住方向键不放，矩形就能一直移动，该怎么办呢？

#### 2.3 key.get_pressed()——检测"持续按住"

Pygame 提供了另一种检测键盘的方式：`pygame.key.get_pressed()`。

这个方法不关心"键是什么时候按下去的"，它只关心**"此时此刻，哪些键正在被按着"**。

可以把它想象成：`pygame.event.get()` 是"快递员送信"（事件驱动的通知方式），`pygame.key.get_pressed()` 是"你一直盯着键盘看"（主动轮询的检查方式）。

`pygame.key.get_pressed()` 会返回一个列表，里面记录了键盘上每一个键的当前状态（按下是 `True`，没按是 `False`）。我们可以这样使用它：

```python
keys = pygame.key.get_pressed()  # 获取所有键的当前状态

if keys[pygame.K_LEFT]:          # 如果左键正在被按着
    x -= 5                        # 每帧都移动 5 像素
if keys[pygame.K_RIGHT]:         # 如果右键正在被按着
    x += 5
if keys[pygame.K_UP]:            # 如果上键正在被按着
    y -= 5
if keys[pygame.K_DOWN]:          # 如果下键正在被按着
    y += 5
```

注意这里的一个关键区别：**`keys[pygame.K_LEFT]` 后面没有 `event` 对象，它是直接在游戏主循环里判断的，不需要写在 `for event in ...` 里面。**

用这种方式，只要键盘一直按着，矩形就会每一帧都移动，实现**平滑的连续移动**。

#### 2.4 两种方式大对比——什么时候用哪个？

这是本节课最重要的知识点。很多初学者会搞混，我们来一个清晰的对比：

| 对比维度 | event.get() 方式 | key.get_pressed() 方式 |
|----------|-------------------|------------------------|
| **触发方式** | 事件驱动（键被按下的瞬间触发一次） | 轮询检测（每帧都检查键是否被按着） |
| **按住不放** | 只触发一次，不会连续移动 | 持续触发，每帧都会移动 |
| **代码位置** | 写在 `for event in ...` 循环里面 | 写在游戏主循环中，事件循环之外 |
| **写法示例** | `if event.key == pygame.K_LEFT:` | `if keys[pygame.K_LEFT]:` |
| **适合场景** | 跳跃（按一下跳一次）、发射子弹、打开菜单 | 角色移动、赛车加速、飞机飞行 |

**生活类比帮你记住：**

- `event.get()` 就像**门铃**：有人按一下，你听到"叮咚"一声，就去开门。按住门铃不放也只会响一次。
- `key.get_pressed()` 就像你**盯着门口看**：你每秒钟都在看门口有没有人站着，有的人就一直开着门。

> **什么时候用哪个？** 简单口诀：**"单次操作用事件，连续移动用轮询"**。

**完整的"两合一"代码示例：**

```python
import pygame
import sys

pygame.init()
screen = pygame.display.set_mode((800, 600))
pygame.display.set_caption("两种键盘检测方式演示")

x, y = 400, 300
speed = 5
rect_size = 50

clock = pygame.time.Clock()
running = True

while running:
    # 第一部分：事件检测（适合单次操作）
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False
        if event.type == pygame.KEYDOWN:
            # 按空格键：矩形变大（单次效果）
            if event.key == pygame.K_SPACE:
                rect_size += 10
                print(f"变大！当前大小：{rect_size}")

    # 第二部分：轮询检测（适合连续移动）
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        x -= speed
    if keys[pygame.K_RIGHT]:
        x += speed
    if keys[pygame.K_UP]:
        y -= speed
    if keys[pygame.K_DOWN]:
        y += speed

    # 绘制
    screen.fill((255, 255, 255))
    pygame.draw.rect(screen, (255, 80, 80), (x, y, rect_size, rect_size))
    pygame.display.update()
    clock.tick(60)

pygame.quit()
sys.exit()
```

在这个例子中：
- 方向键用 `key.get_pressed()`，按住就可以连续移动
- 空格键用 `KEYDOWN` 事件，按一下变大一次，按住了也不会一直变大

两种方式各司其职，配合使用！

#### 2.5 边界限制——给矩形装上"围栏"

现在矩形可以自由移动了，但很快你就会发现一个问题：**矩形会跑到窗口外面去！** 向左走得太远，它就消失了。

我们需要给矩形加上"围栏"，限制它的活动范围。这就是**边界限制（Boundary Limiting）**。

**核心思路**：每次移动矩形之后，检查它的位置是否超出了窗口边界。如果超出了，就把它"拉"回来。

矩形的位置由左上角坐标 `(x, y)` 决定，窗口的大小是 `(800, 600)`，矩形的大小是 `50 × 50`。那么：

- **左边界**：矩形不能跑到窗口左边外面，所以 `x` 不能小于 `0`
- **右边界**：矩形不能跑到窗口右边外面，所以 `x` 不能大于 `窗口宽度 - 矩形宽度` = `800 - 50 = 750`
- **上边界**：矩形不能跑到窗口上边外面，所以 `y` 不能小于 `0`
- **下边界**：矩形不能跑到窗口下边外面，所以 `y` 不能大于 `窗口高度 - 矩形高度` = `600 - 50 = 550`

用代码来表达就是：

```python
WINDOW_WIDTH = 800
WINDOW_HEIGHT = 600
RECT_WIDTH = 50
RECT_HEIGHT = 50

# 移动矩形后，立即进行边界检查
if x < 0:                          # 如果跑出左边界
    x = 0                          # 就停在左边界上
if x > WINDOW_WIDTH - RECT_WIDTH:  # 如果跑出右边界
    x = WINDOW_WIDTH - RECT_WIDTH  # 就停在右边界上
if y < 0:                          # 如果跑出上边界
    y = 0                          # 就停在上边界上
if y > WINDOW_HEIGHT - RECT_HEIGHT: # 如果跑出下边界
    y = WINDOW_HEIGHT - RECT_HEIGHT # 就停在下边界上
```

**为什么要减去矩形自身的大小？**

因为 `(x, y)` 是矩形左上角的坐标。如果只看 `x < 800`，矩形左上角在窗口内不代表整个矩形都在窗口内——矩形还会有向右延伸的 50 像素。所以右边界的限制是 `800 - 50 = 750`，同样的，下边界是 `600 - 50 = 550`。

可以这样理解：**边界限制的不是矩形的"原点"，而是矩形的"整个身体"。**

**更优雅的写法——使用 `max()` 和 `min()`：**

```python
# 一行代码搞定边界限制（更高级的写法，供感兴趣的同学参考）
x = max(0, min(x, WINDOW_WIDTH - RECT_WIDTH))
y = max(0, min(y, WINDOW_HEIGHT - RECT_HEIGHT))
```

这个怎么理解呢？
- `min(x, 750)`：取 `x` 和 `750` 中较小的那个，保证 `x` 不超过 750
- `max(0, ...)`：取 `0` 和上一步结果中较大的那个，保证 `x` 不小于 0

两层嵌套之后，`x` 就被牢牢限制在 `0` 到 `750` 之间了。

#### 3.3 完整参考答案

```python
import pygame
import sys
import random

# 初始化
pygame.init()

# 窗口设置
WINDOW_WIDTH = 800
WINDOW_HEIGHT = 600
screen = pygame.display.set_mode((WINDOW_WIDTH, WINDOW_HEIGHT))
pygame.display.set_caption("我的键盘遥控器")

# 矩形设置
RECT_SIZE = 50
x = WINDOW_WIDTH // 2 - RECT_SIZE // 2    # 水平居中
y = WINDOW_HEIGHT // 2 - RECT_SIZE // 2   # 垂直居中
color = (0, 128, 255)                      # 初始颜色：蓝色
speed = 5                                  # 移动速度

# 帧率控制
clock = pygame.time.Clock()

# 游戏主循环
running = True
while running:
    # ========== 事件处理 ==========
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

        # 空格键变色（单次操作，用事件方式）
        if event.type == pygame.KEYDOWN:
            if event.key == pygame.K_SPACE:
                r = random.randint(0, 255)
                g = random.randint(0, 255)
                b = random.randint(0, 255)
                color = (r, g, b)

    # ========== 键盘轮询（连续移动） ==========
    keys = pygame.key.get_pressed()
    if keys[pygame.K_LEFT]:
        x -= speed
    if keys[pygame.K_RIGHT]:
        x += speed
    if keys[pygame.K_UP]:
        y -= speed
    if keys[pygame.K_DOWN]:
        y += speed

    # ========== 边界限制 ==========
    if x < 0:
        x = 0
    if x > WINDOW_WIDTH - RECT_SIZE:
        x = WINDOW_WIDTH - RECT_SIZE
    if y < 0:
        y = 0
    if y > WINDOW_HEIGHT - RECT_SIZE:
        y = WINDOW_HEIGHT - RECT_SIZE

    # ========== 绘制画面 ==========
    screen.fill((255, 255, 255))                          # 白色背景
    pygame.draw.rect(screen, color, (x, y, RECT_SIZE, RECT_SIZE))  # 画矩形
    pygame.display.update()                                # 刷新屏幕
    clock.tick(60)                                        # 60 FPS

# 退出
pygame.quit()
sys.exit()
```

#### 3.4 课堂巡视要点

在学生练习过程中，教师应注意检查以下常见错误：

1. **缩进错误**：`keys` 相关代码写在 `for event` 循环里面了，导致按住键也动不了。
2. **变量名拼写**：`K_LEFT` 写成了 `K_LEFTT` 或 `K_lEFT`（注意大小写）。
3. **忘记边界限制**：矩形跑出屏幕不见了。
4. **忘记 `pygame.display.update()`**：画面不刷新，看不到移动效果。
5. **`speed` 值太大或太小**：太快控制不住，或太慢感觉不到移动。

### 四、总结与作业（5分钟）

#### 4.1 本节课重点回顾

1. **事件机制**：游戏通过 `pygame.event.get()` 接收玩家的操作信号，这就是事件。
2. **QUIT 事件**：处理窗口关闭，否则程序关不掉。
3. **KEYDOWN 事件**：检测按键被按下的瞬间，`event.key` 可以知道是哪个键。
4. **方向键常量**：`K_LEFT`、`K_RIGHT`、`K_UP`、`K_DOWN`。
5. **两种检测方式**：
   - `event.get()`：事件驱动，适合单次操作（跳跃、发射、开关菜单）
   - `key.get_pressed()`：轮询检测，适合连续操作（角色移动、赛车驾驶）
6. **边界限制**：用 `if` 条件判断，防止角色移出窗口，记得减去角色自身的大小。

## 💡 常见问题与解决

### Q1：为什么我按住方向键，矩形不动？

**可能原因一**：你把 `keys = pygame.key.get_pressed()` 和对应的 `if` 判断写在 `for event` 循环里面了。记住：`key.get_pressed()` 要写在事件循环外面，和 `for event` 平级。

**可能原因二**：你用的是 `KEYDOWN` 事件方式（`event.key == pygame.K_LEFT`），这种方式只在按下的瞬间触发一次，按住不动。想要连续移动，要用 `key.get_pressed()`。

### Q2：为什么我的矩形会跑出屏幕？

你忘记了添加边界限制代码。在每次移动矩形之后，用 `if` 判断位置并修正。

### Q3：边界限制为什么要减去矩形大小？

因为 `(x, y)` 是矩形**左上角**的坐标。如果限制条件写成 `x < 800` 和 `y < 600`，那矩形右半边和下半边还是会超出窗口。必须减去矩形自身的宽高：`x < 800 - 50`、`y < 600 - 50`。

### Q4：event.get() 和 key.get_pressed() 到底有什么区别？我还是搞不懂。

记住两个场景：

- **玩超级玛丽**：按一下空格键，马里奥跳一次。你按住空格不放，马里奥也只跳一次，不会一直飞在天上。这是用 `event.get()` 处理的。
- **玩赛车游戏**：按住方向键不放，赛车一直拐弯。你按多久，它就拐多久。这是用 `key.get_pressed()` 处理的。

**什么时候用哪个，取决于你想要"按一下就做一次"还是"按住就一直做"。**

### Q5：我的空格键按一次变了两次颜色，怎么回事？

`KEYDOWN` 事件可能会因为键盘的"重复延迟"而触发多次（操作系统认为你按住不放就等于多次按下）。如果你希望严格按一次只变一次，可以给空格键用 `event.get()` 方式，这通常是正常的。如果还是触发多次，检查一下你的键盘设置。

### Q6：键盘检测代码写在哪里比较好？

推荐的代码组织方式：

```python
while running:
    # 1. 事件处理（处理 QUIT、KEYDOWN 等单次事件）
    for event in pygame.event.get():
        ...

    # 2. 轮询检测（处理连续按键，如方向键移动）
    keys = pygame.key.get_pressed()
    ...

    # 3. 游戏逻辑（边界限制、碰撞检测等）
    ...

    # 4. 绘制画面
    ...
```

保持这个顺序，代码清晰又不容易出错。
