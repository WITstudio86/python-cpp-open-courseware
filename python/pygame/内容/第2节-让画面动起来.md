### 二、核心讲解（25分钟）

#### 2.1 动画的秘密：游戏主循环（8分钟）

**关键概念**：动画 = 一张一张的静态画面快速切换

就像翻页动画书——每页画得稍微不同，快速翻动时就"动"起来了！

```
帧1: 矩形在左边  →  帧2: 矩形在中间  →  帧3: 矩形在右边
  ┌────────┐         ┌────────┐         ┌────────┐
  │  ┌──┐  │         │    ┌──┐ │         │      ┌──┐
  │  └──┘  │         │    └──┘ │         │      └──┘
  └────────┘         └────────┘         └────────┘
     ↓                   ↓                   ↓
  快速连续播放 → 矩形看起来就在移动了！
```

**游戏主循环的结构**：

```python
while True:                          # 无限循环（游戏运行期间）
    # 1. 处理输入（键盘、鼠标等）
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    # 2. 更新游戏状态（移动位置、检测碰撞等）
    rect_x += speed_x                # 改变矩形的位置
    rect_y += speed_y

    # 3. 绘制画面（清屏 → 画图 → 显示）
    screen.fill(BLACK)               # 擦掉上一帧
    pygame.draw.rect(screen, color, (rect_x, rect_y, w, h))  # 画新位置
    pygame.display.flip()            # 翻到屏幕上

    # 4. 控制速度
    clock.tick(60)                   # 每秒最多60帧
```

**每个循环 = 1 帧**，一帧里做的事情：**处理输入 → 更新状态 → 绘制画面 → 控制速度**

#### 2.2 帧率控制：为什么需要 Clock？（5分钟）

**FPS = Frames Per Second（每秒帧数）**

| FPS 值 | 效果 | 类比 |
|--------|------|------|
| 1 FPS | 画面卡顿，像幻灯片 | 翻书翻得很慢 |
| 30 FPS | 基本流畅 | 正常翻书速度 |
| 60 FPS | 非常流畅 | 快速翻书 |
| 不控制 | 飘忽不定，不同电脑速度不同 | ❌ 不可取 |

```python
clock = pygame.time.Clock()  # 创建一个"节拍器"
# ... 在主循环中 ...
clock.tick(60)  # 控制每秒不超过 60 帧
```

**为什么需要控制帧率？**
- 没有 Clock：电脑快就跑得快，电脑慢就跑得慢，不同电脑上表现不一致
- 有了 Clock：所有电脑上都按统一的速度运行

**生活类比**：Clock 就像一个**节拍器**，嘀嗒一下走一帧，保证节奏稳定。

#### 2.3 清屏与重绘：fill() 的重要性（5分钟）

> 让学生**先运行没有 `screen.fill()` 的版本**，观察"拖尾"效果，再解释原理。

**如果没有 fill()**：

```
帧1        帧2        帧3
┌─┐       ┌──┐      ┌───┐
└─┘  →   └──┘  →  └───┘    ← 新矩形和旧矩形都在屏幕上
 └─┘       └──┘
            └─┘
```

矩形会留下"尾巴"！因为旧位置没有被擦掉。

**有了 fill()**：

```
帧1        帧2        帧3
┌─┐       ┌──┐      ┌───┐
└─┘  →   └──┘  →  └───┘
(擦干净)   (擦干净)   (擦干净)
```

每帧先用背景色覆盖整个画面，再画新内容。像在黑板上写字前，先把上一行的擦掉。

#### 2.4 绘制矩形：draw.rect()（4分钟）

```python
pygame.draw.rect(画布, 颜色, (x坐标, y坐标, 宽度, 高度))
```

**参数说明**：

| 参数 | 含义 | 示例 |
|------|------|------|
| `screen` | 要画在哪个画布上 | 我们的窗口 |
| 颜色 | RGB 元组 | `(255, 0, 0)` 红色 |
| x | 矩形左上角的 X 坐标 | 100 |
| y | 矩形左上角的 Y 坐标 | 200 |
| width | 矩形的宽度 | 120 |
| height | 矩形的高度 | 80 |

```python
# 画一个红色矩形：位置(100, 50)，大小 120×80
pygame.draw.rect(screen, (255, 0, 0), (100, 50, 120, 80))
```

#### 2.5 边缘反弹的原理（3分钟）

```python
# 碰到左边缘或右边缘？
if rect_x <= 0:                    # 左边出去了
    speed_x = -speed_x             # 速度反转（向右改成向左）

if rect_x >= WIDTH - rect_width:   # 右边出去了
    speed_x = -speed_x             # 速度反转（向左改成向右）

# 上下同理
if rect_y <= 0:
    speed_y = -speed_y
if rect_y >= HEIGHT - rect_height:
    speed_y = -speed_y
```

**关键理解**：
- `rect_x` 是矩形**左上角**的 X 坐标
- 矩形的右边缘位置 = `rect_x + rect_width`
- 碰到右边缘的条件是：`rect_x + rect_width >= WIDTH`，即 `rect_x >= WIDTH - rect_width`

## 💡 常见问题与解决

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 矩形不动 | 更新速度的代码写在了主循环外面 | 确保 `rect_x += speed_x` 在 `while` 循环内部 |
| 矩形移动太快/太慢 | FPS 设置不合适或速度值太大/太小 | 调整 `FPS`（建议 30~60）或 `speed_x`/`speed_y`（建议 1~10） |
| 矩形飞出窗口不见 | 没有写碰撞检测 | 添加边缘反弹的条件判断 |
| 矩形留下拖尾 | 没有调用 `screen.fill()` | 在每帧绘制前先 `fill(背景色)` |
| 窗口仍然是无响应状态 | 事件循环没有正确处理 QUIT 事件 | 检查 `for event in pygame.event.get()` 和 `QUIT` 判断 |
| 矩形颜色没有变化 | 忘记在反弹时更新 `rect_color` | 在反弹代码块中添加颜色切换逻辑 |
| 程序报错 `pygame.error` | 颜色值超出范围或坐标格式错误 | 检查 RGB 值是否在 0~255 之间，draw.rect 参数是否为元组 |
