### 二、核心讲解（25分钟）

#### 2.1 第一关：用字典存储物品属性（8分钟）

**问题引出：**

> 上节课我们用 `Rect` 表示水果，Rect 只有 x、y、width、height 四个属性。现在我们需要为每个下落的物品记录更多信息：
> - 它的**类型**是什么？（苹果/西瓜/香蕉/炸弹）
> - 它的**分值**是多少？（接到加几分）
> - 它的**下落速度**是多少？（快还是慢）

**解决方案：用字典！**

字典是 Python 中非常强大的容器。它可以让我们把一组相关的信息打包在一起，用一个变量来表示。

```python
# 上节课：一个水果只是一个 Rect
fruit_rect = pygame.Rect(400, 0, 30, 30)

# 本节课升级：一个物品 = 一个字典，包含所有属性！
item = {
    "rect": pygame.Rect(400, 0, 30, 30),  # 位置和大小
    "type": "apple",                        # 物品类型
    "score": 10,                            # 接到加几分
    "speed": 3                              # 下落速度
}

# 同理，炸弹是另一种物品：
bomb = {
    "rect": pygame.Rect(200, 0, 25, 25),
    "type": "bomb",
    "score": -50,                           # 接到扣分！
    "speed": 5                              # 炸弹掉得更快
}
```

**字典的读取和修改：**

```python
# 读取字典中的值
item_type = item["type"]      # "apple"
item_score = item["score"]    # 10
item_rect = item["rect"]      # pygame.Rect(...)

# 修改字典中的值
item["rect"].y += item["speed"]  # 让水果下落
item["speed"] += 0.1             # 随时间加速（后面细讲）
```

**为什么用字典更好？**
- 所有跟这个物品相关的信息都放在一起，不会乱
- 传参数方便：只需传一个 `item` 变量，不用传一堆变量
- 新增属性容易：想加颜色？加一个 `"color"` 键就行

**多种水果的配置表**（用列表装字典）：

```python
# 水果类型配置表：每种水果的默认属性
FRUIT_TYPES = [
    {"type": "apple",  "score": 10, "speed": 3, "color": (255, 0, 0),    "size": 30},
    {"type": "banana", "score": 15, "speed": 2, "color": (255, 255, 0),  "size": 28},
    {"type": "berry", "score": 20, "speed": 4, "color": (255, 0, 255),   "size": 20},
    {"type": "melon",  "score": 30, "speed": 5, "color": (0, 200, 0),    "size": 40},
    {"type": "bomb",   "score": -50, "speed": 6, "color": (50, 50, 50),  "size": 26},
]
```

> **小贴士**：先定义一个"配置表"，然后在生成物品时从配置表里拷贝一份，这样修改每个物品的速度时不会影响配置表中的原始值。

**生成物品的代码：**

```python
import copy

def create_item(difficulty_speed=0):
    """随机生成一个水果或炸弹"""
    # 1. 从 FRUIT_TYPES 中随机选一种
    config = random.choice(FRUIT_TYPES)
    # 2. 拷贝配置（用 copy 避免修改原表）
    item = config.copy()
    # 3. 为这个物品创建 Rect
    x = random.randint(50, WIDTH - 50)
    size = item["size"]
    item["rect"] = pygame.Rect(x, -size, size, size)
    # 4. 在基础速度上加上难度速度
    item["speed"] = item["speed"] + difficulty_speed
    return item
```

#### 2.2 第二关：用 random.randint 控制出现概率（5分钟）

**问题引出：**

> 我们希望炸弹偶尔出现，不能太多（不然玩家会疯掉），也不能太少（不然没挑战）。大概每 10 个物品中出现 1 个炸弹，怎么实现？

**思路：用 random.randint 做概率抽奖！**

```python
# 方法一：用 randint 模拟概率（最直观，推荐给初学者）
# 生成 1~10 的随机整数，如果是 10（概率 10%），就生成炸弹
def create_item_with_probability(difficulty_speed=0):
    rand_num = random.randint(1, 10)  # 1 到 10（包含10）
    if rand_num == 10:
        # 10% 概率 → 生成炸弹
        config = FRUIT_TYPES[4]  # 炸弹在配置表的第5个（索引4）
    else:
        # 90% 概率 → 生成水果
        config = random.choice(FRUIT_TYPES[:4])  # 只在前4个水果中选
    # ... 后续创建物品的代码
```

**讲解要点：**

| `random.randint(1, 10)` 的值 | 概率 | 产生什么 |
|------|------|------|
| 1 ~ 9 | 90% | 水果（前4种随机选一个） |
| 10 | 10% | 炸弹 |

> **类比理解**：就像你有一个 10 面的骰子，掷出 10 就是炸弹，掷出 1~9 就是水果。非常直观！

**扩展：如果想让炸弹概率可调节？**

```python
BOMB_CHANCE = 8  # 炸弹概率 = 1/8 = 12.5%
rand_num = random.randint(1, BOMB_CHANCE)
if rand_num == BOMB_CHANCE:
    # 生成炸弹
    ...
```

> **思考题**：如果想把炸弹概率改成 5%，怎么做？（答案：`randint(1, 20)` 判断是否为 20）

#### 2.3 第三关：难度递增（7分钟）

**问题引出：**

> 从上节课的程序可以看到，水果下落速度一直是固定的（比如 `speed = 5`）。如果从头到尾都这个速度，玩久了会觉得无聊。怎么做才能让游戏越来越难、越来越刺激呢？

**核心思路：速度随时间递增！**

```python
# 游戏开始的时间戳
start_time = pygame.time.get_ticks()  # 返回游戏从开始到当前的毫秒数

# 在游戏循环中计算已经过的秒数
elapsed_seconds = (pygame.time.get_ticks() - start_time) / 1000

# 根据已过时间动态计算难度速度
difficulty_speed = elapsed_seconds * 0.1  # 每秒增加 0.1 的速度
```

**难度增加的几种方式：**

```python
# 方式一：线性递增（最简单）
# 每秒物品速度增加 0.1
difficulty_speed = elapsed_seconds * 0.1

# 方式二：阶梯递增（每 10 秒上一个台阶）
level = elapsed_seconds // 10  # 0, 1, 2, 3, ...
difficulty_speed = level * 1.0  # 每个台阶速度加 1

# 方式三：生成间隔缩短（单位时间内物品更多）
base_interval = 60  # 初始每60帧生成一个物品
extra_interval = elapsed_seconds * 0.5  # 每秒缩短0.5帧间隔
spawn_interval = max(20, base_interval - extra_interval)  # 最小间隔20帧
```

**完整示例（速度递增 + 生成加速）：**

```python
# 初始化
start_time = pygame.time.get_ticks()
frame_count = 0
items = []  # 存储所有下落的物品（字典列表）

# 游戏循环中
while running:
    elapsed = (pygame.time.get_ticks() - start_time) / 1000

    # 难度计算
    difficulty_speed = elapsed * 0.15            # 速度每秒增加 0.15
    spawn_interval = max(15, int(60 - elapsed))  # 生成间隔越来越短

    # 生成物品
    if frame_count % spawn_interval == 0:
        new_item = create_item_with_probability(difficulty_speed)
        items.append(new_item)

    # 更新每个物品的位置
    for item in items[:]:  # 用切片遍历，方便边遍历边删除
        item["rect"].y += item["speed"]
        # 飞出屏幕底部的删除
        if item["rect"].top > HEIGHT:
            items.remove(item)

    # ... 碰撞检测和绘制
    frame_count += 1
```

**速度递增 vs 速度不变 对比图**（板书）：

```
速度
  |                                    ╱
 8 |  难度递增模式                  ╱
 7 |                            ╱
 6 |                        ╱
 5 | ────────────────────────  固定速度模式（上节课）
 4 |
 3 |
 2 |
 1 |
 0 └──────────────────────────— 时间（秒）
    0   10   20   30   40   50   60
```

> **要点**：难度递增的核心就是——用一个随时间不断增长的变量，加在物品的基础速度上。时间越久，变量越大，物品越快！

#### 2.4 第四关：游戏状态机 —— playing 和 game_over（5分钟）

**问题引出：**

> 上节课的程序只有一个简单的游戏循环，游戏结束后窗口就直接关闭了。用户来不及看自己得了多少分，也没法选择"再来一局"。
>
> 在一个成熟的游戏中，通常会有不同的"状态"：
> - **开始画面**（标题、按任意键开始）
> - **游戏进行中**（playing）—— 正常玩
> - **暂停**（paused）—— 暂停中
> - **游戏结束**（game_over）—— 显示得分、按 R 重新开始

**什么是状态机？**

> 状态机就像红绿灯：红灯时只能等，绿灯时才能走，黄灯时准备停。游戏中的不同状态也是这样，不同状态下程序做的事情完全不同。

```
                   按空格键开始
       ┌──────────────┐
       │              ▼
  ┌────┴────┐   ┌──────────┐   生命归零   ┌──────────┐
  │ 开始画面 │──▶│ playing  │───────────▶│ game_over │
  └─────────┘   └──────────┘             └──────────┘
                      ▲                        │
                      │       按 R 重新开始      │
                      └────────────────────────┘
```

**代码实现：**


**game_over 画面的绘制示例：**

```python
def draw_game_over(screen, score):
    """绘制游戏结束画面"""
    # 半透明遮罩（让背景变暗）
    overlay = pygame.Surface((WIDTH, HEIGHT))
    overlay.set_alpha(180)  # 透明度：0=完全透明，255=完全不透明
    overlay.fill((0, 0, 0))
    screen.blit(overlay, (0, 0))

    # 显示"游戏结束"文字
    font_big = pygame.font.Font(None, 72)
    text = font_big.render("GAME OVER", True, (255, 50, 50))
    screen.blit(text, (WIDTH//2 - text.get_width()//2, HEIGHT//2 - 80))

    # 显示最终分数
    font_medium = pygame.font.Font(None, 48)
    score_text = font_medium.render(f"最终得分: {score}", True, (255, 255, 255))
    screen.blit(score_text, (WIDTH//2 - score_text.get_width()//2, HEIGHT//2))

    # 提示重新开始
    font_small = pygame.font.Font(None, 36)
    restart_text = font_small.render("按 R 键重新开始", True, (200, 200, 200))
    screen.blit(restart_text, (WIDTH//2 - restart_text.get_width()//2, HEIGHT//2 + 60))
```

**状态机的核心要点：**

| 要点 | 说明 |
|------|------|
| 状态切换 | 用 `=` 赋值改变 `game_state` 变量 |
| 逻辑隔离 | 用 `if game_state == ...` 让不同状态执行不同代码 |
| 数据重置 | 从 game_over 回到 playing 时，要重置所有变量 |
| 画面区分 | playing 画游戏内容，game_over 画结束画面 |

> **形象理解**：状态机就像你的一天——早上是"起床状态"，做的是刷牙洗脸；白天是"学习状态"，做的是上课写作业；晚上是"睡觉状态"，做的是关灯躺下。不同状态下做的事情完全不同，但都是"你"这个程序在执行。用一个 `game_state` 变量来标记当前处于哪个状态，程序就知道该做什么了。

```python
    # 无敌中，炸弹无效
    pass
```

**挑战3：连击加分**

连续接到水果时，加成分数递增：
- 第1个：正常分数
- 第2个（连续）：1.5 倍
- 第3个（连续）：2 倍
- （漏接一个后连击中断）

```python
combo = 0  # 当前连击数

# 接到水果时
combo += 1
bonus_score = item["score"] * (1 + combo * 0.5)
score += int(bonus_score)

# 漏接水果时（水果飞出屏幕）
combo = 0
```

**挑战4：水果飞行轨迹**

加入水平方向的速度（vx），让水果不是垂直下落，而是斜着飞，增加趣味性：

```python
item["vx"] = random.uniform(-1.5, 1.5)  # 水平速度
# 更新时
item["rect"].x += item["vx"]
item["rect"].y += item["speed"]
```

## 💡 常见问题与解决

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 物体不显示了 | 从 Rect 列表改成字典列表后，忘记 `["rect"]` 访问 | 绘制时用 `item["rect"]` 而不是直接用 `item` |
| 修改了配置表中的原始数据 | 直接用 `=` 赋值而不是 `copy()` | 用 `item = config.copy()` 拷贝后再修改 |
| 炸弹出现过多/过少 | `randint` 参数写错 | 检查 `randint(1, 10)` 范围是否正确（含10） |
| 速度递增太快导致游戏不可玩 | `elapsed * 0.5` 系数太大 | 减小系数，如 `elapsed * 0.1`，并设置速度上限 |
| 重新开始后速度还在飞速增长 | 没有重置 `start_time` | 在重置游戏时 `start_time = pygame.time.get_ticks()` |
| 按下 R 键不能重新开始 | 只检查了 `KEYDOWN` 但没用 `event.key` | 用 `event.type == pygame.KEYDOWN and event.key == pygame.K_r` |
| game_over 画面只闪一下就没了 | 状态切换后没有正确隔离逻辑 | 确保更新和绘制都包在 `if game_state == PLAYING:` 中 |
| 字典的 key 写错了（如 `"typ"` 写成了 `"type"`） | 拼写错误 | 仔细检查 key 的拼写，统一定义常量避免手打 |

> **特别提醒（关于状态机）**：最常见的 bug 是 game_over 画面一闪而过，然后又回到 playing。原因是：在 `KEYDOWN` 事件中重置了变量并设置了 `PLAYING`，但同一帧中如果有物品碰到篮子把分数扣到负数……又会触发 `GAME_OVER`。解决方案：重置时把 `lives` 设成大于 0 的值，或者重置逻辑中同时也重置碰撞状态。
