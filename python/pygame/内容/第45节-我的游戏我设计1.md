# 第45节：我的游戏我设计①

## 🎯 教学目标
- 学生能够综合运用所学Pygame知识，独立设计游戏方案
- 学生能够进行需求分析，拆解游戏功能模块
- 学生能够独立排查和解决编程中的Bug
- 学生能够进行有效的团队协作与分工（如分组）

## ⏱️ 时间分配（60分钟）
| 环节 | 时间 | 内容 |
|------|------|------|
| 导入与选题引导 | 10min | 回顾已学项目，激发创作灵感 |
| 需求分析与设计 | 15min | 每组确定游戏方案，画出设计草图 |
| 编程实践 | 30min | 开始编写代码，老师巡回指导 |
| 进度小结 | 5min | 各组汇报进度，明确下次目标 |

## 📖 教学内容

### 一、导入与选题引导（10分钟）

#### 1.1 热身互动（3分钟）

**教师话术：**
> "同学们，今天是一个特别的日子！我们从第1节课走到现在，已经一起做了多少个小游戏？"

让学生七嘴八舌地回忆。老师引导归纳：

> "我们来数一数——弹球消砖块、接苹果、贪吃蛇、打地鼠、限时挑战、翻牌配对、战机起飞、躲避陨石、2048数字合并、无限跳跃、Flappy Bird、太空射击、赛车漂移、迷宫探险、塔防、俄罗斯方块、平台跳跃、炸弹人、弹幕射击、推箱子、回合对战、方块消消看……已经有二十多个项目了！"

**板书/PPT展示已学项目清单**（激发自豪感）：
```
弹球消砖块   接苹果      贪吃蛇      打地鼠      限时挑战
翻牌配对     战机起飞    躲避陨石    2048       无限跳跃
Flappy Bird  太空射击    赛车漂移    迷宫探险    塔防
俄罗斯方块   平台跳跃    炸弹人      弹幕射击    推箱子
回合对战     方块消消看
```

#### 1.2 宣布任务（3分钟）

**教师话术：**
> "今天开始，我们进入这门课最后一个阶段——'我的游戏我设计'。接下来的两节课（第45节和46节），你们每个人或每个小组，要**自己设计、自己开发一个完整的游戏**。"
>
> "这个游戏可以是对之前某个项目的改造升级——比如给贪吃蛇加上关卡、给飞机大战加上Boss战；也可以是一个全新的创意——你脑子里一直想做的那个游戏，现在就是实现它的机会！"
>
> "下节课第47节，我们会举办'游戏博览会'，每个人都要上台展示自己的作品，让同学试玩。第48节我们还会颁奖——最佳创意奖、最佳技术奖、最受欢迎奖、最佳进步奖！"

**关键要点**：用"游戏博览会 + 颁奖"制造期待感和仪式感，激发学生的创作动力。

#### 1.3 选题引导（4分钟）

**教师话术：**
> "有同学可能想：'我想做，但我不知道做什么…'没关系，老师给大家一些灵感。"

**选题灵感清单（PPT展示/板书）：**

| 类别 | 具体方向 | 难度参考 |
|------|----------|----------|
| 改造升级 | 给贪吃蛇加上障碍物和关卡 | ★★☆ |
| 改造升级 | 给飞机大战加上Boss战和技能系统 | ★★★ |
| 改造升级 | 给推箱子设计更多关卡（用文件读取） | ★★☆ |
| 改造升级 | 给俄罗斯方块加上对战模式 | ★★★ |
| 改造升级 | 给2048加上撤销和存档功能 | ★★☆ |
| 全新创意 | 弹球打砖块（Breakout） | ★★☆ |
| 全新创意 | 井字棋/五子棋 | ★★☆ |
| 全新创意 | 记忆翻牌（自己设计卡牌图案） | ★★☆ |
| 全新创意 | 跑酷游戏（简单版） | ★★★ |
| 全新创意 | 射击僵尸/怪物 | ★★★ |
| 全新创意 | 音乐节奏游戏 | ★★★★ |
| 全新创意 | 投篮/射门小游戏 | ★★☆ |
| 全新创意 | 你画我猜 | ★★★ |
| 全新创意 | 宠物养成（电子宠物） | ★★★★ |

**互动环节——"灵感碰撞"：**
> "现在给大家1分钟，和旁边的同学讨论一下：你想做什么游戏？为什么想做这个？"
> 
> 1分钟后，随机请2-3位同学分享想法，老师给予积极反馈和适度引导。

**教师引导原则：**
- 对想法太大（不可能2节课完成）的学生：帮他缩小范围。"Boss战可以先做1个Boss、3种技能，不用做10个Boss。"
- 对想法太简单（几分钟就能做完）的学生：帮他增加挑战。"光接苹果有点简单，要不要加上'炸弹'——接到了扣分？"
- 对完全没有想法的学生：建议他从"改造升级"方向选一个，降低决策门槛。
- **所有想法都先肯定，再给建设性建议。**

### 二、需求分析与设计（15分钟）

#### 2.1 设计引导（5分钟）

**教师话术：**
> "有想法了，但先别急着写代码。我们先做一件程序员最重要的事——**需求分析**。就是把你脑子里的游戏，变成一张清晰的'设计图'。"

**发给每组/每人一张"游戏设计卡"（可提前打印或让学生在纸上画）：**

```
┌─────────────────────────────────────────┐
│           🎮 我的游戏设计卡              │
├─────────────────────────────────────────┤
│ 游戏名称：_____________________________ │
│                                         │
│ 游戏类型：□ 动作 □ 益智 □ 射击 □ 其他____│
│                                         │
│ 游戏玩法（一句话描述）：                 │
│ _______________________________________ │
│                                         │
│ 操作方式：□ 键盘 □ 鼠标 □ 混合          │
│ 具体按键：______________________________ │
│                                         │
│ 获胜条件：______________________________ │
│ 失败条件：______________________________ │
│                                         │
│ 需要哪些游戏元素？（多选）               │
│ □ 玩家角色 □ 敌人 □ 子弹 □ 道具         │
│ □ 分数 □ 生命值 □ 关卡 □ 计时器          │
│ □ 其他：_______________                 │
│                                         │
│ 功能模块拆解：                           │
│ 1. ___________________（优先级：高/中/低）│
│ 2. ___________________（优先级：高/中/低）│
│ 3. ___________________（优先级：高/中/低）│
│ 4. ___________________（优先级：高/中/低）│
│                                         │
│ 你准备用到的知识点：                     │
│ □ Rect碰撞  □ 列表  □ 字典  □ 函数       │
│ □ 状态机  □ 精灵类  □ 定时器  □ 其他____ │
└─────────────────────────────────────────┘
```

**教师引导填写**（边引导学生边填，逐一解释每个字段）：
> "游戏名称——给你的游戏起一个酷炫的名字！"
> "玩法——用一句话说清楚玩家要干什么。比如'控制飞机躲避陨石，活得越久分数越高'。"
> "功能模块——把大任务拆成小任务。比如做贪吃蛇升级版，模块可以是：1.蛇的移动 2.食物生成 3.障碍物碰撞 4.分数系统。给每个模块标优先级——先做最重要的！"

#### 2.2 独立设计（8分钟）

学生独立或小组讨论填写"游戏设计卡"。老师巡回，关注以下几点：

- **是否在能力范围内**：2节课（约60-90分钟编程时间）能否完成
- **功能是否拆解得足够细**：有没有学生写"做一个完整的RPG"——帮他拆成"角色移动 → 对话系统 → 战斗系统"，告诉他这节先做其中1-2个
- **知识点是否匹配**：检查学生列出的知识点是否足以支撑他的设计
- **鼓励原创性**：对独特的想法大力表扬

#### 2.3 快速分享（2分钟）

**教师话术：**
> "好了，设计卡填完的同学举一下手。我来随机请2位同学分享一下他们的设计——不用很详细，就说：你做什么游戏 + 核心玩法是什么。"

快速点名分享，老师做简短点评/鼓励，目的是：
- 让还犹豫的同学听到别人的想法获得启发
- 营造"大家都在认真创作"的氛围

### 三、编程实践（30分钟）

#### 3.1 开写前的叮嘱（2分钟）

**教师话术：**
> "在大家开始写代码之前，老师有三句'金句'送给大家："

> **金句1**："先跑起来，再变漂亮。先让最核心的功能能动，再去想颜色好不好看、字体大不大。"
> 
> **金句2**："遇到Bug别怕，Bug是你的老师。每修好一个Bug，你就变强了一点点。"
> 
> **金句3**："做了再说，别想太多。哪怕今天的代码很烂，那也是你的代码——明天可以改。不写的话，永远没有。"

**交代规则：**
> "编程时遇到问题，先自己试3分钟——看报错信息、回想之前学过的方法。如果还解决不了，举手，老师过来帮你。如果老师在帮别的同学，你可以先问同组的伙伴。"

#### 3.2 编程实践阶段（28分钟）

**教师角色：巡回指导者，不是演讲者。**

**巡回指导策略：**

| 阶段 | 时间 | 老师做什么 |
|------|------|-----------|
| 启动期 | 前5分钟 | 观察所有人是否都开始敲代码了。对还在发呆的同学：坐下，帮他打开编辑器，引导他写出第一行 `import pygame`，打破"空白文件恐惧症"。 |
| 稳定期 | 5-20分钟 | 巡查，重点关注：① 游戏窗口能不能跑起来 ② 主循环结构对不对 ③ 有没有明显的逻辑错误。发现问题先不直接告诉答案，用提问引导："你觉得这行代码在干什么？""你期望它干什么？""实际它干了什么？" |
| 深入期 | 20-28分钟 | 开始帮助遇到具体技术问题的同学。把共性问题记录在黑板角落（如"大家注意：rect的坐标要写成rect.x，不是rect[0]"），在下课前2分钟集中提醒。 |

**常见问题预判与应对：**

| 常见问题 | 引导话术 |
|----------|----------|
| "老师我写不出来…" | "没关系，你设计卡上第一个模块是什么？我们先只做这一个，把它做出来就好。" |
| "报错了！" | "很好！报错信息是程序员最好的朋友。来，我们一起读这行红字——它告诉你错在哪一行、什么错误？" |
| "我想做的太难了…" | "那我们降低一点难度。比如先把Boss做成一个不会动的大方块，能打中就行，后面再慢慢变复杂。" |
| "我的代码好乱…" | "没关系，第一版就是会很乱。功能跑通之后，我们再一起整理——这叫'重构'，很高级的词哦！" |
| 两个学生做一样的 | "挺好的！你们可以互相参考。但最后要有一点不一样哦——比如你的背景是太空，他的是海洋。" |
| 某个功能做不出来 | "这个确实有点难。我们换个思路——有没有更简单的方法实现差不多的效果？" |

**分组策略说明（给老师参考）：**

- **按能力分组**：不建议"强+弱"搭配（强的全包，弱的没事干）。建议"相近水平"搭配，或"个人独立做"。
- **按兴趣分组**：想做同类游戏的可以坐在一起，方便交流。
- **单人创作也完全可以**：不强求分组。有些学生喜欢独自完成，这完全OK。
- **最多3人一组**：人多容易有人"划水"。
- **每组/每人一个"主程"**：明确谁负责写代码。如果是2人组，可以一人写代码、一人负责测试和找素材。

#### 3.3 创意生成器Demo（可选环节）

如果班上有学生完全没有想法，可以在他们电脑上运行"游戏创意生成器"demo程序（见程序文件），点击按钮随机生成游戏创意组合，帮助他们打开思路。

**教师话术：**
> "还拿不定主意的同学，可以试试这个'创意生成器'——它会随机组合游戏类型、玩法和主题。不一定照做，就当灵感来源！"

### 四、进度小结（5分钟）

#### 4.1 各组快速汇报（3分钟）

**教师话术：**
> "好了，时间差不多了。请大家停一下——不需要保存关闭，手离开键盘就行。"
>
> "我来快速走一圈，每组用一句话告诉我：你们今天做了什么？遇到最大的困难是什么？下次课要继续做什么？"

快速听取汇报（每组不超过30秒），老师做简短回应：
- 对进展快的："很棒！下次课可以考虑加音效和优化UI。"
- 对遇到困难的："这个问题很典型，下次课我统一讲一下解决方案。"
- 对进展慢的："没关系，今天搭好了框架就是胜利，下次继续！"

#### 4.2 总结与预告（2分钟）

**教师话术：**
> "今天的表现非常好！我看到每个人都在认真设计自己的游戏，这就是程序员真正的工作方式——不是抄代码，而是创造代码。"
>
> "下节课（第46节），我们继续完善作品。到时候会讲两个新技能：**如何加音效和背景音乐**、**如何设置游戏图标**——让你的游戏更像一个'真正的游戏'。"
>
> "第47节就是我们的'游戏博览会'了！每个人都要上台演示——所以下节课一定要把游戏做到可以展示的程度。"
>
> "好，下课！记得保存你的代码！"

## 💡 教师指导要点

### 选题建议清单（给学生参考）

**适合1人独立完成（2节课）：**
- 弹球打砖块（Breakout）
- 井字棋/五子棋
- 记忆翻牌
- 贪吃蛇升级版（加障碍物）
- 接苹果升级版（加炸弹/加速）
- 简易跑酷（单键跳跃躲避障碍）
- 投篮小游戏（鼠标控制角度力度）

**适合2人小组完成（2节课）：**
- 飞机大战升级（Boss战 + 技能）
- 俄罗斯方块（含计分和等级）
- 打地鼠升级版（多种地鼠、道具）
- 双人对战（如双人贪吃蛇、双人射击）

**挑战级（学有余力的同学）：**
- 平台跳跃（带关卡设计）
- 射击僵尸（波次系统）
- 音乐节奏游戏（简易版）

### 分组策略建议

| 分组方式 | 适合情况 | 注意 |
|----------|----------|------|
| 个人独立 | 学生自驱力强，有明确想法 | 鼓励，不必强求合作 |
| 2人搭档 | 一个想逻辑、一个写代码 | 必须两人都动手写，不能一人全包 |
| 3人小组 | 项目较复杂，需分工 | 最大人数，再多容易有人不参与 |
| 按兴趣自由组合 | 想做同类项目的坐一起 | 互相参考但各有不同 |

### 时间弹性方案

- 如果学生大多在10分钟内确定了方案：提前进入编程阶段，把更多时间留给实践
- 如果有学生15分钟还没确定方案：老师直接帮他选一个，用"二选一"降低决策难度："弹球消砖块还是贪吃蛇升级版？"
- 如果编程阶段学生热情高涨：可适当延长编程时间，压缩小结到3分钟

### 教室布局建议

- 电脑座位按"创作区"布置：想做同类项目的坐在一起
- 在黑板/白板上留一块"求助区"：学生可以把遇到的问题写在上面，其他同学或老师看到后去帮助
- 老师不要固定在一个位置，要全场走动
