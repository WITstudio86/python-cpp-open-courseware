**1.2 引出问题（2分钟）**

好的，现在我们来思考一个问题：**如果你按了右方向键，但是棋盘上所有数字都靠在最右边了，没有任何移动发生——这时游戏应该生成一个新的数字吗？**

（让学生讨论 30 秒）

答案是：**不应该！** 如果棋盘没有发生任何变化，说明这个方向的移动是"无效的"，我们不希望凭空冒出新的数字。那么问题来了——我们怎么判断"移动前后棋盘有没有变化"呢？

我们需要在移动**之前**给棋盘拍一张"快照"，移动**之后**再和快照对比。如果一模一样，就是无效移动。而拍这张"快照"的方法，就是今天要学的第一个重要概念——**深拷贝（deepcopy）**。

### 二、核心知识讲解（25分钟）

**2.1 深拷贝 copy.deepcopy()（8分钟）**

**为什么不能用简单赋值？**

先看一段代码，大家猜猜会发生什么：

```python
# 错误示范：直接赋值
board = [[0, 2, 0, 0], [0, 0, 4, 0], [0, 0, 0, 0], [2, 0, 0, 0]]
before = board  # 这可不是"快照"！

# 执行移动逻辑……board 里面的数字发生了变化
# 现在去看看 before：
print(before)  # 哦豁！before 也跟着变了！
```

这是因为列表是**可变对象**，`before = board` 只是给同一个列表起了一个新名字，就像一个人有两个名字——叫哪个名字指的都是同一个人。无论通过 `board` 还是 `before` 修改，改的都是同一个东西。

**浅拷贝 vs 深拷贝——用画图理解**

想象一个列表 `board` 就像一栋公寓楼，每层（子列表）有四个房间（数字）：

```
浅拷贝 copy.copy(board)：
┌──────────────────────────────────┐
│  建了一栋新公寓楼（新的大列表）    │
│  但每层还是指向原来的楼层地址     │
│  所以改房间里的数字，原楼也会变   │
└──────────────────────────────────┘

深拷贝 copy.deepcopy(board)：
┌──────────────────────────────────┐
│  建了一栋全新的公寓楼             │
│  每层每个房间都是独立重建的       │
│  修改新楼的任何东西，原楼完全不变  │
└──────────────────────────────────┘
```

**2048 中的实际应用：**

```python
import copy

def move(board, direction):
    # 第一步：移动前，深拷贝一份棋盘快照
    board_before = copy.deepcopy(board)
    
    # 第二步：执行移动合并逻辑（上节课的代码）
    # ... 这里是对 board 的实际操作 ...
    
    # 第三步：移动后，对比棋盘是否发生了变化
    if board_before == board:
        # 棋盘一模一样 → 无效移动
        return False  # 不生成新数字
    else:
        # 棋盘有变化 → 有效移动
        return True   # 生成新数字
```

**关键点总结：**

| 方式 | 写法 | 效果 |
|------|------|------|
| 直接赋值 | `a = b` | 同一个对象，改一个另一个也变 |
| 浅拷贝 | `a = copy.copy(b)` 或 `a = b[:]` | 外层新对象，内层还是共享的 |
| 深拷贝 | `a = copy.deepcopy(b)` | 完全独立的新对象，改任何一个都不影响另一个 |

对于我们的棋盘 `board`（列表套列表），**必须用深拷贝**，因为内部的小列表也要独立复制。

**还有一个更简单的替代方法**：如果不想用 `copy.deepcopy`，也可以自己写一个函数，遍历棋盘把每个数字复制到新列表：

```python
def copy_board(board):
    new_board = []
    for row in board:
        new_row = []
        for num in row:
            new_row.append(num)
        new_board.append(new_row)
    return new_board
```

不过既然 Python 已经提供了 `copy.deepcopy()`，直接用就好——代码更简洁，不容易出错。

**2.2 胜利条件检测（5分钟）**

2048 的胜利条件很简单：**棋盘上出现一个 2048 数字，你就赢了！**

实现起来也非常直接——遍历棋盘每个格子，看有没有值是 2048 的：

```python
def check_win(board):
    """遍历棋盘，检查是否有格子达到 2048"""
    for row in range(4):
        for col in range(4):
            if board[row][col] == 2048:
                return True
    return False
```

或者用更 Pythonic 的写法：

```python
def check_win(board):
    return any(2048 in row for row in board)
```

**胜利后的处理：**

注意：检测到胜利不等于游戏立刻结束！2048 的设计是——达到 2048 后显示一个"你赢了！"的画面，但玩家可以**选择继续游戏**，挑战 4096、8192 甚至更高分：

```python
# 在游戏主循环中
if check_win(board) and not win_shown:
    # 显示胜利画面
    draw_win_screen(screen)
    win_shown = True
    # 按任意键继续游戏，按 R 重新开始
```

这样设计让学生体会到：2048 的目标不只是到达 2048，可以是不断挑战更高分！

**2.3 失败条件检测（7分钟）**

失败判定比胜利稍微复杂一点，需要**两步判断**：

**第一步：检查有没有空格（值为 0 的格子）**

```python
def has_empty(board):
    """检查棋盘上是否还有空格"""
    for row in range(4):
        for col in range(4):
            if board[row][col] == 0:
                return True
    return False
```

如果有空格，那玩家一定还能移动（把数字滑到空格里去）→ **没有失败**。

**第二步：如果没有空格，检查是否还能合并**

棋盘满了不代表一定输了——还要看有没有**相邻的相同数字**可以合并。需要检查四个方向：

```python
def can_merge(board):
    """检查棋盘上是否有相邻的相同数字（水平或垂直方向）"""
    for row in range(4):
        for col in range(4):
            current = board[row][col]
            # 检查右边（除了最后一列）
            if col < 3 and current == board[row][col + 1]:
                return True
            # 检查下方（除了最后一行）
            if row < 3 and current == board[row + 1][col]:
                return True
    return False
```

**完整失败判定函数：**

```python
def check_lose(board):
    """判断游戏是否失败：无空格且无相邻相同数字"""
    if has_empty(board):
        return False        # 还有空格，没失败
    if can_merge(board):
        return False        # 还能合并，没失败
    return True             # 既没空格又不能合并 → 失败！
```

这里有个常见的 bug：有的同学只检查了水平和垂直方向的相邻……但这是对的！因为 2048 只有上下左右四个移动方向，对角线方向不能合并，所以不需要检查对角线。

**在游戏主循环中的使用：**

```python
if check_lose(board):
    # 绘制失败画面
    draw_lose_screen(screen)
    game_over = True
```

**2.4 最高分记录保存（5分钟）**

一个好的 2048 游戏需要记住玩家的最高分，下次打开还能看到。我们可以用文件来保存。

**方案 A：使用文件保存（适合学了文件操作的同学）**

```python
import os

BEST_SCORE_FILE = "best_score.txt"

def load_best_score():
    """从文件读取历史最高分"""
    try:
        with open(BEST_SCORE_FILE, "r") as f:
            content = f.read().strip()
            if content:
                return int(content)
    except FileNotFoundError:
        # 文件不存在，说明第一次玩
        pass
    except ValueError:
        # 文件内容不是有效数字
        pass
    return 0  # 默认最高分为 0

def save_best_score(score):
    """将当前分数保存为最高分（覆盖写入）"""
    with open(BEST_SCORE_FILE, "w") as f:
        f.write(str(score))

# 使用方式：
best_score = load_best_score()

# 游戏循环中，每次移动后:
if current_score > best_score:
    best_score = current_score
    save_best_score(best_score)
```

**为什么用 `try-except`？** 因为文件可能不存在（第一次运行游戏），也可能被意外修改成奇怪的内容。用 `try-except` 来防止程序崩溃，这叫**防御性编程**。

**方案 B：只用变量（更简单，适合初学者）**

```python
best_score = 0  # 游戏运行期间的最高分

# 每次移动后：
if current_score > best_score:
    best_score = current_score
```

方案 B 的缺点是一关程序最高分就没了。但代码少，逻辑简单，可以先用变量实现，再升级到文件保存。

**在游戏界面上显示分数和最高分：**

```python
def draw_scores(screen, score, best_score):
    font = pygame.font.SysFont("Arial", 24)
    # 当前分数
    score_text = font.render(f"分数: {score}", True, (255, 255, 255))
    screen.blit(score_text, (20, 20))
    # 最高分
    best_text = font.render(f"最高: {best_score}", True, (255, 255, 0))
    screen.blit(best_text, (20, 50))
```

这样玩家就能一直看到自己的分数和最高分了，更有动力去突破记录！

## 💡 常见问题与解决

| 常见问题 | 解决方法 |
|----------|----------|
| 深拷贝忘了 import copy | 在文件顶部添加 `import copy` |
| 移动后总是生成新数字 | 检查深拷贝比较逻辑是否正确：必须在移动**前**保存快照，移动**后**再比较 |
| 胜利后游戏直接退出 | 应该显示胜利画面，允许按 R 键重新开始或按任意键继续游戏 |
| 最高分文件读取失败 | 用 try-except 捕获 `FileNotFoundError`，默认返回 0 |
| 棋盘满了但实际还能移动 | 检查 `can_merge()` 的逻辑：水平和垂直方向都要检查（右 + 下，左和上会因为循环自动覆盖） |
| R 键重开时最高分丢失 | 最高分应从文件读取而不是存在变量里，重开时再次 `load_best_score()` 即可 |
| `board_before == board` 不相等但移动没变化 | 确保深拷贝后没有误操作修改了 `board_before`；检查合并逻辑中是否有多余的零移位操作 |
| 分数计算不准确 | 应该在合并时累加分数（每合并一对就把和加到总分），而不是移动后再算差值 |
| 异常退出后 `best_score.txt` 损坏 | 写入前先备份，或使用 JSON 格式存储更健壮（但会增加复杂度，根据学生水平决定是否引入） |
